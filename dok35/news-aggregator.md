# Анализ репозитория: news-aggregator

### 1. Техническая реализация и архитектура
Проект `news-aggregator` представляет собой классическое **Full-Stack веб-приложение**, состоящее из двух частей:
*   **Бэкенд (backend/):** Реализован на Node.js с использованием фреймворка Express. Сервер выступает в роли прокси или API-шлюза (API Gateway) для скрытия ключей доступа к внешним сервисам. Настроены CORS-политики для связи с фронтендом.
*   **Фронтенд (src/):** Реализован на React и TypeScript. Для управления состоянием запросов к серверу (data fetching) и кэширования используется библиотека `@tanstack/react-query`.

Архитектура очень простая (клиент-сервер) без использования баз данных. Бэкенд является stateless.

### 2. Функции и как логически это работает
**Логика работы:**
1.  Пользователь взаимодействует с UI (вводит поисковый запрос или выбирает категорию новостей).
2.  Фронтенд с помощью React Query отправляет GET-запрос на эндпоинт `/api/news` бэкенда, передавая параметры (категория, поиск, страница).
3.  Бэкенд в `backend/index.js` перехватывает этот запрос, добавляет секретный `NEWS_API_KEY` (который хранится в `.env`) и с помощью `axios` формирует запрос к внешнему API (`newsapi.org`).
4.  Если есть поисковый запрос (search), вызывается эндпоинт `/everything`, иначе — `/top-headlines` с указанной категорией.
5.  Полученный JSON-ответ от NewsAPI возвращается клиенту и отрисовывается в компонентах React.

### 3. Обмен информации, память, потоки данных
**Потоки данных:**
`Пользователь -> React Frontend -> Fetch/XHR -> Express Backend -> Axios -> NewsAPI.org -> Express Backend -> React Frontend`. Данные представлены в формате JSON на всем пути следования.

**Управление памятью:**
*   Бэкенд не хранит состояние в оперативной памяти между запросами (Stateless). Вся информация берется из параметров запроса (`req.query`).
*   На фронтенде управление "памятью" (в данном случае — локальным кэшем браузера для загруженных новостей) возложено на `React Query`. `QueryClientProvider` кэширует результаты API-вызовов на определенное время, что минимизирует количество повторных запросов к бэкенду при переключении между категориями, снижая нагрузку на сеть. Состояние компонентов (например, текущая страница) хранится в хуках (useState).
