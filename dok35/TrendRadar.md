# Анализ репозитория: TrendRadar

### 1. Техническая реализация и архитектура
Проект `TrendRadar` — это мощный инструмент для агрегации и анализа горячих новостей на языке **Python**.
*   **Архитектура:** Приложение состоит из ядра (`trendradar/__main__.py`), которое управляет жизненным циклом (загрузка конфигураций, шедулинг, вызов краулеров, анализ через AI, генерация отчетов и уведомления). Структура директорий `trendradar/` отражает модульный монолит: `crawler`, `ai`, `core`, `report`, `notification`, `storage`.
*   **Интеграции:** Присутствует директория `mcp_server`, что указывает на поддержку протокола MCP (Model Context Protocol) для интеграции в экосистемы LLM-инструментов.
*   **Окружение:** Проект поддерживает управление зависимостями через `uv` (современный быстрый пакетный менеджер для Python, присутствует `uv.lock`) и стандартный `requirements.txt`. Предоставляются установочные скрипты для Mac и Windows.

### 2. Функции и как логически это работает
**Логика работы:**
1.  **Настройка контекста (Context):** При запуске (через `__main__.py`) инициализируется `AppContext`, который загружает конфигурации платформ-источников.
2.  **Сбор данных (Crawling):** Модуль `crawler` (в лице `DataFetcher`) делает запросы к различным платформам и парсит популярные темы, посты и новости.
3.  **Унификация и фильтрация:** Сырые результаты парсинга конвертируются в единый формат (`convert_crawl_results_to_news_data`). Происходит фильтрация по датам (модуль `utils.time`) и ключевым словам.
4.  **AI-Анализ:** Модуль `ai` (`AIAnalyzer`) принимает агрегированные новости и передает их в LLM для выделения главных трендов, суммаризации и получения инсайтов (возвращает объект `AIAnalysisResult`).
5.  **Отчеты и Уведомления:** Результаты могут сохраняться в статические файлы (`report`, генерация HTML-дашбордов или Markdown отчетов) и отправляться пользователю (модуль `notification`).

### 3. Обмен информации, память, потоки данных
**Потоки данных:**
`Платформы -> HTTP/Crawlers -> JSON/Dict (Сырые данные) -> Унифицированные структуры Python -> AIAnalyzer (Вызов внешнего LLM API) -> Структурированные инсайты -> Генератор отчетов (HTML/Markdown) / Уведомления`.
При запуске через MCP-сервер (`mcp_server/server.py`), TrendRadar может выступать как источник данных (Tool), отвечая на запросы внешних AI-агентов по стандарту MCP.

**Управление памятью:**
*   Архитектура подразумевает пакетную (batch) обработку. Данные загружаются, агрегируются в памяти в виде списков словарей/объектов Python, обрабатываются и выгружаются.
*   Объект `AppContext` играет роль Singleton-хранилища глобального состояния во время исполнения одного цикла (run).
*   Так как это консольная утилита / cron-job, длительного хранения состояния в памяти не требуется. Все промежуточные результаты сбрасываются в подсистему `storage` (скорее всего, в локальные файлы) между запусками, чтобы избежать OOM (Out Of Memory) при анализе больших массивов новостей за длительный период.
