# Анализ репозитория: genRSS

### 1. Техническая реализация и архитектура
Репозиторий `genRSS` — это консольная утилита (CLI), написанная на **Python**.
*   **Архитектура:** Это простой Python-пакет (`src/generss/`), не использующий сложных фреймворков. Вся бизнес-логика сосредоточена в двух файлах: `__init__.py` (парсинг аргументов и формирование XML) и `util.py` (вспомогательные функции для работы с файловой системой и метаданными).
*   **Зависимости:** Утилита использует стандартные библиотеки Python (`os`, `argparse`, `xml.sax.saxutils` для эскейпинга) и опциональные зависимости для извлечения метаданных из медиафайлов: `mutagen` и `eyed3` (извлечение длительности аудио), а также может использовать внешние команды (subprocess), такие как `ffprobe` (ffmpeg) или `soxi`.
*   **Дистрибуция:** Проект упакован с использованием `pyproject.toml` (современный стандарт сборки) и `setup.py`. Поддерживает запуск напрямую из командной строки.

### 2. Функции и как логически это работает
**Логика работы:**
1.  **Парсинг аргументов:** При запуске `genRSS` пользователь указывает директорию (`-d`) и URL хоста, на котором будут размещены файлы (`-H`).
2.  **Обход директории:** Скрипт сканирует указанную локальную директорию на наличие файлов (с возможностью фильтрации по расширениям).
3.  **Извлечение метаданных:** Для каждого найденного медиафайла утилита пытается определить MIME-тип (через модуль `mimetypes`), размер файла (`os.path.getsize`) и длительность (если это аудио/видео, используя `mutagen`, `eyed3` или вызовы `subprocess` к `ffprobe`/`soxi`).
4.  **Генерация RSS:** Скрипт формирует строку в формате XML, соответствующую спецификации RSS 2.0. Каждый файл становится элементом `<item>` внутри `<channel>`. В качестве ссылки используется комбинация хоста (`-H`) и имени файла. Название `<title>` берется из имени файла или метаданных ID3. Теги эскейпятся с помощью `saxutils.escape`.
5.  **Вывод:** Сгенерированный XML-контент выводится в стандартный поток вывода (STDOUT) или сохраняется в файл (`-o`).

### 3. Обмен информации, память, потоки данных
**Потоки данных:**
Поток данных полностью локальный, за исключением конечного пользователя, потребляющего RSS.
`Локальная файловая система -> Чтение атрибутов файлов -> Python-скрипт (парсинг метаданных) -> Формирование XML-строки -> Вывод в STDOUT / Файл`.
Скрипт не делает сетевых запросов.

**Управление памятью:**
*   Скрипт не читает содержимое медиафайлов целиком в память. Он читает только заголовки (метаданные) с помощью библиотек (`mutagen`) или запрашивает атрибуты файлов у операционной системы (`os.stat`). Это делает потребление памяти крайне низким и константным, независимо от размера файлов.
*   Результирующий XML-файл формируется в виде массива строк, который затем объединяется (через `join`). Для директорий с десятками тысяч файлов это может потребовать некоторого объема оперативной памяти, но в типичных сценариях использования (подкасты, видео-директории) потребление памяти будет ничтожным. Сборщик мусора Python (Garbage Collector) легко справляется с очисткой временных строковых объектов.
