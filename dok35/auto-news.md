# Анализ репозитория: auto-news

### 1. Техническая реализация и архитектура
Репозиторий `auto-news` представляет собой сложное агрегационное приложение, построенное на **Python**. Архитектура системы включает:
*   **Слой данных и интеграций (src/):** Большое количество файлов, отвечающих за интеграцию с различными платформами (Notion через `notion.py`, Reddit через `reddit_agent.py`, RSS).
*   **Оркестрация (dags/):** Использование Apache Airflow (`news_pulling.py`, `collect_weekly.py`) для управления фоновыми задачами и периодического сбора данных.
*   **Интеграция с LLM (src/llm_agent.py):** В проекте активно используется `langchain` для построения пайплайнов обработки естественного языка. Поддерживаются интеграции с ChatOpenAI, ChatOllama и ChatGoogleGenerativeAI, а также используются различные "loader-ы" (WebBaseLoader, YoutubeLoader) для получения сырого контента.
*   **Контейнеризация и деплой:** Проект поставляется с полной поддержкой развертывания (Docker, Helm, ArgoCD).

Архитектура четко разделяет сбор данных (Airflow DAGs), извлечение признаков/суммаризацию (LLM Agents) и хранение результатов (Notion/ChromaDB).

### 2. Функции и как логически это работает
**Логика работы системы:**
1.  **Сбор данных (Ingestion):** По расписанию (определенному в Airflow DAG) запускаются процессы загрузки данных из внешних источников (новости, статьи, транскрипты YouTube видео).
2.  **Анализ и суммаризация (Processing):** Загруженные документы (например, транскрипты) разбиваются на фрагменты (chunks) с помощью `RecursiveCharacterTextSplitter`. Затем они пропускаются через LLM-агентов (langchain chains, например `load_summarize_chain`) для генерации сводок и выделения главных инсайтов.
3.  **Экспорт (Publishing):** Извлеченные знания и сводки форматируются и отправляются в базу данных Notion (взаимодействие через самописный клиент `notion.py`, который парсит и создает блоки Notion: цитаты, параграфы, списки).
Таким образом, система работает как конвейер: `Источник -> Airflow Worker -> Langchain Agent -> Notion API`.

### 3. Обмен информации, память, потоки данных
**Потоки данных:**
*   Внешние API -> `httpx` / Web Loaders -> Внутренние структуры Python (Langchain Documents).
*   Контекст для LLM собирается в оперативной памяти в виде промптов (файлы `llm_prompts.py`) и списков документов.
*   Для долговременной памяти (хранение векторных эмбеддингов для RAG) используется `ChromaDB` и `Milvus` (как видно из файлов `chromadb_cli.py`, `milvus_cli.py`). Это позволяет агентам "запоминать" контекст прошлых новостей.

**Управление памятью:**
Поскольку обработка длинных видео или статей может привести к переполнению контекстного окна LLM или оперативной памяти, система использует чанкинг (разбиение текста на части) через `langchain.text_splitter`. Состояние пайплайна между тасками передается через метаданные Airflow (XComs) или промежуточное хранилище (Redis/MySQL, на что указывают файлы `redis_cli.py` и `mysql_cli.py`).
