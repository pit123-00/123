# Анализ репозитория: yfinance

### 1. Техническая реализация и архитектура
Библиотека `yfinance` — самая популярная **Python** библиотека для скачивания финансовых данных с Yahoo Finance.
*   **Архитектура:** Организована как пакет (`yfinance/`) с разделением логики по специализированным "скраперам" (папка `scrapers/`: `history.py`, `fundamentals.py`, `analysis.py`). Фасад (основная точка входа) находится в модулях `ticker.py` и `base.py`.
*   **Зависимости и Сеть:** Для обхода блокировок со стороны Yahoo Finance используется не стандартный `requests`, а `curl_cffi` (оболочка над libcurl, позволяющая имитировать TLS-отпечатки браузеров, `impersonate="chrome"`). Это критическое отличие архитектуры для борьбы с капчей и банами. Также широко применяются `numpy` и `pandas`.

### 2. Функции и как логически это работает
**Логика работы:**
1.  **Создание Ticker'а:** Пользователь создает объект `yf.Ticker("AAPL")`.
2.  **Ленивая загрузка (Lazy Evaluation):** При создании объекта запросы к серверам не выполняются. Данные загружаются только при обращении к свойствам (например, `ticker.info`) или методам (например, `ticker.history()`).
3.  **Получение данных (History):** Модуль `PriceHistory` извлекает исторические цены. Он отправляет GET-запрос на эндпоинт `v8/finance/chart/AAPL`. Если возникает ошибка Rate Limit или блокировка, библиотека использует модуль `shared` и `utils` для повторных попыток (retries) и обновления cookie/crumb (уникальный токен сессии).
4.  **Восстановление данных (Repair):** У Yahoo Finance иногда бывают пропуски или сплиты в данных. В `scrapers/history.py` реализована сложная математическая логика (с использованием `numpy` и `bisect`) для "ремонта" (repair) графиков и заполнения пропущенных цен на основе других доступных интервалов.
5.  **Возврат:** JSON конвертируется в `pandas.DataFrame`.

### 3. Обмен информации, память, потоки данных
**Потоки данных:**
`Пользователь -> yf.Ticker -> curl_cffi HTTP Client -> Yahoo API -> JSON -> Обработка часовых поясов (dateutil) -> Data Repairing -> pandas.DataFrame -> Пользователь`.
Существует функция массовой загрузки (`yf.download()`), которая использует многопоточность (`threading` или `multiprocessing`) для одновременного скачивания данных по множеству тикеров.

**Управление памятью:**
*   **Кэширование на уровне инстанса:** Класс `PriceHistory` (и другие) использует внутренние словари (например, `self._history_cache = {}`) для кэширования результатов (memoization). Если пользователь запросит историю за один и тот же период дважды, второй раз данные будут отданы из оперативной памяти, а не из сети.
*   **Оптимизация DataFrame:** В последних версиях pandas конвертация JSON в датафреймы выполняется с использованием векторизованных операций C-бэкенда, что значительно снижает потребление RAM. Тем не менее, скачивание минутных данных (1m) за 30 дней по индексу S&P500 одновременно вызовет сильный всплеск потребления памяти (сотни мегабайт), так как все данные должны быть собраны в RAM перед возвратом объединенного MultiIndex DataFrame.
