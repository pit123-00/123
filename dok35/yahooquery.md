# Анализ репозитория: yahooquery

### 1. Техническая реализация и архитектура
Библиотека `yahooquery` является Python-клиентом для доступа к неофициальному API Yahoo Finance.
*   **Архитектура:** Это строго объектно-ориентированная библиотека. Вся логика построена вокруг базового класса `_YahooFinance` (определен в `base.py`), который наследуют основные интерфейсные классы, такие как `Ticker` (для акций) в `ticker.py` и `Research` (для рыночной аналитики).
*   **Интеграции:** Модуль опирается на тяжеловесные библиотеки для обработки данных: `pandas` используется повсеместно для формирования и возврата структур. Для сетевых запросов используется `requests_futures`, позволяющая делать асинхронные HTTP-запросы.
*   **Защита и обход:** Присутствует модуль `headless.py`, который импортирует `selenium` для обхода продвинутых защит (например, для получения файлов cookies или крошек (crumbs), необходимых для доступа к некоторым скрытым эндпоинтам API).

### 2. Функции и как логически это работает
**Логика работы:**
1.  **Инициализация (Ticker):** Пользователь импортирует класс `Ticker` и передает один или список символов (например, 'AAPL', 'MSFT').
2.  **Сессия (Session Management):** При инициализации базового класса `_YahooFinance`, создается HTTP-сессия (`requests`). Библиотека автоматически делает предварительный запрос к Yahoo, чтобы извлечь `crumb` (уникальный токен) и `cookies`, без которых API отклонит последующие запросы.
3.  **Формирование запросов:** При вызове методов, таких как `.history()`, `.financials()` или свойств (например, `ticker.asset_profile`), библиотека формирует URL к скрытым JSON эндпоинтам Yahoo Finance. Символы разбиваются на "чанки" (размером до 1500) для обхода ограничений на длину URL.
4.  **Асинхронный fetch:** Запросы выполняются конкурентно с помощью `requests_futures` (`concurrent.futures.as_completed`).
5.  **Парсинг и Нормализация:** Сырые JSON-ответы очищаются, flattening (выравниваются словари) и конвертируются в `pandas.DataFrame`. Время в форматах Unix Timestamp конвертируется в объекты datetime.

### 3. Обмен информации, память, потоки данных
**Потоки данных:**
`Пользовательский вызов -> _YahooFinance -> Requests_Futures (HTTP GET) -> Yahoo Finance API -> JSON Response -> Утилиты парсинга -> Pandas DataFrame -> Пользователь`.

**Управление памятью:**
*   Для ускорения работы с множественными символами (тикерами) используется пул потоков (Thread Pool через `requests_futures`). Это переводит работу из режима ожидания (I/O Bound) в многопоточный режим.
*   Так как Yahoo API возвращает значительные объемы JSON данных (особенно для истории котировок с интервалом в 1 минуту), создание `pandas.DataFrame` может быть требовательно к оперативной памяти.
*   Для минимизации задержек и экономии памяти при инициализации сетевых соединений активно используется HTTP Keep-Alive (через объекты `requests.Session()`). Это предотвращает накладные расходы (overhead) на постоянное переоткрытие TCP/TLS соединений к серверам Yahoo.
