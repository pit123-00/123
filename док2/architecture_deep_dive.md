# Глубокий анализ архитектуры и потоков данных oh-my-claudecode

## 1. Техническая реализация и архитектура
В основе проекта лежит оркестрация множества LLM-агентов (чаще всего Claude). Архитектура представляет собой систему управления роем (swarm) или командой агентов, где агенты являются экземплярами Claude (или других LLM) с преднастроенными промптами.

**Главный компонент — Оркестратор (Team Leader/Bridge):**
Он управляет "рабочими" (workers) — дочерними CLI-процессами. Оркестратор написан на TypeScript (запускается через Node.js) и использует утилиту **tmux** для изоляции и запуска CLI-процессов.
Каждый "рабочий" агент запускается в отдельной панели tmux (pane) с помощью команды `tmux send-keys` (описано в `src/team/tmux-session.ts`).

Оркестратор отвечает за:
- Создание сессий и управление жизненным циклом (`src/team/runtime.ts`).
- Управление файлами задач (`src/team/task-file-ops.ts`), где используется блокировка файлов для атомарной записи и избежания гонки данных.
- Поддержание каналов связи (`src/team/inbox-outbox.ts`).

## 2. Агенты и конфигурация промптов
Файлы конфигурации агентов лежат в `src/agents/` (например, `architect.ts`, `planner.ts`), где они экспортируют базовые метаданные (допустимые инструменты, уровень сложности, триггеры).

Сами подробные **инструкции/промпты лежат в корневой папке `agents/`** в формате Markdown.
Например:
- `agents/analyst.md` — агент-аналитик извлекает требования.
- `agents/architect.md` — архитектор создает спецификацию (имеет уровень "read-only", то есть ему запрещено редактировать файлы).
- `agents/critic.md` — критик проверяет план реализации.
- `agents/executor.md` — исполнитель, который непосредственно пишет код.

Загрузка промптов происходит с помощью утилиты `loadAgentPrompt()` (в `src/agents/utils.ts`), которая считывает содержимое нужного `md`-файла и передает его в системный промпт соответствующего агента.

**Пайплайн (Skills):**
Как описано в навыке `autopilot` (`skills/autopilot/SKILL.md`), оркестратор читает ввод пользователя и разбивает его на задачи, следуя жесткому фазовому подходу:
*   Аналитик извлекает требования, Архитектор создает спецификацию.
*   Затем Архитектор создает план реализации, а Критик его проверяет.
*   Каждая фаза должна завершиться успешно (быть одобрена проверяющими агентами), прежде чем начнется следующая.

## 3. Обмен информацией и память

Так как агенты работают как изолированные CLI-сессии внутри tmux, они не делят общую оперативную память. Обмен происходит исключительно через файловую систему в скрытой папке `.omc/state/team/`.

**Каналы связи (Inbox / Outbox):**
Для каждого агента создаются файлы `.jsonl` (JSON Lines):
- `inbox.jsonl` (входящие от лидера к агенту)
- `outbox.jsonl` (от агента к лидеру)

Обмен асинхронный. Функция `readNewInboxMessages` (в `src/team/inbox-outbox.ts`) читает файл с использованием "курсора" (сохраняя смещение в байтах в файле `.offset`). Это позволяет оркестратору не читать весь лог общения целиком при каждом обновлении, экономя память и ресурсы (в коде установлен лимит чтения за раз — 10 МБ).

**Система Heartbeat (сердцебиение):**
Чтобы лидер команды понимал, жив ли агент, используется система "сердцебиения" (`src/team/heartbeat.ts`). Агенты регулярно пишут свой текущий статус и timestamp в свой файл `heartbeat.json` внутри `.omc/state/team/{team}/workers/{workerName}/`.
Если файл давно не обновлялся, лидер с помощью таймера-наблюдателя (watchdog) может признать агента "умершим" (stalled) и перезапустить или сообщить об ошибке.

**Внедрение контекста (Bootstrap Overlays):**
Оркестратор "внедряет" контекст, создавая начальные файлы-заглушки (bootstrap overlay) в рабочих директориях агентов до их запуска (`src/team/worker-bootstrap.ts`).
Функция `generateWorkerOverlay` формирует специфичный для агента контент и сохраняет его как локальный файл `AGENTS.md` в скрытой директории рабочего.
При старте CLI-процесса Claude автоматически считывает этот `AGENTS.md`. Благодаря этому LLM понимает свою роль, текущие назначенные задачи (`tasks`), команды для связи (например, `omc team api ...`) и исторический контекст.
