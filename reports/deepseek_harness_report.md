# Отчет 3: Анализ проекта deepseek-harness (DeepSeek AI)

## 1. Архитектура и кодовая база проекта
Проект **deepseek-harness** — это масштабируемый монорепозиторий на **TypeScript**, построенный вокруг модульного компонентного фреймворка **Cordis** (`@deepseek-ai/cordis`).
Ключевые пакеты, реализующие оркестрацию и работу с субагентами:
- `packages/subagent/`:
  - `subagent/src/manager.ts`: центральный диспетчер жизненного цикла субагентов (`SubagentManager`). Отвечает за запуск (`startActivation`), cold resume, контроль лимитов ресурсов и изоляцию сессий.
  - `subagent-spawn-in-process/`: провайдер чистого запуска (`spawn`) дочернего агента. Создает свежий экземпляр `Agent` с чистой собственной сессией, собственным системным промптом и **нулевым контекстом родителя** (полное соответствие требованию `fork_turns="none"`).
  - `subagent-fork-in-process/`: провайдер форка, передающий историю только до последнего `turn/end`.
  - `subagent/src/depth.ts`: монотонный счетчик глубины рекурсии (`subagentDepth`). Хранится в заголовке сессии, предотвращает бесконечные вызовы дочерних агентов.
  - `subagent/src/structured.ts`: scoped-инструмент структурированного вывода (`structured_output`) с валидацией схемы (`ObjectJsonSchema`) и блокировкой повторных вызовов после фиксации терминального результата.
- `packages/team/agent-team/`:
  - `task-board.ts`, `task-graph.ts`, `journal.ts`: механизм общей доски задач и направленного графа зависимостей (`TeamTaskBoard`). Реализует разделение ролей, синхронизацию задач и фиксацию переходов.
- `packages/workflow/workflow-ptc/`:
  - `runtime.ts`: движок выполнения рабочих процессов в изолированной среде VM (`node:vm`) с жесткими лимитами времени/памяти и обсерверами событий.

## 2. Что и как взять для `AGENT_WORKFLOW_FRAMEWORK_RU.md`

Из архитектуры `deepseek-harness` для целевого фреймворка можно заимствовать:

1. **Модель изоляции "Spawn-with-Zero-Context" (Раздел 2.2, 2.5):**
   - **Откуда взять:** `packages/subagent/subagent-spawn-in-process/src/index.ts` и `subagent/src/depth.ts`.
   - **Как применить:** Концепция полного запрета передачи родительского контекста при создании исполнителя (`zero parent context`). Субагенту назначается строго `depth = parent_depth + 1`, и в контракте запрещается создание субагентов второго уровня (`depth >= 1 -> subagents forbidden`).
2. **Гарантия схемы результата через Scoped Structured Output (Раздел 4.1, 7.3, 8.2):**
   - **Откуда взять:** `packages/subagent/subagent/src/structured.ts`.
   - **Как применить:** Включение специального терминального инструмента (или валидатора), который валидирует итоговый JSON по схеме `result_schema` перед принятием результата. Повторный вызов после фиксации результата монотонно блокируется.
3. **Журнал событий и доска задач (Раздел 1.5, 3.4, 7):**
   - **Откуда взять:** `packages/team/agent-team/src/journal.ts` и `task-board.ts`.
   - **Как применить:** Паттерн проекции событий (`projection`), когда состояние реестра (`registry.json`) формируется через последовательный журнал неизменяемых событий (создание задачи, привязка агента, подтверждение части, сдача результата).

## 3. Технические плюсы и минусы `deepseek-harness`

### Плюсы:
- **Четкое разделение Spawn vs Fork:** Реализован чистейший запуск субагента без родительской истории на уровне ядра (`subagent-spawn-in-process`), что полностью совпадает с принципом минимального контекста.
- **Строгий контроль глубины делегирования (`depth.ts`):** Исключает неконтролируемое порождение субагентов субагентами.
- **Монорепозиторная организация сервисов:** Архитектура на основе плагинов Cordis (`Service`, `Context`) позволяет легко включать/выключать модули изоляции, журналирования и инструментов.
- **Изоляция исполнения кода (`workflow-ptc`):** Поддержка выполнения в песочнице VM для скриптовых шагов.

### Минусы:
- **Языковая несовместимость:** Код написан на **TypeScript** с глубоким использованием внутренней экосистемы (Cordis, Schemastery, Typert), что делает невозможным прямой импорт в Python-пайплайн без переписывания.
- **Сложный оверхед экосистемы:** Пакеты тесно связаны между собой сложными внутренними зависимостями (более 50 пакетов в монорепозитории).
- **Отсутствие готового протокола cursor-based chunked reading:** Нет готового механизма постраничной доставки UTF-8 текста фиксированными частями с подтверждением (акками), который прямо предписывается в разделе 5 фреймворка.
