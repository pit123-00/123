# Отчет 4: Анализ проекта harness2-dsh (xisnn/harness2-dsh)

## 1. Назначение и архитектура проекта
Проект **harness2-dsh** — это специализированная утилита на **чистом Python (без внешних зависимостей)**, предназначенная для конвертации древовидных конфигураций агентов (Harness2 harness trees от Google Research) в готовые бандлы пресетов для **DeepSeek Harness (DSH)** (`@deepseek-ai/dsh-agent-preset`).

Архитектура кодовой базы (`src/harness2_dsh/`):
- `tree.py`:
  - Парсер структуры каталогов без внешних библиотек. Считывает компоненты: `systemprompt.md`, `guardrails.md`, `LongTermMEMORY.md`, `tool_descriptions/tool_guidance.md`, скиллы `skills/<name>/SKILL.md`, субагентов `sub_agents/<name>/AGENT.md` и скрипты `scripts/<name>.py`.
  - Умеет извлекать метаданные из YAML Frontmatter (имя, описание) с помощью регулярных выражений (`_FRONTMATTER_RE`).
- `convert.py`:
  - Преобразует дерево инструкций и ролей в валидный DSH-бандл (структура `package.json` + YAML-патч конфигурации Cordis).
  - Отображает роли и субагентов:
    - Всегда активные файлы (`systemprompt`, `guardrails`, `memory`) -> в `dsh-persona` пресета.
    - Скиллы -> в скиллы DSH (`dsh-skill-filesystem.customSkillDirs`).
    - Описания субагентов `sub_agents/<n>/AGENT.md` -> в дочерние пресеты агентов + регистрация в `dsh-tool-subagent`.
    - Скрипты `scripts/<n>.py` -> копируются в бандл и объявляются в блоке персоны.
- `yaml_emit.py`:
  - Детерминированный генератор YAML на чистом Python без зависимостей (`PyYAML`). Гарантирует воспроизводимый вывод конфигураций без искажения типов (чисел, булевых значений YAML 1.1 и кавычек).
- `cli.py`:
  - CLI интерфейс с командами `convert` и `inspect`.

## 2. Чем и как этот проект полезен для вашего случая (`AGENT_WORKFLOW_FRAMEWORK_RU.md`)

Хотя `harness2-dsh` является утилитой конвертации, в контексте вашего фреймворка он решает важную прикладную задачу: **декларативное управление инструкциями ролей, субагентов и автоматическая сборка окружения**.

### 1. Декларативное разделение ролей на диске (Раздел 1.3 и 3)
В `AGENT_WORKFLOW_FRAMEWORK_RU.md` структура проекта требует разделения инструкций:
```text
workflow/
  instructions/
    orchestrator.md
    author.md
    auditor.md
```
Паттерн из `harness2-dsh/tree.py` показывает, как автоматически парсить папки ролей и субагентов:
- Читать метаданные роли из Frontmatter (ограничения, разрешенные инструменты).
- Разделять постоянную системную инструкцию (`systemprompt.md`), правила качества (`guardrails.md`) и ограничения по инструментам (`tool_guidance.md`).

### 2. Сборка контекста субагента без "мусора" (Раздел 2.4, 5.1)
В `convert.py` реализована изоляция: субагент не получает чужие системные промпты или глобальную историю. Для каждого субагента (`sub_agents/<n>/AGENT.md`) компилируется собственный автономный манифест с изолированными правами. Этот подход можно применить в вашем `delivery.py` для формирования файла задания `assignment.json`.

### 3. Детерминированный генератор конфигов (`yaml_emit.py`)
В скриптах управления процессом (`runner.py`, `registry.py`) критически важно сохранять файлы конфигураций и манифестов детерминированно и без внешних тяжелых зависимостей. Код `yaml_emit.py` можно напрямую скопировать в `workflow/scripts/` для генерации воспроизводимых артефактов без необходимости ставить `pyyaml`.

## 3. Технические плюсы и минусы `harness2-dsh`

### Плюсы:
- **Zero dependencies (чистый Python):** Работает на стандартной библиотеке Python `>=3.10`. Никаких сложных рантаймов.
- **Готовый парсер структуры агентов и ролей:** Протестированная логика извлечения спецификаций субагентов, скиллов и скриптов из папок с Markdown-файлами.
- **Автоматическая адаптация под DeepSeek Harness:** Если в качестве базового движка для запуска моделей/агентов вы выберете экосистему DeepSeek Harness, `harness2-dsh` позволит "в один клик" превращать папки с инструкциями вашего фреймворка в исполняемые пресеты DSH.

### Минусы:
- Это инструмент **статической сборки / компиляции манифестов**, а не рантайм-оркестратор. Он не содержит конечного автомата выполнения задач (`State Machine`), не ведет учет квитанций (`ToolReceipt`) и не управляет проверкой выполнения на лету.
- Узкая направленность целевого формата: конвертирует спецификации строго в формат бандлов Cordis/DSH.
