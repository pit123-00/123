# Анализ репозитория whatsapp-api-client-python

## 1. Техническая реализация и архитектура
Библиотека является клиентом-оберткой (wrapper) для REST API сервиса green-api.com, который предоставляет шлюз к WhatsApp.
Архитектура предельно минималистична и прагматична:
- Ядро библиотеки находится в пакете `whatsapp_api_client_python`.
- Главный класс `API.py` выступает в роли фасада, агрегируя различные категории методов (например, `serviceMethods.py`, `device.py` из папки `tools`).
- Поддерживается как синхронный, так и асинхронный вызов методов (демонстрируется в папке `examples/async/` и `examples/sync/`).
- Для HTTP запросов используется библиотека `requests` (или `aiohttp`/аналог для асинхронности). Оборачивание ответов реализовано через класс в `response.py`.

## 2. Функции и как логически это работает
Цель библиотеки — упростить отправку и получение сообщений в WhatsApp через Green-API.
- Разработчик передает `idInstance` и `apiTokenInstance` (ключи от Green-API) при инициализации `GreenAPI`.
- Вызов метода, например, `api.sending.sendMessage(...)`, преобразуется во внутренний вызов HTTP POST на эндпоинт Green-API.
- Библиотека также поддерживает функции настройки вебхуков (`setSettings`) и получения уведомлений (`receiveNotification`) методом long-polling или обработки вебхуков на стороне пользователя.

## 3. Как происходит обмен информации, память, потоки данных и так далее
- **Потоки данных:** Пользовательский код -> Метод Python SDK -> HTTP POST (JSON) -> Сервер Green-API -> Серверы WhatsApp -> Конечное устройство.
- **Обмен информацией:** Абсолютно все данные сериализуются в JSON. Библиотека возвращает объекты `response.py`, которые инкапсулируют статус-код HTTP и само тело ответа, позволяя легко проверять статус успешности операции (`response.code == 200`).
- **Память и состояние:** Библиотека не сохраняет состояние (stateless), кроме учётных данных API, хранящихся в объекте конфигурации в памяти во время исполнения процесса.
