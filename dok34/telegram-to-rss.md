# Анализ репозитория telegram-to-rss

## 1. Техническая реализация и архитектура
Проект реализован на Python и предназначен для конвертации сообщений из Telegram в формат RSS-лент.
Архитектура состоит из нескольких ключевых компонентов:
- Веб-сервер (`server.py`), который предоставляет доступ к сгенерированным RSS-потокам по HTTP.
- Модуль генерации (`generate_feed.py`), отвечающий за форматирование данных в стандарт RSS/Atom.
- Клиентская часть (`client.py` и `poll_telegram.py`), использующая Telegram API (скорее всего через Telethon или Pyrogram) для извлечения сообщений.
- Модуль базы данных (`db.py`), управляющий кэшированием или хранением метаданных.
Все упаковано для использования через Docker (наличие `Dockerfile` и `docker-compose.yml`).

## 2. Функции и как логически это работает
Главная задача — создать персональную RSS-ленту из Telegram-каналов без необходимости использовать само приложение Telegram для чтения.
- Пользователь авторизует приложение в Telegram, используя `api_id` и `api_hash`.
- В фоновом режиме `poll_telegram.py` слушает или периодически запрашивает новые сообщения из выбранных чатов/каналов.
- Полученные сообщения сохраняются в локальной базе (`db.py`) для быстрого доступа.
- При HTTP-запросе к серверу (`server.py`), система обращается к базе данных, берет последние записи и через `generate_feed.py` формирует XML/RSS документ.

## 3. Как происходит обмен информации, память, потоки данных и так далее
- **Потоки данных:** Telegram API (сеть) -> Python клиент -> Локальная БД -> Веб-сервер -> RSS Reader пользователя (HTTP GET).
- **Память и состояние:** Состояние (сообщения, токены авторизации) хранится персистентно в локальной базе данных (вероятно SQLite, судя по `db.py`), что позволяет серверу быстро отдавать ленту без задержек на запросы к Telegram API.
- **Обмен информацией:** Модули используют внутренние модели данных (`models/feed_entry.py`, `models/feed.py`) для типизированного обмена сообщениями внутри приложения, отделяя логику Telegram от логики рендеринга XML.
