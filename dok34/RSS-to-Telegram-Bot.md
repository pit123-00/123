# Анализ репозитория RSS-to-Telegram-Bot

## 1. Техническая реализация и архитектура
Бот написан на Python с использованием асинхронного программирования (`aio_helper.py`, `asyncio`).
Архитектура состоит из:
- Главного цикла приложения `telegramRSSbot.py` / `src/__main__.py`.
- Модулей управления конкурентностью (`locks.py`).
- Системы логирования (`log.py`).
Бот разворачивается как отдельный процесс, конфигурация управляется через внешние файлы/переменные окружения.

## 2. Функции и как логически это работает
Программа работает в обратном направлении (в сравнении с telegram-to-rss): она читает внешние RSS/Atom ленты и пересылает новые статьи в Telegram (в чаты, группы или каналы).
- Подписки и их настройки (форматирование, фильтры) задаются пользователем через команды боту или конфигурацию.
- Встроенный планировщик или асинхронный цикл (с использованием `aiohttp` или аналогов) периодически опрашивает RSS-ленты.
- При обнаружении новой записи бот форматирует ее в HTML/Markdown.
- Форматированное сообщение отправляется через Telegram Bot API (вероятно, используется `python-telegram-bot` или `aiogram`).

## 3. Как происходит обмен информации, память, потоки данных и так далее
- **Потоки данных:** Сторонние RSS-серверы (HTTP GET) -> Асинхронный парсер (XML/RSS -> Python dict) -> Форматтер -> Telegram Bot API (HTTP POST).
- **Память и состояние:** Используется система блокировок (`locks.py`) для предотвращения состояния гонки (race conditions) при параллельной обработке нескольких лент и отправке сообщений. Для отслеживания уже отправленных новостей используются базы данных или локальные кэши.
- **Обмен информацией:** Модули взаимодействуют асинхронно, передавая задачи между корутинами. `aio_helper.py` оборачивает сетевые запросы для неблокирующего ввода-вывода, что критично при опросе сотен RSS-источников.
