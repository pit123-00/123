# Анализ репозитория client-py

## 1. Техническая реализация и архитектура
Это клиентская библиотека на Python (`android_sms_gateway`) для интеграции с мобильным приложением Android SMS Gateway.
- Архитектура основана на паттерне Gateway/Adapter.
- Проект использует `pipenv` (`Pipfile`) для управления зависимостями.
- В модуле `domain.py` определены структуры данных (сообщения, статусы, устройства).
- Сетевая логика абстрагирована в `http.py` (синхронные запросы, возможно через `requests`) и `ahttp.py` (асинхронные запросы).

## 2. Функции и как логически это работает
Библиотека предоставляет разработчикам удобный API для отправки SMS-сообщений через свои собственные Android-устройства, на которых установлено соответствующее приложение (Android SMS Gateway).
- Разработчик инициализирует клиент, передавая URL сервера (где зарегистрировано устройство) и ключи доступа (токены).
- Метод отправки сообщения упаковывает номер телефона получателя и текст сообщения в DTO (Data Transfer Object).
- Далее вызывается HTTP клиент (`http.py`), который отправляет POST-запрос на центральный сервер шлюза.
- Сервер шлюза маршрутизирует этот запрос на физическое Android-устройство через Firebase Cloud Messaging (FCM) или WebSockets, а устройство уже отправляет реальное SMS через сотовую сеть.

## 3. Как происходит обмен информации, память, потоки данных и так далее
- **Потоки данных:** Пользовательский Python-скрипт -> Вызов метода библиотеки -> Формирование HTTP REST запроса -> Сервер (Cloud или Self-hosted) -> Android устройство -> Сотовая сеть оператора.
- **Обмен информацией:** Модуль `domain.py` описывает жесткие контракты (классы или датаклассы), что гарантирует правильную сериализацию в JSON. Возвращаемые сервером ответы о статусе доставки (Delivery Reports) десериализуются обратно в Python-объекты для удобной обработки в коде пользователя.
- **Память и состояние:** Клиент является полностью stateless. Он не кэширует исходящие сообщения и не хранит очередь в локальной памяти; вся маршрутизация и обеспечение доставки (retry-логика) делегируется удаленному серверу шлюза и самому Android-устройству.
