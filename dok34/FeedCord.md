# Анализ репозитория FeedCord

## 1. Техническая реализация и архитектура
Проект разработан на C# (.NET). Архитектура приложения строится на базе принципов внедрения зависимостей (DI) и включает в себя множество слоев абстракции:
- `Program.cs` / `Startup.cs` для настройки сервисов.
- Директория `Infrastructure` содержит воркеры (`FeedWorker.cs`), фабрики (`FeedWorkerFactory.cs`, `NotifierFactory.cs`) и клиенты HTTP (`CustomHttpClient.cs`).
- Директория `Core` включает в себя логирование (`BatchLogger.cs`, `LogAggregator.cs`) и сервисы по созданию payload для Discord (`DiscordPayloadService.cs`).
- Слой сервисов `Services` связывает логику парсинга (`RssParsingService.cs`, `YoutubeParsingService.cs`) с менеджерами (`FeedManager.cs`).
Все сущности разделены интерфейсами (например, `IFeedManager`, `INotifier`), что позволяет легко тестировать и масштабировать систему.

## 2. Функции и как логически это работает
FeedCord предназначен для парсинга различных источников (RSS, YouTube) и уведомления пользователей через Discord.
- После старта `Program.cs` инициализирует `FeedManager`.
- Воркеры из `FeedWorker.cs` запускаются по расписанию. Они используют `CustomHttpClient` для получения XML-лент и HTML страниц (для изображений/видео).
- Парсеры (`RssParsingService`, `ImageParserService`) извлекают необходимую информацию, формируя внутренние объекты `Post`.
- Конфигурации фильтров (`FilterConfigs.cs`) отбрасывают ненужные записи.
- Далее вызывается фабрика уведомлений (`NotifierFactory.cs`), которая создает `DiscordNotifier.cs`.
- Payload формируется с помощью `PostBuilder.cs` и `DiscordPayloadService` и отправляется через Webhook Discord API.

## 3. Как происходит обмен информации, память, потоки данных и так далее
- **Потоки данных:** Сторонние API (RSS/YouTube) -> HTTP Client -> Парсинг (XML/JSON to C# objects) -> Фильтрация -> Формирование JSON Payload -> Discord Webhook API.
- **Память и состояние:** Приложение отслеживает последние прочитанные посты (`FeedState.cs`), вероятно, сохраняя их в памяти во время работы сервиса или сбрасывая на диск. Используются объекты `Post` и `ReferencePost` для хранения состояния между циклами поллинга.
- **Обмен информацией:** Компоненты связаны через DI-контейнер .NET. Обмен информацией строго типизирован. Логирование аггрегируется (`BatchLogger`, `LogAggregator`) для снижения нагрузки при вводе/выводе, обеспечивая высокую стабильность при обработке больших массивов данных.
