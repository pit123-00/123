# Отчёт 3: Архитектурное устройство систем

Данный отчёт посвящён детальному анализу архитектурных шаблонов, слоёв абстракции, границ подсистем и протоколов взаимодействия в проектах [nousresearch/hermes-agent](https://github.com/nousresearch/hermes-agent) и [deepseek-ai/deepseek-harness].

---

## 1. Архитектура hermes-agent

### 1.1. Архитектурный стиль: Модульный Монолит с Фасадом Миксинов
Архитектура `hermes-agent` построена вокруг центрального класса `AIAgent`, выполняющего роль фасада и оркестратора над набором специализированных модулей:

```
+-------------------------------------------------------------------+
|                            AIAgent                                |
|  +---------------------+  +-----------------+  +---------------+  |
|  | ClientLifecycleMixin|  | StreamDelivery  |  | TurnFacade    |  |
|  +---------------------+  +-----------------+  +---------------+  |
|  | InterruptControl    |  | RateLimitCredits|  | SessionPersist|  |
|  +---------------------+  +-----------------+  +---------------+  |
+---------------------------------+---------------------------------+
                                  |
        +-------------------------+-------------------------+
        |                         |                         |
        v                         v                         v
+-----------------+      +-----------------+      +-----------------+
|  SQLite State   |      |  Tool Execution |      |  Skills/Plugins |
| (WAL, Sessions, |      |  (Terminal,     |      |  (AST Audit,    |
|  Messages, FTS) |      |   Docker, Web)  |      |   Dynamic Load) |
+-----------------+      +-----------------+      +-----------------+
```

### 1.2. Основные архитектурные слои hermes-agent
1. **Слой представления (Presentation & UI):**
   - `hermes_cli/` — CLI-парсер, интерактивный REPL, управление конфигурацией (`config.yaml`).
   - `ui-tui/` — терминальный интерфейс на базе Rich/Textual с поддержкой вывода статусов, индикаторов затрат, списков сессий и горячих клавиш.
   - `gateway/` — фоновый веб-сервер и WebSocket-шлюз (`gateway/session_worker_delegation.py`) для подключения внешних клиентов (включая десктопные обёртки).
2. **Слой оркестрации агента (Agent Core):**
   - Директория `agent/` содержит свыше 350 файлов, каждый из которых отвечает за узкую функциональность (например, `turn_context_compaction.py`, `reasoning_timeouts.py`, `empty_response_guard.py`).
   - Модель расширения основана на прямом импорте и вызове функций в едином процессе.
3. **Слой инструментов и песочниц (Tools & Sandboxes):**
   - `tools/` — более 290 модулей. Инструменты регистрируются через `tools/toolsets.py`.
   - Включает системные инструменты (`file_tools.py`, `terminal_tool.py`), интеграции с внешними API (`web_search_provider.py`) и поддержку протокола MCP (Model Context Protocol).
4. **Слой персистентности (Persistence Layer):**
   - Реализован как плоский реляционный движок на базе SQLite: `hermes_state_*.py`.
   - Используются прямые SQL-запросы без ORM, что минимизирует накладные расходы и гарантирует предсказуемое время отклика.

## 2. Архитектура deepseek-harness

### 2.1. Архитектурный стиль: Микроядерный Inversion of Control (IoC) фреймворк
`deepseek-harness` спроектирован на основе фреймворка **Cordis**, аналогичного по своей концепции OSGi в мире Java или микроядру VS Code:

```
+-------------------------------------------------------------------+
|                          Cordis Kernel                            |
|             (Context, Dependency Injection, Life Cycle)           |
+---------------------------------+---------------------------------+
                                  |
            +---------------------+---------------------+
            |                     |                     |
            v                     v                     v
+-----------------------+ +-------------------+ +-------------------+
|   Capability Seams    | |  Event Sourced    | |  Isolated Runtime |
| - ctx.subagents       | |     Session       | | - Native Executor |
| - ctx.llm             | | - Append-only log | | - PTC Worker RPC  |
| - ctx.ptcRuntime      | | - Projections     | | - Sandbox Policy  |
| - ctx.settings        | | - State Forks     | | - Win32/Linux ACL |
+-----------------------+ +-------------------+ +-------------------+
            ^                     ^                     ^
            |                     |                     |
+-----------+---------------------+---------------------+-----------+
|                           Cordis Plugins                          |
|  (@deepseek-ai/dsh-subagent-spawn-in-process, -fork, -acp, etc.)  |
+-------------------------------------------------------------------+
```

### 2.2. Основные концепции архитектуры deepseek-harness
1. **Capability Seams («Швы возможностей»):**
   - Ни один модуль не зависит от конкретной реализации сервиса.
   - Базовые пакеты объявляют абстрактные контракты:
     - `@deepseek-ai/dsh-subagent` объявляет `ctx.subagents`.
     - `@deepseek-ai/dsh-ptc-runtime` объявляет `ctx.ptcRuntime`.
     - `@deepseek-ai/dsh-llm` объявляет `ctx.llm`.
   - Реализации поставляются в виде отдельных взаимозаменяемых плагинов (например, `subagent-spawn-in-process`, `subagent-fork-in-process`, `subagent-acp`, `subagent-claude-code`).
2. **Событийно-ориентированное состояние (Event-Sourcing):**
   - Все изменения состояния сессии происходят исключительно через добавление событий (`SessionEvent`).
   - Любой компонент (UI, телеметрия, детекторы зацикливаний, индексаторы) является подписчиком на поток событий и строит собственные независимые проекции.
3. **Строгое разделение Host и Client:**
   - Пакеты четко разграничены: `packages/host/` отвечает за работу с ОС, процессами, файловой системой и демонами; `packages/client/` содержит реактивные UI-компоненты (на базе Vue/Solid/React) и протоколы связи; `packages/api/` реализует контроллеры и RPC.
4. **Протокол ACP (Agent Client Protocol):**
   - Стандартизированный протокол взаимодействия агент-клиент, позволяющий запускать `deepseek-harness` как headless-сервер и управлять им удаленно.

## 3. Сравнительный анализ архитектурных решений

| Архитектурный аспект | `hermes-agent` | `deepseek-ai/deepseek-harness` |
| :--- | :--- | :--- |
| **Степень связности (Coupling)** | Средняя / Высокая. Большинство компонентов полагаются на интерфейс `AIAgent` и общие глобальные константы | Экстремально низкая (Loose coupling). Зависимости инжектируются через `Context` Cordis по строгим контрактам |
| **Масштабируемость кода** | Усложняется добавлением новых миксинов и утилит в `agent/` (более 350 файлов в одной папке) | Высокая масштабируемость благодаря pnpm-воркспейсам и независимым npm-пакетам со своими `package.json` |
| **Тестируемость (Testability)** | Тестирование через интеграционные тесты с моками SQLite и LLM-клиентов (`tests/tools/`, `tests/agent/`) | Модульное тестирование в изоляции через фикстуры Cordis Context и замену сервисов моками в Vitest |
| **Изоляция сбоев** | Сбой в обработчике тула перехватывается в цикле `run_conversation`, но память и ресурсы делят один процесс | Сбой в PTC-воркере изолирован на уровне отдельного дочернего процесса ОС; ядро Harness остаётся стабильным |
| **Протоколы интеграции** | Собственный WebSocket Gateway + REST-эндпоинты | Стандартизированный Agent Client Protocol (ACP), Typed JSON RPC, Cordis Service Bus |

## 4. Резюме архитектурного анализа
Архитектура **hermes-agent** оптимизирована для быстрого прототипирования, высокой скорости выполнения на Python и плотной интеграции с локальной ОС и инструментарием разработчика. Она представляет собой высокоразвитый практический монолит.

Архитектура **deepseek-harness** создана по канонам сложного корпоративного системного ПО, разделенного на десятки сервисов с инверсией управления. Это делает её идеальным фундаментом для построения масштабируемых платформ, облачных IDE, десктопных комбайнов и распределённых мультиагентных сетей.
