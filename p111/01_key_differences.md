# Отчёт №1: Ключевые отличия между проектами ai-proxy и EasyCLIProxyAPI

Данный сравнительный отчёт составлен на основе прямого и всестороннего анализа исходного кода обоих репозиториев (без использования обзорной документации README).

---

## 1. Концептуальное и целевое назначение проектов

| Критерий | `ai-proxy` (`lee-to/ai-proxy`) | `EasyCLIProxyAPI` (`router-for-me/EasyCLIProxyAPI`) |
| :--- | :--- | :--- |
| **Ключевая роль в экосистеме** | **DLP & Security Redaction Proxy (Шлюз безопасности и санитизации)**. Специализированный высокопроизводительный обратный и MITM-прокси, задача которого — перехват, обнаружение и маскирование конфиденциальных данных (API-ключи, токены, пароли, PII) перед отправкой во внешние LLM-провайдеры, а также восстановление замаскированных данных в потоковых ответах. | **Agent Hub & Multi-Provider Router Manager (Десктопная платформа управления агентами и маршрутизацией)**. Полномасштабный графический центр управления локальным прокси-ядром (`cli-proxy-api`), сессиями, субагентами, MCP-серверами, квотами, OAuth-токенами и автоматической конфигурацией 16+ сторонних AI CLI/GUI клиентов. |
| **Форм-фактор и интерфейс** | Консольный автономный сервис (CLI-демон/сервер), управляемый через файл `config.toml` и переменные окружения, с опциональным встроенным легковесным веб-дашбордом телеметрии (HTML/SSE). | Кроссплатформенное десктопное приложение (Tauri 2 + React 19 + TypeScript + Go-плагины), системный трей, глубокие графические редакторы параметров и конфигураций. |
| **Уровень воздействия на агентов** | **Сетевой уровень (L7 MITM / Reverse HTTP)**. Прозрачный посредник в сетевом трафике между агентом и апстримом. Не управляет локальными файлами агентов, их установкой или запуском. | **Системный и конфигурационный уровень (OS Process + File Patching)**. Прямое обнаружение установленных CLI-агентов в ОС, инъекция настроек в их внутренние конфигурационные файлы (`~/.claude.json`, `~/.codex/config.toml`, `.openclaw/`, и др.), транзакционный rollback изменений, запуск через эмуляторы терминалов. |

## 2. Сравнительный анализ поддерживаемых протоколов и моделей сетевого взаимодействия

### Сетевая модель `ai-proxy`
* **Прозрачный MITM через HTTP CONNECT**: Реализует полноценный TLS-терминатор (`mitm.rs`) на базе динамической генерации сертификатов через `rcgen` для любого запрашиваемого домена, перехватывая вызовы HTTPS от агентов, которым настроен `HTTP_PROXY` / `HTTPS_PROXY`.
* **Reverse Proxy Mode**: Прямой маршрутизатор входящих путей. Например, автоматическое разделение между Anthropic (`/v1/messages`) и OpenAI/Codex (`/v1/responses`, `/backend-api/codex/responses`).
* **Полнодуплексный WebSocket Inspection**: Перехват и расшифровка двунаправленного WebSocket-трафика (`tokio-tungstenite`) с маскированием данных на лету в текстовых фреймах.
* **Тонкая нормализация подписок Codex**: Автоматически нормализует запросы подписок ChatGPT/Codex (флаг `store: false` и очистка служебных полей).

### Сетевая модель `EasyCLIProxyAPI`
* **Управление локальным ядром прокси**: Запускает и контролирует дочерний бинарный процесс ядра (`cli-proxy-api`) на локальном порту (по умолчанию `8317`).
* **Встроенный TLS Reverse Proxy (`reverse_proxy.rs`)**: Легковесный проксирующий сервер на `hyper 1.0` + `rustls`, предназначенный для защиты самого ядра (биндинг ядра на loopback `127.0.0.1` и публикация наружу по HTTPS через порт 443 с hardening-параметрами).
* **Multi-Family маршрутизация провайдеров**: Полномасштабный диспетчер десятков провайдеров: `codex`, `claude`, `gemini`, `vertex`, `xai`, `meta`, `openai-compatibility`. Поддержка балансировки (`round-robin`, `weighted-round-robin`, `fill-first`), `session-affinity` с настраиваемым TTL, автокулдауна при ошибках и пула учетных записей.

## 3. Матрица функциональных различий по ключевым подсистемам

| Подсистема | `ai-proxy` | `EasyCLIProxyAPI` |
| :--- | :--- | :--- |
| **Безопасность и DLP (Data Loss Prevention)** | **Ядро функционала**. Многоуровневый конвейер: регулярные выражения, энтропийный анализ Шеннона с оценкой расстояния до ключевых слов, структурный парсер (JWT, JDBC/Postgres/MySQL connection strings, ENV-блоки), валидация через локальные LLM (Ollama) и адаптер OpenAI Privacy Filter (`opf`). | **Базовый фильтр ключевых слов (Sensitive Words)**. Управление списком запрещенных/чувствительных слов на уровне ядра прокси, а также переключатель `privacy_mode` для сокрытия чувствительных идентификаторов в GUI при демонстрации экрана. |
| **Восстановление данных (Response Restoration)** | **Поддерживается (Stateful Response Restore)**. Запоминает плейсхолдеры в контексте запроса (`RedactionContext`) и восстанавливает исходные значения (email, телефоны и др.) в потоковых ответах SSE без дешифровки секретов провайдером. | **Не поддерживается**. Трафик не модифицируется с целью подмены/восстановления секретов; ядро ориентировано на корректную передачу и адаптацию API. |
| **Управление агентами (AI Clients)** | **Отсутствует**. Агент рассматривается как произвольный сетевой клиент HTTP/HTTPS. | **Глубокая оркестрация 16+ клиентов**: Claude Code, Claude Desktop, Codex CLI, OpenCode, OpenClaw, Hermes, DeepSeek Harness, ZCode, Workbuddy, Antigravity CLI, Copilot CLI, VSCode Copilot, Kimi Code, Grok Build, OMP, Pi. |
| **Управление субагентами** | **Отсутствует**. | **Специализированные модули**: управление субагентами для `zcode` (парсинг и генерация markdown-спецификаций субагентов, привязка инструментов и `thoughtLevel`), для `codex` (настройка `default_subagent_model`, `default_subagent_reasoning_effort`), для `deepseek-harness` (Cordis patch субагентов). |
| **Управление сессиями агентов** | Запись истории запросов/ответов в SQLite телеметрию; возможность воспроизведения контекста отсутствует. | **Полноценный Codex Session Manager**: интроспекция локальной БД Codex SQLite (`~/.codex/`), поиск сессий, просмотр веток сообщений, удаление, экспорт контекста, восстановление поврежденных сессий (`repair_corrupted_sessions`). |
| **Интеграция с протоколами инструментов (MCP)** | Отсутствует. Проксирует только HTTP/WS вызовы моделей. | **Полноценный реестр MCP-серверов (`mcp_servers.rs`)**: CRUD для stdio, SSE и HTTP MCP-серверов, импорт/экспорт конфигураций, динамическое включение/выключение серверов. |
| **Система плагинов** | Фиксированная архитектура сканеров, компилируемая в бинарный файл (хотя есть поддержка внешнего CLI/HTTP для сканеров). | **Динамическая архитектура плагинов**: поддержка внешних Go-плагинов (`semantic-router`, `weekly-reset-priority`), интеграция с GitHub Releases для автообновления, локальная установка zip/tar.gz плагинов. |
| **Телеметрия и учет токенов** | SQLite БД на базе ULID: сбор токенов (`TokenUsageRecord`), времени запроса, детекция вызовов инструментов (`ToolEventRecord`), запись превью запросов/ответов с обязательной санитизацией перед сохранением. | SQLite + JSON агрегатор: парсинг локальных логов использования агентов (`agent_usage.rs`), расчет затрат на основе каталога цен моделей (`model_prices.json`), учет по провайдерам, дням, часам и типам токенов. |

## 4. Глубокие различия в конфигурации

### Конфигурация в `ai-proxy`
Определяется файлом `config.toml`. Основной фокус на сетевых параметрах безопасности и правилах санитизации:
* `[proxy]`: `listen_addr`, `anthropic_upstream_url`, `codex_upstream_url`, `codex_subscription_url`, `codex_subscription_routing_enabled`, `mitm_enabled`, `mitm_ca_cert_path`, `mitm_cert_cache_size`, `mitm_excluded_hosts`, `websocket_mode` (`reject` | `passthrough` | `inspect`).
* `[redaction]`: `strategy` (`partial` | `mask`), `prefix_len`, `suffix_len`, `mask`, `response_restore_enabled`, `restorable_categories`.
* `[scanner]`: `scan_scope` (`body` | `full`), `header_whitelist`.
* `[scanner.entropy]`: `threshold`, `min_length`, `max_length`, `keywords`, `keyword_proximity`.
* `[scanner.structural]`: `detect_jwt`, `detect_connection_strings`, `detect_env_patterns`.
* `[scanner.model]` & `[scanner.privacy_filter]`: `mode` (`hybrid` | `verify_only` | `direct`), `endpoint`, `timeout_ms`, `fail_policy` (`regex_only` | `fail_closed`).

### Конфигурация в `EasyCLIProxyAPI`
Определяется иерархическим YAML-документом ядра (`config.yaml`), настройками GUI (`tauri.conf.json`) и файлами профилей агентов:
* `server`: `host`, `port`, `trusted-proxies`.
* `routing`: `strategy` (`round-robin`, `weighted-round-robin`, `fill-first`), `session-affinity`, `session-affinity-ttl`, `retry` (`request-retry`, `max-retry-credentials`, `max-retry-interval`), `cooldown` (`disable-cooling`, `transient-error-cooldown-seconds`).
* `providers`: группы провайдеров, веса моделей, переопределение URL, таймауты, сопоставление заголовков и параметров авторизации (OAuth, API-Keys, Bearer tokens).
* `agents`: профили интеграции агентов, пути к исполняемым файлам, сопоставление моделей (Opus/Sonnet/Haiku), переопределение аргументов запуска в терминале.
* `plugins`: каталоги плагинов, приоритеты, локальные хранилища манифестов.

## 5. Выводы по первому отчёту

* Проект **`ai-proxy`** представляет собой **специализированное решение информационной безопасности (Security Gateway / DLP)**. Его назначение — защитить пользователя или компанию от случайной утечки секретов и персональных данных в облачные модели через агентов кодинга.
* Проект **`EasyCLIProxyAPI`** представляет собой **комплексную платформу управления и оркестрации (Enterprise Agent Hub)**. Его назначение — устранить фрагментацию локальных инструментов разработчика, предоставить централизованное управление ключами, мульти-провайдерной маршрутизацией, сессиями, квотами и конфигурациями множества различных автономных агентов.
