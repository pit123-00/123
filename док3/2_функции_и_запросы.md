# Какие есть функции, как писать запросы и их отличия от SQL Postgres

## Функции
SereneDB поддерживает множество стандартных скалярных, оконных и агрегатных SQL-функций (на базе фреймворка Meta Velox). Однако, её главная особенность — это встроенные в движок функции для текстового и векторного поиска.

Среди специфичных поисковых функций в движке (на основе IResearch):
1. **Полнотекстовый поиск (BM25, TF-IDF):** Эффективный поиск токенов с ранжированием по релевантности.
2. **Нечеткий поиск (Fuzzy):** Функции вроде `sdb_levenshtein_match` (по расстоянию Левенштейна) и `sdb_ngram_match` (n-граммы).
3. **Векторный поиск (ANN):** Встроенные функции для расчета косинусного расстояния (Cosine Similarity), Евклидова расстояния (L2 Distance).
4. **Гибридный поиск (Hybrid Ranking):** Одновременное ранжирование результатов по тексту (BM25) и по вектору.

## Как писать запросы
Запросы пишутся на стандартном SQL, так как парсер взят напрямую из PostgreSQL (через `libpg_query`).
Вы можете писать стандартные `SELECT`, `JOIN`, `GROUP BY`, `ORDER BY`.

```sql
SELECT title, content
FROM documents
WHERE sdb_levenshtein_match(content, 'postgres', 1);
```

Специфичные настройки поиска (например, анализаторы для токенизации текста, стемминг, стоп-слова) задаются обычно на этапе DDL (создание таблиц) через опции таблиц и колонок, так как это база данных со встроенными Lucene-подобными возможностями.

## Отличия от обычных SQL запросов Postgres
1. **Функции поиска в WHERE:** В Postgres для полнотекстового поиска используются операторы `@@` и типы `tsvector` / `tsquery`. В SereneDB используются специальные функции `MATCH` с параметрами.
2. **Ранжирование:** В Postgres для ранжирования используется `ts_rank`. В SereneDB ранжирование встроено в поисковый движок IResearch и работает прозрачно и быстрее для сложных комбинаций предикатов.
3. **Обновления в реальном времени:** SereneDB оптимизирована на "колоночные обновления в реальном времени" (Column-wise updates), что в SQL-синтаксисе выглядит как обычные `INSERT`/`UPDATE`, но под капотом обрабатывается движком RocksDB и IResearch без просадок производительности аналитики.
4. **Отсутствие транзакционных ограничений:** Вы не можете использовать конструкции типа `BEGIN ... COMMIT` (или они будут проигнорированы), `FOR UPDATE`, или полагаться на `UNIQUE` constraints (зависит от конкретной реализации DDL SereneDB, так как она колоночная).
