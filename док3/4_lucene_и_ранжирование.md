# Подробнее: встроенные Lucene-подобные возможности и ранжирование

Одной из самых главных отличительных черт SereneDB является интеграция продвинутых поисковых функций в само ядро базы данных.

## Что означает "встроенные Lucene-подобные возможности"?
Обычно реляционные базы данных (как Postgres или MySQL) используют B-Tree индексы, которые хороши для точного поиска (`id = 5` или `date > '2025-01-01'`).
Для полнотекстового поиска по большим объемам текста (с опечатками, морфологией, синонимами, ранжированием по релевантности) стандартно применяют поисковые движки, такие как Elasticsearch или Solr. Они основаны на библиотеке **Apache Lucene**.

В SereneDB разработчики пошли другим путем: они встроили в базу данных **IResearch** — это C++ библиотека для поиска, которая является высокопроизводительным налогом Lucene.
В исходниках SereneDB (`libs/iresearch`) есть даже парсер Lucene-синтаксиса (`lucene_parser.cpp`). Это значит, что SereneDB может разбирать сложные поисковые запросы, к которым привыкли пользователи Elasticsearch.

**Благодаря IResearch, внутри SQL базы данных доступны:**
1. Инвертированные индексы (Inverted indices) для мгновенного поиска по тексту.
2. Анализаторы текста (Text Analyzers) для токенизации, удаления стоп-слов, стемминга.
3. Нечеткий поиск (Fuzzy search) с поддержкой N-грамм и расстояния Левенштейна.
4. Вычисление релевантности документов (Scoring/Ranking) через алгоритмы BM25 и TF-IDF.

В классическом паттерне вы храните структуру и транзакции в Postgres, а затем асинхронно переливаете текстовые данные в Elasticsearch для поиска. SereneDB позволяет хранить данные и искать по ним в *одной системе* с высокой скоростью.

## Ранжирование: Postgres (ts_rank) против SereneDB (BM25)

Когда вы ищете текст, вам недостаточно просто найти документы, в которых есть искомое слово. Нужно **отсортировать их по релевантности** (насколько хорошо документ соответствует запросу).

### Как это делает PostgreSQL
В Postgres для этого используются функции полнотекстового поиска `ts_vector` и `ts_query`.
Для оценки релевантности применяется функция **`ts_rank`** или **`ts_rank_cd`** (Cover Density).
Пример:
```sql
SELECT title, ts_rank(to_tsvector('english', body), to_tsquery('english', 'database & search')) as rank
FROM documents
ORDER BY rank DESC;
```
*Минусы Postgres:* `ts_rank` работает относительно медленно на больших объемах данных, потому что для расчета ему часто нужно читать сами данные из таблицы (Heap fetches), а возможности кастомизации формул (TF-IDF/BM25) сильно ограничены.

### Как это делает SereneDB
SereneDB использует современные алгоритмы ранжирования из IResearch, в первую очередь **BM25** (лучший стандарт в индустрии, используемый в Elasticsearch) и **TF-IDF**.
Поиск и ранжирование (Scoring) встроены глубоко в движок выполнения запросов.

Пример в SereneDB (внутренняя реализация SQL парсера перехватывает функции):
```sql
SELECT title, bm25(2.0, 0.75) AS score
FROM documents
WHERE sdb_ngram_match(content, 'database search', 0.8)
ORDER BY score DESC;
```
*(где 2.0 и 0.75 — это параметры k1 и b для алгоритма BM25).*

**Преимущества ранжирования в SereneDB:**
1. **Скорость:** Оценка BM25 считается на лету прямо при чтении инвертированного индекса IResearch (в С++ коде), без необходимости доставать "толстые" строки из основного хранилища.
2. **Гибридный поиск (Hybrid Ranking):** SereneDB умеет объединять релевантность текста (BM25) с релевантностью векторного поиска (например, вектор из нейросети), позволяя легко реализовать RAG (Retrieval-Augmented Generation) прямо SQL-запросом.
3. **Настройки:** Вы можете управлять параметрами алгоритма BM25 (настраивать вес частоты терминов `k1` и влияние длины документа `b`), чтобы точно настроить выдачу под свою предметную область.
