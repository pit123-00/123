# Анализ архитектуры памяти SimpleMem

## 1. Введение
В данном отчете представлен подробный анализ логики и технической реализации проекта SimpleMem (`aiming-lab/SimpleMem`). Основное внимание уделено процессу построения памяти (`memory_builder.py`): семантическому структурированному сжатию диалогов и гибридному извлечению информации (`hybrid_retriever.py`).

## 2. Логическое устройство
SimpleMem решает проблему разрастания контекста в диалогах с AI, преобразуя сырые текстовые переписки в структурированные, автономные и сжатые "юниты памяти".

Пайплайн делится на стадии:
1.  **Семантическое Структурированное Сжатие (Stage 1 & 2):** Сырые диалоги разбиваются на "скользящие окна" (Sliding Window). Затем LLM анализирует каждое окно и извлекает факты. При этом происходит разрешение кореференций (местоимения вроде "он/она/это" заменяются на конкретные имена) и относительные временные метки ("завтра") преобразуются в абсолютные ISO форматы.
2.  **Индексация в нескольких слоях:** Полученные факты сохраняются в трех представлениях:
    *   **Semantic:** Плотные вектора (embeddings) для поиска по смыслу.
    *   **Lexical:** Ключевые слова (BM25) для точного поиска терминов.
    *   **Symbolic:** Метаданные (время, персоны, локации, сущности) для жесткой фильтрации.
3.  **Гибридный ретривер (Stage 3 - Hybrid Retriever):** При получении запроса система строит "план поиска" (infer search intent) и распараллеливает запросы в три слоя, после чего объединяет (merging) и ранжирует результаты для ответа агента.

## 3. Техническая реализация в коде

### 3.1 Класс `MemoryBuilder`
*   **Буферизация и Sliding Window:** Метод `add_dialogues_parallel` накапливает сообщения в `self.dialogue_buffer`. Сообщения разбиваются на чанки размером `window_size` с перекрытием `overlap_size`. Перекрытие гарантирует, что контекст на стыках окон не будет потерян.
*   **Использование пула потоков:** С помощью `concurrent.futures.ThreadPoolExecutor` окна обрабатываются параллельно (метод `_process_windows_parallel`).
*   **Извлечение через LLM:** Функция `_build_extraction_prompt` содержит строгие инструкции для LLM. Она требует возвращать JSON, запрещает местоимения (Force Disambiguation) и требует формировать `lossless_restatement` — полное, независимое, понятное вне контекста предложение (например: "Alice suggested at 2025-11-15T14:30:00 to meet with Bob...").
*   **Контекст окон:** При обработке текущего окна LLM передаются последние 3 извлеченных факта (из `self.previous_entries`) для предотвращения дублирования памяти.

### 3.2 Класс `HybridRetriever`
*   Реализует поиск по трем направлениям: `semantic_top_k`, `keyword_top_k`, `structured_top_k`.
*   Логика планирования: с помощью LLM определяет, какие параметры поиска важны для текущего запроса (нужен ли поиск по точному слову, семантике или фильтр по дате). Затем параллельно выполняет запросы в базу данных и формирует единый список `C_q = R_sem ∪ R_lex ∪ R_sym`.

## 4. Инструкция: Как повторить это в вашем проекте

Чтобы внедрить систему памяти со сжатием и гибридным поиском, выполните следующие шаги:

### Шаг 1: Механизм скользящего окна
Вместо того чтобы подавать в память сообщения по одному, реализуйте буфер на стороне вашего бэкенда (например, в Redis).
Как только в буфере накапливается, скажем, 10 сообщений, берите 10 сообщений + 2 последних сообщения из предыдущего окна (overlap) и отправляйте их на обработку (сжатие).

### Шаг 2: Промпт для сжатия и де-референсинга
Ключевая фишка SimpleMem — правильный промпт. Создайте задачу для LLM:
```text
Твоя задача — извлечь все факты из диалога и вернуть их в формате JSON.
Правила:
1. НИКАКИХ МЕСТОИМЕНИЙ. Заменяй "он/она" на имена. Заменяй "завтра" на конкретную дату (сегодня: [текущая дата]).
2. Каждый факт должен быть независимым предложением (lossless_restatement).
3. Укажи ключевые слова, людей и локации.
Пример выхода:
[
  {
    "lossless_restatement": "Иван согласился встретиться с Марией в ресторане 'Пушкин' 2023-10-15 в 18:00.",
    "keywords": ["встреча", "ресторан"],
    "persons": ["Иван", "Мария"],
    "timestamp": "2023-10-15T18:00:00"
  }
]
```

### Шаг 3: Сохранение и индексация (База данных)
Возьмите векторную БД, которая поддерживает хранение метаданных (Milvus, Qdrant или PostgreSQL с pgvector).
1. Рассчитайте вектор (embedding) для поля `lossless_restatement` и сохраните его.
2. Сохраните поля `persons`, `timestamp`, `keywords` как метаданные (дополнительные колонки или JSON-поле).
3. Дополнительно можно использовать полнотекстовый поиск (например, ElasticSearch или PostgreSQL `tsvector`) по тексту `lossless_restatement` для покрытия лексического поиска.

### Шаг 4: Гибридный Retrieval (Поиск)
При запросе пользователя:
1. Выполните семантический поиск (по вектору) -> Топ 5.
2. Выполните лексический поиск (по ключевым словам в полнотекстовом индексе) -> Топ 5.
3. Объедините результаты, удалите дубликаты и передайте их как контекст ("память агента") в основной промпт перед генерацией ответа.
