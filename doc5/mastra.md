# Анализ архитектуры памяти и клонирования тредов Mastra

## 1. Введение
В данном отчете рассмотрена подсистема памяти фреймворка Mastra, реализованная в модуле `@mastra/memory` (`packages/memory/src/index.ts`). Разобраны механизмы хранения истории чатов, работа с векторными представлениями (Semantic Recall) и, самое главное, логика клонирования тредов (историй переписок) с сохранением метаданных в постоянном хранилище (например, PostgreSQL).

## 2. Логическое устройство
Подсистема памяти Mastra предназначена для надежного хранения контекста диалогов (тредов) между агентом и пользователем.

**Ключевые концепции:**
*   **Threads (Треды):** Сессии общения. Тред объединяет сообщения в единый контекст.
*   **Клонирование (Clone history):** Иногда агенту или пользователю нужно создать "ответвление" от существующего диалога, чтобы не портить исходный контекст (например, для проверки другой гипотезы). Система позволяет клонировать тред, создавая новый `threadId`, но сохраняя связь с оригиналом через `cloneMetadata`.
*   **Semantic Recall (Семантический возврат):** Сообщения автоматически векторизуются (embedding) и сохраняются в векторной базе. При необходимости агент может искать релевантные прошлые сообщения не только по ID, но и по смыслу.
*   **Observational Memory:** Механизм, который анализирует историю и извлекает долгосрочные наблюдения (факты о пользователе).

## 3. Техническая реализация в коде

Класс `Memory` (наследующий внутренний базовый класс `MastraMemory`) отвечает за интеграцию БД (Postgres) и Векторной БД.

### 3.1 Клонирование тредов
В коде реализованы методы для отслеживания и управления клонированными тредами:
*   `getCloneMetadata(thread)`: Извлекает объект `ThreadCloneMetadata` из метаданных треда (поля `metadata.clone`). Этот объект содержит `sourceThreadId` (ID оригинального треда).
*   `isClone(thread)`: Удобная обертка, возвращающая `True`, если тред является клоном.
*   `getSourceThread(threadId)`: Загружает тред по ID, извлекает его `sourceThreadId` и загружает родительский тред.
*   `getCloneHistory(threadId)`: Проходит в цикле `while` по всем родителям треда, используя `cloneMetadata.sourceThreadId`, и выстраивает полную цепочку (историю ветвления) от самого первого оригинала до текущего клона.

### 3.2 Семантическая память (`SemanticRecall`)
Метод `embedClonedMessages` обрабатывает сообщения для сохранения в векторную базу:
1.  Извлекает текстовое содержимое (`textForEmbedding`) из структуры сообщения (будь то просто текст или массив частей `content.parts`).
2.  Параллельно (с помощью `Promise.all` и `embedMessageContent`) получает эмбеддинги для каждого сообщения.
3.  Батчирует полученные вектора и метаданные (включающие `message_id`, `thread_id`, `resource_id`) и выполняет `vector.upsert()` в индекс векторной БД.

Модуль `semantic-recall.ts` (процессор) использует `embedder` для векторизации запроса и ищет сообщения по `thread` или `resource`, ограничивая выдачу с помощью `topK` и возвращая окружающие сообщения (`messageRange`).

### 3.3 Работа с БД (Postgres)
Сама запись в таблицы (`workflow_runs`, `workflow_steps`, таблицы сообщений) абстрагирована через `MemoryStorage`. Треды хранятся в формате JSONB или в реляционных полях, где метаданные (включая инфу о клонировании) лежат в сериализованном виде.

## 4. Инструкция: Как повторить это в вашем проекте

Чтобы внедрить систему памяти с историей, семантическим поиском и клонированием в свой проект (используя PostgreSQL и Python/Node.js), выполните следующие шаги:

### Шаг 1: Проектирование схемы БД (PostgreSQL)
Создайте таблицы для тредов и сообщений:
```sql
CREATE TABLE threads (
    id UUID PRIMARY KEY,
    resource_id VARCHAR(255), -- ID пользователя или проекта
    created_at TIMESTAMP DEFAULT NOW(),
    metadata JSONB -- Здесь будет храниться инфа о клонах
);

CREATE TABLE messages (
    id UUID PRIMARY KEY,
    thread_id UUID REFERENCES threads(id),
    role VARCHAR(50), -- user, assistant, system
    content TEXT,
    created_at TIMESTAMP DEFAULT NOW()
);
```

### Шаг 2: Реализация логики клонирования (Forking)
Когда пользователь хочет создать ветку от сообщения X в треде Y:
1. Создайте новую запись в таблице `threads`. В поле `metadata` запишите: `{"clone": {"sourceThreadId": "ID_старого_треда", "clonedAtMessageId": "X"}}`.
2. Скопируйте все сообщения из старого треда до сообщения X включительно и вставьте их в таблицу `messages` с новым `thread_id`.
3. Для получения истории (аналог `getCloneHistory`): напишите рекурсивный запрос в SQL (CTE - `WITH RECURSIVE`) или сделайте несколько SELECT'ов в коде, чтобы по цепочке `metadata->'clone'->>'sourceThreadId'` восстановить весь путь ветвлений.

### Шаг 3: Векторный поиск (Семантическая память)
Для Semantic Recall понадобится векторное расширение (например, `pgvector` в PostgreSQL или отдельная БД вроде Pinecone/Qdrant).
1. Добавьте в таблицу `messages` колонку для вектора: `embedding vector(1536)`.
2. При добавлении нового сообщения в БД, асинхронно отправляйте текст в модель (например, OpenAI `text-embedding-3-small`).
3. Сохраняйте полученный вектор в строку сообщения.
4. При генерации ответа агента сделайте векторный поиск по похожим сообщениям текущего пользователя (`WHERE resource_id = ?`) и добавьте найденный текст (Top-K) в системный промпт как дополнительный контекст: "Вот что вы обсуждали ранее: ...".
