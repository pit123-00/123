# Симбиоз двух систем: Проектирование продвинутой ИИ-среды разработки

## 1. Стратегическое видение

Слияние Superpowers (SP) и AI Factory (AIF) позволяет создать "Автономного ИИ-инженера уровня Senior", который обладает как глубиной инженерного мышления (SP), так и широтой операционной эффективности (AIF).

**Центральная идея:** Использовать SP как ядро процесса разработки логики (написание кода), а AIF — как оболочку и память системы (DevOps, документация, обучение).

---

## 2. Универсальный рабочий процесс (The Hybrid Lifecycle)

### Этап 1: Интеллектуальная разведка (Reconnaissance)
*   **Действие:** Прежде чем вступать в диалог, агент запускает `aif-explore` в связке с `aif-grounded`.
*   **Почему это важно:** SP часто начинает brainstorming на основе поверхностных знаний. Интеграция AIF-разведки позволяет агенту оперировать реальными фактами об архитектуре и зависимостях еще до начала проектирования.

### Этап 2: Проектирование с Визуальным Контекстом (Design)
*   **Действие:** Запуск `brainstorming` (SP) с обязательным предложением `Visual Companion`.
*   **Симбиоз:** В процессе проектирования используется `aif-roadmap` для проверки, не противоречит ли текущая фича глобальным целям продукта. Дизайн фиксируется не только в тексте, но и в ADR-формате.

### Этап 3: Высокоточное Планирование (Precision Planning)
*   **Действие:** Использование `writing-plans` (SP) для декомпозиции, усиленное `aif-plan` для управления ветками и `git worktrees`.
*   **Спецификация задач:** Каждая подзадача плана получает "политику" из AIF (уровень логирования, требования к документации, проверки безопасности).

### Этап 4: Исполнение через TDD и Субагентов (Implementation)
*   **Действие:** Активация `subagent-driven-development` (SP).
*   **Усиление:** Субагенты работают в цикле `test-driven-development` (SP), но с использованием `Reflex Loop` (AIF) для самокритики. После написания кода автоматически вызывается `aif-verify` для проверки не только тестов, но и соблюдения линтов, типов и роадмапа.

### Этап 5: Автоматизация "Обвязки" (Automation)
*   **Действие:** По завершении кода автоматически срабатывают навыки `aif-dockerize`, `aif-ci` и `aif-docs`.
*   **Результат:** Код не просто написан, он готов к деплою, протестирован в контейнере и задокументирован.

### Этап 6: Эволюционное обучение (Evolution)
*   **Действие:** После завершения задачи запускается `aif-evolve`.
*   **Симбиоз:** Система анализирует, какие тесты SP падали чаще всего, какие замечания давал Code Quality Reviewer, и на основе этого обновляет `skill-context` проекта.

## 3. Список противоречий и способы их разрешения

| Противоречие | Подход Superpowers | Подход AI Factory | Решение (Симбиоз) |
| :--- | :--- | :--- | :--- |
| **Философия тестов** | TDD обязателен (Hard-gate) | Тесты — желательная опция | **Динамическая строгость:** Тесты обязательны для бизнес-логики и критических путей, опциональны для UI-прототипов и инфраструктурных скриптов. |
| **Управление ветками** | Git Worktrees (изоляция) | Обычные ветки (скорость) | **Контекстная изоляция:** Worktrees для параллельных задач субагентов, ветки для последовательной работы пользователя. |
| **Ревью кода** | Многоуровневое (субагенты) | Верификация (скрипты/чек-листы) | **Гибридное ревью:** Сначала `aif-verify` (автоматика), затем `Code Quality Reviewer` (семантика). |
| **Обучение системы** | Статичные навыки | Динамический эволюционный цикл | **База + Настройка:** SKILL.md — неизменяемые лучшие практики, `skill-context` — живой опыт проекта. |

## 4. Что СЛЕДУЕТ объединить (Синергия)

1.  **Grounded Brainstorming:** Объединение сократовских вопросов SP с доказательной базой AIF. Агент не верит пользователю на слово ("У нас используется PostgreSQL"), а проверяет это через `grounded` режим.
2.  **Visual Docs:** Автоматическое встраивание диаграмм из Visual Companion (SP) в документацию, генерируемую `aif-docs`.
3.  **Security-Aware TDD:** Включение проверок из `aif-security-checklist` непосредственно в фазу написания тестов. Тест должен не только проверять "что работает", но и "что не ломается при атаке".
4.  **Learn Mode + Writing Skills:** Использование способности AIF обучаться на внешних доках для автоматического обновления/создания навыков в формате SP.

## 5. Что НЕ СТОИТ объединить (Разные подходы)

1.  **Метод планирования задач:** В AIF планирование часто более свободное и ориентировано на высокоуровневые задачи. SP требует микро-менеджмента (задачи по 5 минут). **Не стоит смешивать:** лучше оставить жесткую структуру SP для исполнения, так как она доказала большую стабильность для текущих LLM.
2.  **Интерфейсы взаимодействия:** AIF сильно полагается на CLI и MCP. SP — на промпты и инструкции внутри чата. **Не стоит заменять одно другим:** они должны дополнять друг друга (CLI для тяжелых операций, инструкции для логики).
3.  **Обработка ошибок:** SP фокусируется на поиске Root Cause через тесты. AIF — на исправлении через эволюцию правил. **Оставить раздельными:** сначала исправляем по SP (лечим болезнь), затем эволюционируем по AIF (создаем иммунитет).

## 6. Выявленные пробелы (Gap Analysis)

Даже при объединении систем остаются серые зоны:
1.  **Управление ресурсами (Token Economy):** Обе системы очень "прожорливы". Необходим общий модуль "Context Manager", который будет агрессивно сжимать историю и удалять ненужные файлы из контекста.
2.  **Кросс-проектная память:** Обе системы ограничены одним репозиторием. Нет механизма переноса опыта ("мудрости") между разными проектами одной компании/разработчика.
3.  **Архитектурная инспекция:** Нет навыка, который мог бы оценить "красоту" и "чистоту" архитектуры на высоком уровне (например, нарушение гексагональной архитектуры или утечка абстракций между слоями).

## Заключение

Симбиоз Superpowers и AI Factory — это переход от "ИИ-помощника" к "ИИ-напарнику". Объединив дисциплину SP с инструментальной мощью AIF, мы получаем систему, которая не просто пишет код, а управляет сложностью программного продукта на всех этапах его жизни.
