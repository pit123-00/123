# Отчёт 2: Техническая реализация решений и их преимущества

В данном отчёте детально разбирается внутренняя реализация ключевых подсистем **Dokku** и **Dokploy** на уровне исходного кода: как устроены процессы сборки, жизненный цикл развертывания, сетевой стек, хранение данных и фоновые задачи, а также в чём заключаются технические преимущества каждого решения.

---

## 1. Механизм плагинов и управление вызовами

### Техническая реализация в Dokku:
В Dokku расширяемость основана на шине хуков **Plugn** (`plugins/common/plugn.go`):
1. **Регистрация триггеров:** Каждый плагин декларирует свои триггеры либо как исполняемые файлы/симлинки в папке плагина (например, `triggers/builder-detect`), либо через файл метаданных `plugin.toml`.
2. **Синхронный пайплайн:** Когда в системе происходит событие (например, `core-post-extract`), Dokku вызывает `plugn trigger <trigger-name> [args]`. Вызов сканирует все включенные плагины (`$PLUGIN_ENABLED_PATH/*/`), находит зарегистрированные обработчики и выполняет их последовательно или параллельно с перехватом STDOUT/STDERR.
3. **Единый бинарный мультиплексор Go:** Плагины написаны на Go и собираются в единый бинарник `commands` или `triggers`, а специфичные команды (`builder-build`, `install`, `post-delete`) представляют собой симлинки на этот бинарник, определяющий своё поведение по `os.Args[0]`.

*Преимущества реализации Dokku:*
* **Сверхнизкий оверхед:** Нет постоянного фонового процесса; вызов CLI поднимает только необходимые бинарники в рамках одной подсистемы ядра.
* **Изолированность:** Ошибка или падение одного плагина в триггере ловится через статус завершения процесса (`exit code`), не подвешивая долгоживущие демоны.
* **Полиглотность:** Плагин может быть написан на любом языке (Go, Bash, Python, Rust) — достаточно реализовать исполняемый файл с нужным именем в директории плагина.

### Техническая реализация в Dokploy:
В Dokploy расширяемость построена на **сервисно-ориентированной модульности TypeScript**:
1. **Сервисный слой (`packages/server/src/services/`):** Каждая сущность (`application.ts`, `compose.ts`, `server.ts`, `database/**`) инкапсулирует бизнес-логику внутри асинхронных функций, оперирующих базой данных через Drizzle ORM.
2. **API маршрутизация (`apps/dokploy/server/api/routers/`):** Сервисы напрямую экспортируются в процедуры tRPC (`publicProcedure`, `protectedProcedure`) со строгой валидацией входных данных через Zod (`packages/server/src/db/validations/**`).
3. **Очередь задач Inngest (`apps/api/src/index.ts`):** Долгие операции деплоя вынесены в асинхронные шаги (`step.run("execute-deployment")`). Деплой-запрос помещается в очередь с ключом конкурентности (`concurrency: [{ key: "event.data.serverId", limit: 1 }]`), что предотвращает конфликты одновременного развертывания на одной ноде.

*Преимущества реализации Dokploy:*
* **Полная реактивность и асинхронность:** Пользователь не ждёт блокировки CLI; статус деплоя стримится в реальном времени через Server-Sent Events / WebSockets.
* **Контроль конкурентности и отменяемость:** Встроенная поддержка `cancelOn: [{ event: "deployment/cancelled" }]` позволяет остановить зависшую сборку прямо из UI/API в любой момент.
* **Строгая типизация от базы до фронтенда:** Изменение структуры схемы в БД гарантированно ломает сборку TypeScript (`pnpm build`), если валидация на уровне API или компонентов не обновлена.

## 2. Пайплайн сборки и доставки (Build & Deploy Pipelines)

### Dokku (Git push -> Procfile -> Release -> Deploy):
1. **Приём кода:** SSH-сервер аутентифицирует пользователя и передает поток в `plugins/git/receive-app`.
2. **Распаковка и детекция билдера:**
   * Код кладётся во временную директорию `/tmp/dokku-$PID-...`.
   * Вызывается триггер `builder-detect`, опрашивающий по очереди `builder-dockerfile`, `builder-nixpacks`, `builder-pack`, `builder-herokuish`.
3. **Сборка образа (`builder-build`):** Вызывается выбранный плагин сборщика. Образ компилируется в локальный Docker демон и помечается метками:
   `com.dokku.app-name=$APP`, `com.dokku.image-stage=build`.
4. **Фаза Release (`builder-release`):** Временный контейнер запускает команду релизной фазы (если определена в `Procfile` как `release: bundle exec rake db:migrate`), применяя миграции базы данных до переключения пользовательского трафика.
5. **Фаза Deploy (`scheduler-deploy`):**
   * Запуск новых контейнеров параллельно (`GNU parallel`).
   * Запуск проверок работоспособности (`check-deploy`).
   * Переключение конфигурации прокси (`proxy-build-config`).
   * Отправка `SIGTERM` старым контейнерам и мягкое завершение через `wait-to-retire` (дефолт 60 сек).

*Преимущества Dokku:*
* Непревзойденная зрелость пайплайна: алгоритм zero-downtime оттачивался более 10 лет.
* Автоматическая поддержка релизных фаз для миграций БД прямо в процессе сборки.
* Поддержка K3s через Helm-компиляцию прямо из того же git-репозитория.

### Dokploy (Git/Registry/Compose -> Docker Engine / Swarm):
1. **Инициация:** Триггер через GitHub/GitLab Webhook, веб-дашборд или вызов `/deploy` (API Key).
2. **Создание записи в БД:** Сервис `deployment.ts` создает запись `deployments` со статусом `pending` и генерирует уникальный лог-файл (`paths(isServer).LOGS_PATH`).
3. **Выбор цели (Local / Remote via SSH):**
   * Если у приложения указан `serverId`, Dokploy использует SSH-соединение с приватным ключом для удаленного выполнения (`execAsyncRemote`).
   * В случае сборки Nixpacks/Dockerfile код клонируется в рабочую директорию на целевой машине.
4. **Развертывание через Dockerode / Docker CLI:**
   * Для одиночных приложений создаются контейнеры или сервисы Swarm с метками Traefik (`dokploy-labels.ts`).
   * Для Docker Compose Dokploy парсит YAML (`utils/docker/compose.ts`), модифицирует имена сервисов (`addAppNameToPreventCollision`), чтобы избежать коллизий между превью-окружениями, создает оверлейную сеть и запускает стек.
5. **Обновление статуса:** Inngest отправляет событие `deployment/completed` или `deployment/failed`, сохраняя финальный лог и уведомляя пользователя через Telegram/Discord/Slack/Email.

*Преимущества Dokploy:*
* **Поддержка Docker Compose как первоклассной сущности:** Dokku традиционно ориентирован на одно приложение (с Procfile), в то время как Dokploy позволяет деплоить комплексные многосервисные стеки одной кнопкой.
* **Превью-деплои (Preview Deployments / Pull Request Environments):** Модуль `preview-deployment.ts` автоматически поднимает изолированную копию ветки или PR с уникальным URL (`randomizeIsolatedDeploymentComposeFile`).
* **Мультисерверное управление из одной панели:** Возможность деплоить на десятки внешних VPS без необходимости ставить Dokploy на каждый из них.

## 3. Обратный прокси, маршрутизация и SSL

### Dokku (Nginx / Caddy / Traefik / HAProxy):
* Dokku использует шаблонную генерацию конфигураций на диске:
  * Для Nginx генерируется файл `/home/dokku/<app>/nginx.conf` с помощью встроенного парсера шаблонов Sigil (`templates/nginx.conf.sigil`).
  * Валидация конфигурации через `nginx -t` перед перезагрузкой (`subcommands/validate-config`).
  * Если проверка не прошла, деплой откатывается, защищая рабочий Nginx от падения.
* **Преимущество Dokku:** Возможность переопределить конфигурационный файл целиком для конкретного приложения, положив кастомный `nginx.conf.sigil` прямо в корень git-репозитория приложения.

### Dokploy (Traefik v3 Engine):
* Dokploy полностью полагается на динамический провайдер Traefik:
  * Маршрутизация настраивается либо через Docker Labels (`traefik.http.routers.<name>.rule=Host(...)`), либо через генерацию файлов в динамической папке Traefik (`packages/server/src/utils/traefik/domain.ts`).
  * Полностью реактивное применение изменений: Traefik слушает события Docker Socket и изменения файлов, не требуя перезапуска прокси-демона (Zero-Reload / Hot-Reload).
  * Встроенная интеграция с Let's Encrypt и поддержка кастомных TLS-сертификатов (`services/certificate.ts`).
* **Преимущество Dokploy:** Мгновенное применение правил маршрутизации без перезагрузки веб-сервера, нативная поддержка WebSockets и gRPC из коробки, поддержка распределенной маршрутизации через Docker Swarm Overlay Network.

## 4. Базы данных и управление персистентностью

### Dokku:
* Управление базами данных вынесено в плагины экосистемы `dokku-datastore` (`plugins/datastore/datastore.go`):
  * Команды вида `dokku postgres:create db1`, `dokku postgres:link db1 myapp`.
  * При линковке плагин инжектирует переменную окружения `DATABASE_URL` в приложение через `plugins/config/config.go`.
* **Особенность:** Базы данных запускаются как независимые Docker-контейнеры с примонтированными volume на диске хоста.

### Dokploy:
* Базы данных — это глубоко интегрированные схемы в ядре системы (`postgres.ts`, `mysql.ts`, `redis.ts`, `mariadb.ts`, `mongo.ts`, `libsql.ts`):
  1. **Жизненный цикл:** Создание через единую панель, автоматическая генерация безопасных паролей, портов и учетных данных.
  2. **Автоматическое резервное копирование в S3 (`utils/backups/`):**
     * Dokploy генерирует команду бэкапа (`pg_dump`, `mongodump`, `mysqldump`), сжимает поток (`gzip`) и напрямую через утилиту `rclone` заливает архив в S3-совместимое хранилище (AWS S3, Cloudflare R2, MinIO, Wasabi).
     * Возможность настроить расписание (cron) и автоматическое удаление старых копий (retention policy).
  3. **Бэкап томов Docker (`utils/volume-backups/`):** Бэкап не только дампов баз данных, но и произвольных постоянных томов приложений.

*Преимущество Dokploy:* Готовая промышленная система бэкапов с отправкой уведомлений о статусе резервного копирования в каналы связи.

## 5. Мониторинг, логирование и сбор метрик

### Dokku:
* Модуль логирования (`plugins/logs/logs.go`):
  * Чтение логов через Docker logging driver (`dokku logs <app> -t`).
  * Поддержка агрегатора **Vector** (`vector-sink`): Dokku может транслировать логи контейнеров во внешние системы (Elasticsearch, Logstash, Datadog) через Vector DSN (`SinkValueToConfig`).

### Dokploy:
* Полноценная подсистема телеметрии и мониторинга:
  * Встроенный Go-демон `apps/monitoring/`: собирает метрики CPU, Memory, Disk, Network с хоста и контейнеров.
  * Интеграция с Vector Agent (`packages/server/src/services/logs-and-metrics/vector-agent.ts`): поддержка провайдеров Datadog, Elasticsearch, Loki, BetterStack, New Relic, Splunk, AWS CloudWatch, InfluxDB, Prometheus Remote Write.
  * Интерактивные графики в веб-интерфейсе в реальном времени.

## 6. Итоговые выводы по технической реализации

1. **Dokku** представляет собой образец надежной системной инженерии в стиле Unix. Он опирается на стандартные утилиты ОС, минималистичен, не требует поддержки тяжелой инфраструктуры (БД, веб-серверов интерфейса) и идеально подходит для разработчиков, предпочитающих полный контроль через терминал и скрипты автоматизации.
2. **Dokploy** представляет собой современный облачный стек управления инфраструктурой. Он закрывает потребности команд в визуализации, мультисерверности, совместной работе (RBAC), работе с Docker Compose и готовых решениях для резервного копирования баз данных «из коробки».
