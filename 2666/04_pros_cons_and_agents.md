# Отчёт 4: Плюсы и минусы решений, управление агентами, субагентами и пайплайнами

В данном отчёте проводится глубокий анализ реализации механизмов оркестрации агентов, порождения и контроля субагентов, конвейеров выполнения (pipelines), а также формулируются объективные плюсы и минусы обоих проектов на основе изученного кода.

---

## 1. Управление агентами, субагентами и пайплайнами

### 1.1. Подход `grok-build` (xAI)

#### Модель агента и субагента:
1. **Разрешение конфигурации (`xai-grok-subagent-resolution`):**
   - Механизм спавна субагентов выделен в отдельный детерминированный крейт.
   - Четкая иерархия приоритетов (Precedence):
     $$\text{Explicit Override} > \text{Role} > \text{Persona} > \text{Parent Agent}$$
   - Наследование навыков (`inherit_skills`) и динамическое обнаружение (`discover_skills` из CWD).
   - Ограничение типов спавна (`allowed_subagents`): родительский агент может быть ограничен только определенным подмножеством типов дочерних агентов или полностью лишен права их создания.
2. **Ограничение прав и возможностей (`capability_mode`):**
   - При спавне субагента в рантайме применяется фильтрация набора инструментов (`SubagentCapabilityMode`), что исключает неконтролируемое повышение привилегий дочерним агентом.
3. **Изоляция и фоновое исполнение:**
   - Поддерживаются флаги `isolation: IsolationMode` и `background: Option<bool>`. Субагенты могут выполняться в отдельном изолированном контексте.
4. **Конвейер сжатия контекста (`CompactionTranscript` & `xai-grok-compaction`):**
   - Алгоритм сжатия транскрипта с сохранением ключевых этапов рассуждений, удалением избыточных выводов инструментов и защитой от переполнения окна токенов.

---

### 1.2. Подход `opencode` (Anomaly)

#### Модель агента и субагента:
1. **Режимы агентов (`mode`):**
   - Агенты классифицируются по типам: `primary`, `subagent`, `all`.
   - Субагенты могут быть скрыты из автодополнения (`hidden: true`).
2. **Асинхронная модель заданий (`SubagentJob` & `Job.Service`):**
   - Субагенты запускаются как полноценные фоновые задания (`Job`), имеющие собственный `Scope` и жизненный цикл, переживающий вызвавший их контекст:
     ```typescript
     const notify = Effect.fn("SubagentJob.notify")(function* (recovery: Recovery, startedAt: number) {
       // Jobs outlive the caller scope and report completion via SubagentCompletion.deliver
     });
     ```
   - Завершение субагента доставляется обратно в родительскую сессию через `SubagentCompletion.deliver`.
3. **Лимиты шагов и принудительный вывод:**
   - Параметр `steps` строго ограничивает число итераций агента. При достижении лимита агент принудительно переключается в режим формирования только текстового ответа, предотвращая зацикливание.
4. **Координация выполнения пайплайна (`SessionRunCoordinator`):**
   - Гарантирует, что одновременные запросы пользователя, фоновые ответы субагентов и таймеры обрабатываются строго последовательно, без состояния гонки за историю сообщений сессии.

## 2. Сравнительный анализ управления агентами

| Аспект оркестрации | `grok-build` | `opencode` |
|---|---|---|
| **Порождение субагентов** | Жестко валидируемый крейт разрешения (`xai-grok-subagent-resolution`) со статическими ролями и персонами. | Динамический запуск через службу `Job.Service` с асинхронным отслеживанием статуса. |
| **Ограничение прав субагентов** | Фильтрация по `SubagentCapabilityMode`, явные `allowed_subagents`, системные права ядра ОС. | Конфигурационные политики разрешений `ConfigPermissionV1`, наследование или переопределение правил. |
| **Сжатие истории диалога** | Специализированный `CompactionTranscript` с сохранением системных ремайндеров. | `SessionCompaction` с поддержкой детекции `context-overflow` и эвристической очисткой сообщений. |
| **Параллелизм пайплайнов** | Асинхронные задачи Tokio, изолированные очереди промптов, объединение очередей (`CombineGate`). | Файберы Effect, `FiberSet`, дверные звонки `wake()`, неблокирующий дренаж очереди. |

## 3. Плюсы и минусы `grok-build`

### Плюсы:
1. **Максимальный уровень безопасности на уровне ядра:** Использование `Landlock` и `Seatbelt` делает невозможным несанкционированное чтение или запись файлов агентом даже в случае prompt injection или компрометации LLM.
2. **Корпоративная управляемость:** Встроенная поддержка централизованных политик через macOS MDM и проверку цифровых подписей Ed25519 в `signed_policy`.
3. **Надежность и производительность:** Системный язык Rust, строгие линтеры (`clippy::indexing_slicing`), отсутствие накладных расходов GC, высокая скорость работы с крупными монорепозиториями.
4. **Качественная интеграция с терминалом:** Эмуляция терминала на уровне `alacritty_terminal` позволяет полноценно взаимодействовать со сложными консольными программами.
5. **Устойчивость к сетевым сбоям:** Механизм `xai-circuit-breaker` и локальный HTTP-прокси для гранулярного контроля исходящих соединений.

### Минусы:
1. **Высокая сложность кодовой базы:** Более 100 крейтов в монорепозитории создают высокий порог входа для доработки и длительное время компиляции.
2. **Привязка к экосистеме xAI / Grok:** Архитектура в первую очередь оптимизирована под нативные API xAI, сторонние провайдеры требуют адаптеров.
3. **Сложность разработки кастомных расширений:** Написание новых инструментов и плагинов на Rust требует глубоких знаний языка и перекомпиляции проекта (в отличие от скриптовых экосистем).

## 4. Плюсы и минусы `opencode`

### Плюсы:
1. **Высокая гибкость и мультипровайдерность:** Из коробки поддерживает работу с десятками моделей (Claude, GPT, Copilot, Ollama, Bedrock, Groq) с возможностью тонкой настройки параметров генерации.
2. **Инновационный Code Mode:** Вызов цепочек инструментов через генерируемый TypeScript/JavaScript код кардинально сокращает потребление токенов и ускоряет решение комплексных задач.
3. **Архитектурная чистота благодаря Effect TS:** Композиция сервисов, предсказуемое управление ресурсами через Scopes, отсутствие скрытых исключений благодаря типизации ошибок.
4. **Мультиплатформенность и разделение UI/Core:** Единое ядро обслуживает CLI, TUI, веб-приложение, Electron-десктоп и даже edge-рантаймы (Cloudflare workerd).
5. **Легкость расширения:** Добавление новых агентов, провайдеров и инструментов осуществляется декларативно через TypeScript/JSON/YAML конфиги без необходимости сложной компиляции.

### Минусы:
1. **Меньший уровень системной изоляции:** Песочница ограничивается программными проверками разрешений и средой выполнения Node/Bun; отсутствует нативная изоляция ядра (нет Landlock/Seatbelt).
2. **Накладные расходы рантайма:** Использование Node.js/Bun и Effect TS создает дополнительное потребление оперативной памяти и задержки сборщика мусора по сравнению с нативным Rust.
3. **Потенциальная хрупкость PTY на разных платформах:** Управление процессами PTY в средах Bun/Node через внешние демоны требует поддержания совместимости различных версий платформенных бинарников.

## 5. Итоговые выводы

Оба проекта представляют собой передовые архитектуры агентных систем, но решают задачи для разных сценариев:
- **`grok-build`** — это тяжеловесное, бескомпромиссное системное решение корпоративного уровня на Rust, где во главу угла поставлены безопасность ядра ОС, криптографический контроль политик и глубокая работа с системными процессами.
- **`opencode`** — это гибкая, модульная и расширяемая среда на Effect TS/TypeScript, идеально подходящая для мультимодельных сценариев, быстрой разработки плагинов, клиент-серверной работы (Web/Desktop/CLI) и пакетного вызова инструментов через Code Mode.
