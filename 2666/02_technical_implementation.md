# Отчёт 2: Техническая реализация систем OpenClaw и Pi

В данном отчёте приведён подробный технический разбор кодовой базы проектов [openclaw/openclaw](https://github.com/openclaw/openclaw) и [earendil-works/pi](https://github.com/earendil-works/pi). Анализируются конкретные модули, используемые среды исполнения, движки валидации данных, механизмы устойчивости к сбоям, управления памятью и транзакциями.

---

## 1. Технический стек и среды исполнения (Runtime Engines)

### OpenClaw: Node.js Multi-Process и системные демоны
- **Базовый рантайм**: Node.js (v20+ / ESM) с широким использованием нативных системных вызовов (`node:process`, `node:child_process`, `node:worker_threads`, `node:async_hooks`).
- **Собственные системные адаптеры**:
  - `node-compile-cache.mjs` и `node-runtime-recovery.mjs`: механизм кэширования скомпилированного байткода V8 для мгновенного перезапуска процессов без задержек холодного старта.
  - `worker-process-protocol.ts` и `node-host/`: супервизор фоновых процессов, управляющий пулом дочерних воркеров с мониторингом потребления памяти кучи (`worker-heap-flag.mjs`, `child-memory.ts`).
  - Механизм `watchCliRespawnParent`: автоматический перезапуск упавших процессов с сохранением дескрипторов соединений и состояния в локальной БД.
- **PTY и эмуляция терминала**: Использование низкоуровневых псевдотерминалов (`terminal-pty.ts`) для безопасной изоляции интерактивных команд оператора.

### Pi: Гибридный полиглотный стек (Node.js, Bun, QuickJS WASM, Web standards)
- **Многоплатформенный рантайм**: Кодовая база спроектирована для работы как в Node.js, так и в виде скомпилированных бинарных файлов Bun (`isBunBinary`, `isBunRuntime` в `config.ts`).
- **Codemode и изолированные песочницы (`@earendil-works/pi-codemode`)**:
  - Интеграция легковесного движка JavaScript **QuickJS, скомпилированного в WebAssembly** (`src/wasm.ts`, `quickjs-wasm.d.ts`).
  - Позволяет агенту генерировать JavaScript/TypeScript скрипты и выполнять их в изолированной песочнице с микросекундным оверхедом, вызывая инструменты агента через хостовый интерфейс (`host.ts`, `vm.ts`).
  - Совместимость с Cloudflare Workers (`cloudflare.ts`).
- **Фреймворк долговечности (`@earendil-works/pi-durable`)**:
  - Асинхронные очереди задач, таймеры (`timers.ts`) и снапшоты состояния, устойчивые к сбоям сетевых соединений.

## 2. Валидация данных и декларация контрактов: Zod vs TypeBox

### OpenClaw: Комплексные динамические схемы на Zod
- В OpenClaw все схемы конфигураций, входящих полезных нагрузок каналов и параметров методов описаны через библиотеку `zod` (`src/config/zod-schema.root-shape.ts`, `types.openclaw.ts`).
- **Особенности реализации**:
  - Глубокая композиция схем: проверка адресов электронной почты, телефонных номеров, токенов ботов, сетевых политик SSRF (`types.ssrf.ts`).
  - Трансформация и очистка данных на лету (`z.preprocess`, `.transform()`).
  - Минусы: повышенный оверхед по памяти и скорости при разборе сотен тысяч входящих JSON сообщений в реальном времени.

### Pi: Высокопроизводительные статические TypeBox схемы
- В Pi валидация вынесена в специализированный пакет `@earendil-works/pi-schema` на базе `@sinclair/typebox`.
- **Особенности реализации**:
  - `packages/schema/src/compiler.ts` использует JIT-компиляцию валидаторов в нативный JavaScript код через генерацию функций `CodeCheck`. Это обеспечивает скорость валидации в десятки раз быстрее Zod.
  - Строгая совместимость с форматом **JSON Schema Draft 7 / 2020-12**, что идеально подходит для спецификации инструментов LLM (Function Calling / Tool Use) без дополнительных адаптеров конвертации.
  - Строгие проверки типов времени компиляции TypeScript без дублирования деклараций (`Static<typeof Schema>`).

## 3. Управление состоянием, транзакционность и хранилище

### OpenClaw: Реляционная СУБД SQLite с WAL и пулом соединений
В OpenClaw реализована архитектура корпоративного хранилища данных:
- **База данных SQLite**: Используется `better-sqlite3` / `node:sqlite` с обязательным включением режима `PRAGMA journal_mode=WAL` (`src/state/openclaw-state-db.ts`).
- **Схема изоляции**:
  - Очереди транзакций и мьютексы доступа (`session-actor-transaction.ts`).
  - Сегрегация данных: сессии, участники (`session-accessor.sqlite-participant-read.ts`), транскрипты, системные цели (`goals-operations.ts`), история вызовов инструментов.
- **Очистка и рекультивация (Reclamation Worker)**:
  - Фоновый процесс `session-accessor.sqlite-page-reclamation.ts` производит периодический сброс устаревших записей, компактизацию страниц БД и перенос тяжелых медиа-вложений в архивное хранилище (`session-cold-storage-inventory.ts`).

### Pi: Легковесный файловый DAG и персистентность событий
- **Формат JSONL (Append-Only Log)**: Сессия в Pi (`@earendil-works/pi-coding-agent/src/modes/rpc/jsonl.ts`) хранится в виде непрерывного потока событий JSONL. Каждая строка — неизменяемое атомарное событие (`AgentEvent`).
- **Атомарность записи**:
  - Запись осуществляется через блокировки очередей мутаций файлов `file-mutation-queue.ts`.
  - Отсутствует тяжелая зависимость от сторонних СУБД в базовом рантайме агента — агент работает непосредственно с файловой системой пользователя, что гарантирует мгновенный запуск и переносимость между машинами.
- **Durable Storage**: В пакете `@earendil-works/pi-durable` для распределенного режима опционально подключается локальный Key-Value / Document Store с интерфейсом для синхронизации через `@earendil-works/pi-chord`.

## 4. Механизмы устойчивости: Compaction, Retry и Recovery

### Механизмы в Pi
1. **Интеллектуальная компактизация контекста (`compaction.ts`)**:
   - `isContextOverflow()` и `isRecoverableLength()` в `@earendil-works/pi-ai/compat`: точный подсчет токенов с учетом служебных сообщений.
   - Автоматическая обрезка вывода инструментов (`truncate.ts`) с сохранением первых и последних строк лога.
   - Сжатие веток диалога (`branch-summarization.ts`): модель формирует сжатый конспект предыдущего контекста при достижении лимита токенов, освобождая окно для продолжения работы без потери цели.
2. **Адаптивный Retry-пайплайн (`packages/ai/src/utils/retry.ts`)**:
   - Экспоненциальный откат (backoff) с джиттером.
   - Детекция типов ошибок провайдера (Rate Limit 429, Server Error 5xx, Overloaded) с динамическим таймаутом `retryDelayMs`.

### Механизмы в OpenClaw
1. **Глобальный супервизор падений (`node-runtime-recovery.mjs`)**:
   - Ловит uncaughtException и unhandledRejection на уровне процесса демона.
   - Проверяет кодовые маркеры процессов (`openclaw-exec-env.ts`) и выполняет «горячий» перезапуск сокетов без потери сетевых соединений клиентов мессенджеров.
2. **Rate Limiting & Admission Control**:
   - Входной фильтр запросов шлюза (`preauth-connection-budget.ts`, `http-work-admission.ts`).
   - Защита от исчерпания дескрипторов файлов и портов при скачках нагрузки (`listenGatewayHttpServer` с циклом повторных попыток при `EADDRINUSE`).

## 5. Технические преимущества каждого решения

### Технические преимущества OpenClaw
1. **Готовность к высоким серверным нагрузкам**: Архитектура демона с супервизором, пулом воркеров и очередями сообщений изначально ориентирована на режим 24/7.
2. **Промышленное хранение истории**: SQLite WAL обеспечивает строгую консистентность данных, транзакционность и возможность репликации/бэкапа на лету.
3. **Безопасность сетевого периметра**: Встроенная система фильтрации SSRF, валидация Origin и белые списки каналов защищают инфраструктуру от компрометации через входящие вебхуки.
4. **Мультимодальность из коробки**: Нативная поддержка потокового аудио (TTS/STT), транскодирования медиа (`playback-transcode.ts`) и интеграции с удаленными рабочими столами по протоколу RFB.

### Технические преимущества Pi
1. **Минималистичность и экстремальная скорость**: Отсутствие тяжелого рантайма демона и СУБД; старт CLI занимает миллисекунды, особенно при использовании скомпилированного Bun-бинарника.
2. **QuickJS WASM Sandboxing (Codemode)**: Уникальная возможность безопасно исполнять код, написанный LLM, в изолированном WASM-контейнере прямо в памяти процесса без развертывания Docker.
3. **Производительность валидации TypeBox**: JIT-компилированные схемы входных и выходных параметров инструментов дают колоссальный выигрыш в скорости при большом объеме параллельных вызовов.
4. **Модульность монорепозитория**: Четкое разделение слоев (`agent-core`, `ai`, `schema`, `durable`, `coding-agent`) позволяет встраивать любые компоненты Pi в сторонние продукты как независимые NPM-библиотеки.
5. **Файловая безопасность при редактировании кода**: Специализированный модуль `file-mutation-queue.ts` предотвращает гонки при модификации файлов в репозитории проекта и гарантирует консистентность диффов.
