# Отчёт 1: Ключевые отличия между OpenClaw и Pi

Данный аналитический отчёт составлен на основе глубокого исследования исходного кода репозиториев [openclaw/openclaw](https://github.com/openclaw/openclaw) и [earendil-works/pi](https://github.com/earendil-works/pi). Анализ сфокусирован на назначении систем, философии проектирования, функциональности, концепции сессий, каналов взаимодействия и системах конфигурации.

---

## 1. Сравнительная сводная таблица фундаментальных концепций

| Параметр сравнения | OpenClaw (`openclaw`) | Pi (`pi`) |
| :--- | :--- | :--- |
| **Основное назначение системы** | Multi-channel AI Gateway & Enterprise Hub (многоканальный шлюз ИИ-агентов, хаб для мессенджеров, веб-сервисов, телефонии и внешних узлов). | Modular Coding Agent & Runtime (специализированная среда разработки, автономный coding-agent CLI/TUI, фреймворк долговечного выполнения `durable`/`chord`). |
| **Центральная парадигма** | Серверный шлюз (Gateway Daemon) с постоянным подключением каналов, брокером сообщений, RPC-роутингом и распределенным реестром сессий. | Сессионный агент разработки (Agent Session & Loop), запускаемый локально, во встроенном TUI, headless RPC через stdin/stdout или в легковесных воркерах. |
| **Каналы взаимодействия (Ingress / Channels)** | Огромный встроенный стек коннекторов: Telegram, Discord, Slack, WhatsApp, Signal, iMessage, IRC, Google Chat, MS Teams, Nostr, Webhooks, Twilio Voice/TTS, RFB/VNC. | Терминальный UI (`@earendil-works/pi-tui`), CLI-флаги, интерактивный REPL, JSONL RPC над stdin/stdout (`rpc-mode.ts`), клиент/сервер приложения `p2`. |
| **Архитектурная модель монорепозитория** | Монолитный шлюз с внутренними пакетами: `packages/agent-core`, `packages/gateway-protocol`, `packages/model-catalog-core`, `src/gateway`, `src/channels`. | Высокорасщепленный монорепозиторий независимых библиотек: `schema`, `ai`, `agent`, `coding-agent`, `mcp`, `codemode`, `durable`, `telemetry`, `chord`. |
| **Концепция сессий** | Глобальные персистентные сущности в SQLite WAL, привязанные к пользователям, токенам устройств, каналам чата и родительским контекстам. | Локальные сессии на основе файлов журнала/событий (`jsonl`), версионируемые деревья диалогов с возможностью ветвления (`branch`), сжатия (`compaction`) и экспорта в HTML. |
| **Схема конфигурации и настроек** | Развитая Zod-схема (`src/config/types.openclaw.ts`), включающая профили безопасности, SSRF-фильтрацию, права каналов, политики роутинга и каталоги моделей. | Строгие TypeBox-схемы (`@sinclair/typebox`) с JIT-компиляцией, дефолтные структуры (`SETTINGS_DEFAULTS` в `coding-agent`), `settings.json` и проектные настройки. |
| **Исполнение кода (Code Execution)** | Изолированные внешние воркеры (`Node-Host`, docker/sandbox, PTY псевдотерминалы, approval flow через операторов). | Встроенный `bash` инструмент, прямой `node:child_process`, QuickJS WASM песочницы для Codemode, изоляция в cloudflare-workers / durable runtime. |

## 2. Разница в философии и назначении

### OpenClaw: Шлюз и платформа автоматизации уровня предприятия
OpenClaw спроектирован как **управляющий шлюз (Gateway Daemon)**. Его задача:
- Выступать центральной точкой входа для сообщений из десятков различных источников (от корпоративных мессенджеров Slack/Teams до личных мессенджеров Telegram/Signal и голосовых сессий).
- Принимать входящие запросы, аутентифицировать пользователей и устройства (собственный протокол `openclaw-id`, токены устройств, парные ключи pairing keys).
- Маршрутизировать вызовы между различными профилями агентов, изолированными воркерами и сессиями в БД SQLite.
- Обеспечивать непрерывность сервиса (daemon lifecycle, graceful restart, автоматическое восстановление после падений воркеров через `node-runtime-recovery.mjs`).

### Pi: Специализированный автономный инструмент для разработчиков
Pi спроектирован с упором на **высокопроизводительный цикл разработки, автономное написание кода и компонуемость фреймворка**:
- Ядром системы является `@earendil-works/pi-coding-agent` и низкоуровневый `@earendil-works/pi-agent-core`.
- Главный фокус — решение задач программной инженерии: чтение, индексация, поиск по коду (grep, find), точечное редактирование файлов с контролем изменений (`file-mutation-queue.ts`, `edit-diff.ts`), выполнение терминальных команд.
- Архитектура библиотек Pi ориентирована на максимальную переиспользуемость: модуль `@earendil-works/pi-ai` абстрагирует работу с провайдерами моделей, `@earendil-works/pi-mcp` предоставляет чистый типизированный клиент MCP, `@earendil-works/pi-codemode` компилирует инструменты в TypeScript/JavaScript функции для исполнения в QuickJS WASM, а `@earendil-works/pi-durable` обеспечивает персистентность выполнения задач.

## 3. Модели сессий и управление состоянием

### Сессии в OpenClaw
- **Многоуровневая адресация**: Сессия идентифицируется сложным составным ключом (аккаунт, канал, peer ID, subagent ID).
- **Персистентность в БД**: Хранилище сессий реализовано поверх SQLite в режиме WAL (`src/state/openclaw-state-db.ts`, `src/config/sessions/session-accessor.sqlite-transcript-store.ts`).
- **Синхронизация и блокировки**: Использование очередей захвата состояния, атомарных транзакций миграции, распределенного сброса на диск (`disk-budget.ts`, `session-reclamation-worker.ts`).
- **Транскрипты**: Поддержка версионирования транскриптов, очистки устаревших сообщений по retention-политикам и сброса в холодное хранилище (`session-cold-storage-inventory.ts`).

### Сессии в Pi
- **Файловая модель дерева**: Сессия представляет собой направленный ациклический граф (DAG) или последовательную ленту событий, сериализуемую в `.jsonl`.
- **Ветвление и откат (Branching / Switch)**: В коде `agent-session.ts` реализованы методы переключения веток диалога, возможность вернуться к любому предыдущему сообщению и создать альтернативную ветку вычислений (`branchSummary`, `session-export.ts`).
- **Автоматическая компактизация (Compaction)**: Модуль `core/compaction/compaction.ts` вычисляет расход контекстного окна по токенам (`reserveTokens`, `keepRecentTokens`). При превышении лимита система автоматически генерирует саммари ветки диалога и очищает ранние шаги без потери ключевого контекста.
- **Экспорт в автономные форматы**: Встроенный генератор HTML-отчетов (`core/export-html/index.ts`) с визуализацией ANSI-цветов, результатов выполнения инструментов и markdown-версткой.

## 4. Глубокие настройки и конфигурация систем

### Настройки OpenClaw (`types.openclaw.ts`)
В OpenClaw файл настроек (`openclaw.json` / `openclaw.yaml`) представляет собой масштабную конфигурационную структуру:
1. **`gateway`**: настройки прослушивания портов, SSL/TLS сертификаты, лимиты памяти воркеров, таймауты preauth, CORS и origin policy.
2. **`channels`**: раздельные секции для каждого адаптера (токены ботов, webhooks, polling intervals, rate limits, белые списки пользователей).
3. **`tools` & `security`**: детальные списки запрещенных/разрешенных команд (`alsoAllow`), песочницы, правила утверждения действий человека в контуре (human-in-the-loop: `exec.approvals`).
4. **`models`**: каталог провайдеров, переопределения базовых URL, маппинг параметров контекстного окна, fallback-цепочки и балансировка.
5. **`tts` & `meeting-bot`**: настройки синтеза речи, захвата аудио, подключения к видеоконференциям и транскрипции реального времени.

### Настройки Pi (`settings-defaults.ts` & `config.ts`)
В Pi настройки лаконичны, прагматичны и нацелены на поведение агента и интерфейс:
1. **`compaction`**: пороги сжатия контекста (`reserveTokens: 16384`, `keepRecentTokens: 20000`).
2. **`retry`**: детальная политика повторных попыток для API провайдеров (`maxRetries: 3`, экспоненциальный `baseDelayMs: 2000`, `maxAgentDelayMs`).
3. **`codemode`**: режим работы (`on`/`off`, лимит байт инлайн-скрипта `inlineBudget: 3000`).
4. **`terminal` & `tui`**: настройки рендеринга терминала (поддержка изображений Kitty/Sixel/iTerm, ширина в ячейках `imageWidthCells: 60`, полноэкранный TUI режим, обработка скролла колесом мыши).
5. **`steeringMode` & `followUpMode`**: режимы управления очередью сообщений (`one-at-a-time`).

## Резюме первого отчёта
OpenClaw представляет собой **инфраструктурный шлюз-сервер**, объединяющий разнообразные протоколы коммуникаций, распределенные воркеры и мультимодальные сервисы вокруг централизованной базы данных. В то же время Pi — это **высокооптимизированный агентно-ориентированный движок разработки и фреймворк компонентов**, сфокусированный на максимальной точности работы с кодом, низком потреблении ресурсов, гибких стратегиях сжатия контекста и глубокой терминальной интеграции.
