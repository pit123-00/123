# Отчёт 4: Плюсы и минусы решений (Управление агентами, субагентами, MCP, CLI, API и пайплайнами)

В данном отчёте проведён детальный сравнительный анализ преимуществ и недостатков [openclaw/openclaw](https://github.com/openclaw/openclaw) и [earendil-works/pi](https://github.com/earendil-works/pi) в разрезе ключевых подсистем: управление агентами и субагентами, поддержка протокола Model Context Protocol (MCP), возможности интерфейса командной строки (CLI), API-доступ, организация конвейеров (пайплайнов) инструментов и политик безопасности.

---

## 1. Управление агентами и субагентами

### OpenClaw: Иерархическое дерево субагентов и централизованный оркестратор
В OpenClaw управление агентами и субагентами реализовано в модулях `src/agents/subagents/`, `src/agents/tools/subagents-tool.ts` и `src/gateway/server-methods/agent-subagent-registration.ts`.
- **Механизм работы**:
  - Агент может порождать дочерних агентов через инструмент `subagents_spawn` / `subagents-tool.ts`.
  - Субагенты регистрируются в SQLite и получают уникальный `runId` с привязкой к контроллеру (`subagent-control-scope.ts`).
  - Реализован протокол оповещения об окончании работы: `announce` (`subagent-announce-dispatch.ts`, `subagent-announce-completion-delivery.ts`).
  - Родительский процесс может отслеживать статус, приостанавливать (`yield-pause`), возобновлять (`resume`) или принудительно убивать (`killSubagentRunAdmin`) выполнение субагентов.
  - Поддержка фонового запуска через Cron (`cron/isolated-agent/`).
- **Плюсы**:
  - Полный контроль жизненного цикла субагентов (deadlock detection, timeout enforcement, лимиты времени `MAX_RECENT_MINUTES`).
  - Результаты работы субагентов надежно фиксируются в базе данных и не теряются при авариях процессов.
  - Поддержка межагентного делегирования с прозрачной доставкой ответов в исходный канал (например, в тред Discord или Slack).
- **Минусы**:
  - Высокая сложность системы: десятки вспомогательных файлов синхронизации, блокировок транзакций и очередей.
  - Значительные накладные расходы по памяти и задержкам на создание каждого субагента (тяжелый контекст, инициализация БД).

### Pi: Вложенные вызовы инструментов (Nested Tool Calls) и расширения
В Pi концепция агентов и субагентов построена на модулях `@earendil-works/pi-agent-core/src/agent-loop.ts`, `nested-tool-calls.ts` и примерах расширений (`examples/extensions/subagent/index.ts`).
- **Механизм работы**:
  - Агентный цикл `AgentSession` позволяет любому инструменту вызвать другой инструмент через контекст `ctx.executeTool()`.
  - При выполнении субагента дочерний цикл запускается прямо внутри процесса или передается в изолированную песочницу Codemode (QuickJS WASM).
  - События выполнения порождают `tool_execution_*` с атрибутом `parentToolCallId`, а токены агрегируются через `combineUsage()`.
- **Плюсы**:
  - Минимальные накладные расходы (вызовы происходят в памяти процесса практически с нулевой задержкой).
  - Codemode позволяет LLM самостоятельно оркестровать параллельные вызовы через JavaScript код (например, `Promise.all([tool1(), tool2()])`), не тратя лишние токены и раунды общения с основной моделью.
- **Минусы**:
  - Отсутствие встроенного в ядро долгоживущего дерева процессов уровня ОС (нет фонового планировщика убийства зависших субагентов по умолчанию в базовом CLI, если не используется пакет `@pi/durable`).

## 2. Интеграция Model Context Protocol (MCP)

### OpenClaw: Сервер и мост MCP для внешних клиентов
Код: `src/mcp/`, `src/mcp/tools-stdio-server.ts`, `src/mcp/openclaw-tools-serve.ts`.
- **Реализация**:
  - OpenClaw в первую очередь выступает **MCP-сервером**. Он экспортирует свои внутренние инструменты наружу по протоколу stdio или через WebSocket-каналы для других MCP-клиентов (например, Claude Desktop).
  - Наличие `codex-supervision-tools-serve.ts` для предоставления инструментов аудита и инспекции внешним агентам.
- **Плюсы**:
  - Позволяет легко подключать всю экосистему OpenClaw (каналы мессенджеров, доступ к БД, браузерную автоматизацию) в любые сторонние IDE и среды, поддерживающие MCP.
- **Минусы**:
  - Клиентская часть MCP менее модульна; фокус смещен на роль шлюза-провайдера инструментов, а не гибкого динамического подключения сотен сторонних серверов на лету.

### Pi: Полнофункциональный клиент MCP промышленного уровня с поддержкой OAuth 2.0 PKCE
Код: `packages/mcp/`, `packages/coding-agent/src/extensions/mcp/`.
- **Архитектура клиента MCP в Pi**:
  - Пакет `packages/mcp/src/client.ts` реализует строго типизированный протокол JSON-RPC для взаимодействия с MCP-серверами.
  - Поддержка 4 транспортов: `stdio` (локальные процессы через пайпы), `streamable-http` (потоковый HTTP), `in-memory` (для тестирования), `pipe` (`src/transports/pipe.ts`).
- **Спецификация и реализация OAuth 2.0 PKCE (`packages/mcp/src/oauth/`)**:
  - **Автоматическое обнаружение (`discovery.ts`)**: автоматический опрос Well-Known эндпоинтов авторизационного сервера для извлечения URL авторизации, обмена токенов и списка поддерживаемых скоупов.
  - **Локальный Loopback сервер (`loopback.ts`)**: запуск временного локального HTTP-сервера для перехвата редиректа браузера с кодом авторизации (`callback.ts`). Пользователю не нужно вручную копировать токены.
  - **PKCE верификаторы (`flow.ts`)**: использование криптографического Proof Key for Code Exchange (SHA-256 code challenge) для защиты от перехвата авторизационного кода.
  - **Автообновление токенов (`auth-provider.ts`, `client-settings.ts`)**: автоматическая ротация refresh token при истечении срока действия access token без прерывания пользовательской сессии.
- **Кэширование и строгая валидация схем через TypeBox (`src/input-schema.ts`)**:
  - Все JSON-схемы входящих инструментов от сторонних MCP-серверов валидируются и компилируются через `@earendil-works/pi-schema`.
  - Устраняются ошибки синтаксиса сторонних серверов, генерируются детерминированные TypeScript типы параметров.
- **Защита от переполнения контекста (`src/output-limit.ts`)**:
  - Интеллектуальный контроль размера ответа инструмента: обрезка вывода по байтам и строкам, предотвращающая падение LLM при выдаче мегабайтных дампов от серверов.
- **Плюсы реализации Pi**:
  - Один из самых технически совершенных и чистых MCP-клиентов на TypeScript в open-source сообществе.
  - Поддержка аутентифицированных корпоративных MCP-серверов в облаке через OAuth без ручного прописывания токенов в открытом виде.
  - Конфигурация в `settings.json` позволяет одной строкой подключить любой внешний MCP-сервер как инструмент агента (`mcp.servers`).
- **Минусы**:
  - По умолчанию Pi действует как MCP-клиент, а не сервер (хотя архитектура позволяет экспортировать инструменты, это требует дополнительного кода обертки).

## 3. CLI интерфейсы и режимы взаимодействия

### OpenClaw CLI
Код: `src/entry.ts`, `src/cli/program/build-program.ts`, `src/commands/`.
- Построен на базе `commander`.
- Насчитывает десятки специализированных сервисных команд: `setup`, `onboard`, `configure`, `database`, `migrate`, `backup`, `audit`, `maintenance`, `transcripts`, `doctor` (огромный модуль самодиагностики инфраструктуры).
- **Плюсы**:
  - Исчерпывающие утилиты для администрирования production-инсталляции (проверка валидности миграций БД, аудит ключей шифрования, управление демоном `systemd`/`launchd`).
- **Минусы**:
  - Интерактивный терминальный интерфейс для общения с кодом не является приоритетом — команды нацелены на обслуживание сервера.

### Pi CLI & TUI
Код: `packages/coding-agent/src/main.ts`, `packages/tui/`, `modes/interactive/`.
- Поддерживает 3 основных режима:
  1. **Интерактивный TUI**: Полноэкранный терминальный интерфейс на базе `@earendil-works/pi-tui` с поддержкой мыши, рендеринга Mermaid-диаграмм в реальном времени, отображения изображений в высоких разрешениях (Kitty, Sixel) и автодополнения слэш-команд.
  2. **Print Mode**: Пакетный режим вывода в `stdout` для скриптов CI/CD.
  3. **RPC Mode (`rpc-mode.ts`)**: Headless-режим взаимодействия по протоколу JSONL через стандартные потоки ввода-вывода.
- **Плюсы**:
  - Непревзойденный пользовательский опыт для разработчика в терминале.
  - Мгновенная отзывчивость, поддержка кастомных тем, внешних редакторов (`external-editor.ts`) и интерактивного выбора моделей.

## 4. API доступ и протоколы интеграции

### OpenClaw API: Двусторонний WebSocket Gateway и RPC-методы
- Основа взаимодействия — постоянное WebSocket-соединение (`src/gateway/server/ws-connection.ts`) с сериализацией JSON-RPC / бинарных фреймов.
- Более 540 типизированных методов управления (`CORE_GATEWAY_METHOD_SPECS`): чтение логов в реальном времени (`logs.tail`), управление звонками, рассылка сообщений по каналам, статус здоровья нод.
- **Плюсы**: Идеально для корпоративных веб-панелей, мобильных клиентов (React Native/iOS/Android) и внешних систем интеграции.
- **Минусы**: Требует постоянного сетевого подключения, поддержки протокола рукопожатия и контроля пингов/понгов.

### Pi API: Чистый JSONL RPC и SDK для встраивания
- Режим `rpc-mode.ts` принимает команды через `stdin` и отдает события `AgentSessionEvent` через `stdout`.
- Пакет `@earendil-works/pi-agent-core` и `@earendil-works/pi-coding-agent/sdk` можно импортировать напрямую в любой TypeScript/JavaScript проект как библиотеку (`createAgentSession()`).
- **Плюсы**:
  - Отсутствие зависимости от сети и открытых сокетов; легко оборачивается в плагины для VS Code, JetBrains IDE или веб-серверы.
  - Потокобезопасная передача сообщений с детерминированным вводом-выводом.
- **Минусы**:
  - Нет встроенного готового HTTP REST / WebSocket сервера «из коробки» в базовом пакете (сетевой слой вынесен в приложение `p2`/`chord`).

## 5. Пайплайны (Конвейеры) и политики инструментов

### OpenClaw: Многоуровневые политики разрешений (Security Pipeline)
Код: `src/agents/conversation-tool-policy-pipeline.ts`, `src/agents/tool-policy-pipeline.ts`.
- **Пайплайн включает**:
  - `mergePolicyAllowlist` и профили `capabilityProfile`.
  - Проверку прав отправителя (`sender policy`), ограничение запуска в песочницах (`sandbox policy`), правила утверждения человеком (`approval rules`).
  - Runtime-cap ограничения (лимиты на количество вызовов на один раунд).
- **Плюсы**: Максимальная безопасность корпоративного уровня — исключена ситуация неконтролируемого выполнения опасных команд от недоверенных пользователей мессенджера.
- **Минусы**: Сложный каскад проверок увеличивает задержку перед каждым вызовом инструмента.

### Pi: Перехватчики жизненного цикла (Lifecycle Hooks Pipeline)
Код: `packages/agent/src/agent-loop.ts`, `packages/coding-agent/src/core/nested-tool-calls.ts`.
- **Пайплайн включает**:
  - Хуки `beforeToolCall`: могут модифицировать параметры инструмента, заблокировать выполнение или вернуть кэшированный результат.
  - Хуки `afterToolCall`: могут нормализовать ответ, перехватить ошибки или скрыть избыточный вывод.
  - Хук `prepareNextTurn`: позволяет инжектировать системные напоминания или динамически изменять список доступных инструментов перед следующим шагом модели.
- **Плюсы**:
  - Полная свобода для разработчика расширений; лаконичный код без переусложненных абстракций.
- **Минусы**:
  - Ответственность за безопасность возложена на автора расширения или конфигурацию доверия к проекту (`project-trust.ts`).

## 6. Итоговая матрица плюсов и минусов

| Компонент / Направление | OpenClaw | Pi |
| :--- | :--- | :--- |
| **Управление агентами** | **+** Централизованное управление, персистентность в БД, Cron.<br>**–** Тяжеловесность, оверхед памяти. | **+** Легковесность, реактивный цикл, запуск в QuickJS WASM.<br>**–** Нет встроенного фонового демона. |
| **Субагенты** | **+** Дерево процессов, pause/resume, announce completion.<br>**–** Сложная синхронизация транзакций. | **+** Вложенные вызовы (`ctx.executeTool`), параллелизм через JS.<br>**–** Управление в рамках одного процесса. |
| **MCP** | **+** Выступает как богатый инструментами MCP-сервер.<br>**–** Меньше акцента на подключение сторонних серверов. | **+** Полноценный клиент с поддержкой OAuth 2.0 PKCE и Streamable HTTP.<br>**–** Не является сервером по умолчанию. |
| **CLI** | **+** Мощный инструментарий администрирования, миграций и doctor.<br>**–** Нет глубокого TUI для интерактивного кодинга. | **+** Полнофункциональный TUI с графикой, темами, автодополнением.<br>**–** Минимум утилит системного администрирования. |
| **API доступ** | **+** Масштабный WebSocket Gateway с 540+ RPC-методами.<br>**–** Высокий порог интеграции клиента сокетов. | **+** Простой JSONL над stdin/stdout (RPC) + прямое SDK для TypeScript.<br>**–** Нет готового публичного REST/WS API сервера. |
| **Пайплайны инструментов** | **+** Строгие корпоративные политики безопасности и approvals.<br>**–** Оверхед на многоступенчатую проверку. | **+** Гибкие хуки `before/afterToolCall`, быстрая валидация TypeBox.<br>**–** Меньше встроенных политик разграничения прав. |
