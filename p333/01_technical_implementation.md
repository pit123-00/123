# Отчёт №1: Техническая реализация репозитория agentic-coding-design-patterns

## 1. Введение и область анализа

Данный технический отчёт подготовлен на основе прямого анализа исходного кода и конфигурационных файлов репозитория `https://github.com/mokevnin/agentic-coding-design-patterns`. Анализ выполнен исключительно по кодовой базе, скриптам, конфигурациям инструментов и структуре скиллов без обращения к общим обзорным текстам и маркетинговым описаниям (README).

Репозиторий представляет собой специализированную инженерную инфраструктуру и исполняемую среду для агентного программирования (Agentic Coding), включающую:
1. Конфигурацию рантаймов и тулинга AI-агентов (Claude Code, OpenAI Codex, Agnix).
2. Систему блокировок и хэширования внешних навыков (`skills-lock.json`).
3. Изоляцию памяти и предотвращение дрейфа контекста (`autoMemoryEnabled: false`, `memories = false`).
4. Внутренний плагин компиляции диаграмм Mermaid в headless-браузере (`plugins/honkit-plugin-mermaid/index.js` на базе Playwright и `mermaid-isomorphic`).
5. Мультиинструментальную цепочку валидации, линтинга и контроля качества через декларативный конфиг `hk.pkl`, пакетный менеджер `mise.toml` и pnpm workspaces.

## 2. Глубокие настройки рантаймов и AI-агентов

В проекте реализован строгий контракт управления поведением AI-агентов на уровне системных конфигурационных файлов.

### 2.1. Конфигурация Claude Code (`.claude/settings.json`)
```json
{
  "autoMemoryEnabled": false
}
```
- **Параметр `autoMemoryEnabled: false`**: В кодовой базе принудительно отключена внутренняя автоматическая память Claude Code (`~/.claude/projects/.../memory/`).
- **Техническая мотивация**: Автоматическая скрытая память LLM приводит к «галлюцинациям состояния», скрытым побочным эффектам между сессиями разных разработчиков и невозможности воспроизвести поведение агента на CI или другой машине. Вся память проекта должна быть детерминированной, ревизуемой через Git и явно описанной в версионируемых файлах (например, `AGENTS.md` или `docs/`).

### 2.2. Конфигурация OpenAI Codex (`.codex/config.toml`)
```toml
# Agent memory stays off in this repo: project knowledge goes to reviewed files (AGENTS.md), see book/en/private-agent-memory.md.
[features]
memories = false
exclude = [
  "node_modules/**",
  ".git/**",
  "dist/**",
  # Vendored skills, pinned by hash in skills-lock.json; never edited here.
  ".agents/skills/**",
  ".claude/skills/**"
]
```
- **Параметр `features.memories = false`**: Аналогично Claude Code, для Codex отключается сохранение неявных воспоминаний.
- **Параметр `exclude`**: Исключает из контекстного окна агента служебные директории сборки, кэшей и репозитория (`node_modules/**`, `.git/**`, `dist/**`).
- **Защита вендоринга**: Исключение `.agents/skills/**` и `.claude/skills/**` гарантирует, что агент не станет самовольно модифицировать вендоренные файлы навыков, которые закреплены криптографическим хэшем в `skills-lock.json`.

### 2.3. Конфигурация линтера агентов Agnix (`.agnix.toml`)
```toml
exclude = [
  "node_modules/**",
  ".git/**",
  "dist/**",
  # Vendored skills, pinned by hash in skills-lock.json; never edited here.
  ".agents/skills/**",
  ".claude/skills/**"
]
```
- Проект использует статический анализатор `agnix` (`github:agent-sh/agnix = "0.61.0"`), проверяющий валидность промптов, соответствие форматов `AGENTS.md`, `CLAUDE.md` и разметки скиллов.
- Исключение путей предотвращает ошибки валидации в сторонних неизменяемых зависимостях.

## 3. Криптографический вендоринг навыков (`skills-lock.json`)

Одной из уникальных технических подсистем является фиксация целостности навыков агентов через `skills-lock.json`.
Формат файла:
```json
{
  "version": 1,
  "skills": {
    "ask-matt": {
      "source": "mattpocock/skills",
      "sourceType": "github",
      "skillPath": "skills/engineering/ask-matt/SKILL.md",
      "computedHash": "cacd2e77c8c0b456133a60be07493dd091ace65f52b02f90cbb8f75de15989f5"
    },
    "code-review": {
      "source": "mattpocock/skills",
      "sourceType": "github",
      "skillPath": "skills/engineering/code-review/SKILL.md",
      "computedHash": "4a17d9d3e0fc87ae48544d371a820fac5a4a78f4c05e7e6b3229094fbf8a7e26"
    },
    ...
  }
}
```

### Механика работы и преимущества:
1. **Защита от дрейфа инструкций (Prompt Injection / Drift Prevention)**: При обновлении внешних навыков (например, из upstream-репозитория `mattpocock/skills`) система проверяет `computedHash` (SHA-256). Агент не может «подхватить» измененную логику без явного коммита нового хэша разработчиком.
2. **Вендоринг в кодовой базе**: Все файлы скиллов располагаются физически в `.agents/skills/<skill-name>/SKILL.md`, а также симлинкуются в `.claude/skills/`. Это гарантирует работу в автономном офлайн-режиме без обращений к внешним серверам во время генерации кода.
3. **Строгий запрет ручных правок**: В `AGENTS.md` и `hk.pkl` зафиксировано правило, что файлы внутри `.agents/skills` не редактируются вручную.

## 4. Рендеринг диаграмм в SVG через Playwright (`plugins/honkit-plugin-mermaid`)

Репозиторий содержит собственный плагин для Honkit (`plugins/honkit-plugin-mermaid/index.js`), решающий фундаментальную проблему документации для агентов и компиляции в PDF/HTML.

### 4.1. Архитектура плагина:
- **Гибридный CJS/ESM загрузчик**: Honkit требует плагины через синхронный `require()`, в то время как современный `mermaid-isomorphic` поставляется исключительно как ESM. В плагине применен отложенный динамический импорт:
  ```javascript
  rendererPromise ??= import('mermaid-isomorphic').then(({ createMermaidRenderer }) =>
    createMermaidRenderer()
  );
  ```
- **Изоляция в Headless-браузере**: `mermaid-isomorphic` запускает Playwright в headless-режиме, передавая диаграмму внутрь браузерного контекста с подключенным Mermaid.js. Это позволяет генерировать валидный, самодостаточный векторный SVG без использования клиентского JavaScript при просмотре книги или генерации PDF (`honkit pdf` не поддерживает выполнение клиентского JS).
- **Кэширование по хэшу конфигурации и исходника**:
  ```javascript
  function digest(source, config) {
    return crypto
      .createHash('sha256')
      .update(JSON.stringify(config))
      .update(source)
      .digest('hex')
      .slice(0, 16);
  }
  ```
  Плагин высчитывает SHA-256 от комбинации `JSON.stringify(config) + source` и сохраняет результат в `node_modules/.cache/honkit-mermaid/<hash>.svg`. Это ускоряет пересборку в десятки раз: если ни конфигурация темы, ни диаграмма не изменились, результат мгновенно берется из файлового кэша.
- **Поддержка двух тем (Light / Dark) в едином бандле**:
  Для веб-сборки плагин компилирует две версии каждого графа:
  ```javascript
  const light = await render(source, mermaidConfig);
  const dark = await render(source, darkConfig);
  return `<figure class="mermaid mermaid-themed"><div class="mermaid-light">${light}</div><div class="mermaid-dark">${dark}</div></figure>`;
  ```
  Переключение происходит чисто через CSS (`website.css`), исключая мигание или динамический перерендер.
- **Парсинг DOM через Cheerio**: Плагин перехватывает сгенерированный Honkit HTML, находит теги `pre > code.lang-mermaid` и заменяет их на готовые теги `<figure>`, устраняя необходимость хрупкого регулярного выражения.

## 5. Инфраструктура сборки, хуков и линтинга (`mise.toml`, `hk.pkl`)

Управление зависимостями и процессами выстроено через связку **Mise** (унифицированный менеджер окружения) и **hk** (быстрый раннер хуков и чеков на базе языка конфигураций Apple Pkl).

### 5.1. Управление окружением (`mise.toml`)
- Фиксация рантайма Node.js (`26.13.0`), pnpm через `packageManager` в `package.json` (`pnpm@12.18.0`).
- Пинирование бинарных линтеров:
  - `hk` (2.11.1) — раннер проверок на Pkl.
  - `pkl` (0.33.0) — движок типизированной конфигурации.
  - `jactionlint` (2.5.0) — линтер GitHub Actions.
  - `betterleaks` (1.10.0) — сканер утечек секретов.
  - `typos` (1.52.0) — сверхбыстрый спеллчекер исходников.
  - `rumdl` (0.3.2) — специализированный форматер Markdown.
  - `agnix` (0.61.0) — линтер агентных промптов и спек.
  - `osv-scanner` (2.7.0) — сканер уязвимостей в зависимостях.
  - `lychee` (0.24.2) — валидатор внутренних и внешних гиперссылок.
- Задачи (`tasks`):
  - `mise run setup`: установка зависимостей, компиляция инструментов и инсталляция git-хуков.
  - `mise run check`: параллельный запуск всех проверок через `hk check --all`.
  - `mise run fix`: автоматическое безопасное исправление форматирования и линтинга.

### 5.2. Декларативная конфигурация хуков в Apple Pkl (`hk.pkl`)
Конфигурация хуков написана на типизированном языке Apple Pkl с наследованием от `Builtins.pkl`:
- Разделение зон ответственности:
  - Форматирование кода, конфигов и стилей (`*.js`, `*.json`, `*.css`, `*.yml`, `*.toml`) отдано `oxfmt` (на Rust).
  - Форматирование Markdown жестко закреплено за `rumdl`, чтобы поддерживать жесткое правило: *один физический абзац текста на одну строку файла* (без искусственных разрывов строк), что критично для парсеров LLM и минимизации диффов.
  - `syncpack` проверяет консистентность версий зависимостей в pnpm-монорепозитории.
  - `lychee` запускается в офлайн-режиме (`--offline --no-progress`) для мгновенной валидации связности документации.
  - Встроены проверки на конфликты слияния Git (`check_merge_conflict`), конфликты регистра файловых систем (`check_case_conflict`) и валидность симлинков (`check_symlinks`).
- Прекоммит-хук автоматически применяет безопасные фиксы (`fix = true`) и изолирует изменения через stash (`stash = "git"`).

## 6. Технические преимущества реализации

1. **Детерминизм контекста LLM**: Полный отказ от скрытой автопамяти (`autoMemoryEnabled: false`, `memories: false`) исключает расхождение поведения агентов у разных инженеров и на CI.
2. **Нулевой сетевой оверхед при исполнении скиллов**: Все 21 скилл с вендоренными хэшами лежат локально в репозитории.
3. **Безопасность вендоринга**: Исключение `.agents/skills` из области поиска агентов в `.codex/config.toml` и `.agnix.toml` защищает ядро воркфлоу от несанкционированной перезаписи самим LLM-агентом.
4. **Сверхбыстрый пайплайн проверок**: Использование Rust-утилит (`oxlint`, `oxfmt`, `typos`, `rumdl`, `lychee`) под управлением `hk` позволяет выполнять полный цикл проверки сотен файлов менее чем за секунду.
5. **Векторная графика без JS-зависимости в рантайме**: Предварительный рендеринг Mermaid в headless Playwright на этапе сборки плагина позволяет генерировать чистые SVG-изображения, работающие как в браузере, так и в оффлайн PDF-документах.
