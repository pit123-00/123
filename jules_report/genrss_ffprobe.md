# 1. Техническая реализация и архитектура
Если анализ нативного Python-кода (mutagen) терпит неудачу, `genRSS` применяет интеграцию с системной утилитой `ffprobe` (часть пакета FFmpeg) через модуль `subprocess`. Это архитектурное решение (оболочка над CLI-инструментом) позволяет поддерживать практически любые видео и аудио форматы для извлечения технических параметров (в частности, длительности). Вызов обернут в функцию-помощник `_run_command`, которая безопасно выполняет команду, перехватывает вывод и ошибки (stderr).

# 2. Функции и логическая работа
Функция `get_duration_ffprobe(filename)` формирует массив аргументов для вызова `ffprobe`:
`["ffprobe", "-i", filename, "-show_entries", "format=duration", "-v", "quiet", "-of", "csv=p=0"]`.
- `-i filename`: указывает входной файл.
- `-show_entries format=duration`: запрашивает только длительность файла (игнорируя остальные сотни параметров).
- `-v quiet`: отключает вывод отладочной информации и баннеров FFmpeg.
- `-of csv=p=0`: форматирует вывод как чистый текст (CSV без заголовков), так что `ffprobe` возвращает только одно число (длительность в секундах с плавающей точкой).
Затем `subprocess.Popen` (внутри `_run_command`) выполняет процесс. Результат (строка) конвертируется во `float`, округляется до целых секунд с помощью `round()` и возвращается. В случае ошибки `ValueError` (если ffprobe вернул мусор или не установлен) возвращается `None`.

# 3. Информационный обмен, память и потоки данных
Поток данных происходит между основным Python-процессом и дочерним системным процессом.
- Python передает аргументы и путь к файлу в операционную систему для запуска бинарника `ffprobe`.
- `ffprobe` читает файл с диска. Подобно `mutagen`, он оптимизирован для быстрого чтения заголовков (moov atom в MP4 и т.д.), поэтому файл не загружается в RAM целиком.
- Вывод (stdout) буферизуется Python через пайпы (`subprocess.PIPE`). Поскольку мы запрашиваем только одно конкретное значение, размер возвращаемой строки составляет всего несколько байт (например, `"125.43\n"`).
- Строка парсится в памяти Python-процесса и интегрируется в итоговый XML-документ. Данная изоляция исключает утечки памяти в Python, так как всю сложную работу с медиаконтейнерами делает изолированный процесс `ffprobe`, который корректно завершается и освобождает свои ресурсы.
