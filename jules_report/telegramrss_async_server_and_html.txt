# Отчет по TelegramRSS

## 1. Техническая реализация и архитектура
Проект реализован на PHP 8+ с использованием асинхронного фреймворка `amphp` (`Amp`).
Его архитектурная суть заключается в том, что он выступает высокопроизводительным HTTP-прокси/сервером для Telegram.
Однако `TelegramRSS` **не реализует протокол MTProto самостоятельно**. Вместо этого он подключается через HTTP к отдельному микросервису `TelegramApiServer` (который использует MadelineProto для связи с Telegram через MTProto).
- `app/Server/Server.php` (и `server.php`) инициализирует асинхронный HTTP сервер (`SocketHttpServer` из Amp).
- `app/TgClient.php` является асинхронным HTTP-клиентом (также на базе Amp `HttpClient`), который перенаправляет запросы к `TelegramApiServer` для получения сырых данных или скачивания медиа.

## 2. Функции и логическая работа
- **Асинхронный PHP-сервер как прокси:**
  Сервер принимает HTTP запросы пользователей (через браузер или RSS ридеры), затем `TgClient` асинхронно опрашивает `TelegramApiServer` (который уже работает с MTProto). За счет Amp достигается высокая конкуррентность - сервер не блокируется (non-blocking I/O) при ожидании ответа от Telegram или скачивании файлов. Маршрутизация запросов (RSS, JSON, Media) реализована в `Router.php`.
- **Алгоритмы конвертации специфичного форматирования Telegram в чистый HTML (Messages.php):**
  Файл `app/RSS/Messages.php` преобразует JSON-ответ с сырыми сообщениями в стандартизированные элементы:
  - **Группировка медиа (Альбомы):** Сообщения объединяются по полю `grouped_id`, что позволяет собрать несколько фото/видео (`preview`, `href`) в один блок публикации.
  - **Заголовки и Description:** Логика в функции `setTitle` берет первое предложение из текста (с помощью регулярных выражений, ищущих точку, знак вопроса, абзац) или урезает строку до 100 символов, если первое предложение не найдено. К заголовку добавляются префиксы `[Video]`, `[Photo]`, `[Sponsored]`, если присутствуют соответствующие типы вложений.
  - **Обработка форвардов и ссылок (WebPage/Link Preview):** Если сообщение является репостом (`fwd_from`), извлекается информация об исходном канале и авторе. Если есть `webpage` preview (ссылка внутри Telegram), к результату добавляются метаданные этой ссылки.
  - **Реакции:** Извлекаются `reactions` и их количество (`reactionCount`), прикрепляя к публикации emoji-реакции.

## 3. Обмен информацией, память и потоки данных
- Внешний RSS-ридер обращается к эндпоинту `TelegramRSS` (например `/rss/channelname`).
- `TelegramRSS` через асинхронный HTTP клиент (Amp) отправляет POST-запрос с JSON Payload в `TelegramApiServer`.
- `TelegramApiServer` общается с серверами Telegram по MTProto и возвращает массив сообщений.
- `TelegramRSS` получает JSON. Если в сообщениях есть медиа-вложения, параллельно (с помощью `Amp\Future\await(async(...))`) отправляются новые запросы к `TelegramApiServer` для получения ссылок/информации о медиа (`getMediaInfo`).
- Все полученные данные трансформируются (через методы `Messages.php`) в унифицированный вид (массив) и передаются в классы генерации (например, `Feed.php` -> `mibe/FeedWriter`), после чего клиенту отдается XML RSS-поток или JSON. При запросах медиа-файлов, они скачиваются порциями и стримятся клиенту "на лету" с поддержкой диапазонов.
