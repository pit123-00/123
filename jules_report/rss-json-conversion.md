# Преобразование JSON Feed в RSS и обратно

Технический анализ механизмов обработки, нормализации и маппинга форматов RSS и JSON в проекте Folo.

## 1. Техническая реализация и архитектура

В Folo обработка различных форматов новостных лент строится на основе стандартизированной модели данных, унифицирующей параметры. Архитектура основывается на:

- **Обфускация и кодирование (`JsonObfuscatedCodec`):** Для передачи и сохранения сложных JSON-объектов (например, конфигураций или сырых данных фида) проект использует утилитарный класс `JsonObfuscatedCodec`. Он конвертирует JSON-строку в массив байт, шифрует с помощью XOR (ключ "Folo") и переводит в кастомный `charset` (Base64-подобный).
- **RSSHub Интеграция (`models/src/rsshub.ts`):** Проект тесно интегрирован с экосистемой RSSHub. Модель `RSSHubRouteDeclaration` стандартизирует маршруты, параметры и категории для генерации RSS/JSON фидов из сайтов, не поддерживающих RSS нативно.
- **Маппинг категорий (`constants/src/rsshub.ts`):** Стандартизированный список категорий (`social-media`, `blog`, `programming` и т.д.) позволяет единообразно отображать и фильтровать ленты независимо от их исходного формата.

*Примечание: Прямой парсинг XML-строк (RSS) в JSON Feed обычно выполняется на стороне бэкенда (или через сервер-сайд парсеры на Node.js). В инспектируемом клиентском коде и утилитах упор сделан на унификацию метаданных (через `RSSHub`) и сериализацию JSON (через `JsonObfuscatedCodec`).*

## 2. Функции и логическая работа

Процесс обработки данных включает следующие механизмы:

- **Сериализация JSON Feed (`JsonObfuscatedCodec.encode`):**
  Функция принимает любой JS-объект, применяет `JSON.stringify()`, конвертирует строку в `Uint8Array`, XOR-шифрует и возвращает безопасную обфусцированную строку, состоящую из кастомного алфавита.
- **Десериализация в JSON (`JsonObfuscatedCodec.decode`):**
  Функция выполняет обратный процесс: преобразует кастомную строку в байты, расшифровывает XOR и делает `JSON.parse()`. Это полезно для кэширования сырых фидов или передачи метаданных через URL-параметры.
- **Нормализация RSSHub маршрутов:**
  Интерфейс `RSSHubRoute` описывает параметры (`parameters`), примеры URL (`example`) и рекомендуемый тип отображения (`view?: FeedViewType`), что позволяет приложению "на лету" понимать, как запрашивать данные (ожидать XML или JSON) и в каком виде рендерить результат (например, `social-media` вид для Twitter).

## 3. Обмен информацией, память и потоки данных

Поток преобразования данных:

1. **Входящие данные:** Внешний сервис или бэкенд Folo запрашивает RSS/JSON. Если используется RSSHub, возвращается стандартизированный JSON Feed.
2. **Адаптация модели:** Сырые данные (XML RSS или JSON Feed) преобразуются бэкенд-парсером в универсальные модели `FeedSchema` и `EntrySchema`.
3. **Хранение (SQLite/Drizzle):** Категории сохраняются как JSON-массив (`categories: text("categories", { mode: "json" })`), а медиа-вложения нормализуются в массивы `MediaModel[]` и `AttachmentsModel[]`.
4. **Безопасная передача:** Для сохранения состояния парсера или передачи сложных настроек фида между процессами (например, из Electron-бэкенда в UI) используется `JsonObfuscatedCodec`, который гарантирует целостность переданного JSON.
