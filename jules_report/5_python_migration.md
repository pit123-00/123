# Как переписать проект на Python

## 1. Техническая реализация и архитектура
Архитектура NodeRSSBot состоит из трех основных компонентов: Telegram-бот (UI и обработка команд), Планировщик/Воркер (фоновый опрос RSS-лент) и База Данных (хранение состояния). При миграции на Python эту архитектуру можно сохранить, заменив Node.js библиотеки на эквивалентные Python-решения:

*   **Telegram-бот:** Заменить `Telegraf` на **`aiogram`** (асинхронный, быстрый, современный) или `python-telegram-bot`. Учитывая, что NodeRSSBot написан с использованием `async/await`, `aiogram` (v3) станет идеальной заменой.
*   **База данных и миграции:** Заменить `Knex.js` (Query Builder) на ORM. Лучшие варианты: **`SQLAlchemy`** (классика, мощная) или **`SQLModel`** (современная надстройка над SQLAlchemy и Pydantic). Для управления миграциями вместо Knex Migrations использовать **`Alembic`**. База данных остается PostgreSQL (драйвер `asyncpg`) или SQLite (драйвер `aiosqlite`).
*   **Парсинг XML/RSS:** Заменить библиотеку `camaro` на индустриальный стандарт Python — **`feedparser`**. Эта библиотека отлично справляется с RSS/Atom, нормализует кривой XML и извлекает все нужные поля. Для извлечения фидов со страниц (как `detect-feed`) можно использовать `BeautifulSoup4` + `aiohttp`/`httpx`.
*   **HTTP Кэширование и прокси:** Заменить `got`/`make-fetch-happen` на **`httpx`** (асинхронный HTTP-клиент, поддерживает HTTP/2 и прокси). Кэширование `ETag` и `Last-Modified` легко реализуется путем передачи нужных заголовков в `httpx.get(url, headers=...)`.
*   **Очереди и фоновые задачи:** Заменить `fastq` и `node-schedule`. В Python для асинхронных периодических задач можно использовать:
    *   **`APScheduler`** (простой вариант, встраивается прямо в процесс бота).
    *   **`Celery`** или **`Arq`** (Redis-based) (архитектурно надежнее для масштабирования: один процесс крутит Telegram-бота, другие процессы работают как воркеры для обхода тысяч фидов).

## 2. Функции и логическая работа
При переписывании логики парсинга и подписок:
1. **Команды:** В `aiogram` создать хэндлеры `@router.message(Command("sub"))`, которые будут парсить текст команды, проверять URL (с помощью `urllib` и регулярных выражений), вызывать HTTP-клиент `httpx` для первой проверки фида.
2. **Очистка текста:** Для очистки HTML-тегов перед отправкой в Telegram (как делает функция `sanitize` в Node.js) использовать Python-пакет **`bleach`** или встроенные возможности `BeautifulSoup`.
3. **Хэширование постов:** Python-функция сравнения будет брать `feedparser.entries`, извлекать `entry.id` (или `entry.link`), сериализовать этот список в JSON и записывать в БД SQLAlchemy в поле `JSONB` (или строковое поле).
4. **Конвертация в JSON Feed:** Если вы хотите реализовать двустороннюю конвертацию (которой нет в оригинале), вы можете использовать **`Pydantic`** для описания строгой схемы (Universal Atom) и пакет **`feedgen`** для обратной генерации XML-фидов из ваших Python-моделей.

## 3. Обмен информацией, память и потоки данных
Поток данных в Python-версии будет выглядеть так:
- **State (Память):** Модели `SQLAlchemy`: `Feed` (id, url, title, last_modified, etag, error_count, next_fetch_time, hash_list) и `Subscribe` (feed_id, user_id).
- **Сбор:** Воркер (Celery/APScheduler) каждую минуту выбирает из `Feed` записи, где `next_fetch_time <= datetime.now()`.
- **Парсинг:** Воркер делает асинхронный вызов `httpx.get()`. Если возвращается код 304 (Not Modified), дата `next_fetch_time` обновляется, и воркер идет дальше. Если код 200, данные передаются в `feedparser`.
- **Дифференциация:** Новые ID постов определяются через `set(new_ids) - set(old_hashes)`. Новые элементы передаются в очередь на отправку.
- **Отправка:** Экземпляр `aiogram.Bot` асинхронно отправляет сообщения в Telegram (используя `bot.send_message(chat_id, text, parse_mode="HTML")`). В случае ошибки `BotBlocked` подписка удаляется из БД.

Разделение проекта на микросервисы (FastAPI для API/Админки, Celery для парсинга, aiogram для бота) позволит легко масштабировать проект и изолировать сложные части.
