# Отчет: BayLang AI
Full-stack AI platform based on BayLang ecosystem.

## 1. Назначение проекта
BayLang AI — это амбициозная платформа, построенная на базе экосистемы BayLang (авторского языка программирования и набора библиотек от Ильдара Бикмаматова). Проект представляет собой полноценную инфраструктуру для работы с ИИ-агентами, включая чаты, заметки, журналы и, самое главное, сложную многоуровневую систему памяти. Особенность проекта в том, что он объединяет высокоуровневую логику на языке BayLang с производительностью Node.js и возможностями современных моделей машинного обучения.

## 2. Архитектура и технический стек
Проект демонстрирует уникальный подход к разработке — использование кросс-компилируемого языка BayLang:
- **Core:** Логика описана на `.bay` файлах, которые затем компилируются в JavaScript для исполнения в Node.js.
- **Backend:** Fastify используется в качестве веб-сервера.
- **Database:** MySQL/MariaDB (используется через `Runtime.ORM`) для хранения структурированных данных и векторов.
- **AI Engine:** Интеграция с `@huggingface/transformers` и `onnxruntime` для локального запуска моделей (например, для генерации эмбеддингов).
- **Frontend:** Vue.js интегрирован в структуру компонентов BayLang.

## 3. Логика и техническая реализация памяти
Память в BayLang AI — это не просто хранилище текста, а структурированная система, разделенная на несколько уровней (сервисов):

### А. AI Memory (`MemoryService`)
Это уровень «рабочей» или «краткосрочной» памяти, организованный по категориям:
- **Categorization:** Память разделена на именованные области (например, `personal`, `work`). Категория `soul` является зарезервированной, что намекает на реализацию "личности" агента.
- **Aggregation:** Метод `readAll` позволяет агенту получить полный снимок знаний, сгруппированный по контекстам, что упрощает формирование системного промпта.

### Б. AI Notes (`NoteService`) — Векторная память
Самая технически сложная часть. Используется для хранения больших объемов информации с возможностью семантического поиска:
- **Vector Embeddings:** При сохранении заметки (`ai.note/save`) система генерирует векторное представление контента.
- **Similarity Search:** Поиск (`ai.note/search`) реализован через расчет косинусного расстояния (Cosine Distance) между вектором запроса и векторами в БД.
- **Distance Thresholding:** Параметр `max_distance` позволяет фильтровать результаты, отсекая нерелевантные знания, что критично для чистоты контекста LLM.
- **Metadata tagging:** Каждая запись поддерживает теги и приоритеты, позволяя комбинировать векторный поиск с жесткими фильтрами.

### В. AI Journal (`ai.journal`)
Слой «событийной» памяти. Фиксирует хронологию действий и состояний системы. Это позволяет агенту «вспоминать» цепочку событий, приведшую к текущему состоянию.

## 4. Нестандартные решения
- **BayLang Ecosystem:** Самое нестандартное решение — это сам язык разработки. BayLang обеспечивает строгую типизацию и модульность, которые редко встречаются в чистом JavaScript/Node.js мире.
- **Local-first Embedding Generation:** Проект настроен на генерацию векторов локально (через ONNX), что обеспечивает приватность данных и независимость от внешних API (типа OpenAI Embeddings).
- **Hybrid ORM:** Использование `Runtime.ORM` позволяет прозрачно работать с MySQL как с объектным хранилищем, при этом сохраняя возможность выполнять сложные SQL-запросы для векторной математики.
- **Environment-driven DB Factories:** Класс `DatabaseConnection` (`MySQLFactory`) динамически настраивает пулы соединений на основе переменных окружения, что делает проект идеально подходящим для контейнеризации (Docker).

## 5. Вывод
BayLang AI — это пример того, как глубокая кастомизация инструментов (свой язык, своя ORM) позволяет построить очень стройную и логичную архитектуру ИИ-платформы. Система памяти в проекте реализована профессионально: от простых ключ-значение хранилищ до продвинутого векторного поиска, что делает её жизнеспособной для создания сложных, долгоживущих ИИ-агентов с "чувством контекста".
