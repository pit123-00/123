# Полный текст (content_html) в библиотеке jsonfeed

В вопросе ставится задача: справляется ли `jsonfeed` (или feed2json) с вытягиванием полного текста статьи (`content_html`), а не только превью (`summary`), который необходим для глубокого анализа в PBD.

## Анализ библиотеки jsonfeed

Библиотека `jsonfeed` (`lukasschwab/jsonfeed`) — это исключительно **Dumb Data Class** библиотека (просто обертка над JSON-структурой).

Вот как выглядит класс `Item` в `jsonfeed/__init__.py`:
```python
class Item:
    def __init__(
        self,
        id,
        url: Optional[str] = None,
        # ...
        content_html: Optional[str] = None,
        content_text: Optional[str] = None,
        summary: Optional[str] = None,
        # ...
```
Она **вообще не выполняет никаких сетевых запросов** и не парсит HTML со сторонних сайтов.
- Если источник данных (например, RSS конвертируемый в JSON Feed) уже содержит поле `content_html`, библиотека просто запишет эту строку.
- Если в источнике есть только `summary`, а поле `content_html` пустое, библиотека оставит его `None`. Она не пойдет по `url` скачивать страницу.

## Как решить проблему полного текста в PBD?

Для вашего `L2_normalized` слоя (NormalizationService) и `L3/L4/L5` (ReasoningService, где LLM нужен полный текст для F-G-R скоринга), полагаться на то, что RSS или JSON Feed сразу отдаст полный текст — фатальная ошибка. Большинство RSS-лент отдают только урезанный `summary` (чтобы заставить пользователя перейти на сайт).

**Вам необходимо реализовать отдельный шаг Full-Text Extraction в пайплайне:**

1. **Ingestion Layer:** Сохраняет тот `Universal Atom` в формате `JSON Feed`, который отдал источник. Если там есть только `summary`, сохраняется только `summary`.
2. **NormalizationService (L2):** Этот сервис должен:
   - Проверить наличие `content_html` в Атоме.
   - Если полного текста нет (или он подозрительно короткий, как превью), сервис должен выполнить HTTP GET запрос по `atom.url`.
   - Скачанный сырой HTML страницы пропустить через библиотеку типа **`readability-lxml`** или **`trafilatura`** (отличная библиотека на Python для извлечения основного контента статей без рекламы и навигации).
   - Очищенный текст/HTML сохранить в таблицу `L2_normalized` как обогащенный `content_html` или `content_text`.

Только так вы гарантируете, что ваш AI-конвейер получит "глубокий" текст для суммаризации и тегирования, независимо от того, насколько жадным был изначальный RSS-фид.
