# 1. Техническая реализация и архитектура
Проект `rss-mcp` реализован на TypeScript с использованием Model Context Protocol (MCP) SDK для интеграции с LLM. Для предварительной зачистки текста и декодирования HTML используется библиотека `cheerio` (мощный парсер HTML/XML на базе jQuery для Node.js). Интеграция парсинга встроена прямо в обработчик команды извлечения фида (`get_feed`), чтобы передавать LLM чистый текстовый контент, не перегружая контекстное окно HTML-разметкой.

# 2. Функции и логическая работа
Логика зачистки запускается в цикле обхода элементов RSS-фида. Для каждой записи (`item`):
- Проверяется наличие поля `item.content`.
- Если контент есть, он загружается в `cheerio.load(item.content)`.
- Функция `$.text()` извлекает только текстовое содержимое, полностью удаляя HTML-теги.
- Далее применяется регулярное выражение `replace(/\s+/g, ' ')` для сжатия множественных пробелов и символов переноса строки в один пробел.
- Метод `.trim()` удаляет пробелы в начале и конце строки.
- Если `item.content` отсутствует, логика использует резервное поле `item.contentSnippet`, которое обычно уже содержит сырой текст, предоставленный самим RSS-фидом.

# 3. Информационный обмен, память и потоки данных
С точки зрения потоков данных, сервер запрашивает RSS XML по URL, который парсится библиотекой `rss-parser` в JS объекты.
Затем данные проходят через слой нормализации (цикл обработки элементов). В памяти временно создается дерево DOM (с помощью `cheerio`) для каждого элемента, из которого извлекается текст.
После нормализации избыточные HTML-данные отбрасываются, собирается компактный и "чистый" JSON-ответ, соответствующий заранее определенной Zod-схеме (`RssFeed`). Этот чистый JSON отправляется LLM-клиенту (через `StdioServerTransport`), обеспечивая эффективное использование контекстного окна и исключая влияние вредоносного или избыточного HTML-кода на генерацию ответа нейросетью.
