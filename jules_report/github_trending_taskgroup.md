# 1. Техническая реализация и архитектура
В `GitHubTrendingRSS` для параллельного парсинга данных (в частности, для загрузки файлов ReadMe для множества репозиториев одновременно) применяется нативный механизм структурированного конкурентного программирования Swift — `TaskGroup`. Это архитектурное решение позволяет безопасно создавать асинхронные задачи (таски), которые автоматически отменяются в случае возникновения критических ошибок, и объединять их результаты в единую структуру после выполнения всех потоков.

# 2. Функции и логическая работа
Функция `fetchRepositories` в классе `GitHubDownloader` вызывает `withTaskGroup(of: (Int, Repository).self)`, создавая изолированную группу задач.
Логика:
- Итерируется список распарсенных репозиториев.
- Для каждого репозитория в группу добавляется новая подзадача (`group.addTask`).
- Внутри подзадачи асинхронно вызывается функция `fetchReadMePage`. Если она бросает исключение (например, ReadMe не существует), ошибка перехватывается, и репозиторий возвращается без ReadMe-текста (игнорирование ошибки для продолжения потока).
- Каждая подзадача возвращает кортеж: индекс (Int) и измененный объект (Repository).
- Затем основной поток ожидает завершения всех подзадач в асинхронном цикле `for await result in group`.
- Наконец, результаты сортируются по индексу (поскольку асинхронные задачи завершаются в непредсказуемом порядке), чтобы восстановить исходный порядок трендов, и массив объектов извлекается из кортежей.

# 3. Информационный обмен, память и потоки данных
Использование `TaskGroup` обеспечивает оптимизированное использование памяти и потоков. Swift Actor model управляет пулом потоков, поэтому создание 20-30 задач не означает создания 30 системных потоков (thread). Задачи легковесно мультиплексируются операционной системой.
Поток данных "распаковывается" из единого массива (список репозиториев) во множество конкурентных HTTP-запросов (скачивание ReadMe), а затем "упаковывается" обратно (редукция). Для предотвращения нарушения целостности памяти Swift компилятор гарантирует (`@unchecked Sendable` или нативная семантика структур), что потоки не перезаписывают данные друг друга (репозитории передаются по значению `var repo = repository`). Окончательный отсортированный массив занимает 연속ную область в памяти и готов для генерации HTML/RSS.
