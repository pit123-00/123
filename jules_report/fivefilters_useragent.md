# 1. Техническая реализация и архитектура
Репозиторий `fivefilters-full-text-rss-docker` является Docker-оберткой вокруг официального (и сторонних патчей) PHP-сервиса `Full-Text RSS` от FiveFilters. Механизмы обхода антибот-систем, такие как ротация User-Agent и подмена заголовков Referer, реализованы в самом ядре (в исходных кодах, клонируемых при сборке Docker-образа) через конфигурационные параметры `custom_config.php` или переменные окружения, а также site-specific инструкции. Архитектура опирается на PHP cURL для выполнения сетевых запросов.

# 2. Функции и логическая работа
- **User-Agent ротация**: Механизм ротации User-Agent часто настраивается в файле конфигурации (`site_config`). Для определенных доменов (fingerprints) или глобально, сервис позволяет настроить массив случайных User-Agent'ов. Перед выполнением `curl_exec`, PHP-скрипт выбирает случайный элемент из этого массива и устанавливает опцию `CURLOPT_USERAGENT`.
- **Подмена Referer**: В Site Config файлах (правила для конкретных сайтов) можно определить параметр `http_header(Referer)`. При парсинге страницы, сервис извлекает это правило и добавляет заголовок `Referer: <целевой_URL>` в HTTP-запрос. Это обходит защиту от хотлинкинга или базовые антибот-скрипты, которые ожидают, что пользователь перешел по ссылке с определенного поисковика или внутренней страницы сайта.
- В файле конфигурации `custom_config.php` также поддерживается использование прокси (`$options->proxy_servers`), что в связке с ротацией UA делает парсер еще более "анонимным".

# 3. Информационный обмен, память и потоки данных
Конфигурационные данные (списки User-Agent, правила Referer) загружаются в память один раз при старте или кэшируются через APCu (как настроено в `$options->apc = true`).
Когда пользователь запрашивает парсинг URL:
1. Система сопоставляет домен с базой Site Config в памяти.
2. Извлекаются специфичные заголовки для этого домена.
3. Формируется структура HTTP-заголовков.
4. Выполняется вызов cURL.
Память используется эффективно: файлы конфигурации хранятся в кэше PHP (OPcache/APCu), поэтому нет необходимости читать их с диска на каждый запрос, что ускоряет время генерации HTTP-запроса для обхода защиты.
