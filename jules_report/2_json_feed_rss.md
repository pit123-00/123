# Преобразование JSON Feed в RSS и обратно

## 1. Техническая реализация и архитектура
В кодовой базе NodeRSSBot **отсутствует** нативная поддержка генерации или обратного преобразования в формат `JSON Feed` (https://jsonfeed.org/).
Текущая архитектура проекта ориентирована исключительно на чтение и парсинг XML-основанных форматов (RSS 2.0, Atom, RDF) и их конвертацию во внутренние объекты TypeScript/JavaScript для последующей отправки в Telegram.
Для чтения и конвертации XML в JavaScript-объекты используется высокопроизводительная библиотека `camaro` на базе XPath-шаблонов. Архитектура парсера (`source/parser/parse.ts` и `source/parser/templates.ts`) построена так, что для каждого типа XML-формата описан свой XPath-шаблон:
- `rss2Tpl` (для RSS)
- `atomTpl` (для Atom)
- `rdfTpl` (для RDF)

## 2. Функции и логическая работа
В текущей реализации преобразование работает в одностороннем порядке:
1. **Детектирование:** Функция `detectFeed` (в `source/parser/detect-feed.ts`) анализирует строковый XML и определяет его тип (atom, rss или rdf).
2. **Конвертация:** Функция `parseString` (`source/parser/parse.ts`) вызывает `camaro.transform(xml, template)`, применяя соответствующий шаблон.
3. **Нормализация:** Шаблоны `camaro` описывают декларативное преобразование XML-документа в единый унифицированный TS-интерфейс `TRSS` и `RSSItem` (с полями `title`, `link`, `id`/`guid`, `publishedAt`).

*Примечание по реализации JSON Feed <-> RSS:*
Поскольку вы планируете добавить это в свой проект, для реализации двухстороннего преобразования потребуется:
- Для чтения JSON Feed: добавить ветвление в функцию парсера, которое при получении валидного JSON-документа (проверка через `JSON.parse`) будет просто мапить ключи `JSON Feed` во внутренние DTO (объекты `RSSItem`).
- Для генерации RSS из JSON Feed (если вам нужен экспорт из БД обратно в RSS): потребуется внедрить библиотеку-генератор (например, `feed` или `feedgen` в Python), которая на основе сохраненных данных из базы будет рендерить XML-строку по спецификациям RSS 2.0 или Atom.

## 3. Обмен информацией, память и потоки данных
В NodeRSSBot обмен данными при парсинге фида выглядит следующим образом:
- Вход: XML-строка (RAW text) от HTTP-ответа (`res.textConverted()`).
- Поток данных: `HTTP Response (XML) -> detectFeed -> camaro.transform -> JS Object (TRSS)`.
- Выход (Память): Объект типа `TRSS`, содержащий список элементов `items: RSSItem[]`.
- Для оптимизации и предотвращения повторных отправок постов формируется массив хэшей или ID (`recent_hash_list`), который сохраняется в базу данных. В БД сам текст постов или XML **не сохраняется** — база хранит только состояние, метаданные каналов и ссылки на посты, которые были отправлены в Telegram, а генерация лент из базы обратно не предусмотрена (бот только читает и уведомляет).
