# Какой доступ требуется для просмотра пабликов и ботов в Telegram

## 1. Техническая реализация и архитектура
В NodeRSSBot за взаимодействие с Telegram отвечает библиотека Telegraf (`source/index.ts`). Для того чтобы бот мог работать, ему необходим доступ к API Telegram (по протоколу HTTP/HTTPS). Технически для этого требуется только **Telegram Bot Token** (выдается через @BotFather).

Проект использует токен из переменных окружения (`process.env.RSSBOT_TOKEN`) для инициализации `new Telegraf(config.token)`. Этот токен позволяет боту читать отправленные ему команды и отправлять сообщения (push-уведомления) в личные сообщения, группы и каналы.

## 2. Функции и логическая работа
Для работы бота в разных типах чатов (пабликах, каналах, группах) требуются разные уровни доступа и настройки:

1. **Личные сообщения (Private Chats):** Бот по умолчанию имеет полный доступ к чтению всех сообщений, которые пишет ему пользователь. Специальных прав не требуется, кроме команды `/start` от пользователя.
2. **Группы (Groups / Supergroups):**
   - По умолчанию боты в группах работают в **Privacy Mode** (Режим приватности). В этом режиме бот "видит" только те сообщения, которые:
     - Начинаются с символа слеша `/` (команды, например, `/sub`).
     - Являются ответами (Reply) на сообщения самого бота.
     - Содержат упоминание бота (например, `@your_bot_name`).
   - Если боту нужно читать *все* сообщения в группе (что для RSS-бота обычно не требуется, но может понадобиться для других функций), администратор бота должен отключить Privacy Mode через @BotFather (`/setprivacy -> Disable`).
3. **Публичные каналы (Channels):**
   - Бот **не может** быть просто участником канала и читать оттуда посты, если он не является администратором.
   - Чтобы бот мог отправлять обновления RSS в канал (команда `/sub @channelname url`), бот **должен быть добавлен в администраторы канала**.
   - Необходимое право: **"Post Messages"** (Публикация сообщений).
   - В NodeRSSBot при попытке подписать канал бот пытается отправить тестовое сообщение или проверяет права, чтобы удостовериться, что он может писать в указанный `chat_id` (которым в данном случае выступает @username канала или его внутренний числовой ID).

## 3. Обмен информацией, память и потоки данных
- **Входящий поток:** Команды от администраторов/пользователей обрабатываются через Long Polling или Webhooks (в Telegraf настраивается прозрачно).
- **Идентификация:** Телеграм передает боту `chat_id`. Для личных чатов это положительное число (например, `123456789`), для групп — отрицательное (например, `-123456789`), для супергрупп и каналов — ID с префиксом `-100` (например, `-100123456789`).
- **Сохранение:** Эти `chat_id` записываются как `user_id` в таблице `users` и `subscribes` базы данных NodeRSSBot.
- **Исходящий поток:** Фоновый воркер (парсер RSS), обнаружив новую запись, передает сообщение процессу отправки, который вызывает `telegram.sendMessage(chat_id, text, options)`. Если бот был удален из чата или лишен прав администратора в канале, Telegram API вернет ошибку (например, `Forbidden: bot was kicked from the channel`), после чего логика обработки ошибок NodeRSSBot удалит эту подписку из БД (чтобы не спамить API ошибками).
