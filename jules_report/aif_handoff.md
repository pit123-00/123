# Отчет: AIF Handoff
Autonomous Kanban board where AI agents plan, implement, and review your tasks.

## 1. Назначение проекта
AIF Handoff представляет собой новый класс инструментов — «автономную фабрику разработки». Это не просто ассистент в чате, а полноценная система управления задачами, где ИИ-агенты выступают в роли сотрудников: менеджеров, разработчиков и ревьюеров. Проект автоматизирует весь цикл жизни тикета на Kanban-доске, позволяя человеку лишь ставить высокоуровневые задачи и подтверждать финальный результат.

## 2. Архитектура и технический стек
Проект реализован как современный TypeScript монорепозиторий с четким разделением ответственности:
- **Shared Package:** Общие типы, схемы Zod, машина состояний (State Machine) и логгер. Это гарантирует консистентность данных между API и агентом.
- **Data Package (@aif/data):** Слой абстракции над SQLite (используется Drizzle ORM). Централизованный доступ к БД предотвращает конфликты записи.
- **Runtime Package (@aif/runtime):** Сложная система адаптеров. Поддерживает Claude (через SDK и CLI), OpenAI Codex, OpenRouter и OpenCode. Это позволяет проекту быть независимым от конкретного провайдера LLM.
- **Agent Coordinator:** «Мозг» системы. Написан на Node.js, работает по принципу событийного цикла (WebSockets) с откатом на поллинг (polling).
- **Frontend:** React-приложение с использованием TailwindCSS и `@dnd-kit` для реализации интерактивной доски.

## 3. Логика работы и функции
### Жизненный цикл задачи (Task Pipeline):
Задачи двигаются по конвейеру через строго заданные переходы состояний:
1. **Backlog → Planning:** Координатор назначает `plan-coordinator`. Тот итерирует над планом реализации, используя `plan-polisher` для уточнения деталей, пока план не станет «готовым».
2. **Planning → Plan Ready:** Человек может просмотреть план и внести коррективы, либо система в авто-режиме перейдет к реализации.
3. **Plan Ready → Implementing:** Самый сложный этап. `implement-coordinator` рассчитывает слои зависимостей (Dependency Layers). Если части задачи независимы, они могут выполняться параллельно разными инстансами ИИ.
4. **Implementing → Review:** Запуск «сайдкаров» (Sidecars). Один агент проверяет бизнес-логику, другой — безопасность (security-sidecar).
5. **Review → Done/Rework:** Анализ «сходимости» правок.

### Ключевые функции:
- **Layer-aware Parallelism:** Реализация механизма параллельного выполнения задач внутри одного тикета. Система понимает, какие файлы можно менять одновременно, а какие — последовательно.
- **Self-healing Pipeline:** Если агент «умирает» или LLM выдает ошибку, координатор использует систему heartbeats. Если статус не обновлялся слишком долго, задача переводится в режим восстановления или блокируется с понятной причиной.
- **Bidirectional Task Sync (MCP):** Благодаря Model Context Protocol, задачи на доске синхронизируются с инструментами разработчика. Изменения в коде могут автоматически двигать тикеты на доске.

## 4. Нестандартные решения
- **Convergence-aware Strategy:** Это уникальное решение проблемы бесконечных циклов правок. Система использует две стратегии: `full_re_review` (полный пересмотр) и `closure_first` (фокус на закрытии найденных багов). Если новые баги продолжают появляться после исправления старых в течение N итераций, система останавливается и требует вмешательства человека (Explicit Handoff).
- **Project Scaffold Initialization:** При запуске задачи в новом проекте, `aif-handoff` автоматически инициализирует окружение (`.ai-factory/`), настраивая необходимые скиллы и промпты для агентов.
- **Usage Reporting & Sink:** Детальный трекинг использования токенов на каждом этапе каждой задачи. Это позволяет владельцу «фабрики» видеть точную стоимость реализации каждой функции в долларах или токенах.
- **Hybrid Execution Modes:** Возможность переключения между режимом «Subagents» (максимальное качество, много итераций) и режимом «Skills» (быстрое выполнение в один проход).

## 5. Вывод
AIF Handoff — это демонстрация того, как будет выглядеть разработка ПО в ближайшем будущем. Проект выделяется среди конкурентов своей жесткой архитектурой управления состояниями и прагматичным подходом к «несовершенству» ИИ через механизмы явной передачи управления человеку и самовосстановления.
