# Отчет: aif-handoff (AI Agent Orchestration)
Multi-agent pipeline for high-fidelity code generation and review.

## 1. Назначение проекта
aif-handoff — это сложная система оркестрации ИИ-агентов, предназначенная для автоматизации полного жизненного цикла разработки: от планирования задачи до её реализации и финальной верификации. В отличие от простых чат-ботов, этот проект реализует концепцию «Pipeline as a Service», где каждая задача проходит через строгую цепочку специализированных субагентов, гарантируя высокое качество кода и минимизацию «галлюцинаций» ИИ.

## 2. Архитектура и технический стек
Проект представляет собой современный TypeScript-монорепозиторий (управляемый через `pnpm`), разделенный на четкие слои:
- **`packages/agent`:** Сердце системы — Координатор (Coordinator) и набор субагентов.
- **`packages/runtime`:** Абстрактный слой для работы с различными LLM (Claude, OpenRouter, Codex) и средами исполнения.
- **`packages/mcp`:** Реализация протокола Model Context Protocol для интеграции с внешними инструментами.
- **`packages/api` & `packages/web`:** Бэкенд на Node.js и фронтенд на React/Vite для визуализации процесса.
- **`packages/shared`:** Общие типы данных, схемы базы данных (Drizzle ORM) и логика верификации.

### Ключевые субагенты:
1. **Planner:** Разбирает требования и строит пошаговый план реализации.
2. **Implementer:** Выполняет конкретные шаги плана, взаимодействуя с файловой системой.
3. **Reviewer:** Проводит аудит изменений на соответствие контракту.
4. **PlanChecker:** Проверяет логическую целостность и достижимость плана перед началом работ.

## 3. Логика работы и функции
### Глубокий разбор Координатора (`coordinator.ts`):
Центральным элементом является бесконечный цикл `pollAndProcess`, который управляет жизненным циклом задач:
- **CAS-style Claiming:** Используется механизм Compare-And-Swap для захвата задачи из базы данных. Это предотвращает состояние гонки (race conditions), если запущены несколько экземпляров координатора.
- **Semaphore Concurrency:** Реализована система семафоров для ограничения глобальной и локальной (по стадиям) параллельности. Например, можно ограничить общее количество активных задач до 10, но в стадии `implementing` разрешить только 3.
- **Poll Cycle Stages:** Цикл включает в себя очистку «протухших» (stale) блокировок, восстановление задач, зависших в статусе `in-progress`, и запуск авто-очередей.

### Автоматизированная очередь (Auto-queue):
Проект поддерживает два режима работы проектов:
- **Sequential (Последовательный):** Новая задача из бэклога переходит в стадию планирования только после того, как предыдущая достигла терминального статуса (`done` или `verified`).
- **Parallel (Параллельный):** Система поддерживает «глубину пула» (pool depth), автоматически подхватывая новые задачи до тех пор, пока не будет достигнут лимит `COORDINATOR_MAX_CONCURRENT_TASKS`.

### Механизм Handoff:
При переходе между стадиями (например, от Planner к Implementer) передается не просто текст, а полное состояние контекста (Context Snapshot), включая изменения в файловой системе, логи предыдущих шагов и текущие метрики использования токенов.

## 4. Нестандартные решения
- **Strict Runtime Contracts:** Система не просто просит ИИ выполнить код. Она оборачивает каждый вызов в «контракт выполнения», который включает в себя тайм-ауты, лимиты на чтение/запись и обязательную проверку побочных эффектов.
- **Activity Log as an Audit Trail:** Каждое действие агента (даже внутренние размышления) записывается в `appendTaskActivityLog`. Это позволяет разработчику-человеку «отмотать» процесс назад и понять, в какой момент агент принял неверное решение.
- **Multi-adapter Model Discovery:** Runtime-слой умеет динамически определять возможности подключенных моделей (например, поддерживает ли модель `tools` или `streaming`) и адаптировать логику агентов под конкретные API.
- **Telegram/Broadcast Notifier:** Встроенная система уведомлений не ограничивается вебом. Координатор может отправлять отчеты о завершенных этапах в Telegram или через WebSocket-вещание для командной работы.
- **Self-Healing Loop:** Если Implementer сталкивается с ошибкой компиляции или тестов, система не падает. Вместо этого `stageErrorHandler` может отправить задачу обратно на стадию `planning` для корректировки плана с учетом возникшей ошибки.

## 5. Вывод
aif-handoff — это промышленное решение для тех, кто перерос простые скрипты для ИИ. Проект демонстрирует, как с помощью жесткой типизации, надежной координации задач и многоуровневой проверки можно превратить нестабильную выдачу LLM в предсказуемый процесс разработки ПО. Его архитектура ориентирована на масштабируемость и отказоустойчивость, что делает его отличным примером "Agentic Workflow" в 2024-2025 годах.
