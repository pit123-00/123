# 1. Техническая реализация и архитектура
Проект `feed-mcp` написан на Go и реализует MCP сервер. Он предоставляет набор стандартных инструментов (Tools), которые LLM может использовать для управления состоянием фидов через текстовый интерфейс чата (например, Claude). Архитектурно инструменты отделены от ресурсов (Resources); инструменты предназначены для изменения состояния (мутации) и активного поиска (get/search/add), тогда как ресурсы предназначены для пассивного чтения. Состояние фидов хранится в кэше и/или локальной базе данных.

# 2. Функции и логическая работа
Ключевые инструменты, экспонируемые через `tools_test.go` и `server.go`:
- **add_feed**: Позволяет LLM добавить новый RSS-фид в систему. Принимает URL и валидирует его.
- **get_feed**: Запрашивает конкретный фид (часто с возможностью пагинации/лимита), возвращает массив статей.
- **Управление статусом (Read status)**: Инструменты, которые помечают статью как прочитанную (mark_read). Логика обновляет статус в базе (SQL/память), чтобы при следующем вызове `get_feed` статья либо скрывалась, либо получала флаг `read: true`.
- **Управление тегами**: Инструменты для категоризации (add_tag, remove_tag). LLM может анализировать текст статьи и, вызвав этот инструмент, передать массив тегов (например, `["tech", "AI"]`), которые привязываются к ID статьи в базе данных.

# 3. Информационный обмен, память и потоки данных
Поток данных инициируется запросом пользователя в чате.
- LLM распознает интент (например, "добавь тег AI к последней статье") и генерирует вызов инструмента (Tool Call) с JSON-аргументами (`article_id: 123, tag: "AI"`).
- MCP-сервер на Go десериализует этот JSON.
- Сервер выполняет бизнес-логику: обновляет карту в памяти (или SQL-таблицу), создавая связь многие-ко-многим между `Entry` и `Tag`.
- Для оптимизации производительности сервер очищает или инвалидирует кэши (`rm.InvalidateResourceCache`), чтобы обновленный статус прочтения или теги немедленно отразились при следующем запросе.
- В ответ LLM возвращается статус `success: true` или `error`. Вся коммуникация строго типизирована (через `jsonschema` в Go) и передается по стандартным потокам `stdin/stdout`.
