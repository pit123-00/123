# Анализ механизма: Автоматическое добавление новых источников (из LetterFeed)

## 1. Техническая реализация и архитектура
В проекте `LetterFeed` предусмотрен механизм `auto_add_new_senders`, который решает проблему падения парсера при встрече с неизвестным отправителем письма. Это реализовано в `LetterFeed/backend/app/services/email_processor.py`.

Архитектурно механизм внедрен на этапе обработки отдельного сообщения:
- Сначала извлекается адрес отправителя (`sender = email.utils.parseaddr(msg["From"])[1]`).
- Затем проверяется наличие отправителя в кэшированной мапе известных источников (`newsletter = sender_map.get(sender)`).
- Если отправитель не найден, и в глобальных настройках включен флаг `settings.auto_add_new_senders`, вызывается логика создания новой записи: формируется DTO `NewsletterCreate` с извлеченным именем и email'ом, и новая запись сохраняется в базу данных. Вновь созданный объект сразу же добавляется в кэш (`sender_map[sender] = newsletter`), позволяя обработке письма продолжиться без ошибок Foreign Key Constraint.

## 2. Функции и логическая работа
Ключевая логика сосредоточена в функции `_process_single_email`:
```python
newsletter = sender_map.get(sender)
if not newsletter and settings.auto_add_new_senders:
    newsletter = _auto_add_newsletter(db, sender, msg, settings)
    sender_map[sender] = newsletter

if not newsletter:
    return
```
Функция `_auto_add_newsletter` корректно обрабатывает декодирование заголовков "From" (для поддержки non-ASCII символов) и создает сущность "Newsletter". Если настройка выключена, письмо от неизвестного отправителя просто игнорируется (`if not newsletter: return`), что предотвращает загрязнение базы спамом.

## 3. Информационный обмен, память и потоки данных (Интеграция в PBD)
В архитектуре PBD (Personal Browser Dashboard) этот паттерн критически важен для отказоустойчивости слоев `Ingestion Layer` и формирования графа знаний. При работе с коннекторами (например, Telegram или Email):
- Когда `IngestionService` сталкивается с пересланным сообщением из нового канала (Telegram) или новым Email-адресом, он не должен прерывать обработку с ошибкой внешнего ключа (Foreign Key Constraint) при попытке привязать атом к несуществующему `Source`.
- Поток данных: `Новый контент` -> `IngestionLayer`. Привязка: проверяем наличие Source по ID/Email. Если отсутствует -> `SourceCreate(status='auto_created')` -> Создание атома `L1_raw` и привязка к новому Source.
- В таблице `sources` (источники) должна появиться новая запись с флагом `status='auto_created'`. Это позволит на уровне дашборда (фронтенд Reflex) легко отфильтровать автоматически созданные источники для последующей модерации пользователем (подтверждение важности или удаление/игнор), не прерывая при этом фоновый асинхронный процесс сбора данных.
