# 1. Техническая реализация и архитектура
Проект `Github-Trends-Aggregator` реализует микросервисную архитектуру с использованием Go, обернутую в готовый Docker-контейнер. Контейнеризация (`Dockerfile` на базе образа `golang:1.23-alpine`) позволяет быстро развернуть агрегатор трендов как независимый сервис. Docker-образ включает компиляцию приложения и подготовку легковесной среды выполнения. Это устраняет необходимость писать и поддерживать сложный парсер трендов вручную, предоставляя вместо этого готовый эндпоинт, который отдает актуальные данные в формате JSON или через WebSocket.

# 2. Функции и логическая работа
Docker-сервис компилирует и запускает HTTP-сервер на Go (`main.go`). В фоне работает планировщик (`scheduler.go`), который:
- С заданной периодичностью (используя `time.NewTicker`) обращается к внешним парсерам или напрямую к источникам GitHub.
- Получает массив репозиториев (свойства: имя, автор, язык, количество звезд).
- Обновляет внутреннее хранилище в памяти (`store.UpdateRepos()`).
- В случае успешного получения данных инициирует широковещательную рассылку (`Broadcast`) всем подключенным клиентам (по WebSocket).
Внешним клиентам (фронтенду или другим микросервисам) остается лишь отправить GET запрос к API-эндпоинту, который просто читает данные из `store` и возвращает их в виде готового JSON-массива.

# 3. Информационный обмен, память и потоки данных
Контейнер работает по принципу in-memory кэша.
Поток данных на запись: Планировщик периодически загружает данные из интернета, формирует срез (slice) Go-структур `Repository` и атомарно (с блокировками, если это необходимо) обновляет состояние приложения в памяти.
Поток данных на чтение: API-вызовы не блокируются сетевыми запросами к GitHub. При обращении к эндпоинту сервер немедленно маршалит (`json.Marshal`) текущий срез структур из оперативной памяти и отдает клиенту.
Данный подход обеспечивает сверхбыстрое время ответа для фронтенда и защищает GitHub API от Rate Limit'ов, так как множество клиентских запросов не приводит к множественным обращениям к GitHub (запрос делает только внутренний планировщик раз в заданный интервал).
