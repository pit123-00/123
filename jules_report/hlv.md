# Отчет: hlv (Human-Led Validation)
Specs first. Code second. Proof always.

## 1. Назначение проекта
HLV (Human-Led Validation) — это радикальный инструмент для управления процессом ИИ-генерации кода. Проект исходит из постулата: код, написанный ИИ, — это «расходный материал», который нельзя принимать на веру. HLV предоставляет фреймворк для создания формальных спецификаций и автоматизированной проверки того, насколько сгенерированный код им соответствует. Это «поводок» для нейросетей, гарантирующий, что они не отклоняются от архитектурного замысла.

## 2. Архитектура и технический стек
Проект написан на Rust, что выбрано ради бескомпромиссной производительности. HLV должен работать быстрее, чем ИИ пишет код. Архитектура построена на идее жестких границ (Hard Boundaries):
- **Слой Инвариантов:** Определение того, что система *обязана* делать и чего делать *не должна*.
- **Слой Контрактов:** Формализованные в YAML/Markdown описания интерфейсов и поведения.
- **Слой Валидации:** Мощный движок на Rust, который сопоставляет файлы на диске с графом требований.
- **MCP Server:** Встроенная поддержка протокола для интеграции с Claude Desktop и другими ИИ-клиентами.

## 3. Логика работы и функции
### Основной рабочий цикл:
1. **Scaffolding (`hlv init`):** Создание структуры проекта, где «человеческие» артефакты (папка `human/`) отделены от результатов работы ИИ.
2. **Capture Intent:** Использование скилла `/artifacts` для проведения «интервью» с разработчиком. Результат — набор принятых решений в формате Markdown.
3. **Generate Specs:** На основе намерений ИИ генерирует детальные контракты и план реализации.
4. **Verification (`hlv check`):** Это ключевая команда. Она проводит 30+ видов проверок в 8 доменах:
    - **Project Map:** Проверка целостности YAML-файлов проекта.
    - **Contracts:** Соответствие MD-секций и YAML-блоков.
    - **Traceability:** Проверка цепочек REQ → CTR → TST → GATE (Требование -> Контракт -> Тест -> Гейт).
    - **Plan Integrity:** Проверка DAG (направленного ациклического графа) плана на отсутствие циклов.
    - **Code Markers:** Поиск специальных меток `@hlv` в коде, подтверждающих реализацию конкретных пунктов контракта.

### Ключевые функции:
- **Quality Gates:** Система «пропускных пунктов». Вы не можете завершить этап (milestone), пока все автоматизированные тесты, линтеры и проверки безопасности не вернут статус «успешно».
- **Phase-aware Diagnostics:** Умная система диагностики. Предупреждения (Warnings) автоматически понижаются до информационных сообщений (Info), если проект находится на ранней стадии (Draft), и становятся блокирующими ошибками на стадии валидации.
- **TUI Dashboard:** Интерактивная панель управления в терминале, позволяющая видеть прогресс по этапам, состояние контрактов и открытые вопросы.

## 4. Нестандартные решения
- **Борьба с LLM Anti-patterns:** Авторы проекта открыто заявляют, что общепринятые «лучшие практики» людей (например, глубокая вложенность папок или магическая инъекция зависимостей) вредны для ИИ. HLV заставляет разработчиков использовать плоские структуры и явные связи, что драматически снижает вероятность ошибок ИИ.
- **Code as Disposable Artifact:** Код в HLV — это вторичный продукт. Если код не проходит проверку `hlv check`, он просто удаляется и перегенерируется по неизменным контрактам. Источником истины является спецификация, а не репозиторий с кодом.
- **Security Markers:** Встроенная система `@hlv:sec`, которая требует от ИИ (и человека) явно помечать участки кода, критичные для безопасности, для последующего усиленного аудита.
- **Traceability Visualizer:** Генерация ASCII-графов связей требований с кодом прямо в терминале, что позволяет мгновенно увидеть «дыры» в реализации.

## 5. Вывод
HLV — это инструмент для тех, кто хочет строить надежные системы с помощью ИИ, не теряя при этом контроля над архитектурой. Его нестандартность в том, что он не пытается «помочь» ИИ писать код, а создает среду, в которой ИИ *вынужден* быть точным и дисциплинированным.
