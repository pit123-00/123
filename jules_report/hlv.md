# Отчет: hlv (Human-Led Validation)
Specs first. Code second. Proof always.

## 1. Назначение проекта
HLV (Human-Led Validation) — это радикально новый инструмент для управления процессом генерации кода искусственным интеллектом. Основная философия проекта заключается в том, что код, написанный ИИ, — это «расходный материал» (disposable artifact), который нельзя принимать на веру без математически точной верификации. HLV предоставляет инфраструктуру для создания формальных спецификаций (инвариантов) и автоматизированного контроля за тем, чтобы сгенерированный код им соответствовал. Это не просто помощник, а «контролер качества», обеспечивающий дисциплину в разработке.

## 2. Архитектура и технический стек
Проект написан на языке Rust, что критически важно для обеспечения производительности валидационных движков и безопасности работы с памятью при анализе больших кодовых баз.

### Многоуровневая структура данных:
- **Project Root:** Центральный узел, объединяющий все артефакты.
- **Human Layer (`human/`):** Единственное место, где хранятся знания, созданные человеком (намерения, дизайн-документы).
- **Validation Layer (`validation/`):** Слой, содержащий контракты, планы и тестовые спецификации.
- **Code Layer:** Конечный продукт, который всегда вторичен по отношению к валидационному слою.

### Технические компоненты:
- **Rust CLI:** Мощный интерфейс командной строки для управления жизненным циклом (init, check, milestone, task).
- **MCP Server:** Реализация Model Context Protocol, позволяющая «скармливать» спецификации HLV напрямую в ИИ-агентов (например, через Claude Desktop).
- **Markdown & YAML Parser:** Гибридная система парсинга, которая извлекает формальные данные (ID контрактов, версии) из обычных Markdown-файлов.

## 3. Логика работы и функции
### Процесс "Verification-Driven Development":
1. **Define Invariants:** Разработчик описывает, ЧТО система должна делать, в виде инвариантов.
2. **Draft Contracts:** На основе инвариантов создаются контракты. HLV проверяет их целостность через `hlv check`.
3. **Generate Implementation Plan:** ИИ предлагает план реализации. Валидатор проверяет план на отсутствие циклических зависимостей (DAG check) и полноту покрытия контрактов.
4. **Validation Loop (`hlv check`):** Это «сердце» проекта. Функция проверки (`validation.rs`) выполняет следующие действия:
    - **TST-001/002:** Проверка наличия и читаемости тестовых спецификаций для каждого контракта.
    - **TST-010/011:** Верификация связей между тестами и контрактами, включая проверку версионности.
    - **TST-020/021:** Обязательное наличие как минимум одного контрактного теста (CT-*) и одного теста на основе свойств (PBT — Property-Based Test).
    - **Traceability Matrix:** Автоматическое построение матрицы прослеживаемости от требования до конкретной строки кода.

### Управление состоянием (Milestones & Tasks):
HLV отслеживает прогресс через систему вех (milestones). Вы не можете закрыть веху (команда `milestone done`), пока валидатор не подтвердит, что все гейты (Quality Gates) пройдены и все инварианты соблюдены.

## 4. Нестандартные решения
- **Property-Based Testing (PBT) as a Requirement:** В отличие от большинства систем, HLV считает обычные unit-тесты недостаточными для ИИ. Проект принуждает к использованию PBT, что заставляет ИИ (и человека) думать о граничных условиях и инвариантах данных, а не просто о «счастливом пути».
- **Phase-aware Diagnostics:** Умная система диагностики меняет строгость в зависимости от стадии. На этапе черновика (Draft) ошибки считаются предупреждениями, но при попытке слияния или закрытия задачи они становятся блокирующими (Blocking Errors).
- **Code Markers (`@hlv`):** Использование специальных аннотаций в коде для «заземления» спецификаций. Это позволяет инструменту точно знать, какой файл и функция отвечают за выполнение конкретного пункта контракта.
- **The "Disposable Code" Concept:** HLV поощряет подход, при котором, если код не прошел проверку, его проще удалить и перегенерировать на основе спецификаций, чем пытаться «починить» вручную. Это радикально меняет отношение к качеству кода.
- **ASCII Visualization:** Встроенные инструменты для визуализации графа зависимостей и плана работ прямо в терминале, что обеспечивает мгновенную обратную связь без использования тяжелых GUI.

## 5. Вывод
HLV — это ответ на хаос, приносимый бесконтрольной генерацией кода ИИ. Проект переносит фокус с «написания кода» на «проектирование проверяемых систем». Используя Rust для жесткой валидации и MCP для интеграции с ИИ, HLV создает среду, в которой ошибки ИИ обнаруживаются на этапе проектирования, а не в продакшене. Это эталонный пример того, как человеческий интеллект должен управлять искусственным через строгие математические и логические рамки.
