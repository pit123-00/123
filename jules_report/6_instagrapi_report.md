# Отчет: Анализ Instagrapi (Эмуляция мобильного API Instagram)

Источник данных:
* instagrapi: https://github.com/subzeroid/instagrapi

## 1. Архитектура миксинов (Mixins)
Для поддержания огромной кодовой базы и сотен различных эндпоинтов Instagram, библиотека использует архитектурный паттерн Mixins.

В файле `__init__.py` класс `Client` почти не содержит логики. Он просто наследуется от десятков миксинов:
```python
class Client(
    PublicRequestMixin,
    ChallengeResolveMixin,
    LoginMixin,
    ShareMixin,
    PhotoMixin,
    MediaMixin,
    # и т.д.
):
    pass
```
*   **Преимущества:** Код не превращается в "спагетти". Разработчик знает: всё, что связано с фото, лежит в `photo.py` (класс `PhotoMixin`), всё, что с аутентификацией — в `auth.py`. Общие методы (`self.private.post()`) и настройки (`self.user_agent`) доступны во всех миксинах благодаря общему объекту `Client`.

## 2. Эмуляция мобильного устройства
Чтобы избежать банов, скрипт прикидывается реальным Android-клиентом.
*   **Файл `config.py`:** Содержит "жесткий" слепок конфигурации.
    ```python
    USER_AGENT_BASE = (
        "Instagram {app_version} "
        "Android ({android_version}/{android_release}; "
        "{dpi}; {resolution}; {manufacturer}; "
        "{model}; {device}; {cpu}; {locale}; {version_code})"
    )
    ```
*   **Привязка к аккаунту:** У каждого экземпляра класса `Client` (одного аккаунта) генерируется уникальный `android_device_id` (например, `android-e021b636049dc0e9`), который отправляется в каждом запросе в API (как параметр `device_id`). Если этот ID и User-Agent будут меняться слишком часто, Instagram заблокирует аккаунт.

## 3. Криптография паролей (`#PWD_INSTAGRAM`)
Instagram не принимает пароли в чистом виде. Их нужно шифровать на стороне клиента.

В `mixins/password.py` реализован следующий алгоритм:
1.  **Получение ключей:** Клиент запрашивает у сервера `publickeyid` и `publickey` с эндпоинта `/api/v1/qe/sync/`.
2.  **Шифрование:**
    *   Генерируется случайный `session_key` для AES.
    *   Пароль шифруется с помощью AES (в режиме GCM, вместе с `timestamp` как дополнительными данными).
    *   Сам `session_key` шифруется публичным ключом RSA, полученным от Instagram.
3.  **Payload:** Байты собираются воедино и кодируются в Base64.
4.  **Результат:** Формируется строка вида `#PWD_INSTAGRAM:4:{timestamp}:{base64_payload}`, которая и передается как пароль.

## 4. Загрузка больших медиа (`rupload`)
Для загрузки картинок и видео используется специальный эндпоинт `rupload_igphoto` или `rupload_igvideo`.

В `mixins/photo.py`:
*   Перед загрузкой генерируется уникальный `upload_id` и `waterfall_id`.
*   Картинка сжимается под стандарты Instagram (не более 1080px).
*   Формируется сложный заголовок `X-Instagram-Rupload-Params` с JSON:
    ```json
    {
      "media_type": "1",
      "upload_id": "123456789",
      "image_compression": {"lib_name": "moz", "lib_version": "3.1.m", "quality": "80"}
    }
    ```
*   **Отправка байтов:** Тело картинки отправляется POST-запросом.
*   **Configure:** После успешного аплоада вызывается метод `photo_configure`, который делает еще один POST-запрос с метаданными (ID загрузки, размер, caption, теги), и только тогда фотография появляется в ленте.

## Итог для Cherry-picking
1.  Использовать Mixins для разделения функционала в больших скраперах.
2.  Сгенерировать и жестко сохранить в БД `device_id`, `User-Agent` и `uuid` сессии для каждого рабочего аккаунта.
3.  Если требуется авторизация по паролю, портировать алгоритм RSA+AES-GCM для создания строки `#PWD_INSTAGRAM`.
4.  Для заливки файлов применять двухэтапный процесс: сначала `rupload` (передача байтов), затем `configure` (публикация).
