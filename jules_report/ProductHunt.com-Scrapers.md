# Анализ парсинга ProductHunt

Ссылка на репозиторий:
* ProductHunt.com-Scrapers: https://github.com/scraper-bank/ProductHunt.com-Scrapers

## 1. Техническая реализация и архитектура
Скрапер ProductHunt построен по классической схеме синхронного HTTP-парсинга с использованием прокси-шлюзов для обхода анти-бот защиты. В качестве основного инструмента получения HTML-кода используется библиотека `requests`, а для разбора структуры DOM-дерева — `BeautifulSoup` (модуль `bs4`) с парсером `lxml` (для скорости).
Чтобы ускорить процесс обработки множества URL, архитектура включает встроенный модуль `concurrent.futures.ThreadPoolExecutor`, который реализует многопоточность.

## 2. Функции и логика работы
**Маршрутизация запросов через прокси-шлюзы (Proxy APIs)**:
ProductHunt использует анти-бот защиту (вероятно, Cloudflare), поэтому прямые GET-запросы с обычного IP могут быть заблокированы.
В коде реализован механизм использования Proxy API (например, `ScrapeOps`). Формируется payload `{"api_key": API_KEY, "url": target_url, "optimize_request": True}`. Затем запрос отправляется не напрямую на ProductHunt, а на конечную точку прокси-провайдера (например, `https://proxy.scrapeops.io/v1/?...`). Прокси-провайдер сам обрабатывает ротацию IP, эмуляцию браузера (TLS-фингерпринты) и обход JS-челленджей, возвращая конечному скрипту чистый HTML. Функция `scrape_page` имеет встроенный механизм retries (попыток повтора) при неудачном ответе прокси.

**Паттерны классического парсинга DOM-узлов (CSS-селекторы + BeautifulSoup)**:
Функция `extract_data(soup: BeautifulSoup)` выполняет точечное извлечение данных.
- **Поиск карточек**: Используется селектор элементов `button[data-test^='spotlight-result-product-'], div[data-test^='spotlight-result-product-']`.
- **Извлечение свойств**: Внутри найденного элемента ищутся дочерние узлы с использованием CSS-селекторов (например, `item.select_one("span.text-16.font-semibold")` для имени продукта, `item.select_one("span.text-14.font-normal")` для описания).
- **Счетчик upvotes и отзывы**: Ищется элемент `span.text-brand-500`. Если текст содержит "review", регулярное выражение `re.search(r'(\d+)', review_text)` извлекает число (количество оценок/голосов).
- Все собранные данные упаковываются в словари, которые полностью соответствуют структуре заранее подготовленного `dataclass` под названием `ScrapedData`.

**Использование ThreadPoolExecutor для распараллеливания запросов**:
Функция `concurrent_scraping` принимает список URL-адресов и запускает их параллельную обработку.
Создается `ThreadPoolExecutor(max_workers=max_threads)`. Для каждого URL в пул отправляется задача: `executor.submit(scrape_page, url, pipeline, max_retries)`.
Это позволяет блокирующим сетевым I/O операциям (вызов `requests.get`) выполняться параллельно в разных системных потоках (threads), значительно ускоряя общую скорость сбора данных для простых сайтов.

## 3. Информационный обмен, память и потоки данных
**Модель данных и дедупликация**:
Структура данных определяется датаклассом `ScrapedData`, который содержит списки `products`, `relatedSearches` и `pagination`.
Для управления сохранением используется класс `DataPipeline`. Он реализует шаблон In-Memory базы (сохраняя хэши объектов в свойство `self.items_seen` типа `set`).
При добавлении новых данных (`pipeline.add_data`) происходит вычисление `hash(json.dumps(...))` и проверка его наличия в `items_seen`. Если данные уникальны, они добавляются в множество (set) в оперативной памяти и сразу же дописываются на диск.

**Поток обработки (Pipeline)**:
1. Главный поток (Main thread) инициализирует `DataPipeline` с целевым именем JSONL файла (один объект пайплайна шарится между всеми рабочими потоками).
2. `ThreadPoolExecutor` запускает N потоков.
3. Каждый рабочий поток (Worker) выполняет HTTP GET к Proxy API.
4. Полученный HTML конвертируется в объект `BeautifulSoup`.
5. Парсер извлекает данные и создает объект `ScrapedData`.
6. Объект передается в общий `pipeline.add_data()`.
7. `DataPipeline` выполняет проверку на дубликаты (используя хеширование).
8. Если дубликат не найден, объект сериализуется в JSON-строку и добавляется в конец JSONL-файла (`mode="a"`). Использование дозаписи (Append) на диск позволяет держать потребление RAM на низком уровне, так как в памяти хранятся только хэши уникальных ключей (`items_seen`), а не сами спарсенные данные.
