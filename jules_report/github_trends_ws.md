# 1. Техническая реализация и архитектура
Подсистема реального времени в `Github-Trends-Aggregator` реализована через WebSocket-протокол на языке Go, используя библиотеку `gorilla/websocket`. Архитектура основана на паттерне "Pub/Sub" (издатель/подписчик) с центральным узлом управления (Hub). Структура `Hub` поддерживает регистрацию новых клиентов, удаление отключившихся и маршрутизацию широковещательных сообщений.

# 2. Функции и логическая работа
- **Подключение**: Функция `ServeWs` устанавливает HTTP-соединение и выполняет его "upgrade" до WebSocket-соединения с помощью структуры `websocket.Upgrader`. Создается объект клиента (`Client`), содержащий соединение и буферизованный канал отправки данных.
- **Цикл событий**: Для каждого клиента запускаются две горутины: `readPump` (ожидает закрытия или входящих сообщений) и `writePump` (передает данные из канала клиента в сокет).
- **Главный цикл (Run)**: В методе `Hub.Run` работает бесконечный цикл `select`, который обрабатывает три типа событий в потокобезопасном режиме (с использованием `sync.Mutex`):
  1. `register` — добавление клиента в словарь активных подключений.
  2. `unregister` — удаление клиента и закрытие его канала.
  3. `broadcast` — обход всех активных клиентов и отправка им сообщения.
- **Интеграция с планировщиком**: При поступлении новых данных фоновый планировщик (`scheduler.go`) вызывает `hub.Broadcast(repos)`.

# 3. Информационный обмен, память и потоки данных
Потоки данных строго асинхронны.
- В памяти список подключений хранится в мапе `clients map[*Client]bool`. При изменении этого списка используется `sync.Mutex` для предотвращения состояния гонки (race condition).
- Информационный обмен: когда парсер получает новые тренды (Атомы), они маршалируются в массив байтов (JSON) прямо в методе `Broadcast`.
- Этот массив байтов отправляется в канал `h.broadcast`.
- Главный цикл `Hub` перехватывает его и отправляет в индивидуальный канал `send` каждого клиента. В случае, если канал клиента заблокирован (сообщение не может быть отправлено немедленно), клиент помечается как мертвый, его соединение закрывается, и он удаляется из мапы, предотвращая утечку памяти и зависания сервера.
