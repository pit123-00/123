# Кастомизация просмотра в браузере ленты новостей

Технический анализ реализации кастомизации и отображения пользовательских лент новостей (Feeds) в проекте Folo.

## 1. Техническая реализация и архитектура

Кастомизация отображения ленты новостей опирается на систему представлений (`FeedViewType`) и гибкие обертки компонентов (`EntryItemWrapper`).

Архитектурно процесс разделен на настройки списка (Lists) и рендеринг:
- **Управление списками (SettingsLists):** Пользователь может создавать пользовательские списки (Lists) из различных RSS-источников через интерфейс настроек (`Folo/apps/desktop/layer/renderer/src/modules/settings/tabs/lists/index.tsx`). Для каждого списка назначается иконка и тип представления (`view`).
- **Компонент-обертка (`EntryItemWrapper`):** Каждая запись в ленте оборачивается в этот компонент (`Folo/apps/desktop/layer/renderer/src/modules/entry-column/layouts/EntryItemWrapper.tsx`). Он определяет, как элемент будет реагировать на взаимодействие (наведение, клик, двойной клик) и какой тег использовать для рендеринга (`article` для социальных сетей, `NavLink` для остальных).
- **Заголовок ленты (`EntryListHeader`):** Заголовок адаптивно меняет свои отступы и состав кнопок (например, переключение на Masonry-раскладку для картинок) в зависимости от текущего типа `FeedViewType`.

## 2. Функции и логическая работа

Механизмы кастомизации ленты предоставляют пользователю богатый контроль над контентом:

- **Динамическое переключение представлений (Views):**
  Проект использует перечисление `FeedViewType` (All, Articles, Pictures, Videos, SocialMedia, Audios, Notifications). Компонент `EntryItemWrapper` динамически применяет классы Tailwind CSS (`itemClassName`, условный бордер-радиус) на основе текущего `view` и ширины экрана (`isWide`).
- **Интерактивность и Action Bar:**
  При наведении курсора на запись (событие `onMouseEnter`), с небольшой задержкой (`useDebounceCallback`, 233мс) происходит автоматическое отмечание статьи как прочитанной (если включена настройка `hoverMarkUnread`). Одновременно появляется панель быстрых действий (`ActionBar`), содержащая иконки для шеринга, сохранения, шорткатов и вызова контекстного меню.
- **Интеграция с AI:**
  В заголовке ленты реализована кнопка "Summarize Timeline" (`renderTimelineSummaryButton`). По нажатию вызывается экшен `sendAIShortcut`, который передает текущий контекст ленты в AI-помощника для генерации сводки новостей.
- **Управление непрочитанным (Unread):**
  Пользователь может скрыть прочитанные записи через шорткат или кнопку в `EntryListHeader`. Состояние переключателя (toggle `unreadOnly`) хранится в глобальных настройках (`useGeneralSettingKey`).

## 3. Обмен информацией, память и потоки данных

Поток данных кастомизации ленты управляется через Zustand/Jotai и синхронизируется с базой данных:

- **Списки (Lists) в БД:**
  Настройки пользовательских лент хранятся в SQLite в таблице `lists`. Таблица включает `feedIds` (JSON-массив идентификаторов источников), `view` (числовой енум `FeedViewType`), а также метаданные `title` и `image`.
- **Подписки (Subscriptions):**
  Связь между пользователем, лентой (feed) или списком (list) управляется таблицей `subscriptions`, которая также содержит поле `view` и `hideFromTimeline` (для исключения из общей ленты).
- **Роутинг и состояние:**
  Текущее представление ленты передается через параметры URL (хук `useRouteParams()`). Состояние "отмечено как прочитанное" синхронизируется с БД через сервис `unreadSyncService.markEntryAsRead(entry.id)`. Данные о списках пользователя извлекаются с помощью `useOwnedLists` и `usePrefetchLists` (TanStack Query), обеспечивая оптимистичные обновления UI при редактировании или удалении списков в настройках.
