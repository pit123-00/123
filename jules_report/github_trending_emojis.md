# 1. Техническая реализация и архитектура
Поскольку файлы GitHub ReadMe (в формате Markdown/Asciidoc) часто содержат кастомные эмодзи в формате `:имя_эмодзи:`, `GitHubTrendingRSS` реализует слой нормализации, чтобы корректно отображать их в финальном HTML для RSS. Архитектура полагается на предварительный запрос к официальному API GitHub (`Const.gitHubAPIEmojisURL`) для получения актуального словаря поддерживаемых эмодзи, которые затем маппятся на структуру `GitHubEmoji`.

# 2. Функции и логическая работа
Процесс разделен на две части:
1. Загрузка справочника: В `GitHubDownloader` метод `fetchSupportedEmojis` отправляет GET запрос к API, получает JSON вида `{"smile": "url_to_image"}` и декодирует его в массив объектов `GitHubEmoji`.
2. Замена: В структуре `Repository` функция `normalizeEmojisInHTML` принимает сгенерированный из Markdown HTML и актуальный справочник эмодзи.
   - Запускается цикл по всем эмодзи из справочника.
   - Формируется целевая строка для поиска (`target = ":" + emoji.id + ":"`).
   - Выполняется метод `replacingOccurrences`, который заменяет текстовый код (например, `:smile:`) на HTML представление. HTML представление (метод `emoji.html`) в зависимости от типа возвращает либо текстовый тег `<span>`, либо тег изображения `<img alt='id' src='url' />`.

# 3. Информационный обмен, память и потоки данных
Словарь эмодзи загружается только один раз (или кэшируется), так как его объем (сотни элементов) является константой и отлично помещается в оперативную память.
При парсинге ReadMe поток сырого текста из Markdown сначала проходит через конвертер (DocslothManager) и превращается в HTML строку. Затем эта строка загружается в память и подвергается последовательным мутациям (String replacing). Так как замена работает как простая строковая операция (а не сложный обход DOM-дерева), она выполняется очень быстро. Модифицированная HTML строка (уже с картинками вместо кодов) передается парсеру `SwiftSoup` для финальной очистки ссылок, а затем вставляется в XML RSS фида.
