# Поддержка динамического контента в Folo

Технический анализ архитектуры поддержки различных медиаформатов в проекте Folo. Отчет основан на прямом инспектировании исходного кода React-компонентов и Drizzle-схем.

## 1. Техническая реализация и архитектура

Поддержка динамического контента (видео, аудио, изображения) в Folo реализована через специализированные React-компоненты для каждого типа контента, которые обертывают базовые элементы интерфейса.

Данные о медиа-вложениях поступают из глобального хранилища состояния (Zustand/Jotai), используя хук `useEntry`. Это обеспечивает реактивное обновление UI при изменении данных записи.

Архитектура компонентов:
- **`VideoItem`**: Отвечает за рендеринг видеоконтента. Использует `iframe` или `webview` (в зависимости от среды: Electron или браузер) для отображения мини-превью видео. Поддерживает ленивую загрузку (lazy loading) и отображение заглушек (fallback) при отсутствии медиа.
- **`AudioItem`**: Отвечает за аудио-контент. Построен на базе шаблона `ListItem` и использует скелетоны для индикации загрузки.
- **`MediaGallery`**: Компонент для отображения галереи изображений. Поддерживает два режима раскладки (layout):
  - Горизонтальная прокрутка (если все изображения имеют одинаковое соотношение сторон).
  - Сетка (Grid) (если изображения имеют разные соотношения сторон, с поддержкой `span 2` для акцентирования).

## 2. Функции и логическая работа

Логика обработки динамического контента строго разделяет извлечение метаданных и их рендеринг:

- **Извлечение метаданных (Video):**
  Хук `useEntry` извлекает массив `attachments` и `media`. Для видео длительность (`duration_in_seconds`) конвертируется в удобочитаемый формат через утилиту `formatDuration`.
- **Генерация URL (Video):**
  Утилита `transformVideoUrl` адаптирует URL видео для встраивания (`isIframe` флаг для веб-версии, `webview` для десктопа).
- **Масштабирование и проксирование изображений (MediaGallery):**
  Изображения рендерятся через базовый компонент `Media`. Размеры (width/height) вычисляются динамически на основе `containerWidth`. Для обхода CORS и оптимизации загрузки используется `getImageProxyUrl`, который проксирует запросы к изображениям и применяет ресайз на лету (например, передавая параметры `proxySize`).
- **Интерактивность:**
  Используется хук `useHover` (из `@use-gesture/react`) для отложенного запуска превью видео (задержка 500мс) при наведении курсора. При клике на изображения в `MediaGallery` открывается полноэкранный просмотрщик (`previewMedia`), которому передается массив URL-адресов с пониженным качеством для быстрого отображения (`blurhash` или проксированные превью).

## 3. Обмен информацией, память и потоки данных

Хранение медиа-данных реализовано в SQLite с использованием Drizzle ORM (`Folo/packages/internal/database/src/schemas/index.ts`).

- **Модели данных (`MediaModel`, `AttachmentsModel`):**
  Медиа-файлы и вложения сохраняются в таблице `entries` как JSON-массивы:
  - Колонки `media` и `attachments` имеют тип `text({ mode: "json" })`.
  - `MediaModel` содержит: `url`, `type` ("photo" | "video"), `preview_image_url`, `width`, `height`, и `blurhash` (для скелетной загрузки).
  - `AttachmentsModel` содержит: `url`, `duration_in_seconds`, `mime_type`, `size_in_bytes`, и `title`.

Данные из базы через API-слой попадают в клиентское хранилище (`@follow/store`), откуда компоненты (`VideoItem`, `MediaGallery`) подписываются на изменения через `useEntry(entryId)`. Это гарантирует, что при добавлении нового контента (например, после фонового парсинга ленты), пользовательский интерфейс обновляется мгновенно без перезагрузки страницы.
