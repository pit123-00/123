# Руководство: Адаптация Graphify для глоссария и графа документации

Для того чтобы использовать Graphify не для анализа кода, а как инструмент создания глоссария и графа знаний на основе документации, необходимо изменить фокус системы с детерминированного AST-парсинга на семантическую экстракцию.

## 1. Технический путь адаптации

### А. Изменение логики экстракции (extract.py)
Graphify по умолчанию отдает приоритет коду через Tree-sitter. Для глоссария нужно:
1. **Отключить AST-парсер** или сделать его опциональным, чтобы он не зашумлял граф узлами функций и классов.
2. **Модифицировать системный промпт LLM-агентов** (Claude). В файлах, отвечающих за экстракцию из текстов (например, через подмодули анализа MD), нужно заменить инструкцию:
   - *Было:* «Найди связи между функциями и архитектурными решениями».
   - *Стало:* «Выдели ключевые термины, их определения и иерархические связи между ними (is-a, part-of, related-to)».
3. **Добавить поддержку новых типов узлов:** в манифесте графа нужно явно прописать типы `Term` и `Definition`.

### Б. Структурирование входных данных
Для построения качественного графа по документации следует:
- Использовать Markdown с четкой структурой заголовков.
- Добавить YAML Frontmatter к файлам документации, где явно указывать `type: documentation` или `category: glossary`.

### В. Настройка весов ребер (cluster.py)
Алгоритм Leiden работает на основе плотности связей. Для глоссария важно, чтобы связь «Термин -> Определение» была максимально «тяжелой» (weight = 1.0), а связь «Связанный термин» — легче (weight = 0.5). Это позволит кластеризовать термины по предметным областям автоматически.

## 2. Логический путь (Workflow)

1. **Создание корпуса терминов:** Поместите все `.md` файлы документации в папку `/raw`.
2. **Запуск глубокой экстракции:** Используйте флаг `--mode deep` для того, чтобы LLM активнее искала скрытые связи между терминами в разных файлах.
3. **Генерация Вики (`--wiki`):** Graphify уже умеет генерировать Markdown-вики. Это и будет вашим «живым» глоссарием. Каждый «God Node» станет центральным термином в своей категории.
4. **Использование отчета (`GRAPH_REPORT.md`):** Секция «Surprising Connections» в контексте документации покажет вам нестыковки в определениях или неожиданные пересечения разных разделов знаний.

## 3. Как сделать из этого полноценный глоссарий
Чтобы превратить результат в структурированный список терминов:
- Напишите небольшой Python-скрипт (или модифицируйте `export.py`), который проходит по всем узлам типа `concept` (которые извлекает Claude) и выгружает их в алфавитном порядке в один файл `GLOSSARY.md`.
- Используйте метаданные `rationale_for` для хранения описания термина.

Таким образом, Graphify станет мощным инструментом «смыслового рентгена» вашей документации, позволяя увидеть, какие термины являются центральными, а какие — изолированными и требуют лучшего описания.
