# Отчет: AI Workspace
Persistent Shared Memory for AI Agents across multiple projects.

## 1. Назначение проекта
AI Workspace решает фундаментальную проблему современных ИИ-агентов — «изоляцию контекста». При работе над распределенными системами (микросервисы, монорепозитории) ИИ-ассистент часто теряет связь между компонентами, находящимися в разных папках или репозиториях. AI Workspace создает единый индексируемый слой «памяти», который объединяет связанные проекты в общую экосистему. Через протокол MCP агент получает доступ к глобальному поиску, общим заметкам и структуре всех проектов воркспейса одновременно.

## 2. Архитектура и технический стек
Проект реализован на языке Rust, что обеспечивает высокую скорость индексации и минимальный "отпечаток" в оперативной памяти.

### Основные компоненты:
- **SQLite с модулем FTS5:** В качестве движка хранения используется SQLite. Полнотекстовый поиск (FTS5) позволяет выполнять мгновенные запросы по содержимому тысяч файлов.
- **Virtual Tables & Triggers:** Архитектура БД активно использует виртуальные таблицы для FTS и триггеры для автоматической очистки поискового индекса при удалении элементов из основной таблицы `shared_items`.
- **WAL Mode:** Включен режим Write-Ahead Logging для обеспечения конкурентного доступа (чтение не блокирует запись).
- **MCP Protocol (stdio):** Серверная часть реализует Model Context Protocol, предоставляя агентам стандартизированный набор инструментов (tools) для взаимодействия с базой знаний.

## 3. Логика работы и функции
### Управление знаниями через "Shared Items":
Система оперирует тремя типами объектов (`kind`):
1. **File:** Прямая ссылка на файл в файловой системе.
2. **Directory:** Индексация целой директории.
3. **Note:** Произвольная текстовая информация, не привязанная к файлу (например, архитектурные гайдлайны или секреты проекта).

### Ключевые функции:
- **Project Groups:** Возможность объединять репозитории в логические группы (например, `frontend` + `backend`). Агент может выполнять поиск только внутри конкретной группы, экономя контекстное окно.
- **Deep Indexing (`indexer.rs`):** Воркспейс не просто хранит пути, он индексирует содержимое файлов. При добавлении файла (`share`) или папки, система обходит дерево и заполняет FTS-таблицу.
- **Global Search Tools:** Агенту доступны инструменты `workspace_query` и `workspace_read`, которые позволяют ему самостоятельно находить нужные фрагменты кода в "соседних" проектах.
- **Sync Mechanism:** Команда `sync` позволяет актуализировать состояние воркспейса, проверяя `mtime` (время модификации) файлов и обновляя индекс только для изменившихся данных.

## 4. Нестандартные решения
- **SQLite as a Vectorless Search Engine:** В то время как многие проекты используют тяжелые векторные БД (RAG) и эмбеддинги, AI Workspace доказывает эффективность классического полнотекстового поиска с использованием `unicode61` токенизатора. Это работает на порядки быстрее и не требует обращения к API для генерации векторов.
- **Complex Constraints in SQLite:** Схема базы данных (`schema.rs`) содержит сложные `CHECK`-ограничения, которые на уровне БД гарантируют целостность данных для разных типов `shared_items`. Например, запись типа `note` обязана иметь `content`, но не может иметь `path`, в то время как `file` — наоборот.
- **Transparent Team Sharing:** Конфигурация воркспейса хранится в JSON-файле, который можно закоммитить в Git. Это превращает "память" агента из индивидуального инструмента в командный актив. Новый участник команды получает настроенный контекст мгновенно после клонирования.
- **FTS Tokenization Optimization:** Использование параметров `remove_diacritics 2` в токенизаторе FTS5 позволяет ИИ находить код даже при небольших опечатках или различиях в спецсимволах, что критично для работы с исходным кодом.
- **Discovery-first Tools:** Вместо того чтобы пытаться "запихнуть" всё дерево файлов в промпт, инструменты MCP возвращают компактные сводки (summaries), заставляя агента выполнять итеративный поиск. Это значительно снижает затраты на токены и повышает точность ответов.

## 5. Вывод
AI Workspace — это легкая и эффективная реализация «корпоративной памяти» для ИИ. Отказ от тяжелых векторных индексов в пользу оптимизированного SQLite FTS5 делает инструмент доступным для работы на обычных ноутбуках, обеспечивая при этом мгновенный доступ к контексту множества проектов. Это идеальный фундамент для построения мульти-агентных систем, работающих с большими и сложными кодовыми базами.
