# Отчет: AI Workspace
Give your AI agents memory that spans across projects.

## 1. Назначение проекта
AI Workspace решает фундаментальную проблему современных ИИ-агентов — «изоляцию контекста». Когда разработчик переключается между микросервисами или работает над фронтендом и бэкендом в разных репозиториях, ИИ каждый раз начинает «с чистого листа». AI Workspace создает общую «память» (Shared Memory), которая объединяет связанные проекты в единую экосистему, доступную агенту через Model Context Protocol.

## 2. Архитектура и технический стек
Проект выполнен на Rust, что гарантирует минимальное потребление ресурсов при постоянной работе в фоне. Технические особенности:
- **SQLite + FTS5:** Использование встроенной базы данных с модулем полнотекстового поиска позволяет мгновенно находить нужные фрагменты кода или заметки среди сотен файлов.
- **Virtual Tables:** Для поиска по файлам и заметкам используются виртуальные таблицы SQLite, что обеспечивает гибкость индексации без дублирования данных.
- **MCP Server (stdio):** Реализация протокола MCP позволяет подключать «память воркспейса» к любому современному ИИ-инструменту (Claude Code, Cursor, Windsurf) одной командой.
- **JSON-driven Configuration:** Состояние воркспейса может экспортироваться в `.ai-workspace.json` для совместного использования командой.

## 3. Логика работы и функции
### Концепция «Групп» и «Шаринга»:
Вместо того чтобы индексировать всё подряд, AI Workspace предлагает избирательный подход:
1. **Проекты и Группы:** Вы объединяете репозитории в логические группы (например, `fintech-platform`).
2. **Explicit Sharing:** Командой `share <path>` вы указываете агенту: «Этот файл важен для всей группы». Это могут быть схемы API, документация по деплою или общие типы данных.
3. **Workspace Notes:** Команда `note` позволяет добавлять текстовые знания, которые не хранятся в коде, но критичны для работы (например, «Никогда не удаляйте таблицу логов вручную»).

### Ключевые функции:
- **Cross-project Context:** Агент, работающий в Проекте А, может «видеть» структуру и содержимое файлов из Проекта Б через инструменты `workspace_read` и `project_tree`.
- **Global Full-text Search:** Мощный поиск по всей группе проектов. Можно спросить ИИ: «Найди где в других проектах группы используется этот заголовок авторизации», и он получит доступ к результатам из всей базы данных.
- **Smart Sync:** Команда `sync` проверяет актуальность путей в базе данных и синхронизирует состояние с JSON-конфигурацией, если она была изменена коллегами через Git.

## 4. Нестандартные решения
- **Context without Copying:** В отличие от многих систем «памяти», AI Workspace не создает копий файлов. Он хранит метаданные и пути. Это гарантирует, что агент всегда работает с актуальной версией кода, а не со старым индексом.
- **Team-first Architecture:** Идея коммитить конфиг воркспейса в Git — это прорыв в онбординге. Новый разработчик просто делает `ai-workspace init`, и его ИИ-ассистент мгновенно «узнает» всё о связях проектов, общих контрактах и скрытых нюансах, которые обычно передаются только на словах.
- **Token Efficiency:** Система предоставляет агенту инструменты для «разведки» (discovery tools), а не «заливает» в него весь контекст сразу. Это позволяет экономить токены, давая ИИ возможность самому решать, какие фрагменты из соседних проектов ему нужно прочитать.
- **Security Hardening:** Встроенная очистка имен узлов от контрольных символов и ограничение длины строк предотвращают атаки типа «Prompt Injection» через имена файлов или заголовки функций.

## 5. Вывод
AI Workspace превращает набор разрозненных репозиториев в целостную базу знаний. Это незаменимый инструмент для работы со сложными распределенными системами, где понимание контекста «соседа» важнее, чем знание собственного кода. Его простота и опора на стандарты (Rust, SQLite, MCP) делают его надежным фундаментом для профессиональной ИИ-разработки.
