# Кастомизация и добавление новых каналов

## 1. Техническая реализация и архитектура
В NodeRSSBot добавление новых RSS-каналов реализовано через взаимодействие пользователя с Telegram-ботом, обрабатывающим команды (например, `/sub`). Контроллеры (находящиеся в `source/controlers/rss.ts`) принимают URL фида, после чего прокси-слой (`source/proxies/rss-feed.ts`) отвечает за запись информации о канале в базу данных.
Архитектура спроектирована с использованием Knex.js для работы с базой данных PostgreSQL/SQLite. Отношение "многие-ко-многим" реализовано через связующую таблицу `subscribes`, которая связывает пользователя (`users`) и RSS-канал (`rss_feed`). Если добавляемый канал еще не существует в базе `rss_feed`, он создается.
Также предусмотрена функция автоматического извлечения ссылок на RSS-фиды из HTML-кода веб-страниц (например, чтение тегов `<link type="application/atom+xml">`), которая запускается в случае передачи URL обычной страницы, а не прямого URL фида.

## 2. Функции и логическая работа
Основной процесс добавления канала включает следующие логические шаги:
- **Прием команды:** Пользователь отправляет боту URL фида или веб-страницы.
- **Детектирование:** Если отправлен URL обычной веб-страницы, функция `findFeed` (в `source/utils/feed.ts` или `detect-feed.ts`) делает HTTP-запрос (используя пакет `got`/`make-fetch-happen`) и пытается извлечь RSS/Atom ссылки.
- **Сохранение (подписка):** Функция `sub` (в `source/proxies/rss-feed.ts`) проверяет наличие URL фида в таблице `rss_feed`.
  - Если фид существует: проверяется наличие записи в таблице `subscribes` для данного пользователя. Если записи нет, она добавляется.
  - Если фид не существует: запускается транзакция (transaction), в которой происходит вставка новой записи в `rss_feed` (URL, title, TTL), а затем добавление записи в `subscribes` с идентификатором пользователя (chat ID).
- **Подтверждение:** Бот отправляет сообщение об успешной подписке.

Кастомизация параметров фида (например, частота опроса, прокси-сервера) вынесена в общие конфигурационные файлы (`config.ts`), где определяются такие вещи как `fetch_gap` (интервал парсинга) или настройки SOCKS/HTTP прокси.

## 3. Обмен информацией, память и потоки данных
- **Входные данные:** URL (от пользователя через Telegram API).
- **Поток данных:** `Telegram Message -> Controller (ctx) -> Proxy Layer (RSS.sub) -> DB transaction (INSERT into rss_feed / subscribes)`.
- **Память (Состояние):**
  - **`rss_feed`**: Содержит метаданные канала (`feed_id`, `url`, `feed_title`, `recent_hash_list` для отслеживания старых записей, `error_count`, `next_fetch_time`, `etag_header` и `last_modified_header` для HTTP-кэширования).
  - **`subscribes`**: Содержит связи пользователей с фидами (`subscribe_id`, `user_id`, `feed_id`).
- При последующем обходе каналов (в фоновом воркере `source/utils/fetch.ts`), выборка происходит из `rss_feed` на основе `next_fetch_time`. Новые записи в фидах сравниваются по хэшу с массивом `recent_hash_list` из БД, чтобы отправлять в Telegram только новые посты.
