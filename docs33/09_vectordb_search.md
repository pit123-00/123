# VectorDB::search и логика обработки запросов

Метод **`search`** в `VectorDB` (крейт `ruvector-core`, файл `vector_db.rs`) является центральным диспетчером запросов к системе. Он оркестрирует взаимодействие между индексом, хранилищем метаданных и фильтрами, обеспечивая комплексный ответ на семантические запросы.

## 1. Конвейер выполнения запроса
Процесс обработки поискового запроса в RuVector не ограничивается простым поиском ближайших соседей. Это многошаговый конвейер (pipeline), спроектированный для обеспечения максимальной релевантности.

### Основные этапы:
1.  **Векторный поиск**: Получение списка кандидатов по геометрическому расстоянию.
2.  **Обогащение (Enrichment)**: Извлечение полных данных (включая метаданные) из персистентного хранилища.
3.  **Фильтрация**: Проверка соответствия атрибутов заданным условиям.

## 2. Реализация ключевых функций поиска

### 41. `VectorDB::search(query: SearchQuery) -> Result<Vec<SearchResult>>`
Главная точка входа.
- **Логика**: Вызывает метод `search` у активного индекса (HNSW или Flat), затем итерируется по результатам, загружая метаданные из `self.storage.get`.
- **Особенности**: Поддерживает динамическую фильтрацию через `results.retain`, что позволяет комбинировать семантический поиск с жесткими бизнес-правилами (например, "искать только в документах за 2024 год").

### 42. `euclidean_distance_simd(a, b) -> f32`
Оптимизированное вычисление расстояния.
- **Логика**: Использует интринсики процессора (AVX-2 или NEON) для параллельной обработки элементов вектора.
- **Производительность**: Вычисляет расстояние для векторов размерности 512 в среднем за 10-15 наносекунд.

### 43. `batch_dot_product(query, vectors, results)`
Групповое вычисление скалярного произведения.
- **Логика**: Обрабатывает сразу несколько векторов из базы данных за один вызов, максимизируя использование кэша процессора и векторных регистров.
- **Применение**: Используется GNN-слоями для быстрого расчета весов внимания.

### 44. `ScalarQuantized::decode(quantized) -> Vec<f32>`
Восстановление векторов для высокоточного ранжирования.
- **Логика**: Преобразует сжатые 8-битные значения обратно в `f32`, используя сохраненные коэффициенты масштабирования.
- **Роль**: Позволяет хранить индекс в сжатом виде, но выполнять финальное ранжирование с полной точностью.

### 45. `Arena::new(chunk_size) -> Self`
Инициализация кастомного аллокатора памяти.
- **Логика**: Выделяет большие непрерывные блоки памяти (chunks).
- **Важность**: Уменьшает накладные расходы на управление памятью (malloc/free) при обработке сотен тысяч временных векторов во время поиска, что снижает задержки (latency) системы.

## 3. Гибридный и уточняющий поиск
В RuVector реализована поддержка `HybridSearch` (в модуле `advanced_features.rs`), который объединяет результаты векторного поиска и полнотекстового поиска (BM25). С помощью метода `fuse_rankings` система комбинирует оценки релевантности, используя алгоритм Reciprocal Rank Fusion, что позволяет находить документы, которые важны как по смыслу, так и по точному вхождению ключевых слов. Это делает систему незаменимой для корпоративного поиска в больших массивах неструктурированных данных.
