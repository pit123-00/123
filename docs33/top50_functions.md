# Техническая реализация Топ-50 главных функций RuVector

Обзор реализован на основе анализа исходного кода в репозитории. Функции разбиты по ключевым подсистемам.

## 1. Векторное ядро и Индексация (ruvector-core)
1.  **`HnswIndex::new`**: Инициализация `Hnsw` графа с заданными параметрами `m` и `ef_construction`. Использует `hnsw_rs`.
2.  **`HnswIndex::add`**: Добавление вектора. Выполняет `insert_data` в граф и обновляет DashMap-маппинги ID.
3.  **`HnswIndex::search`**: Поиск k-ближайших соседей с использованием параметра `ef_search` для контроля точности.
4.  **`VectorDB::insert_batch`**: Пакетная вставка. Координирует запись в хранилище и обновление индекса для высокой пропускной способности.
5.  **`VectorDB::search`**: Центральный метод поиска. Обогащает результаты индекса метаданными из хранилища и применяет пользовательские фильтры.
6.  **`euclidean_distance_simd`**: Расстояние L2, реализованное через интринсики AVX2/NEON для максимальной скорости на CPU.
7.  **`cosine_similarity_simd`**: Косинусное расстояние с SIMD-оптимизацией.
8.  **`ScalarQuantized::encode`**: Квантование f32 -> i8. Снижает потребление памяти в 4 раза.
9.  **`BinaryQuantized::encode`**: Бинарное квантование. Позволяет выполнять сравнения векторов через инструкции XOR/Popcount.
10. **`Arena::alloc_vec`**: Выделение памяти в арене для минимизации аллокаций в "горячих" путях кода.

## 2. Графовые нейронные сети (ruvector-gnn)
11. **`RuvectorLayer::forward`**: Проход через GNN-слой. Включает агрегацию сообщений соседей, механизм внимания и GRU-обновление состояния.
12. **`differentiable_search`**: Реализация Soft Attention над кандидатами поиска, позволяющая обучать индекс методом обратного распространения ошибки.
13. **`hierarchical_forward`**: Алгоритм уточнения поискового запроса при движении по иерархическим слоям HNSW.
14. **`GraphMAE::train_step`**: Шаг обучения Masked Autoencoder: маскировка узлов, кодирование GAT, декодирование и вычисление SCE-loss.
15. **`FeatureMasking::mask_nodes`**: Логика случайной замены признаков узлов на обучаемый [MASK] токен.
16. **`ElasticWeightConsolidation::penalty`**: Вычисление штрафа на основе матрицы Фишера для сохранения важных параметров модели.
17. **`ReplayBuffer::add`**: Сохранение траекторий в буфер с использованием Reservoir Sampling для равномерного распределения данных.
18. **`cosine_similarity` (GNN)**: Точное вычисление сходства с использованием аккумуляторов f64 для стабильности градиентов.
19. **`softmax` (with temperature)**: Дифференцируемая функция выбора, где температура регулирует "остроту" распределения весов.
20. **`MmapManager::get_embedding`**: Ленивая загрузка эмбеддингов узлов из файлов, отображаемых в память (Memory-Mapped).

## 3. Самооптимизация (sona)
21. **`SonaEngine::begin_trajectory`**: Создание `TrajectoryBuilder` для записи последовательности активаций нейросети в рамках запроса.
22. **`SonaEngine::apply_micro_lora`**: Быстрая модификация промежуточных состояний через низкоранговые матрицы (rank 1-2).
23. **`LoopCoordinator::on_inference`**: Обработка завершенной траектории и её отправка в циклы обучения.
24. **`ReasoningBank::find_similar`**: Поиск в K-means кластерах похожих паттернов рассуждения для адаптации ответа.
25. **`BaseLoRA::forward_layer`**: Применение весов долгосрочного обучения к конкретному слою модели.
26. **`EwcState::consolidate`**: Фиксация текущих знаний в долгосрочную память системы.
27. **`SonaEngine::tick`**: Периодическая проверка необходимости запуска фонового цикла консолидации знаний.
28. **`TrajectoryBuilder::add_step`**: Регистрация активаций и весов внимания на конкретном этапе обработки запроса.

## 4. Контейнеры и Хранение (rvf-runtime)
29. **`RvfStore::create`**: Создание файла RVF, генерация 128-битного уникального ID и запись начального сегмента MANIFEST.
30. **`RvfStore::boot`**: Инициализация хранилища из файла: чтение сегментной директории, верификация контрольных сумм.
31. **`RvfStore::ingest_batch`**: Формирование `VEC_SEG` и запись в конец файла с автоматическим обновлением манифеста.
32. **`RvfStore::query_with_envelope`**: Поиск с возвратом `QualityEnvelope`, содержащего доказательства качества (SearchEvidence).
33. **`RvfStore::compact`**: Пересборка файла для удаления "дыр" от удаленных данных и слияния мелких сегментов.
34. **`RvfStore::branch`**: Инициализация `CowEngine` для создания виртуальной копии базы данных.
35. **`RvfStore::append_witness`**: Запись сегмента `WITNESS_SEG`, связывающего текущую операцию с хэшем всей предыдущей истории.
36. **`RvfStore::embed_kernel`**: Внедрение бинарного образа ядра в сегмент `KERNEL_SEG` с заполнением `KernelHeader`.
37. **`RvfStore::embed_wasm`**: Запись `WASM_SEG` с указанием роли (Interpreter/Microkernel) и приоритета загрузки.
38. **`generate_file_id`**: Криптографически стойкая генерация ID файла через SHAKE-256 (путь + метка времени).

## 5. Алгоритмы решателя (ruvector-solver)
39. **`SolverRouter::select_algorithm`**: Анализ `SparsityProfile` для автоматического выбора между Neumann, CG или BMSSP.
40. **`SolverOrchestrator::solve_with_fallback`**: Реализация цепочки отказоустойчивости: быстрый метод -> CG -> Dense решатель.
41. **`SolverOrchestrator::analyze_sparsity`**: Вычисление плотности, диагонального доминирования и спектрального радиуса матрицы за O(NNZ).
42. **`NeumannSolver::solve`**: Итерационное решение разреженных систем через ряды Неймана.
43. **`ConjugateGradientSolver::solve`**: Эффективная реализация метода сопряженных градиентов для SPD матриц.
44. **`ForwardPush::compute`**: Локальный алгоритм аппроксимации PageRank для огромных графов.
45. **`TRUE_solver::solve`**: Решатель для пакетных (batch) систем уравнений.

## 6. Продвинутые механизмы (attention & others)
46. **`DynamicMinCut::recompute`**: Динамическое обновление разреза графа с использованием субполиномиальной иерархии j-Tree.
47. **`FastGRNN::predict`**: Быстрый проход через рекуррентную сеть для классификации намерений пользователя и маршрутизации запроса.
48. **`SheafLaplacian::measure_coherence`**: Оценка логической непротиворечивости графа/ответа через энергию сечений пучка.
49. **`FlashAttention::forward`**: Плиточный (tiled) расчет внимания, минимизирующий обращения к основной памяти.
50. **`PrivacyEngine::apply_dp_noise`**: Генерация гауссовского шума для градиентов в рамках дифференциальной приватности (Federated Learning).
