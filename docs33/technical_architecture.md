# Техническая архитектура RuVector

RuVector — это высокопроизводительная «агентная операционная система» (Agentic OS) и векторная база данных, построенная на языке Rust. Она спроектирована для обеспечения долгосрочной памяти ИИ-агентов с возможностью самообучения в реальном времени.

## 1. Модульная структура (Crates)
Проект разбит на множество узкоспециализированных крейтов:
- **ruvector-core**: Основной движок БД. Реализует HNSW-индексацию (используя `hnsw_rs`) и абстракции для хранилищ (Storage). Поддерживает SIMD-интринсики в `simd_intrinsics.rs` для ускорения вычислений расстояний.
- **ruvector-gnn**: Слой графовых нейронных сетей. Ключевой компонент — `GraphMAE` (Masked Graph Autoencoder), реализованный в `graphmae.rs`, который обучается на структуре графа без меток.
- **sona**: Движок самооптимизации. Содержит `LoopCoordinator` для управления тремя циклами обучения (мгновенный, фоновый, глубокий). Реализует `MicroLoRA` (низкоранговая адаптация) и `EWC` (Elastic Weight Consolidation) для предотвращения забывания.
- **rvf (RuVector Format)**: Протокол когнитивных контейнеров. В `rvf-runtime` реализована логика работы с сегментированными бинарными файлами, которые могут содержать не только векторы, но и исполняемые модули (WASM, Kernel).
- **ruvix**: Специализированное микроядро (kernel), ориентированное на работу с графами и векторами.
- **ruvector-solver**: Набор сублинейных алгоритмов (Neumann, CG, ForwardPush) для быстрой работы с графами огромного масштаба.

## 2. Логика самообучения и GNN
В отличие от классических векторных БД, RuVector использует топологию индекса HNSW как структуру графа для GNN.
- **Differentiable Search**: В `ruvector-gnn/src/search.rs` реализован поиск через Soft Attention, что позволяет интегрировать операцию поиска в процесс градиентного обучения.
- **Hierarchical Forward**: Система выполняет иерархический проход по слоям графа, уточняя вектор запроса на каждом этапе.
- **Experience Replay**: В `replay.rs` используется Reservoir Sampling для сохранения успешных траекторий поиска и их повторного использования в обучении.

## 3. Когнитивные контейнеры (RVF)
Формат RVF (`crates/rvf`) — это сегментированный архив:
- **Сегменты**: VEC (данные), INDEX (индекс), MANIFEST (метаданные), KERNEL (образ ядра), WASM (логика).
- **Цепочка свидетельств (Witness Chain)**: Каждая операция записи (ingest, delete) порождает `WitnessEntry`, хэши которого связываются в цепочку (реализовано в `RvfStore::append_witness`).
- **COW-ветвление**: `RvfStore::branch` создает дочерний контейнер, использующий `CowEngine` для ссылок на блоки данных родителя, что позволяет мгновенно клонировать базы данных.

## 4. Нестандартные подходы и методы
- **Proof-Gated Mutations**: В архитектуре `ruvix` и `ruvector-verified` изменения состояния требуют криптографического или математического доказательства (witness), что предотвращает некорректные мутации.
- **Сублинейные вычисления**: Алгоритм `ForwardPush` в решателе позволяет оценивать релевантность узлов без полного обхода графа.
- **Динамический Min-Cut**: Использование субполиномиального алгоритма (N^0.12) для динамического обновления минимального разреза графа, что применяется для кластеризации и оценки когерентности.
- **π-Quantization**: Экзотические методы квантования (2-бит через π-преобразования) для экстремального сжатия моделей и векторов.

## 5. Отличия от аналогов
RuVector — это «живая» система. Если Pinecone или Qdrant просто хранят векторы, то RuVector:
1. Обучается на каждом запросе пользователя через SONA.
2. Позволяет переносить базу как единый исполняемый файл (RVF) с встроенным ИИ-агентом.
3. Интегрирует теорию пучков (Sheaf Theory) для формальной проверки непротиворечивости (coherence) ответов.
