# Глубокий технический анализ 4: Метаданные, фингерпринтинг и умная маршрутизация (Schema-Aware Routing)

## 1. Технология извлечения и структурирования метаданных

В системе OB1 процесс захвата информации — это не просто сохранение текста, а полноценный цикл мгновенного обогащения (Enrichment). Главная техническая задача здесь — превратить неструктурированный поток сознания в набор реляционных связей.

### 1.1. LLM-конвейер извлечения (Extraction)
При поступлении любого сообщения (через Slack, MCP или другие каналы) сервер инициирует параллельный вызов LLM (обычно `gpt-4o-mini`).
- **Response Format**: Система использует жестко заданную схему JSON, извлекая `people` (люди), `action_items` (задачи), `topics` (темы) и `type` (тип мысли).
- **Параллелизм**: Вызов экстрактора происходит одновременно с генерацией вектора эмбеддинга (`Promise.all`), что позволяет выполнить полный цикл обработки за 1-2 секунды.

## 2. Фингерпринтинг и дедупликация (SHA-256)

Для борьбы с "Memory Bloat" (раздуванием памяти) при импорте данных из разных источников, OB1 реализует механизм "отпечатков контента" (Content Fingerprinting).

### 2.1. Алгоритм дедупликации
Примитив `content-fingerprint-dedup` генерирует уникальный хеш (fingerprint) для каждого фрагмента контента.
- **Хеширование**: Используется алгоритм SHA-256.
- **Предварительная нормализация**: Перед расчетом хеша текст очищается от лишних пробелов, непечатных символов и приводится к единому регистру. Это гарантирует, что одно и то же сообщение, скопированное из Slack в почту, будет опознано как дубликат.
- **Атомарная проверка**: Перед вставкой система выполняет поиск:
  `SELECT id FROM thoughts WHERE metadata->>'fingerprint' = [new_hash] LIMIT 1`.
  Если совпадение найдено, вставка игнорируется, предотвращая захламление базы данных.

## 3. Маршрутизация с учетом схемы (Schema-Aware Routing)

Рецепт `recipes/schema-aware-routing/index.ts` реализует один из самых сложных паттернов в системе — распределение данных по доменным таблицам на основе анализа содержимого.

### 3.1. Многотабличные транзакции (Multi-Table Writes)
Вместо того чтобы хранить всё в одной таблице, этот паттерн распределяет информацию:
- **thoughts**: Хранит исходный текст и вектор.
- **people**: Если в тексте найден человек, система инициирует процесс разрешения сущностей.
- **interactions**: Создается запись о взаимодействии, связывающая человека с текущим контекстом мысли.
- **action_items**: Задачи выделяются в отдельный список с привязкой к домену (work, personal, health).

### 3.2. Алгоритм разрешения имен (Fuzzy Name Matching)
Одной из самых сложных задач является разрешение имен ("Rob" ↔ "Robert"). Система реализует трехэтапную стратегию:
1. **Точное совпадение**: По имени или списку алиасов в таблице `people`.
2. **Нечеткое сопоставление (Fuzzy)**: Используется функция `namesAreSimilar`, которая анализирует вхождения первых имен и их длину (минимум 3 символа). Если найдено потенциальное совпадение, запись получает статус `pending` (ожидает подтверждения пользователем).
3. **Обнаружение коллизий**: Система проверяет, не является ли "Иван" из новой записи другим человеком, нежели "Иван" из базы, путем анализа фамилий и контекстных тегов.

## 4. Глубокая интеграция с JSONB и GIN-индексами

Для обеспечения гибкости и скорости работы все извлеченные данные хранятся в PostgreSQL в типе `jsonb`.

### 4.1. Техническая оптимизация запросов
Чтобы поиск по сложным структурам метаданных был мгновенным, OB1 использует:
- **Оператор `@>` (содержит)**: Позволяет выполнять запросы типа "Найди все мысли, где в массиве тем есть 'AI'".
- **GIN-индексы**: Инвертированный индекс на столбце метаданных позволяет Postgres находить вхождения за логарифмическое время, превращая неструктурированный JSON в полноценную индексированную базу данных.

### 4.2. Доменная фильтрация (Domain Routing)
Маршрутизатор автоматически присваивает каждой мысли `domain` (work, family, health, finance). Это позволяет ИИ-агентам выполнять "контекстную изоляцию": при работе над рабочим проектом агент может автоматически отфильтровывать все данные из домена `family`, предотвращая смешивание контекстов и повышая точность генерации.

## Заключение
Техническая реализация захвата в OB1 — это полноценный ETL-процесс в миниатюре. Благодаря **автоматическому извлечению**, **строгой дедупликации через фингерпринтинг** и **умной маршрутизации сущностей**, система превращает хаотичный поток сообщений в высокоорганизованную реляционную базу знаний, готовую к использованию любым интеллектуальным агентом.
