# Глубокий технический анализ 2: Графовые структуры и рекурсивный обход (Recursive CTE, MCP и когнитивные связи)

## 1. Рекурсивный обход графа (SQL Recursive CTE) в реляционной среде

Одной из наиболее технически совершенных частей системы OB1 является реализация полноценной графовой логики непосредственно внутри реляционной базы данных PostgreSQL (рецепт `ob-graph`). Вместо использования специализированных графовых баз данных (таких как Neo4j), разработчики выбрали путь расширения возможностей стандартного SQL через рекурсивные обобщенные табличные выражения (Common Table Expressions, CTE).

### 1.1. Техническая реализация функции `traverse_graph`
Функция обхода графа позволяет ИИ-агентам находить связи между разрозненными фрагментами памяти на произвольной глубине. Это решает проблему "фрагментарности" знаний в RAG-системах.

Структура рекурсивного запроса в OB1 построена по следующему принципу:
1. **Базовый узел (Non-recursive term)**: Выборка начальной точки обхода по переданному UUID.
2. **Рекурсивная итерация (Recursive term)**: Соединение (JOIN) текущих результатов с таблицей `graph_edges`, где идентификатор цели (`target_node_id`) из предыдущего шага становится идентификатором источника для следующего.
3. **Контроль глубины и циклов**: Использование счетчика уровней (`level`) и параметра `max_depth` (обычно 3-6) предотвращает бесконечные циклы в графе и ограничивает потребление ресурсов.

Такой подход позволяет агенту за один вызов получить не просто "похожие тексты", а всю топологию связей вокруг темы. Например: "Найти все задачи, связанные с проектом X через людей из команды Y".

### 1.2. Алгоритм поиска пути (`find_shortest_path`)
Реализованный на чистом SQL поиск кратчайшего пути использует алгоритм поиска в ширину (BFS). Система строит дерево путей и останавливается при первом достижении целевого узла. Это позволяет агенту обосновывать свои выводы, показывая цепочку рассуждений: "Я связал Мысль А с Событием Б, потому что они оба относятся к Сущности В".

## 2. Когнитивный граф на основе перекрытия метаданных

Помимо явного графа, построенного пользователем или агентом, OB1 реализует "неявный" когнитивный граф через функцию `get_thought_connections` (файл `schema.sql`).

### 2.1. Алгоритм детерминированных связей (Metadata Overlap)
В отличие от векторного поиска (который основан на математической вероятности близости смыслов), этот алгоритм работает на основе жестких фактов — совпадения извлеченных сущностей в метаданных `jsonb`.

Логика работы:
1. **Извлечение векторов сущностей**: Функция извлекает массивы `topics` (темы) и `people` (люди) из метаданных текущей мысли.
2. **Перекрестное сопоставление**: SQL-запрос выполняет поиск по всей таблице `thoughts`, используя операторы пересечения массивов.
3. **Ранжирование по "силе перекрытия" (Overlap Count)**: Связь считается тем сильнее, чем больше общих тегов или имен людей объединяют две записи.

Это создает "интуитивную" навигацию: когда агент работает с заметкой о конкретном человеке, система мгновенно подтягивает все остальные записи, связанные с этой личностью, независимо от их семантической близости.

## 3. MCP-интерфейс для графовых операций

OB1 предоставляет набор инструментов Модельного контекстного протокола (MCP), которые превращают ИИ-агента в активного архитектора базы знаний.

### 3.1. Инструменты автономного моделирования
Агенту доступны инструменты:
- `create_node`: Позволяет создавать узлы для людей, проектов, концепций и инструментов. Каждый узел может иметь произвольный набор свойств в формате JSONB.
- `create_edge`: Определение направленных связей с указанием типа (`depends_on`, `works_with`, `related_to`) и веса (доверия).
- `get_neighbors`: Инструмент, позволяющий агенту "осмотреться" вокруг текущего контекста, получая все входящие и исходящие ребра.

Благодаря этому, в процессе диалога агент может самостоятельно достраивать граф: "Я заметил, что этот проект зависит от технологии Y, я зафиксировал эту связь в вашем графе знаний".

## 4. Оптимизация производительности графа

Чтобы рекурсивные запросы работали мгновенно на больших объемах данных, OB1 использует:
- **B-Tree индексы** на столбцах `source_node_id` и `target_node_id`.
- **GIN-индексы** на столбце `properties` в таблице узлов, что позволяет искать сущности по произвольным ключам внутри JSON за логарифмическое время.
- **Интеграцию с `thought_id`**: Узлы графа могут ссылаться на исходные мысли в таблице `thoughts`, что позволяет мгновенно переходить от абстрактных концепций графа к первоисточникам данных.

## Заключение
Графовая архитектура OB1 переводит систему из разряда простого "архива мыслей" в категорию "структурированной базы знаний". Сочетание рекурсивного SQL (CTE) для обхода связей и MCP-инструментов для управления структурой дает ИИ-агентам возможность выстраивать сложные логические цепочки и находить глубокие фактологические зависимости, недоступные обычному поиску.
