# Глубокий технический анализ 3: Логика данных, обогащение схем и SQL-ранжирование (In-DB Logic)

## 1. Архитектура данных как компонент рассуждений

В системе OB1 база данных PostgreSQL — это не пассивное хранилище, а активный вычислительный узел. Одной из ключевых инноваций системы является перенос сложной логики ранжирования и фильтрации непосредственно в ядро базы данных (файл `schema.sql`). Это техническое решение ("Heavy lifting where the data lives") обеспечивает экстремально низкую задержку, необходимую для естественного взаимодействия с ИИ-агентами.

## 2. Обогащенная схема таблицы `thoughts`

Базовая модель хранения расширена набором специфических столбцов, которые превращают неструктурированный текст в "первоклассные" объекты знаний.

### 2.1. Вычисляемые и мета-столбцы
- **type**: Столбец для хранения типа мысли (`idea`, `task`, `person_note`, `reference`, `decision`, `lesson`, `meeting`, `journal`). Это позволяет агентам выполнять мгновенную фактологическую фильтрацию. Например, агент может запросить только "уроки" (lessons), извлеченные из прошлых проектов, полностью исключая из выборки текущие задачи или заметки о людях.
- **importance**: Значение `SMALLINT` (от 1 до 5). Служит множителем при расчете финального ранга релевантности.
- **quality_score**: Числовое значение (0-100), используемое для автоматической фильтрации "шума" (неполных фраз, случайных захватов).
- **source_type**: Отслеживает происхождение данных (Slack, Gmail, Obsidian). Это позволяет агенту оценивать контекстуальную достоверность информации.

## 3. Алгоритм гибридного ранжирования (Ranking Formula)

Центральным элементом поискового движка OB1 является функция `search_thoughts_text`. Она реализует сложную многофакторную модель ранжирования, которая компенсирует математическую "размытость" векторного поиска.

### 3.1. Математика ранга в SQL
Итоговый показатель релевантности (`rank`) каждой строки вычисляется как взвешенная сумма:
```sql
rank = (
    greatest(
        ts_rank_cd(to_tsvector('simple', content), query_ts), -- Полнотекстовый поиск
        CASE WHEN content ILIKE '%' || query || '%' THEN 0.35 ELSE 0 END -- Бонус за точное совпадение
    )
    + (coalesce(importance, 3) / 20.0)::real -- Вес важности (до 0.25)
    + (coalesce(quality_score, 50) / 500.0)::real -- Вес качества (до 0.2)
)::real
```

### 3.2. Техническое преимущество формулы
- **Компенсация векторных галлюцинаций**: Векторный поиск часто связывает слова по смыслу, но ошибается в именах собственных или кодах. Полнотекстовый поиск (`ts_rank_cd`) и бонус `ILIKE` гарантируют, что записи с точным совпадением искомого слова всегда будут выше "просто похожих".
- **Интеграция пользовательских предпочтений**: Добавление `importance` в формулу ранга позволяет системе "вспоминать" наиболее ценные мысли в первую очередь, создавая эффект избирательной памяти.
- **Производительность**: Использование словаря `'simple'` в полнотекстовом поиске отключает стемминг (обрезание окончаний), что критически важно для поиска имен и технических терминов без искажений.

## 4. Глобальные функции статистики и агрегации

Функция `brain_stats_aggregate` реализует сложную аналитику памяти пользователя на уровне SQL.

### 4.1. Агрегация метаданных JSONB
Система выполняет мгновенный анализ тысяч записей для формирования отчета:
- **Топ тем и людей**: Извлекается через `jsonb_array_elements_text`, что позволяет работать с массивами внутри JSON так же эффективно, как с обычными таблицами.
- **Динамика накопления**: Анализ количества новых мыслей по временным интервалам.
- **Изоляция restricted-данных**: Параметр `p_exclude_restricted` автоматически исключает из статистики мысли с высоким уровнем чувствительности, обеспечивая безопасность аналитики.

## 5. Оптимизация через GIN-индексы

Для обеспечения скорости работы на больших объемах данных OB1 использует "обобщенные инвертированные индексы" (GIN):
- **На контенте**: Индекс по `to_tsvector('simple', content)` ускоряет полнотекстовый поиск в сотни раз.
- **На метаданных**: Индекс по столбцу `metadata` (JSONB) позволяет использовать оператор вхождения `@>`. Благодаря этому поиск мыслей, помеченных определенным тегом, происходит по индексу, а не полным сканированием таблицы.

## Заключение
Техническая реализация логики данных в OB1 демонстрирует виртуозное использование возможностей PostgreSQL. Перенос ранжирования, сложной фильтрации и агрегации метаданных непосредственно в базу данных делает систему одной из самых быстрых в своем классе. Это позволяет ИИ-агентам мгновенно получать доступ к структурированной и приоритизированной памяти пользователя, обеспечивая фундамент для глубоких рассуждений.
