# Технический анализ: Обогащение данных и вычисляемые столбцы

## 1. Введение
Система OB1 (Open Brain) не просто сохраняет текст, а превращает его в высокоструктурированную базу знаний. Для поддержки сложных агентных рабочих процессов стандартная реляционная модель расширяется набором специфических столбцов, которые называются "вычисляемыми и обогащенными". Данный документ подробно анализирует назначение и техническую роль полей `type`, `importance`, `quality_score` и `source_type`.

## 2. Поле `type`: Семантическая типизация знаний
В файле `schemas/enhanced-thoughts/schema.sql` определяется столбец `type`. Он служит для первичной классификации каждой "мысли".

### 2.1. Канонические типы
Система использует фиксированный набор строк для классификации:
- **idea**: Сырые инсайты и творческие мысли.
- **task**: Действия, требующие выполнения.
- **person_note**: Информация о конкретном человеке.
- **reference**: Ссылочные данные, документация.
- **decision**: Принятые решения (критически важно для долгосрочного контекста проектов).
- **lesson**: Извлеченный опыт (Lessons Learned).

### 2.2. Роль в работе агента
Наличие типизации позволяет ИИ-агенту выполнять "фактологическую" фильтрацию перед семантической. Вместо того чтобы искать "решения по дизайну" векторным поиском (который может вернуть просто обсуждения), агент вызывает:
`SELECT * FROM thoughts WHERE type = 'decision' AND ...`.
Это значительно повышает точность ответов и снижает количество "галлюцинаций" ИИ.

## 3. Поле `importance`: Управление приоритетами памяти
Столбец `importance` имеет тип `SMALLINT` и принимает значения от 1 до 5.

### 3.1. Техническая реализация ранжирования
Это поле интегрировано непосредственно в SQL-формулу ранжирования поиска (функция `search_thoughts_text`). Важность не просто помечает запись, она "подталкивает" её вверх в результатах поиска.
Математически это выражается как `+ (importance / 20.0)`. Таким образом, важные мысли получают бонус к релевантности, позволяя пользователю или агенту гарантировать, что критическая информация не затеряется в "хвосте" векторной выдачи.

## 4. Поле `quality_score`: Автоматическая фильтрация шума
Числовое значение `quality_score` (от 0 до 100) служит индикатором информативности записи.

### 4.1. Механизм фильтрации
Система использует этот показатель для защиты памяти от "засорения".
- Короткие фразы типа "ок", "принято", технические логи захвата получают низкий балл.
- Развернутые, структурированные записи получают высокий балл.
В поисковой выдаче записи с низким качеством получают штраф к рангу (`+ (quality_score / 500.0)`), что позволяет автоматически скрывать артефакты захвата от взора ИИ-агента, сохраняя чистоту контекста.

## 5. Поле `source_type`: Контекст происхождения
Столбец `source_type` отслеживает, откуда поступила информация (Slack, Gmail, Obsidian, CLI).

### 5.1. Доверие и надежность
Для ИИ-агента знание источника является критическим метаданным.
- Информация из "Официальной почты" может иметь больший вес достоверности, чем "Случайная заметка в Slack".
- Это позволяет реализовывать логику типа: "Найди мне все упоминания этого проекта, но только из моих рабочих диалогов".

## 6. Механизм обратной заливки (Backfill)
В SQL-схеме предусмотрена логика автоматического наполнения этих столбцов из существующего `jsonb` метаданных:
```sql
UPDATE thoughts SET type = metadata->>'type'
WHERE type IS NULL AND metadata->>'type' IS NOT NULL;
```
Это гарантирует, что даже если логика классификации изменится, система сможет синхронизировать типизацию во всей базе данных без ручного вмешательства.

## 7. Заключение
Расширение базовой таблицы "вычисляемыми" столбцами превращает OB1 из простого хранилища в активную базу знаний. Поля **type**, **importance**, **quality_score** и **source_type** создают многомерную систему координат, которая позволяет ИИ-агентам выполнять сверхточную навигацию по памяти пользователя, отделяя ценные инсайты от повседневного информационного шума.
