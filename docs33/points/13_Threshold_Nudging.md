# Технический анализ: Алгоритм адаптивного подталкивания (Threshold Nudging)

## 1. Введение
Одной из самых уникальных функций OB1 (Open Brain) является способность системы самообучаться стандартам классификации пользователя. Это реализуется через алгоритм "адаптивного подталкивания" (Threshold Nudging), который динамически корректирует пороги автоматического принятия решений. Данный документ анализирует техническую реализацию этого цикла обратной связи.

## 2. Математическая модель подталкивания
Алгоритм работает на основе коррекции значения `threshold` для каждого типа данных в ответ на действия пользователя. Реализация находится в функции `adjustThreshold` (файл `capture-with-gating.ts`).

### 2.1. Константы алгоритма
- `THRESHOLD_NUDGE = 0.02`: Шаг изменения порога. Это "атомарная единица" обучения.
- `THRESHOLD_MIN = 0.50`: Нижний предел. Система никогда не должна стать слишком "беспечной".
- `THRESHOLD_MAX = 0.95`: Верхний предел. Система не должна стать параноидально осторожной.

## 3. Сценарии адаптации
Порог изменяется в зависимости от того, согласился ли пользователь с решением ИИ или исправил его.

### 3.1. Сценарий "Успех" (Positive Feedback)
Если пользователь подтверждает автоматическую классификацию (или если авто-захват прошел без возражений):
- **Логика**: `newVal = currentThreshold - THRESHOLD_NUDGE`.
- **Эффект**: Порог немного **снижается**. Система "чувствует", что её текущий стандарт точности соответствует ожиданиям пользователя. Это делает её более автономной для данного типа данных в будущем.

### 3.2. Сценарий "Ошибка/Коррекция" (Negative Feedback)
Если пользователь отклоняет предложенную классификацию или вносит исправление (например, меняет "заметку" на "задачу"):
- **Логика**: `newVal = currentThreshold + THRESHOLD_NUDGE`.
- **Эффект**: Порог **повышается**. Система "понимает", что она была слишком самоуверенной. В следующий раз, при аналогичном уровне внутренней уверенности модели, система сработает как шлюз и запросит подтверждение, а не будет действовать автоматически.

## 4. Техническая реализация в БД
Изменения фиксируются в таблице `capture_thresholds` с использованием операции `UPSERT`.
```typescript
await db.from("capture_thresholds").upsert({
  item_type: itemType,
  threshold: newVal,
  sample_count: (thresholdRow?.sample_count ?? 0) + 1,
  updated_at: new Date().toISOString(),
}, { onConflict: "item_type" });
```
Столбец `sample_count` позволяет отслеживать количество итераций обучения, что в будущем может быть использовано для уменьшения шага `NUDGE` по мере накопления статистики (затухание обучения).

## 5. Преимущества для персонализации
Традиционные ИИ-системы имеют жестко заданные параметры точности. Алгоритм Nudging в OB1 дает следующие преимущества:
- **Индивидуальные стандарты**: Один пользователь может быть строг к определению "задач", другой — нет. Система подстроится под каждого.
- **Дрейф концепций**: Если со временем понимание пользователем того, что является "идеей", изменится, система плавно мигрирует за ним, не требуя перепрограммирования.
- **Минимизация прерываний**: Со временем количество запросов на подтверждение снижается до оптимального минимума, при котором ошибки классификации все еще редки.

## 6. Заключение
Алгоритм Threshold Nudging превращает OB1 из статичного инструмента в обучающийся организм. Техническая простота реализации (инкрементальное изменение одного числа в БД) скрывает под собой мощный механизм формирования персонального ИИ-опыта. Это делает Open Brain по-настоящему адаптивной системой, способной "чувствовать" стандарты качества своего владельца.
