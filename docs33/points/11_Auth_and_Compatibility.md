# Технический анализ: Безопасность и межклиентская совместимость (Auth, CORS, Patches)

## 1. Введение
Система OB1 (Open Brain) спроектирована как открытая платформа, к которой могут подключаться десятки различных ИИ-клиентов: от локальных редакторов кода (Cursor) до облачных чат-ботов (ChatGPT). Такая архитектура требует гибкого подхода к безопасности и совместимости. Данный документ анализирует техническую реализацию аутентификации, управления CORS и специфических паттернов для исправления ошибок сторонних клиентов.

## 2. Аутентификация: Многоканальный подход
В основе доступа к MCP-серверу лежит секретный ключ `MCP_ACCESS_KEY`. Техническая реализация в `server/index.ts` учитывает ограничения различных протоколов передачи данных.

### 2.1. Заголовки против параметров URL
Система поддерживает два способа авторизации:
- **Заголовок `x-brain-key`**: Основной метод для десктопных приложений. Обеспечивает чистоту URL и не оставляет следов в истории браузера.
- **Параметр запроса `key`**: Метод для клиентов, которые не позволяют настраивать HTTP-заголовки (например, некоторые интеграции на базе iframe или специфические мобильные обертки).

Этот "двойной путь" гарантирует, что любой клиент, обладающий ключом, сможет подключиться к "мозгу" без необходимости переписывать код сервера под каждый новый инструмент.

## 3. Управление CORS (Cross-Origin Resource Sharing)
Поскольку MCP-сервер часто разворачивается на доменах типа `supabase.co` или `deno.dev`, а клиент (например, дашборд пользователя) может находиться на другом домене, реализация полноценной политики CORS является критической необходимостью.

### 3.1. Реализация в Hono
В коде сервера определен объект `corsHeaders`, который включает:
- `Access-Control-Allow-Origin: *`: Разрешает запросы с любых доменов (безопасность обеспечивается проверкой ключа `x-brain-key`).
- `Access-Control-Allow-Methods`: GET, POST, OPTIONS, DELETE — полный набор для управления ресурсами.
- `Access-Control-Allow-Headers`: Включает специфические для MCP заголовки, такие как `mcp-session-id` и `mcp-protocol-version`.

Обработка метода `OPTIONS` возвращает пустой ответ с кодом 200 и набором этих заголовков, что позволяет браузерам выполнять последующие "настоящие" запросы.

## 4. Патч для Claude Desktop: Инженерная устойчивость
Одним из самых изящных технических решений в `server/index.ts` является автоматическое исправление входящих запросов от официального клиента Claude Desktop.

### 4.1. Проблема заголовка `Accept`
Транспорт `StreamableHTTPTransport` ожидает, что клиент запросит поток событий через заголовок `Accept: text/event-stream`. Однако было обнаружено, что некоторые версии Claude Desktop не отправляют этот заголовок, что приводит к обрыву соединения или ошибке парсинга на стороне сервера.

### 4.2. Механизм "на лету"
Система проверяет каждый входящий запрос:
```typescript
if (!c.req.header("accept")?.includes("text/event-stream")) {
  const headers = new Headers(c.req.raw.headers);
  headers.set("Accept", "application/json, text/event-stream");
  const patched = new Request(c.req.raw.url, {
    method: c.req.raw.method,
    headers,
    body: c.req.raw.body,
    duplex: "half",
  });
  // Подмена оригинального запроса на пропатченный перед передачей в транспорт
}
```
Это решение устраняет необходимость для пользователя вручную настраивать сложные прокси или ждать обновлений от разработчиков антропных моделей. Система сама адаптируется под несовершенство внешних инструментов.

## 5. Преимущества архитектуры совместимости
- **Универсальность**: Один сервер обслуживает и локальные, и облачные ИИ.
- **Отказоустойчивость**: Система продолжает работать даже при некорректном поведении клиентского ПО.
- **Безопасность**: Несмотря на гибкость подключения, проверка ключа остается жестким барьером для неавторизованного доступа.

## 6. Заключение
Реализация безопасности и совместимости в OB1 — это образец адаптивного программирования. Использование **многоканальной аутентификации**, **прозрачных политик CORS** и **умных патчей для запросов** делает систему максимально дружелюбной к разработчикам и пользователям, превращая Open Brain в действительно универсальный узел связи для любых интеллектуальных агентов.
