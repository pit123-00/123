# Технический анализ: Метаданные и производительность JSONB

## 1. Введение
В системе OB1 (Open Brain) данные — это не просто текст, а богатая структура. Ключевым компонентом хранения этой структуры является столбец `metadata` типа `jsonb` в PostgreSQL. Данный документ анализирует технический процесс извлечения метаданных с помощью LLM, способы выполнения запросов и методы оптимизации производительности с использованием GIN-индексов.

## 2. Извлечение: Автоматическое структурирование знаний
В файле `server/index.ts` и различных функциях захвата (Slack Ingest) реализована логика "Zero-Effort Metadata". Пользователь просто пишет мысль, а система сама её структурирует.

### 2.1. Конвейер LLM-извлечения
При захвате мысли инициируется вызов LLM (обычно `gpt-4o-mini`).
- **Схема извлечения**: Система просит модель вернуть JSON с полями: `people` (массив имен), `action_items` (список задач), `topics` (темы) и `type` (категория).
- **Режим JSON**: Использование `response_format: { type: "json_object" }` гарантирует, что ответ будет машиночитаемым и не потребует сложного парсинга текста.
- **Отказоустойчивость**: Если LLM возвращает некорректный формат, система применяет "дефолтную" структуру: `{ topics: ["uncategorized"], type: "observation" }`. Это предотвращает сбои при захвате данных.

## 3. Запросы: Рассуждение над JSONB
Использование типа `jsonb` в PostgreSQL позволяет системе сочетать гибкость NoSQL и мощь реляционных связей.

### 3.1. Оператор вхождения (`@>`)
Инструмент `list_thoughts` (в MCP-сервере) активно использует оператор `@>`. Это позволяет выполнять высокоэффективную фильтрацию.
Пример логики фильтрации по теме:
```typescript
if (topic) q = q.contains("metadata", { topics: [topic] });
```
Этот код транслируется в SQL: `WHERE metadata @> '{"topics": ["название_темы"]}'`.
Преимущество такого подхода в том, что система может искать вхождение элемента в массив внутри JSON без написания сложных подзапросов или разворачивания (unnest) данных.

## 4. Производительность: GIN-индексы
Для того чтобы поиск по JSON-метаданным не замедлялся при росте базы до сотен тысяч записей, OB1 использует "обобщенные инвертированные индексы" (Generalized Inverted Index).

### 4.1. Техническая роль GIN
Индекс GIN (создаваемый командой `CREATE INDEX ... USING GIN (metadata)`) строит внутреннюю карту всех ключей и значений, присутствующих в столбце JSONB.
- **Скорость**: Поиск по тегу или имени человека происходит не через сканирование всей таблицы, а через прямое обращение к индексу. Время ответа составляет миллисекунды.
- **Гибкость**: В отличие от обычных индексов B-tree, которые требуют индексации конкретного поля (`metadata->>'type'`), GIN-индекс на всем столбце позволяет искать по любому ключу, который LLM решит добавить в будущем (например, `dates_mentioned` или `project_slug`), без изменения схемы БД.

## 5. Агрегация и статистика
Функция `thought_stats` использует возможности PostgreSQL по разворачиванию JSON-массивов (`jsonb_array_elements_text`).
- Система может мгновенно подсчитать: какие темы встречаются чаще всего, с какими людьми пользователь контактирует больше всего.
- Весь этот "тяжелый" расчет происходит внутри базы данных, возвращая на сервер MCP уже готовую сводную таблицу, что минимизирует объем передаваемых данных.

## 6. Заключение
Техническая реализация работы с метаданными в OB1 — это баланс между гибкостью искусственного интеллекта и строгостью базы данных. Использование **LLM-экстракции** снимает когнитивную нагрузку с пользователя, **тип JSONB** обеспечивает расширяемость схемы, а **индексы GIN** гарантируют промышленную скорость поиска. Это делает Open Brain надежным фундаментом для ИИ-агентов, способных ориентироваться в тысячах разрозненных заметок так же легко, как в структурированной таблице.
