# Технический анализ: Инфраструктура развертывания (Docker и Kubernetes)

## 1. Введение
Система OB1 (Open Brain) спроектирована с учетом гибкости развертывания. Хотя канонический путь предполагает использование Supabase Cloud, проект предоставляет полноценные инструменты для самохостинга. Это критически важно для пользователей, которым требуется 100% контроль над своими данными и инфраструктурой. Данный документ анализирует техническую реализацию Docker-образов и Kubernetes-манифестов.

## 2. Docker-архитектура: Портативность "мозга"
В модуле `integrations/kubernetes-deployment/` содержится `Dockerfile`, который служит основой для контейнеризации сервера Open Brain.

### 2.1. Технические особенности образа
1. **Базовый образ**: Используется официальный легковесный образ `denoland/deno`. Это гарантирует минимальный размер контейнера и отсутствие лишних зависимостей, повышая безопасность системы.
2. **Среда выполнения**: Контейнер упаковывает не только код сервера, но и все зависимости, описанные в `deno.json`. Это предотвращает проблему "зависимостей на хосте" и гарантирует идентичность работы локально и в облаке.
3. **Локальный MCP**: Docker-контейнер может быть запущен локально на машине пользователя. Это позволяет ИИ-инструментам (Cursor, Claude Desktop) обращаться к MCP-серверу как к изолированному процессу, не требуя установки Deno в основную операционную систему.

## 3. Kubernetes (K8s): Промышленное развертывание
Папка `k8s/` содержит набор манифестов для развертывания Open Brain в кластере. Это решение ориентировано на пользователей, строящих свои собственные "домашние облака" или корпоративные решения.

### 3.1. Развертывание (Deployment)
Файл `openbrain.yml` описывает жизненный цикл приложения:
- **ReplicaSet**: Определяет количество работающих копий сервера для обеспечения отказоустойчивости.
- **Health Checks**: Конфигурирует пробы готовности (readiness) и живучести (liveness), позволяя Kubernetes автоматически перезапускать сервер при сбоях.
- **Resources**: Устанавливает лимиты потребления CPU и памяти, предотвращая "утечки" и обеспечивая стабильность всего кластера.

### 3.2. Безопасность (Secrets)
Файл `secrets.yml.example` предоставляет шаблон для использования нативных секретов Kubernetes.
- Вместо хранения ключей API (OpenRouter, Supabase) в открытом виде в конфигурациях, они передаются в контейнер через переменные окружения, зашифрованные на уровне кластера.
- Это соответствует лучшим практикам DevSecOps и предотвращает случайную утечку конфиденциальных данных.

## 4. Standalone PostgreSQL + pgvector
Наиболее значимой технической деталью самохостинга является файл `init.sql`. Он позволяет развернуть **собственный** экземпляр базы данных PostgreSQL без привязки к Supabase.

### 4.1. Автономный семантический поиск
Скрипт инициализации выполняет:
1. **Установку расширения `vector`**: Подключает `pgvector` к локальной БД.
2. **Создание схемы**: Реализует структуру таблицы `thoughts` с поддержкой векторного столбца.
3. **Реализацию RPC**: Переносит логику функции `match_thoughts` на чистый PL/pgSQL.

Это означает, что вся математика косинусного сходства векторов выполняется локально на сервере пользователя. Это исключает зависимость от проприетарных облачных функций и обеспечивает максимальную скорость доступа к данным.

## 5. Преимущества инфраструктурного суверенитета
Использование Docker и K8s в OB1 дает пользователю:
- **Независимость от вендора (Vendor Lock-in)**: Вы можете в любой момент мигрировать с Supabase на свой сервер или VPS.
- **Приватность**: Все данные, эмбеддинги и логика поиска остаются внутри вашего защищенного периметра.
- **Масштабируемость**: Возможность легкого расширения ресурсов при росте объема накопленных мыслей до миллионов записей.

## 6. Заключение
Инфраструктурная обвязка OB1 демонстрирует профессиональный подход к архитектуре ПО. Предоставление Docker-образов, K8s-манифестов и автономных SQL-скриптов делает Open Brain универсальной платформой, способной работать в любой среде — от домашнего ноутбука до распределенного серверного кластера, сохраняя при этом высочайшие стандарты производительности и приватности.
