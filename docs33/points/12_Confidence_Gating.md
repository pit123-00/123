# Технический анализ: Механизм шлюзования по уверенности (Confidence Gating)

## 1. Введение
В системе OB1 (Open Brain) захват данных — это процесс, требующий высокого уровня точности. Если ИИ-агент ошибочно классифицирует мысль (например, пометит творческую идею как задачу), это может привести к сбоям в рабочих процессах. Для решения этой проблемы реализован механизм шлюзования по уверенности (Confidence Gating). Данный документ анализирует техническую реализацию этого механизма в рецепте `adaptive-capture-classification`.

## 2. Архитектура механизма уверенности
Шлюзование происходит на этапе классификации мысли и основано на математической оценке собственного "мнения" языковой моделью.

### 2.1. Оценка уверенности (LLM Confidence)
При вызове LLM для классификации мысли (файл `capture-with-gating.ts`), система просит модель вернуть не только тип, но и целое число `confidence` в диапазоне от 0 до 10.
- **0-3**: Низкая уверенность, модель "гадает".
- **4-7**: Средняя уверенность, есть сомнения.
- **8-10**: Высокая уверенность, модель готова нести ответственность за решение.

### 2.2. Порог автоматического принятия (Threshold)
Система считывает текущий порог для данного типа мысли из таблицы `capture_thresholds`. По умолчанию он может составлять 0.75 (что соответствует 7.5 баллам уверенности).

## 3. Логика шлюзования (Gating Logic)
После получения оценки уверенности, система выполняет сравнение:

### 3.1. Сценарий 1: Автоматическое принятие (Confidence >= Threshold)
Если оценка модели выше или равна порогу:
- Мысль считается классифицированной верно.
- Она немедленно записывается в таблицу `thoughts`.
- Пользователь получает уведомление об успешном захвате без дополнительных вопросов.

### 3.2. Сценарий 2: Ручной шлюз (Confidence < Threshold)
Если оценка модели ниже порога:
- Процесс записи приостанавливается.
- Система создает запись в таблице `classification_outcomes` со статусом `auto_classified: false`.
- ИИ-агент обращается к пользователю: "Я думаю, это 'задача', но не совсем уверен. Правильно?".
- Запись попадет в основную базу только после явного подтверждения или исправления пользователем.

## 4. Повышение надежности: Двойной консенсус
Для ситуаций, когда уверенность находится в пограничной зоне (чуть ниже порога), система может инициировать "повторный запуск":
- Выполняется еще один вызов классификации (возможно, другой моделью).
- Если две модели расходятся во мнении по поводу типа мысли, итоговый балл уверенности штрафуется (умножается на `CONSISTENCY_FACTOR`, например, 0.6).
- Это технически гарантирует, что любое противоречие в интерпретации ИИ приведет к срабатыванию ручного шлюза, защищая базу знаний от мусора.

## 5. Преимущества для пользователя
- **Чистота данных**: В "мозг" попадают только верно классифицированные объекты.
- **Снижение контроля**: Пользователю не нужно проверять всё подряд, а только те 5-10% случаев, где ИИ сомневается.
- **Доверие**: Прозрачность сомнений ИИ повышает уровень доверия пользователя к системе.

## 6. Заключение
Механизм шлюзования по уверенности в OB1 — это критически важный фильтр качества. Техническая реализация **количественной оценки уверенности**, **динамических порогов** и **механизма двойного консенсуса** превращает процесс захвата данных из лотереи в надежный промышленный конвейер знаний, где участие человека требуется только в действительно сложных и неоднозначных случаях.
