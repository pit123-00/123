# Технический анализ: Перенос логики в базу данных (In-Database Computing)

## 1. Введение
В архитектуре большинства веб-приложений база данных рассматривается как пассивное хранилище ("dumb storage"), а вся логика обработки данных находится в приложении. Система OB1 (Open Brain) реализует противоположный подход: перенос критически важных вычислений (ранжирование, фильтрация, агрегация) непосредственно в ядро PostgreSQL. Данный документ анализирует техническую реализацию и преимущества стратегии "In-Database Logic".

## 2. SQL-функции как ядро интеллекта
Ключевые операции системы реализованы на языке PL/pgSQL в виде хранимых процедур (RPC). Это позволяет ИИ-агентам вызывать сложные аналитические цепочки одной командой.

### 2.1. Ранжирование и поиск (`search_thoughts_text`)
Вместо того чтобы извлекать тысячи записей и сортировать их на сервере Deno, система выполняет расчет релевантности внутри SQL.
- **Техническая деталь**: База данных комбинирует веса полнотекстового поиска, векторного сходства и метаданных JSONB за один проход планировщика запросов.
- **Эффект**: Приложение получает только финальный результат (обычно 10-25 самых релевантных строк), что снижает сетевую задержку и нагрузку на память сервера в десятки раз.

### 2.2. Аналитическая агрегация (`brain_stats_aggregate`)
Статистика "мозга" (топ тем, активность по датам, упоминаемые люди) рассчитывается на уровне БД.
- **Техническая деталь**: Используются функции `jsonb_array_elements_text` для "разворачивания" массивов из метаданных и их последующей группировки.
- **Эффект**: Сложный анализ сотен мегабайт данных выполняется за миллисекунды, так как СУБД работает напрямую с файлами на диске и индексами, не тратя время на сериализацию данных в JSON для передачи по сети.

## 3. Использование индексов GIN и B-Tree
Эффективность логики внутри БД в OB1 опирается на глубокую индексацию.
1. **GIN (Generalized Inverted Index)**:
   - Применяется к столбцу метаданных (`jsonb`) и вектору полнотекстового поиска (`tsvector`).
   - Позволяет SQL-функциям выполнять операторы вхождения (`@>`) и текстового соответствия (`@@`) мгновенно.
2. **B-Tree**:
   - Используется для классических столбцов (`importance`, `created_at`).
   - Позволяет оптимизатору Postgres быстро отсекать нерелевантные временные диапазоны.

## 4. Архитектурные преимущества
Перенос "тяжелой работы" в место обитания данных дает OB1 следующие преимущества:

### 4.1. Снижение задержки (Latency)
Для ИИ-агента критически важна скорость ответа. Если поиск занимает более 500мс, диалог кажется неестественным. In-DB логика позволяет удерживать время поиска в пределах 50-100мс на объемах данных в сотни тысяч мыслей.

### 4.2. Целостность и атомарность
Все операции (например, `upsert_thought`) выполняются как атомарные транзакции. Это гарантирует, что данные никогда не окажутся в промежуточном, несогласованном состоянии, даже при одновременном обращении нескольких ИИ-агентов.

### 4.3. Упрощение кода приложения
Код сервера на TypeScript становится экстремально легким. Вместо сотен строк сложной логики обработки данных, он содержит простые вызовы RPC:
```typescript
const { data } = await supabase.rpc("match_thoughts", { ...params });
```
Это делает систему более надежной и легкой в поддержке.

## 5. Заключение
Стратегия In-Database Computing в OB1 превращает PostgreSQL из простого архива в "когнитивный сопроцессор". Сочетание **сложных SQL-функций**, **глубокой индексации** и **атомарных операций** обеспечивает производительность и точность, недостижимые при использовании традиционных архитектур с выносом логики в приложение. Это делает Open Brain идеальным фундаментом для построения быстрых и интеллектуальных персональных ИИ.
