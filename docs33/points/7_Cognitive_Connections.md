# Технический анализ: Неявный когнитивный граф (get_thought_connections)

## 1. Введение
В системе OB1 (Open Brain) связи между мыслями строятся не только через явные ссылки или векторное сходство. Инновационным техническим решением является функция `get_thought_connections`, реализованная на уровне базы данных PostgreSQL. Она создает "неявный когнитивный граф", соединяя фрагменты памяти на основе перекрытия извлеченных сущностей. Данный документ анализирует логику работы этого алгоритма и его преимущества.

## 2. Логика алгоритма перекрытия (Overlap Logic)
Функция `get_thought_connections` (файл `schema.sql`) находит мысли, которые имеют общие метаданные с исходной записью. Это "детерминированный" подход к связности, дополняющий "вероятностный" подход векторного поиска.

### 2.1. Шаг 1: Извлечение векторов сущностей
При вызове для конкретной мысли (`p_thought_id`) функция сначала считывает её метаданные. Она извлекает два ключевых массива:
- `topics`: Темы, выделенные LLM.
- `people`: Имена людей, упомянутых в тексте.

Если у мысли нет ни тегов, ни упомянутых людей, функция завершается, так как "фактологических" зацепок для связи нет.

### 2.2. Шаг 2: Поиск кандидатов
SQL-запрос ищет в таблице `thoughts` все остальные записи, которые удовлетворяют хотя бы одному условию:
1. Хотя бы одна тема из новой записи совпадает с темой исходной.
2. Хотя бы один человек из новой записи совпадает с человеком из исходной.

Технически это реализовано через пересечение массивов PostgreSQL (оператор `&&` или использование подзапросов с `ANY`).

### 2.3. Шаг 3: Ранжирование по "силе перекрытия"
Это самая важная часть алгоритма. Каждой найденной связи присваивается оценка `overlap_count`:
```sql
overlap_count = (число общих тем) + (число общих людей)
```
Затем результаты сортируются по `overlap_count DESC`. Мысли, которые имеют больше всего общих сущностей, считаются наиболее тесно связанными и выдаются первыми.

## 3. Преимущества перед векторным поиском
Векторный поиск (Similarity) хорошо находит "похожие по настроению" или "похожие по теме" тексты. Однако он часто проигрывает в точности:
- **Семантический разрыв**: Заметка о "маркетинговом плане" и заметка о "бюджете маркетинга" могут иметь низкое векторное сходство, но обе они критически связаны тегом `маркетинг`.
- **Фактологическая точность**: Когнитивный граф гарантирует, что все записи об "Иване Иванове" будут связаны, даже если в одной он "заключил сделку", а в другой "ушел в отпуск". Векторы могут разнести эти события далеко друг от друга.

## 4. Сценарии использования в ИИ-агентах
ИИ-агенты используют эту функцию для глубокого погружения в контекст:
1. **Обнаружение контекста**: Когда пользователь спрашивает о конкретном событии, агент может вызвать `get_thought_connections`, чтобы мгновенно увидеть всех участников и все смежные проекты.
2. **Предотвращение изоляции знаний**: Алгоритм позволяет находить связи между старыми и новыми проектами, которые ИИ-агент мог бы пропустить при обычном поиске.

## 5. Техническая оптимизация
Для обеспечения быстродействия функция:
- Работает напрямую с индексами GIN на столбце `metadata`.
- Использует параметр `p_limit` для ограничения выборки (обычно 20 самых сильных связей).
- Автоматически исключает из поиска мысли с уровнем доступа `restricted`, обеспечивая конфиденциальность даже при автоматическом поиске связей.

## 6. Заключение
Реализация `get_thought_connections` превращает Open Brain из хранилища файлов в "граф знаний". Перенос логики расчета связей в SQL позволяет системе мгновенно восстанавливать сложные ассоциативные цепочки, предоставляя ИИ-агенту твердую почву из фактов и сущностей для генерации точных и контекстных ответов.
