# Технический анализ: Графовые структуры и рекурсивный обход (Recursive CTE)

## 1. Введение
Система OB1 (Open Brain) выходит за рамки простого текстового поиска, реализуя полноценный слой графа знаний непосредственно внутри реляционной базы данных PostgreSQL. Это позволяет ИИ-агентам выполнять глубокий контекстуальный анализ связей между людьми, проектами и идеями. Данный документ анализирует техническую реализацию рекурсивных запросов и инструментов MCP для управления графом.

## 2. Рекурсивный обход графа (SQL Recursive CTE)
Ключевой технологией рецепта `ob-graph` является использование рекурсивных обобщенных табличных выражений (Common Table Expressions). Это позволяет выполнять многошаговый обход связей без необходимости выгрузки всего графа в память приложения.

### 2.1. Техническая реализация функции `traverse_graph`
В SQL-коде системы реализована логика, которая позволяет агенту исследовать окружение любого узла на произвольную глубину.

Структура рекурсивного запроса:
1. **Базовый элемент (Anchor)**: Выборка исходного узла по его идентификатору.
2. **Рекурсивная итерация**: Выполнение `JOIN` текущего набора узлов с таблицей ребер (`graph_edges`). На каждом шаге идентификатор цели (`target_node_id`) становится новым источником для следующего уровня.
3. **Параметр `max_depth`**: Критически важная настройка, ограничивающая количество итераций (обычно 3-6). Это предотвращает бесконечные циклы в графе (если А связано с Б, а Б с А) и защищает базу данных от перегрузки.
4. **Фильтрация типов**: Запрос позволяет ограничить обход только определенными типами отношений (например, следовать только по связям "написал статью" или "является частью команды").

Результатом работы является структурированный JSON-массив, содержащий все достижимые узлы и пути к ним. Это дает ИИ-агенту понимание "логического ландшафта" вокруг обсуждаемой темы.

### 2.2. Поиск кратчайшего пути (`find_path`)
Система реализует алгоритм поиска в ширину (BFS) на чистом SQL. Это позволяет агенту мгновенно понять, как связаны две произвольные концепции. Например: "Как моя заметка о квантовой физике связана с проектом по маркетингу?". Система может выдать путь: `Заметка -> Человек X -> Встреча Y -> Проект`.

## 3. MCP для графов: Инструменты автономного моделирования
OB1 предоставляет ИИ-агентам набор инструментов через Модельный контекстный протокол (MCP). Это превращает базу данных в "живой" граф, которым агент может манипулировать в реальном времени.

### 3.1. Основные инструменты
- `create_node`: Добавление сущностей (люди, проекты, инструменты). Агент может самостоятельно создавать узлы в процессе разговора, если обнаруживает новые факты.
- `create_edge`: Определение направленных связей. Каждое ребро может иметь тип (`knows`, `depends_on`, `related_to`) и вес (степень уверенности или важности).
- `get_neighbors`: Позволяет агенту мгновенно "осмотреться" вокруг текущего контекста, получая список всех входящих и исходящих связей.

### 3.2. Динамическое построение знаний
Благодаря этим инструментам, ИИ-агент переходит из роли "читателя" в роль "архитектора знаний". Если пользователь говорит: "Я начал работать с Иваном над новым сайтом", агент может автоматически вызвать `create_node` для Ивана (если его нет) и `create_edge` со связью `works_on`. Это формирует структурированную память, которая будет доступна во всех будущих сессиях.

## 4. Оптимизация производительности
Для того чтобы рекурсивные SQL-запросы работали быстро на больших объемах данных, реализованы следующие оптимизации:
- **Индексы B-Tree**: Установлены на столбцы `source_node_id` и `target_node_id`, что делает поиск связанных ребер мгновенным.
- **GIN-индексы на метаданных**: Узлы графа часто содержат произвольные свойства в JSONB. GIN-индексы позволяют искать по этим свойствам (например, "найти все узлы типа 'человек' с навыком 'Python'") без сканирования всей таблицы.
- **Целостность (`ON DELETE CASCADE`)**: При удалении мысли из основной таблицы или узла из графа, все связанные с ними ребра удаляются автоматически на уровне БД, предотвращая появление "битых" ссылок.

## 5. Заключение
Графовая архитектура OB1 дополняет семантический (векторный) поиск слоем жестких логических связей. Использование рекурсивного SQL внутри Postgres в сочетании с MCP-инструментами дает агентам возможность выстраивать сложные цепочки рассуждений и находить глубокие фактологические зависимости в данных пользователя.
