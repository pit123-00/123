# Реализация HNSW и Индексации

Высокая производительность RuVector обеспечивается использованием алгоритма **HNSW** (Hierarchical Navigable Small World). В крейте `ruvector-core` (файл `hnsw.rs`) реализована высокоуровневая обертка над этим графовым индексом, которая обеспечивает баланс между скоростью поиска и возможностью динамического обновления данных.

## 1. Техническая реализация графа
Система использует иерархическую структуру слоев, где верхние слои обеспечивают быструю навигацию в пространстве, а нижние — точное позиционирование среди ближайших соседей.

### Ключевые параметры:
- **`m`**: Максимальное количество связей узла на каждом слое.
- **`ef_construction`**: Глубина исследования графа при вставке нового вектора.
- **`ef_search`**: Глубина поиска при выполнении запроса.

## 2. Реализация главных функций индексации

### 36. `HnswIndex::new(dimensions, metric, config) -> Result<Self>`
Конструктор индекса.
- **Логика**: Настраивает базовые параметры графа и выбирает функцию расстояния.
- **Особенности**: Поддерживает метрики Euclidean, Cosine, Manhattan и DotProduct, оптимизированные под архитектуру процессора.

### 37. `HnswIndex::add(id, vector) -> Result<()>`
Добавление нового элемента.
- **Логика**: Выполняет `insert_data` в базовый граф HNSW и параллельно обновляет `DashMap` (потокобезопасные хэш-таблицы) для маппинга внешних ID во внутренние индексы.
- **Преимущество**: Позволяет выполнять вставки конкурентно из нескольких потоков без блокировки всего индекса.

### 38. `HnswIndex::search_with_ef(query, k, ef_search) -> Result<Vec<SearchResult>>`
Основной метод поиска.
- **Логика**: Инициирует обход графа, начиная с верхнего слоя. Параметр `ef_search` позволяет динамически менять точность (Recall) и скорость поиска для каждого запроса.
- **Особенности**: Включает постобработку для преобразования внутренних идентификаторов узлов обратно в пользовательские ID.

### 39. `HnswIndex::serialize() -> Result<Vec<u8>>`
Полная сериализация состояния.
- **Логика**: Выгружает структуру графа, эмбеддинги и все таблицы соответствия ID в бинарный поток (Bincode).
- **Важность**: Позволяет мгновенно восстанавливать работу БД после перезагрузки, минуя этап повторного построения индекса, который может занимать часы на больших данных.

### 40. `HnswIndex::add_batch(entries) -> Result<()>`
Пакетная вставка векторов.
- **Логика**: Оптимизирует процесс вставки за счет предварительного выделения индексов и снижения накладных расходов на пересчет иерархии графа.
- **Результат**: Групповая вставка работает до 30 раз быстрее, чем последовательная.

## 3. Оптимизация на уровне железа
В коде реализованы специализированные функции расстояния (например, `DistanceFn`), которые прозрачно для пользователя используют SIMD-инструкции. Это позволяет системе RuVector выполнять миллионы сравнений векторов в секунду, что является фундаментом для работы GNN-слоев и сложных графовых алгоритмов поверх индекса.

Кроме того, использование `DashMap` для маппинга идентификаторов позволяет избежать "узкого горлышка" при записи, делая RuVector одной из самых быстрых систем в классе Rust-native векторных баз данных.
