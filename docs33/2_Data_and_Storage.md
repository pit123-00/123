# Технический отчет 2: Моделирование данных, хранение и семантический поиск в OB1

## 1. Введение
В основе OB1 (Open Brain) лежит надежный и специализированный слой данных. Система выходит за рамки простого хранения текста, реализуя гибридный подход, который сочетает в себе структурированные реляционные данные, метаданные JSON без жесткой схемы и высокоразмерные векторные эмбеддинги. В данном отчете анализируется техническая реализация слоя хранения, в частности таблица `thoughts` и логика уровня SQL, обеспечивающая семантический поиск.

## 2. Атомарная единица данных: Таблица `thoughts`
Базовая схема определена в `schemas/enhanced-thoughts/schema.sql`. Таблица `thoughts` спроектирована для обработки различных типов информации без необходимости в жесткой, постоянно меняющейся схеме.

### 2.1. Основные столбцы
- **id**: UUID (первичный ключ).
- **content**: Необработанный текст захваченной мысли.
- **embedding**: Столбец `vector(1536)` (предоставляется расширением `pgvector`).
- **metadata**: Столбец `jsonb` для гибких структурированных данных, извлеченных LLM.
- **created_at и updated_at**: Стандартные временные метки.

### 2.2. Расширенные атрибуты
Для поддержки сложных агентных рабочих процессов OB1 расширяет базовую таблицу столбцами "Вычисленными и обогащенными":
- **type**: Категоризирует мысль (например, `idea`, `task`, `person_note`).
- **importance**: `SMALLINT` (1-5), используемый для ранжирования.
- **quality_score**: Числовое значение, используемое для фильтрации "шума".
- **source_type**: Отслеживает источник данных (Slack, Gmail и т. д.).

## 3. Сила `pgvector` и семантический поиск
OB1 использует `pgvector` для выполнения поиска по векторному сходству непосредственно внутри базы данных. Это критически важное техническое решение, так как оно устраняет необходимость во внешней векторной базе данных (такой как Pinecone), снижая сложность архитектуры и сохраняя все данные в одном ACID-совместимом хранилище.

### 3.1. Интеграция векторов
Система обычно использует модель `text-embedding-3-small` от OpenAI, которая генерирует 1536 измерений. База данных вычисляет косинусное сходство (оператор `<=>` в pgvector) для поиска релевантных воспоминаний.

### 3.2. RPC `match_thoughts`
Специализированная хранимая процедура (RPC) выполняет основную работу по семантическому поиску. Она принимает `query_embedding`, `match_threshold` и `match_count`. Это позволяет ИИ-агенту вызывать одну функцию базы данных, которая возвращает наиболее релевантные результаты, отсортированные по сходству.

## 4. Логика гибридного поиска: Семантика + Полнотекстовый поиск (FTS)
Одной из самых впечатляющих технических реализаций в OB1 является функция `search_thoughts_text`. Она реализует стратегию "Гибридного поиска", которая компенсирует недостатки векторного поиска (который может испытывать трудности с конкретными ключевыми словами, кодами или аббревиатурами).

### 4.1. Фаза 1: FTS с GIN-индексом
Функция сначала использует нативный полнотекстовый поиск Postgres с `GIN`-индексом на `to_tsvector`. Это обеспечивает сверхбыстрое сопоставление ключевых слов с помощью `websearch_to_tsquery`, поддерживая логические операторы, такие как "кавычки" для точных фраз и знаки минуса для исключений.

### 4.2. Фаза 2: Резервный поиск ILIKE
Если FTS не возвращает достаточного количества результатов, система переходит к поиску `ILIKE`, нечувствительному к регистру. Это гарантирует захват даже частичных совпадений слов.

### 4.3. Комбинированное ранжирование
Результаты ранжируются с использованием кастомной формулы, которая объединяет:
1. `ts_rank_cd`: Показатель релевантности FTS.
2. `importance`: Весовой коэффициент на основе оценки важности.
3. `quality_score`: Небольшой бонус для записей высокого качества.

Этот многоуровневый подход гарантирует, что наиболее "значимые" и "релевантные" данные поднимаются в топ, независимо от того, искал ли пользователь по концепции (семантика) или по конкретному ключевому слову (FTS).

## 5. Метаданные и запросы JSONB
OB1 использует мощь Postgres `jsonb` для хранения и запроса извлеченных метаданных.
- **Извлечение**: При захвате мысли LLM извлекает `topics` (темы), `people` (людей) и `action_items` (действия).
- **Запросы**: Инструмент `list_thoughts` использует оператор `@>` (содержит jsonb) для фильтрации результатов по конкретным темам или людям, упомянуным в метаданных.
- **Производительность**: Для обеспечения производительности OB1 использует GIN-индексы для столбца метаданных.

## 6. Графоподобные связи
Функция `get_thought_connections` реализует облегченный "Когнитивный граф". Она идентифицирует связанные мысли не по векторному сходству, а по **перекрывающимся метаданным**.
- Она извлекает массивы тем и людей из исходной мысли.
- Находит другие мысли, имеющие те же массивы.
- Ранжирует их по "количеству перекрытий".

Это обеспечивает "детерминированную" связь между идеями (например, "все мысли о проекте X"), которая дополняет "вероятностные" связи, предоставляемые векторным поиском.

## 7. Целостность данных и дедупликация
Для предотвращения "раздувания памяти" OB1 реализует сложную стратегию дедупликации (примитив `content-fingerprint-dedup`).
- **Фингерпринтинг**: Генерируется хеш SHA-256 (отпечаток) контента.
- **Предварительная проверка**: Перед вставкой система проверяет наличие существующих отпечатков, чтобы предотвратить дублирование данных из разных источников.

## 8. Резюме
Слой данных OB1 — это мастер-класс по использованию расширенных возможностей PostgreSQL. Объединяя `pgvector` для смыслов, FTS для ключевых слов и JSONB для структуры, OB1 создает механизм хранения, который является одновременно невероятно гибким и математически точным. Система относится к "Памяти" как к первоклассному гражданину, гарантируя, что поиск будет быстрым, точным и глубоко контекстуальным.
