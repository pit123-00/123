# Технический отчет 2: Моделирование данных и гибридная система поиска

## 1. Введение: Данные как основа памяти
В системе OB1 данные не рассматриваются как пассивные записи. Каждая "Мысль" (Thought) — это сложный объект, обладающий семантическим смыслом, структурными метаданными и весами важности. Данный отчет анализирует техническую реализацию слоя хранения и поискового движка, который делает эту память по-настоящему полезной для ИИ.

## 2. Атомарная единица знаний: Таблица `thoughts`
Схема данных (файл `schema.sql`) спроектирована для максимальной гибкости и производительности. Основная таблица содержит:
- **content (TEXT)**: Текстовое тело мысли.
- **embedding (vector(1536))**: Векторное представление текста для семантического поиска.
- **metadata (jsonb)**: Контейнер для структурированных данных, извлеченных LLM (темы, люди, задачи).

## 3. Сила `pgvector`: Семантическая близость
OB1 использует расширение `pgvector` для работы с высокоразмерными векторами. Это позволяет выполнять математические операции сравнения смыслов прямо в SQL-запросе.
- **Техническая реализация**: Функция `match_thoughts` вычисляет косинусное сходство (оператор `<=>`) между вектором поискового запроса и векторами всех мыслей в базе.
- **Преимущество**: Агент находит релевантную информацию, даже если в запросе используются синонимы или другие речевые обороты, отличные от оригинала.

## 4. Инновация: Гибридный поиск (Hybrid Search)
Чисто векторный поиск часто страдает от "размытости" — он может выдать похожий по смыслу, но неверный по фактам результат. OB1 решает эту проблему через гибридную модель в функции `search_thoughts_text`.

### 4.1. Полнотекстовый поиск (FTS)
Система использует нативный движок Full-Text Search от PostgreSQL с GIN-индексами.
- **ts_rank_cd**: Функция вычисляет плотность ключевых слов в тексте. Это гарантирует, что точное совпадение специфического имени или термина (например, фамилии коллеги) всегда поднимет запись в топ выдачи.

### 4.2. Алгоритм гибридного ранжирования
Итоговый ранг записи в поиске — это сумма нескольких факторов:
1. **Ранг FTS**: Точность по ключевым словам.
2. **Бонус ILIKE**: Дополнительный вес за прямое вхождение строки (0.35).
3. **Вес важности**: Мысли, помеченные как приоритетные, получают бонус до 0.25.
4. **Вес качества**: Корректировка на основе информативности контента.

## 5. Метаданные JSONB: Структура внутри хаоса
Использование типа `jsonb` позволяет OB1 сохранять любые метаданные без изменения схемы БД.
- **Индексация GIN**: Все ключи и значения внутри JSON индексируются инвертированным индексом. Это позволяет выполнять запросы типа "Найди все мысли, где в массиве тегов есть 'AI' и упомянут 'Иван'" за миллисекунды.
- **Оператор `@>`**: Позволяет выполнять поиск по вхождению (containment), что идеально подходит для фильтрации по извлеченным LLM сущностям.

## 6. Когнитивный граф (Implicit Connections)
Функция `get_thought_connections` реализует логику поиска связей на основе перекрытия метаданных.
- **Алгоритм**: Система анализирует массивы `topics` и `people` в текущей записи и находит другие записи, имеющие максимальное количество общих элементов.
- **Результат**: Это создает "логическую сеть", позволяя агенту переходить от одной идеи к другой не по смысловой схожести, а по жестким фактологическим связям.

## 7. Дедупликация и фингерпринтинг
Для поддержания чистоты базы знаний система использует алгоритм SHA-256 для генерации "отпечатков" контента.
- **Механизм**: Перед записью новой мысли система проверяет наличие идентичного хеша в базе. Это предотвращает дублирование информации при импорте из разных источников (Slack, Gmail), экономя место и повышая точность поиска.

## 8. Итог
Слой данных OB1 — это симбиоз классических реляционных технологий и современных методов машинного обучения. Перенос логики ранжирования и поиска непосредственно в ядро PostgreSQL делает систему экстремально быстрой и точной. База данных перестает быть просто "хранилищем" и становится активным механизмом, который помогает ИИ-агенту "вспоминать" факты с высокой достоверностью.
