# Experience Replay и Reservoir Sampling

В системах непрерывного обучения (Continual Learning), таких как RuVector, одной из сложнейших задач является борьба с "катастрофическим забыванием". Механизм **Experience Replay**, реализованный в `crates/ruvector-gnn/src/replay.rs`, позволяет базе данных сохранять репрезентативную память о своем опыте и использовать её для стабилизации весов нейросетевых слоев.

## 1. Роль буфера опыта в RuVector
Система GNN в RuVector обучается онлайн: каждый новый запрос и клик пользователя — это обучающий пример. Однако данные во времени сильно коррелированы (пользователь может целый час искать только информацию о "Rust", а потом неделю — о "Кулинарии"). Replay Buffer позволяет "перемешивать" текущие ситуации с типичными ситуациями из прошлого.

### Ключевые функции механизма:
- **Усреднение градиента**: Снижение вероятности резкого увода весов модели в сторону последнего запроса.
- **Сохранение редких случаев**: Важные, но редкие паттерны поиска не вымываются из памяти.
- **Обнаружение аномалий**: Статистика буфера служит эталоном для выявления резких изменений в поведении пользователей.

## 2. Реализация главных функций буфера

### 16. `ReplayBuffer::add(query, positive_ids)`
Добавление нового опыта в систему.
- **Логика**: Сохраняет вектор запроса и список ID документов, которые были успешно найдены.
- **Техническая особенность**: Включает проверку соответствия размерности вектора (`dimension_mismatch_handling`).

### 17. `ReplayBuffer::sample(batch_size) -> Vec<&ReplayEntry>`
Формирование обучающего пакета из прошлого опыта.
- **Логика**: Использует `rand::seq::SliceRandom` для выбора случайных примеров.
- **Особенности**: Пакет из буфера обычно смешивается с текущим обучающим примером в пропорции, регулируемой параметром `online_config`.

### 18. `DistributionStats::update(sample: &[f32])`
Онлайн-вычисление статистических характеристик потока данных.
- **Логика**: Использует алгоритм Велфорда для вычисления среднего и дисперсии за один проход, без хранения всех векторов.
- **Важность**: Эти данные используются GNN для нормализации входных признаков (Z-score normalization).

### 19. `ReplayBuffer::detect_distribution_shift(recent_window) -> f32`
Функция самодиагностики системы.
- **Логика**: Сравнивает косинусное расстояние между средним вектором в буфере и средним вектором последних N запросов.
- **Действие**: Если сдвиг значителен, система сигнализирует о необходимости "глубокого" переобучения (SONA Deep Loop).

### 20. `ReplayBuffer::clear()`
Метод сброса когнитивного опыта.
- **Логика**: Очищает буфер и сбрасывает все счетчики.
- **Применение**: Используется при миграции базы данных в новый домен или после радикального изменения моделей эмбеддингов.

## 3. Алгоритм Reservoir Sampling
В основе `ReplayBuffer` лежит алгоритм **Reservoir Sampling**, который решает задачу выбора фиксированного числа элементов из потока неизвестной (или бесконечной) длины.

### Как это работает в коде:
1. Пока буфер не заполнен до `capacity`, каждый новый запрос просто добавляется в конец.
2. Когда буфер полон, каждый новый $i$-й запрос заменяет случайный существующий элемент в буфере с вероятностью $capacity/i$.

Это математически гарантирует, что на любом этапе работы системы каждый когда-либо сделанный запрос имеет равную вероятность находиться в буфере обучения. Таким образом, база знаний RuVector "помнит" общие принципы своей работы, заложенные месяцы назад, так же хорошо, как и события вчерашнего дня, если они статистически равнозначны.
