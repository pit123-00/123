# RvfStore: Инициализация и пакетная загрузка

Компонент **`RvfStore`** (крейт `rvf-runtime`, файл `store.rs`) реализует логику управления когнитивными контейнерами RVF. Его задача — обеспечить быструю "загрузку" базы данных в память и максимально эффективную запись новых векторов на диск.

## 1. Холодный запуск и Процедура Boot
RVF-файл является "самозагружающимся". Процесс инициализации напоминает монтирование файловой системы и гарантирует целостность знаний ИИ-агента.

### Жизненный цикл загрузки:
1. Поиск последнего `MANIFEST` в конце файла.
2. Восстановление иерархии сегментов и эпох.
3. Монтирование векторных данных и графов в активные структуры Rust.

---

## 2. Реализация ключевых функций жизненного цикла

### 46. `RvfStore::boot() -> Result<()>`
Инициализация хранилища из файла.
- **Логика**: Находит последний валидный манифест, считывает размерность векторов (`dimension`) и профиль. Затем последовательно читает все сегменты `VEC_SEG` и вставляет их в структуру `VectorData`.
- **Особенности**: Выполняет проверку чексумм для каждого сегмента, предотвращая загрузку битых данных.

### 47. `RvfStore::ingest_batch(vectors, ids, metadata) -> Result<IngestResult>`
Высокопроизводительная вставка данных.
- **Логика**: Валидирует размерности, группирует векторы в пакет, записывает их в новый сегмент `VEC_SEG` в конец файла и обновляет `self.vectors` в памяти.
- **Атомарность**: Операция завершается записью нового манифеста. До этого момента любые сбои записи не влияют на целостность базы.

### 48. `RvfStore::query_with_envelope(vector, k, options) -> Result<QualityEnvelope>`
Семантический поиск с гарантиями качества.
- **Логика**: Выполняет поиск по HNSW и возвращает результаты, упакованные в "конверт качества".
- **Особенности**: Конверт содержит доказательства качества (`SearchEvidence`), отчеты о деградации точности и использованные лимиты времени (budgets).

### 49. `RvfStore::compact() -> Result<CompactionResult>`
Сборка мусора и дефрагментация.
- **Логика**: Сканирует файл, удаляет сегменты `Journal` (пометки об удалении) и перезаписывает только актуальные векторы в новый непрерывный блок.
- **Совместимость**: Использует функцию `scan_preservable_segments` для сохранения неизвестных типов сегментов, обеспечивая долгосрочную стабильность данных.

### 50. `generate_file_id(path) -> [u8; 16]`
Генерация глобально уникального идентификатора файла.
- **Логика**: Хэширует путь и наносекундную метку времени через SHAKE-256.
- **Роль**: Необходим для корректной работы механизмов COW-ветвления и деривации (отслеживания "предков" базы данных).

## 3. Оптимизация дискового ввода-вывода
В реализации `ingest_batch` используется `BufWriter` объемом 256 КБ, что позволяет системе RuVector записывать тысячи векторов за один физический акт записи на диск. Это минимизирует износ SSD и накладные расходы на переключение контекста процессора. При этом вызов `sync_all` перед финализацией манифеста гарантирует, что данные физически достигли носителя, обеспечивая уровень надежности, сопоставимый с современными СУБД.

Использование `RvfStore` превращает работу с данными ИИ в надежный, масштабируемый и проверяемый процесс.
