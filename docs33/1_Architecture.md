# Технический отчет 1: Архитектура системы OB1 и когнитивная инфраструктура

## 1. Резюме
Система OB1, также известная как "Open Brain" (Открытый Мозг), представляет собой смену парадигмы в управлении персональными знаниями (PKM) и взаимодействии с ИИ-агентами. В отличие от традиционных приложений для заметок или изолированных SaaS-инструментов, OB1 спроектирована как инфраструктурный слой — постоянная, программируемая и независимая от клиента память для искусственного интеллекта. Ее архитектура построена на принципе "Один мозг, любой клиент", используя протокол контекста модели (Model Context Protocol, MCP) для преодоления разрыва между частной базой данных и различными большими языковыми моделями (LLM).

## 2. Философия "Отсутствия посредников" (No Middleware)
Ключевой инновацией OB1 является отказ от сложных цепочек посредников, таких как Zapier, Make или кастомные фреймворки оркестровки. Традиционные рабочие процессы ИИ часто включают хрупкие "SaaS-цепочки", где данные передаются через множество сторонних сервисов. OB1 переносит интеллект и связность непосредственно на "край" (Supabase Functions) и в "базу данных" (Postgres + pgvector).

Устраняя посредников, OB1 достигает следующих преимуществ:
- **Низкая задержка**: Прямое взаимодействие между агентом и базой данных.
- **Конфиденциальность**: Данные остаются в контролируемой пользователем среде Supabase/Postgres.
- **Надежность**: Меньшее количество движущихся частей означает меньше точек отказа.
- **Высокая пропускная способность**: Агенты могут выполнять сложные многоэтапные запросы без ограничений со стороны промежуточных слоев API.

## 3. Технологический стек
Система построена на современном высокопроизводительном стеке, оптимизированном для минимальной задержки и высокой масштабируемости:
- **База данных**: Supabase (PostgreSQL) с расширением `pgvector`. Это основное хранилище как для структурированных метаданных, так и для высокоразмерных векторных эмбеддингов.
- **Среда выполнения**: Deno Deploy. Основной сервер MCP и вебхуки интеграции (например, захват сообщений из Slack) работают на Deno, используя его нативную поддержку TypeScript и безопасную среду выполнения.
- **AI Gateway**: OpenRouter. Использование OpenRouter позволяет OB1 оставаться независимой от моделей, позволяя пользователям переключаться между OpenAI, Anthropic и моделями с открытым исходным кодом (через Ollama) без изменения основной логики.
- **Протокол интерфейса**: Model Context Protocol (MCP). Разработанный Anthropic, MCP позволяет OB1 предоставлять свои функции (поиск, захват, листинг) в виде стандартизированных "инструментов", которые может обнаружить и использовать любой современный ИИ-клиент (Claude Desktop, Cursor, Claude Code).

## 4. Реализация MCP-сервера: Шлюз к мозгу
Центральный узел связности OB1 находится в файле `server/index.ts`. Этот файл реализует сервер двойного назначения:
1. **MCP Server**: Использует `@modelcontextprotocol/sdk` для определения инструментов, которые могут вызывать LLM.
2. **Hono-based Proxy**: Оборачивает MCP-сервер в веб-фреймворк Hono. Это позволяет MCP-серверу быть доступным через стандартные протоколы HTTP/SSE (Server-Sent Events), обеспечивая совместимость с облачными ИИ-клиентами (такими как ChatGPT или Claude.ai).

### 4.1. Безопасность и аутентификация
Безопасность обеспечивается многоуровневым подходом:
- **X-Brain-Key**: Кастомный заголовок или параметр URL, который служит простым, но эффективным привратником.
- **Row Level Security (RLS)**: В базе данных Supabase политики RLS гарантируют изоляцию данных даже в многопользовательских средах. Политики определяются на уровне базы данных (Postgres), а не в приложении, что гарантирует соблюдение безопасности независимо от метода подключения.
- **Service Role Keys**: Взаимодействие между Deno и Supabase использует ключ Service Role, обходя RLS для административных задач и поддерживая строгую границу доверия "Edge-to-DB".

## 5. Интеграция графа знаний (OB-Graph)
Недавнее расширение архитектуры (находится в `recipes/ob-graph/index.ts`) вводит слой графовой базы данных поверх реляционного хранилища.
- **Узлы и ребра**: Система реализует традиционную модель графа свойств с использованием таблиц `graph_nodes` и `graph_edges`.
- **Рекурсивный обход**: Архитектура использует рекурсивные обобщенные табличные выражения SQL (CTE), позволяя агентам выполнять обход на несколько шагов (например, "Найти всех людей, связанных с Проектом X").
- **MCP для графов**: Стандартные графовые операции (create_node, find_path, get_neighbors) представлены как инструменты MCP, позволяя ИИ-агентам автономно строить и запрашивать собственные графы знаний.

## 6. Межклиентская совместимость
Самая сильная сторона архитектуры — способность обслуживать разных клиентов с различными требованиями:
- **Десктопные клиенты**: Подключаются через локальный прокси MCP или напрямую через stdio.
- **Облачные клиенты**: OB1 предоставляет специализированные "инструменты совместимости" (`search` и `fetch`), которые соответствуют специфическим паттернам вызова инструментов, ожидаемым облачными интерфейсами ИИ.
- **Клиенты захвата**: Легковесные вебхуки (Slack/Discord), которые работают только на запись в "мозг", обеспечивая бесшовный ввод данных без необходимости в полноценном интерфейсе агента.

## 7. Модели развертывания
Хотя связка Supabase + Deno является каноническим стеком, архитектура спроектирована для переносимости:
- **Supabase Cloud**: Самый быстрый путь развертывания с использованием управляемых сервисов.
- **Self-Hosted K8s**: Модуль `integrations/kubernetes-deployment` предоставляет манифесты Kubernetes и Docker-файлы для пользователей, которым нужен 100% контроль над инфраструктурой, включая собственный Postgres с pgvector и локальную среду Deno.

## 8. Заключение
OB1 — это больше, чем база данных; это "Когнитивная операционная система". Используя протокол MCP и высокооптимизированный стек Supabase/Deno, она обеспечивает долговечный, интеллектуальный слой памяти, который сохраняется за пределами контекстного окна любой отдельной сессии ИИ. Архитектурная элегантность системы заключается в ее простоте: она использует лучшие современные веб-стандарты для решения проблемы долгосрочного кроссплатформенного управления состоянием ИИ.
