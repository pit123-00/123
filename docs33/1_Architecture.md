# Технический отчет 1: Глобальная архитектура системы OB1 и когнитивная инфраструктура

## 1. Концептуальное введение: "Мозг как сервис"
Система OB1 (Open Brain) представляет собой не просто приложение для хранения заметок, а фундаментальный инфраструктурный слой для искусственного интеллекта. В эпоху, когда ИИ-агенты ограничены контекстным окном, OB1 предлагает решение проблемы долгосрочной памяти, независимой от конкретной модели или клиента. Архитектура построена вокруг идеи "Cognitive Operating System", где данные пользователя являются активным компонентом в цикле рассуждений ИИ.

## 2. Философия "No-Middleware" (Прямая связность)
Одной из самых значимых архитектурных инноваций OB1 является полный отказ от традиционных промежуточных слоев (middleware), таких как Zapier, Make или кастомные серверные прослойки на Python/Node.js, которые обычно связывают интерфейс пользователя с базой данных.
- **Техническая выгода**: Устранение посредников снижает задержку (latency) обмена данными между агентом и памятью до десятков миллисекунд.
- **Безопасность**: Данные не проходят через сторонние облака, а передаются по прямому защищенному каналу между Edge-функцией (Deno) и базой данных (Postgres).
- **Надежность**: Отсутствие сложной логики на стороне приложения минимизирует количество точек отказа.

## 3. Технологический стек и его обоснование
Система построена на связке технологий, обеспечивающих максимальную скорость и портативность:
- **База данных: Supabase (PostgreSQL + pgvector)**. Выбор пал на Postgres из-за его надежности и расширяемости. Плагин `pgvector` позволяет выполнять векторный поиск прямо в БД, исключая необходимость в использовании отдельных векторных баз типа Pinecone.
- **Runtime: Deno Deploy**. Использование Deno вместо Node.js обосновано его безопасностью "по умолчанию" и нативной поддержкой TypeScript без предварительной компиляции. Это позволяет развертывать MCP-серверы за считанные секунды в глобально распределенной среде.
- **Протокол: Model Context Protocol (MCP)**. OB1 является одной из первых систем, полностью внедривших протокол MCP от Anthropic. Это позволяет базе данных "представляться" ИИ-агенту как набор инструментов (tools), которые агент может вызывать самостоятельно.

## 4. Реализация MCP-сервера: Универсальный шлюз
Серверная часть (`server/index.ts`) реализует мост между протоколом MCP и базой данных Supabase.
- **Hono-обертка**: Использование легкого веб-фреймворка Hono позволяет серверу работать не только через стандартный ввод/вывод (stdio), но и через HTTP/SSE. Это делает OB1 совместимым с облачными агентами (ChatGPT, Claude.ai), которые не имеют доступа к локальной файловой системе пользователя.
- **Динамическая регистрация инструментов**: Сервер регистрирует такие инструменты, как `search_thoughts`, `capture_thought` и `thought_stats`. Для агента эти функции выглядят как нативные способности, которыми он может пользоваться для поиска фактов или сохранения выводов.

## 5. Инженерные решения для кросс-платформенности
OB1 включает в себя ряд "невидимых" для пользователя патчей, обеспечивающих стабильность работы:
- **Патч для Claude Desktop**: Специальный код обнаруживает отсутствие заголовков `Accept: text/event-stream` от десктопного клиента и исправляет запрос на лету.
- **CORS и безопасность**: Полноценная поддержка CORS позволяет строить кастомные веб-дашборды (Next.js/Svelte), которые могут напрямую общаться с "мозгом" пользователя через защищенный шлюз.

## 6. Многопользовательская архитектура и RLS
Хотя OB1 часто используется как персональный инструмент, его архитектура изначально готова к командной работе.
- **Row Level Security (RLS)**: Логика доступа к данным зашита не в код сервера, а в саму БД. Это позволяет нескольким пользователям (например, членам семьи или коллегам) хранить данные в одной таблице, при этом каждый видит только свои записи.
- **Service Role**: Для системных задач (например, захват сообщений из Slack) используется отдельный высокопривилегированный ключ, который действует за рамками RLS, обеспечивая целостность всей системы.

## 7. Модульность: Рецепты, Скиллы и Расширения
Структура репозитория отражает архитектурную гибкость:
- **Extensions**: Готовые модули для специфических задач (Household Knowledge, CRM).
- **Recipes**: Портативные скрипты на SQL и TS для быстрого импорта данных из внешних источников (Gmail, Obsidian).
- **Skills**: Инструкции высокого уровня, обучающие ИИ-агентов новым методам работы с памятью пользователя (например, навык "Panning for Gold").

## 8. Итог
Архитектура OB1 — это манифест эффективности и приватности. Перенося интеллект на "край" (Edge) и в саму базу данных, система создает фундамент для появления персональных ИИ-агентов, обладающих памятью, сравнимой по долговечности и доступности с человеческой. Система не просто хранит данные — она создает "когнитивный ландшафт", в котором ИИ может ориентироваться, учиться и действовать автономно.
