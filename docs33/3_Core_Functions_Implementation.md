# Технический отчет 3: Реализация основных функций — Захват, извлечение и специализированные рабочие процессы

## 1. Введение
Технический успех OB1 (Open Brain) зависит от беспрепятственного "входа" информации и ее последующего "обогащения". В данном отчете подробно рассматривается реализация основных функций, которые управляют захватом мыслей, автоматизированным извлечением метаданных и специализированными рабочими процессами, такими как "Schema-Aware Routing" и "Repository Learning Coach".

## 2. Конвейер захвата (Capture Pipeline)
Процесс "захвата" — это основной способ попадания информации в экосистему OB1. Он реализован в инструменте MCP `capture_thought` и различных вебхуках интеграции (например, Slack/Discord).

### 2.1. Технический поток выполнения
При запуске захвата система выполняет высококонкурентную операцию:
1. **Параллельные вызовы API**: Используя `Promise.all()`, система одновременно вызывает API эмбеддингов и API извлечения метаданных (LLM). Это минимизирует задержку, воспринимаемую пользователем.
2. **Атомарный Upsert**: Используется специализированная функция Postgres `upsert_thought` для обработки конфликтов. Если захватывается точно такой же контент, система обновляет существующую запись, а не создает дубликат.
3. **Двухэтапная фиксация**: Система сначала сохраняет структурированный текст и метаданные, а затем обновляет строку векторным эмбеддингом. Это гарантирует сохранение данных даже в случае сбоя API векторов.

## 3. Автоматизированное извлечение метаданных
Отличительной чертой OB1 является подход "Метаданные без усилий". Пользователь никогда не помечает мысль тегами вручную; вместо этого извлечение выполняет LLM.

### 3.1. Логика извлечения
Система использует тщательно настроенный системный промпт, который инструктирует модель (обычно `gpt-4o-mini`) вернуть объект JSON, содержащий:
- **people**: Массив упомянутых лиц.
- **action_items**: Неявные задачи, выведенные из текста.
- **topics**: 1-3 ключевых тега.
- **type**: Категоризация на `observation` (наблюдение), `task` (задача), `idea` (идея), `reference` (ссылка) или `person_note` (заметка о человеке).

## 4. Маршрутизация с учетом схемы (Schema-Aware Routing)
Модуль `recipes/schema-aware-routing/index.ts` демонстрирует сложный паттерн распределения данных.
- **Запись в несколько таблиц**: Помимо таблицы `thoughts`, этот паттерн направляет извлеченные данные в таблицы конкретных доменов: `people`, `interactions` (взаимодействия) и `action_items`.
- **Нечеткое сопоставление людей**: Реализована трехэтапная стратегия разрешения имен: точное совпадение, нечеткое совпадение по имени (например, "Rob" ↔ "Robert") и обнаружение коллизий. Это гарантирует правильную связь профессиональной сети пользователя даже при неформальных упоминаниях.

## 5. Специализированный рабочий процесс: Life Engine
Рецепт "Life Engine" — это основная реализация проактивного помощника.
- **Проактивные брифинги**: В отличие от стандартных систем, работающих по запросу, Life Engine "отправляет" информацию через Telegram или Discord.
- **Интеграция с несколькими системами**: Он связывает Open Brain с календарем пользователя, данными о здоровье и привычками.
- **Генерация видео**: Расширение "Life Engine Video" позволяет рендерить эти брифинги в виде анимированных видеороликов с озвучкой.

## 6. Специализированный рабочий процесс: Repository Learning Coach
`recipes/repo-learning-coach` — это сложная реализация для технического онбординга.
- **Контент против Среды выполнения**: Он обучает принципу отделения "знаний" о репозитории от его "выполнения".
- **Фиксация долгосрочного обучения**: Помогает пользователю "изучить" новую кодовую базу и сохранить эти знания обратно в Open Brain в виде структурированных "уроков".
- **Архитектура синхронизации**: Реализована система синхронизации между локальными файлами и бэкендом Supabase.

## 7. Слой безопасности Hono
Поскольку к OB1 обращаются различные клиенты, системе требуется гибкий и безопасный коммуникационный слой.
- **Аутентификация через заголовки и запросы**: Сервер проверяет наличие `MCP_ACCESS_KEY` в заголовках или параметрах URL.
- **Управление CORS**: Полноценная реализация CORS позволяет облачным клиентам (таким как Claude.ai) безопасно взаимодействовать с частным сервером.
- **Патч для Claude Desktop**: Инженерное решение в `server/index.ts` обнаруживает и исправляет отсутствующие заголовки от клиента Claude Desktop, обеспечивая кроссплатформенную надежность.

## 8. Резюме
Реализация основных функций OB1 отдает приоритет **беспрепятственному вводу** и **автоматизированному обогащению**. Перекладывая когнитивную нагрузку по организации данных с человека на ИИ и предоставляя специализированные рабочие процессы, OB1 гарантирует, что система является не просто "кучей заметок", а активным участником цифровой жизни пользователя.
