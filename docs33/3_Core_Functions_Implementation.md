# Технический отчет 3: Реализация функций — Захват, извлечение и маршрутизация

## 1. Введение: Конвейер превращения текста в знания
Одной из самых сильных сторон OB1 является автоматизация процесса наполнения памяти. Пользователю не нужно помечать тегами свои заметки — система делает это сама в момент захвата. Данный отчет анализирует техническую реализацию конвейера "Capture -> Extract -> Route", который лежит в основе жизнедеятельности системы.

## 2. Процесс захвата (Capture Pipeline)
Захват реализован как в основном сервере MCP (`capture_thought`), так и в специализированных интеграциях (Slack, Discord).

### 2.1. Техническая реализация
При поступлении сообщения система запускает параллельный процесс:
1. **Генерация эмбеддинга**: Вызов модели `text-embedding-3-small` для векторизации смысла.
2. **LLM-извлечение**: Вызов `gpt-4o-mini` для структурного анализа текста.
Использование `Promise.all()` в TypeScript позволяет выполнить эти два внешних вызова одновременно, минимизируя время ожидания ответа пользователем.

## 3. Автоматизированное извлечение метаданных
Логика извлечения — это "глаза" системы. Она реализована через строго заданный системный промпт (System Prompt).

### 3.1. Схема данных
Система инструктирует LLM вернуть JSON-объект, содержащий:
- **people**: Массив имен упомянутых людей. Это фундамент для построения CRM-функционала.
- **topics**: 1-3 ключевых тега, обобщающих тему.
- **action_items**: Неявные задачи ("нужно сделать", "напомни мне").
- **type**: Категоризация (заметка, идея, задача, ссылка).

### 3.2. Устойчивость к ошибкам
В коде реализован механизм "Graceful Degradation": если LLM возвращает некорректный JSON или пустой ответ, система применяет дефолтные метаданные (`uncategorized`), обеспечивая сохранение самого текста мысли в любых условиях.

## 4. Маршрутизация с учетом схем (Schema-Aware Routing)
Это продвинутый уровень захвата, реализованный в рецепте `schema-aware-routing`. Вместо того чтобы писать всё в одну таблицу `thoughts`, система может распределять данные.

### 4.1. Многотабличная запись
На основе извлеченных полей маршрутизатор выполняет:
- Запись в `people`: Создание или обновление карточки контакта.
- Запись в `interactions`: Фиксация факта и контекста общения с человеком.
- Запись в `action_items`: Добавление задачи в оперативный список дел.

### 4.2. Алгоритм разрешения сущностей (Fuzzy Identity)
Для имен людей реализована нечеткая логика сопоставления. Если в тексте упомянут "Алекс", система ищет в базе "Алексея".
- Если соответствие очевидно, запись связывается автоматически.
- Если есть сомнения (коллизия имен), система помечает связь как `pending` и просит подтверждения у пользователя.

## 5. Интеграции: Slack как пример реализации
Интеграция со Slack (`integrations/slack-capture`) демонстрирует, как OB1 встраивается в повседневную жизнь.
- **Deduplication**: Использование `slack_ts` (таймстампа сообщения) в качестве уникального идентификатора для предотвращения дублей при повторных вызовах вебхука.
- **Feedback Loop**: После успешной записи система отправляет ответным тредом в Slack результаты извлечения (какие теги и люди были найдены), подтверждая пользователю, что ИИ всё понял верно.

## 6. Итог
Реализация функций захвата и извлечения в OB1 превращает хаотичный поток сообщений в структурированную базу знаний. Технологии **параллельной обработки**, **LLM-экстракции по схеме** и **нечеткой маршрутизации сущностей** позволяют пользователю "просто думать вслух", в то время как система берет на себя всю работу по организации и классификации информации. Это создает беспрецедентно низкий порог входа для формирования долгосрочной памяти.
