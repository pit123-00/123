# RVF: Сегменты и COW-ветвление когнитивных контейнеров

Бинарный формат **RVF** (RuVector Format), разработанный в рамках проекта, представляет собой не просто формат базы данных, а полноценный стандарт упаковки автономных ИИ-систем. Крейт `rvf-runtime` реализует поддержку этого формата, превращая статичные файлы в "когнитивные контейнеры".

## 1. Сегментированная архитектура
RVF-файл состоит из независимых сегментов. Это позволяет выполнять частичное обновление данных без необходимости перезаписывать весь файл целиком — критически важная особенность для баз данных объемом в сотни гигабайт.

### Типы сегментов (реализация в `rvf-types`):
- **`VEC` (0x01)**: Векторы эмбеддингов, хранящиеся плотными блоками.
- **`INDEX` (0x02)**: Граф индексации, обычно на базе HNSW.
- **`MANIFEST` (0x05)**: Корневой сегмент, содержащий оглавление всех остальных сегментов и их контрольные суммы.
- **`KERNEL` (0x0E)**: Бинарный образ ядра ОС (например, для запуска контейнера как микросервиса).
- **`WASM` (0x10)**: Модули логики, позволяющие файлу "выполнять самого себя".

## 2. Реализация функций управления контейнером

### 21. `RvfStore::branch(child_path) -> Result<Self>`
Функция создания дочерней ветки данных.
- **Логика**: Генерирует новый манифест, в котором все указатели на данные изначально ссылаются на родительский файл.
- **Техническая особенность**: Создает легковесную "виртуальную" базу данных.

### 22. `CowEngine::new()` (и использование в `store.rs`)
Сердце механизма Copy-on-Write.
- **Логика**: При попытке изменить вектор в дочерней ветке, `CowEngine` блокирует доступ к родителю, выделяет новый сегмент в дочернем файле и записывает изменения туда.
- **Преимущество**: Это позволяет создавать тысячи версий базы данных (например, для разных ИИ-агентов) практически без затрат дискового пространства.

### 23. `RvfStore::append_witness(witness_type, action)`
Добавление криптографического подтверждения.
- **Логика**: Формирует запись в сегменте `WITNESS`, содержащую хэш операции и ссылку на предыдущее звено.
- **Особенности**: Реализует концепцию "Chain of Custody" для данных. Любая вставка или удаление в RuVector фиксируется в этой цепочке, которую невозможно подделать.

### 24. `RvfStore::embed_wasm(role, bytecode, ...)`
Внедрение исполняемого кода в структуру базы.
- **Логика**: Записывает байт-код WASM и метаданные (приоритет загрузки, необходимые ресурсы) в файл.
- **Роль**: Позволяет упаковать, например, логику семантического поиска или фильтрации прямо внутрь файла с данными, гарантируя, что код и данные всегда находятся в одной версии.

### 25. `RvfStore::freeze() -> Result<()>`
Заморозка состояния.
- **Логика**: Финализирует текущий манифест и переводит сегменты в режим "только чтение".
- **Важность**: Гарантирует целостность родительской ветки при создании дочерних COW-ветвей.

## 3. Практическая ценность: Переносимый ИИ
Благодаря комбинации сегментации и COW-ветвления, RuVector решает проблему развертывания сложных ИИ-систем. Вместо сложной связки "БД + Модель + Приложение + Контейнер", инженер получает один `.rvf` файл. Этот файл можно переслать по сети, мгновенно "отпочковать" от него новую ветку для специфической задачи и запустить на любой платформе, поддерживающей ядро RuVix или среду выполнения WASM.

Фактически, RVF — это "Docker для данных и интеллекта", где за счет COW-технологии стоимость создания новой среды выполнения практически равна нулю.
