# Топология HNSW как структура графа для GNN

В архитектуре RuVector реализован глубокий синтез классических алгоритмов поиска и современных методов графового обучения. Ключевым решением является использование графа индекса **HNSW** (Hierarchical Navigable Small World) как топологической основы для графовых нейронных сетей (**GNN**). Это превращает статический индекс в активную обучающуюся структуру.

## 1. Концептуальная модель в `ruvector-gnn`
Обычные векторные БД используют HNSW только для навигации. RuVector в крейте `ruvector-gnn` рассматривает каждую связь между узлами в HNSW как ребро графа, по которому передается семантическая информация.

### Архитектурные преимущества:
- **Локальная эффективность**: GNN работает не со всем графом базы, а только с наиболее релевантными соседями, найденными в процессе поиска.
- **Самообучение на лету**: Система улучшает качество поиска по мере его выполнения, обучаясь на траекториях перемещения между узлами.
- **Интеграция метаданных**: Веса ребер в графе могут зависеть не только от расстояния между векторами, но и от совпадения атрибутов или частоты использования связей.

## 2. Реализация ключевых функций GNN

### 6. `RuvectorLayer::forward(node_embedding, neighbor_embeddings, edge_weights) -> Vec<f32>`
Главная функция прохода через слой графовой сети.
- **Логика**: Выполняет агрегацию признаков соседей, применяет механизм внимания и обновляет состояние текущего узла.
- **Техническая деталь**: Использует `w_msg` для трансформации сообщений и `w_agg` для их объединения. После агрегации вызывается `GRUCell` для плавного обновления эмбеддинга.

### 7. `MultiHeadAttention::forward(query, keys, values) -> Vec<f32>`
Механизм внимания, адаптированный для топологии графа.
- **Логика**: Оценивает важность каждого соседа для текущего запроса в нескольких независимых проекциях.
- **Особенности**: Реализация в `layer.rs` включает "Scaled Dot-Product Attention", где веса соседей нормируются через Softmax с защитой от численной нестабильности.

### 8. `GRUCell::forward(input, hidden) -> Vec<f32>`
Функция обновления состояния вектора.
- **Логика**: Реализует Gated Recurrent Unit. Использует гейты обновления (`w_z`) и сброса (`w_r`) для баланса между сохранением старого значения эмбеддинга и внедрением новой информации из графа.
- **Преимущество**: Это позволяет "накапливать" знания в узле на протяжении серии запросов.

### 9. `FeatureMasking::mask_nodes(features, mask_ratio) -> MaskResult`
Логика подготовки данных для самообучения (SSL).
- **Логика**: Случайным образом выбирает долю узлов и заменяет их векторы на обучаемый токен `[MASK]`.
- **Особенности**: Это позволяет системе тренироваться восстанавливать значения векторов, просто анализируя их соседей в HNSW.

### 10. `GraphMAE::train_step(graph: &GraphData) -> f32`
Цикл обучения Masked Autoencoder.
- **Логика**: Маскирует узлы -> Пропускает через GAT-энкодер -> Декодирует только маскированные узлы -> Вычисляет SCE-loss (Scaled Cosine Error).
- **Результат**: Система выучивает такие веса GNN, которые максимально точно предсказывают "смысл" узла на основе его окружения в графе.

## 3. Математическое обоснование: SCE Loss
В файле `graphmae.rs` реализована специфическая функция потерь `sce_loss`. В отличие от стандартного MSE, она фокусируется на угле между векторами (`(1 - cos_sim)^gamma`). Это делает обучение GNN в RuVector крайне устойчивым к разному масштабу векторов и выбросам данных, что критично для реальных поисковых систем.

## 4. Дифференцируемый поиск
Функция `differentiable_search` в `search.rs` является мостом между индексацией и обучением. Она возвращает Softmax-веса кандидатов, что позволяет алгоритму обратного распространения ошибки корректировать не только веса GNN, но и влиять на то, какие связи в HNSW считаются "сильными". Это реализует концепцию **Differentiable Indexing**, где сама структура поиска становится частью нейронной сети.
