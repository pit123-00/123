# Аналитический отчет по системе навыков AI Factory (2.x)

## 1. Введение в AI Factory

AI Factory — это модульная среда для разработки программного обеспечения с помощью ИИ, ориентированная на автоматизацию рабочих процессов (workflows). Основная архитектурная особенность системы — использование «навыков» (skills), которые представляют собой специализированные наборы инструкций для Claude Code или аналогичных агентов.

Система 2.x отличается глубокой интеграцией с Git (через worktrees), поддержкой режима «Handoff» для автономной работы и строгим разделением ответственности за артефакты в папке `.ai-factory/`.

## 2. Карта навыков (Skill Map)

Система включает 25 навыков, которые можно сгруппировать по функциональным блокам:

### Группа А: Стратегическое планирование
1. **aif-roadmap** — создание и поддержка высокоуровневого плана проекта (ROADMAP.md).
2. **aif-architecture** — определение структуры проекта, границ слоев и правил зависимостей.
3. **aif-description** — ведение мастер-документа с описанием стека и конвенций (DESCRIPTION.md).

### Группа Б: Тактическое планирование и Подготовка
4. **aif-plan** — создание детального плана реализации фичи (режимы Fast и Full).
5. **aif-explore** — параллельное исследование кодовой базы субагентами.
6. **aif-reference** — поиск и анализ справочной информации.

### Группа В: Реализация и Исполнение
7. **aif-implement** — пошаговое выполнение задач плана с ведением логов.
8. **aif-fix** — специализированный поток для исправления багов с созданием патчей.
9. **aif-improve** — итеративное улучшение существующего кода.
10. **aif-loop** — запуск автономных циклов разработки.

### Группа Г: Качество и Проверка
11. **aif-verify** — пост-имплементационная проверка соответствия коду плану.
12. **aif-review** — аудит кода (staged изменения, ветки или PR).
13. **aif-qa** — выполнение сценариев тестирования и обеспечения качества.
14. **aif-security-checklist** — проверка кода на соответствие стандартам безопасности.
15. **aif-rules-check** — валидация кода на соответствие локальным правилам (RULES.md).

### Группа Д: Поддержка и Мета-навыки
16. **aif-docs** — генерация и обновление технической документации.
17. **aif-commit** — создание осмысленных коммитов по стандарту conventional commits.
18. **aif-evolve** — самосовершенствование системы на основе опыта (создание skill-context).
19. **aif-skill-generator** — создание новых навыков для расширения фабрики.

## 3. Описание ключевых навыков и их зависимости

### 3.1 aif-plan (Планирование)
Это точка входа для любой новой функциональности.
- **Режимы:** `Fast` (быстрый план в одном файле) и `Full` (создание ветки/worktree, опрос предпочтений пользователя).
- **Зависимости:** Читает `ARCHITECTURE.md` и `DESCRIPTION.md`. При использовании режима `--parallel` автоматически вызывает `aif-implement`.

### 3.2 aif-implement (Реализация)
Основной цикл работы с кодом.
- **Особенности:** Работает строго по одной задаче за раз. Автоматически обновляет чекбоксы в файле плана. Требует обязательного расширенного логирования.
- **Зависимости:** Получает список задач от `aif-plan`. Может предлагать обновить `ROADMAP.md` по завершении. Вызывает `aif-verify` для проверки.

### 3.3 aif-verify (Верификация)
Контроль качества после завершения имплементации.
- **Проверки:** Компиляция, тесты, линтинг, соответствие именований плану, отсутствие «забытых» TODO и console.log.
- **Зависимости:** Если найдены ошибки, рекомендует использовать `aif-fix` для их устранения.

### 3.4 aif-evolve (Эволюция)
Уникальный навык для накопления проектного опыта.
- **Задача:** Анализирует патчи и историю разработки, создавая файлы в `.ai-factory/skill-context/`. Эти файлы становятся «локальными переопределениями» правил для других навыков.
- **Зависимости:** Влияет на поведение `aif-plan`, `aif-implement` и `aif-verify` в будущем.

## 4. Жизненный цикл фичи в AI Factory

Стандартный процесс разработки выглядит так:

1.  **Старт:** Пользователь вызывает `aif-roadmap`, чтобы наметить вехи.
2.  **Проработка:** Вызывается `aif-plan full`. Навык создает ветку `feature/...` и файл плана.
3.  **Исследование:** Внутри планирования `aif-plan` запускает параллельных субагентов `aif-explore`.
4.  **Разработка:** Запускается `aif-implement`. Агент пишет код, добавляет логи, фиксирует прогресс в плане.
5.  **Проверка:** По завершении всех задач вызывается `aif-verify`. Если есть баги — `aif-fix`.
6.  **Ревью:** `aif-review` проверяет дифф перед коммитом.
7.  **Финал:** `aif-commit` сохраняет изменения, ветка мержится (через `aif-plan --cleanup`).

## 5. Анализ архитектурных принципов

- **Skill Context:** Система умеет учиться. Навыки — это не статические промпты, они дополняются проектным опытом через папку `skill-context`.
- **Handoff Mode:** Поддержка автономности. Агенты могут работать в цепочке, передавая состояние через специальные аннотации в файлах планов.
- **Artifact Ownership:** Строгое разграничение прав. Например, `aif-implement` не имеет права менять `RULES.md`, он может только предлагать правки через `aif-rules`.
- **Verbose Logging:** Принудительное требование к наличию логов в генерируемом коде для облегчения последующей отладки.

## 6. Резюме

AI Factory 2.x представляет собой зрелую инженерную экосистему. Ее основная сила — в **самодокументировании и самообучении**. Каждый выполненный проект делает «фабрику» умнее для этого конкретного стека технологий. Высокая степень автоматизации рутинных действий (создание веток, работа с worktrees, обновление чекбоксов) позволяет разработчику сосредоточиться на архитектуре и логике, в то время как «навыки» следят за соблюдением дисциплины и качества.
