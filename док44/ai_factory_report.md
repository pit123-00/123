# Аналитический отчет по системе навыков AI Factory (2.x)

## 1. Введение в AI Factory

AI Factory — это модульная среда для разработки программного обеспечения с помощью ИИ, ориентированная на автоматизацию рабочих процессов (workflows). Основная архитектурная особенность системы — использование «навыков» (skills), которые представляют собой специализированные наборы инструкций для Claude Code или аналогичных агентов.

Система 2.x отличается глубокой интеграцией с Git (через worktrees), поддержкой режима «Handoff» для автономной работы и строгим разделением ответственности за артефакты в папке `.ai-factory/`.

## 2. Карта навыков (Skill Map)

Система включает 25 навыков, разделенных на функциональные блоки:

### Блок А: Стратегия и Архитектура
1. **aif-roadmap** — создание и поддержка стратегического плана (ROADMAP.md).
2. **aif-architecture** — описание структуры слоев и правил зависимостей.
3. **aif-description** — мастер-документ технического стека (DESCRIPTION.md).

### Блок Б: Проектирование и Исследование
4. **aif-plan** — тактическое планирование фичи (режимы Fast/Full).
5. **aif-explore** — параллельное изучение кода субагентами.
6. **aif-reference** — анализ справочных материалов и документации.
7. **aif-roadmap** (аналитика) — проверка текущего прогресса.

### Блок В: Реализация и Исправление
8. **aif-implement** — пошаговое выполнение плана с логированием.
9. **aif-fix** — цикл исправления багов с созданием патчей.
10. **aif-improve** — итеративное улучшение кода без изменения функционала.
11. **aif-loop** — автономный цикл разработки.
12. **aif-grounded** — проверка «заземленности» (реалистичности) решений.

### Блок Г: Качество и Верификация
13. **aif-verify** — итоговая проверка соответствия кода плану.
14. **aif-review** — аудит изменений (staged или PR).
15. **aif-qa** — выполнение сценариев тестирования.
16. **aif-security-checklist** — проверка на уязвимости.
17. **aif-rules-check** — валидация кода на соответствие RULES.md.

### Блок Д: Автоматизация и Поддержка
18. **aif-docs** — ведение технической документации.
19. **aif-commit** — генерация конвенциональных коммитов.
20. **aif-evolve** — обучение системы на основе опыта проекта.
21. **aif-skill-generator** — создание новых навыков.
22. **aif-build-automation** — управление процессами сборки.
23. **aif-ci** — интеграция с пайплайнами.
24. **aif-dockerize** — контейнеризация приложений.
25. **aif** — основной контроллер и точка входа.

## 3. Описание ключевых навыков

### 3.1. aif-plan
Центральный навык для планирования.
- **Режимы:** Fast (быстрый список задач) и Full (создание ветки, опрос предпочтений, разведка через `aif-explore`).
- **Зависимости:** Читает `ARCHITECTURE.md` и `DESCRIPTION.md`. При флаге `--parallel` запускает `aif-implement`.

### 3.2. aif-implement
Исполнитель планов.
- **Правило:** Одна задача за раз. После выполнения — обязательное обновление чекбокса в файле плана.
- **Особенности:** Требует Configurable Verbose Logging (все действия должны логироваться для отладки).

### 3.3. aif-verify
Главный страж качества.
- **Проверки:** Билд, тесты, линтинг, дрейф имен ( drift), наличие забытых артефактов отладки.
- **Связи:** Если найдены недочеты, вызывает `aif-fix`.

### 3.4. aif-evolve
Интеллект системы. Анализирует историю «патчей» (исправлений) и создает локальные переопределения правил в `skill-context`. Это позволяет системе не совершать одну и ту же ошибку дважды в одном проекте.

## 4. Операционный цикл (Life Cycle)

1.  **Strategic**: `aif-roadmap` -> вехи.
2.  **Tactical**: `aif-plan` -> спецификация и задачи.
3.  **Exploration**: `aif-explore` (внутри плана) -> понимание контекста.
4.  **Execution**: `aif-implement` -> написание кода и логов.
5.  **Quality**: `aif-verify` & `aif-review` -> подтверждение готовности.
6.  **Persistence**: `aif-commit` -> фиксация результата.
7.  **Maintenance**: `aif-docs` & `aif-evolve` -> обновление знаний.

---

## 5. Архитектурные инновации

- **Artifact Ownership:** Каждый навык «владеет» своим файлом (например, `aif-roadmap` владеет `ROADMAP.md`). Исполнитель не может менять правила без вызова соответствующего навыка.
- **Skill Context:** Механизм «прививки» опыта. Общие навыки становятся умнее, адаптируясь под конкретный проект.
- **Handoff Mode:** Протокол передачи управления, позволяющий ИИ-агентам работать в цепочке автономно.

## 6. Резюме

AI Factory 2.x — это фабрика, которая строит сама себя. Основная ценность системы заключается в **автоматическом накоплении инженерного опыта** и строгом разделении на стратегический, тактический и исполнительный уровни. Она минимизирует рутину (Git, документация, логи) и максимизирует соблюдение архитектурных границ.
