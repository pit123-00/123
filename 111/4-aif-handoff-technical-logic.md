# Отчет 1: Техническая работа и логика репозитория aif-handoff

Проект `aif-handoff` — это полностековая система управления задачами (Kanban-доска), которая оркестрирует работу автономных LLM-агентов через строгую стейт-машину (State Machine). В отличие от простого набора скриптов, это полноценный бэкенд с базой данных, веб-сокетами и фоновым координатором.

---

## 1. Общая архитектура (Monorepo)
Проект построен как монорепозиторий (Turborepo) и состоит из следующих слоев:
*   **`shared`**: Типы, схемы (Zod), стейт-машина, константы.
*   **`data`**: Слой доступа к БД SQLite (использует `better-sqlite3` + `drizzle-orm`).
*   **`api`**: REST + WebSocket сервер на базе `Hono`. Работает на порту 3009.
*   **`web`**: Frontend на React + Vite + TailwindCSS. Представляет собой Kanban-доску (порт 5180).
*   **`agent`**: Фоновый процесс (node-cron + Claude Agent SDK), который выполняет роль координатора.

## 2. Жизненный цикл задачи (State Machine)
Процесс строго контролируется стейт-машиной. Задача проходит через следующие статусы:
1.  **`backlog`** → (человек нажимает `start_ai`) → **`planning`**
2.  **`planning`** → (агент пишет план) → **`plan_ready`**
3.  **`plan_ready`** → (человек нажимает `start_implementation` или срабатывает autoMode) → **`implementing`**
4.  **`implementing`** → (агент пишет код) → **`review`**
5.  **`review`** → (ревьюеры одобряют) → **`done`** ИЛИ (ревьюеры отклоняют) → **`request_changes`** (возврат в implementing)
6.  **`done`** → (человек аппрувит) → **`verified`** (финальный статус)

Если агент "завис", система переводит задачу в статус `blocked_external` с механизмом экспоненциального бэкоффа (retry).

## 3. Диспетчеризация и пайплайн агентов (Agent Pipeline)
Ядро системы — фоновый координатор, который опрашивает БД (polling каждые 30 секунд) или реагирует на WebSocket-события в реальном времени. Когда задача попадает в активный статус, координатор вызывает специфичного агента из `.claude/agents/*.md`:

*   **Этап Planning:** Запускается `plan-coordinator`, который внутри себя в цикле вызывает `plan-polisher` для итеративного улучшения плана.
*   **Этап Implementing:** Запускается `implement-coordinator`. Он анализирует план, строит граф зависимостей. Если задачи можно выполнять параллельно, он спавнит субагентов `implement-worker` (используя git worktrees для изоляции).
*   **Этап Review:** Запускаются `review-sidecar` и `security-sidecar`. Если включен режим `autoMode`, их замечания автоматически парсятся, и координатор сам отправляет задачу обратно на доработку (rework).

## 4. Режимы выполнения (Execution Modes)
Система поддерживает два режима (переключаются через `AGENT_USE_SUBAGENTS`):
*   **Subagents (true):** Медленный, но качественный режим. Используются координаторы, которые спавнят субагентов для параллельной работы и итеративных проверок.
*   **Skills (false):** Быстрый режим. Каждый этап (`planning`, `implementing`) выполняется за один проход как один скилл (например, `/aif-plan`), экономя токены, но без "шлифовки".

## 5. Интеграция с Claude SDK и MCP
Агенты настраиваются через стандартные markdown-файлы в папке `.claude/agents/` (загружаются через `settingSources: ["project"]`). Handoff взаимодействует с ними, передавая специальную переменную окружения `HANDOFF_MODE=1`. В этом режиме агенты знают, что они работают автономно (без ручного ввода в терминале) и не должны использовать интерактивные промпты. Взаимодействие с базой данных происходит либо напрямую координатором (node.js), либо через инструменты MCP (`mcp__handoff__*`).
