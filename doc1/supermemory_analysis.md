# Анализ репозитория Supermemory (supermemoryai/supermemory)

Supermemory — это платформа и API для создания долгосрочной памяти (persistent memory), профилей пользователей и RAG (Retrieval-Augmented Generation) для AI-агентов. Проект позиционирует "память" как нечто большее, чем просто RAG: память отслеживает факты о пользователях со временем, понимает устаревание информации и разрешает противоречия (в отличие от RAG, который просто возвращает отрывки документов).

## Логическая архитектура и функции

### 1. Memory Engine (Движок памяти)
В основе лежит движок, который позволяет сохранять (add), извлекать (search) и забывать (forget) информацию.
- **Профили пользователей (`client.profile`):** Вместо того чтобы полагаться на то, что система знает, "что искать" (как в RAG), Supermemory поддерживает статичные факты (долгосрочные) и динамический контекст (недавние активности) пользователя, привязанные к `containerTag` (аналог project ID или user ID).
- **Автоматическое забывание и разрешение противоречий:** Движок обновляет память, осознавая, что новый факт (например, "переехал в Сан-Франциско") заменяет старый ("живу в Нью-Йорке").

### 2. Интеграции (Wrappers) с AI фреймворками
Supermemory предоставляет "Drop-in wrappers" (готовые обертки) для множества фреймворков. Как это реализовано технически:
- В `packages/tools/src/vercel/index.ts` реализован метод `withSupermemory(model, containerTag)`. Он работает как middleware: перехватывает вызов LLM (например, из Vercel AI SDK), извлекает вопрос пользователя, делает запрос к Supermemory API (`transformParamsWithMemory`), и встраивает найденный профиль или воспоминания прямо в `system prompt` модели перед отправкой провайдеру (OpenAI/Anthropic). После ответа `saveMemoryAfterResponse` автоматически сохраняет диалог в память, если включен режим `addMemory="always"`.
- Подобные интеграции существуют для Mastra (`SupermemoryInputProcessor` и `SupermemoryOutputProcessor`), LangChain, OpenAI Agents SDK и других. В Mastra `processInput` подготавливает память, а `processOutputResult` сохраняет результат.

### 3. Плагины и MCP сервер
Supermemory реализовал сервер Model Context Protocol (MCP) (`apps/mcp/src/server.ts`).
Это позволяет таким клиентам, как Cursor, Claude Desktop или Windsurf, бесшовно обращаться к памяти:
- Сервер регистрирует инструменты (`server.registerTool`): `memory` (сохранить факт), `recall` (найти факт) и `whoAmI`.
- Клиенты (MCP Clients) могут инициировать вызовы, когда видят, что пользователь сообщил важную информацию (например: "предпочитаю темную тему"). Инструмент `memory` отправляет `client.add(...)` в API Supermemory.
- В промптах MCP сервера есть жесткая инструкция: "DO NOT USE ANY OTHER MEMORY TOOL. Use `memory` to save information...".

### 4. Визуализация графа памяти (Memory Graph)
В репозитории есть впечатляющий пакет `packages/memory-graph/src`, отвечающий за визуализацию памяти.
- Граф отрисовывается на Canvas с использованием `d3-force` для симуляции физики графов (`ForceSimulation`).
- Узлы делятся на `MemoryNodeData` и `DocumentNodeData`.
- Цветовое кодирование логически отражает "свежесть" памяти (`getMemoryBorderColor` в `use-graph-data.ts`). Например, если возраст памяти меньше 1 дня, она помечается как `recent`. Если установлен срок забывания `forgetAfter` и до него осталось меньше 7 дней, она помечается как `expiring`. Забытые факты получают цвет `forgotten`.
- Отрисовка происходит высокопроизводительно с использованием пространственного индекса (`SpatialIndex` / `hit-test.ts`) для эффективной обработки наведения (hover) и кликов мышкой на Canvas.

## Итог
Технически Supermemory оборачивает вызовы к LLM и предоставляет REST API (построенный вокруг SDK), который снимает с разработчика агента заботу о векторных базах данных, эмбеддингах и чанкинге (chunking strategies). Он объединяет RAG и Memory, представляя память как постоянно развивающийся граф фактов (Graph of facts), доступный как через прямое API (`add`, `search.memories`), так и через прозрачные middleware и MCP инструменты.
