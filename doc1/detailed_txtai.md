# Технический анализ txtai: Интеграция SQL и семантического поиска

## Архитектура комбинированного поиска (Hybrid Search)
txtai решает задачу объединения классического реляционного поиска (фильтрации) и семантического сходства (эмбеддинги). Разработчикам больше не нужно вручную скрещивать SQL-запросы к Postgres/SQLite и запросы к векторной БД (как Faiss или pgvector). В txtai это инкапсулировано в одном интерфейсе.

## Механизм SQL-парсинга
В `src/python/txtai/database/sql/base.py` реализован пользовательский парсер SQL:
1. **Трансляция запросов (Translation):** Парсер анализирует SQL запрос (разбивая его на токены `select`, `from`, `where`, `order`, `limit` и др. через `Expression` классы) и переводит его в нативный язык подлежащей СУБД (DuckDB, SQLite).
2. **Функция `SIMILAR()`:** Главное нововведение txtai — внедрение специальной функции подобия `SIMILAR(column, "text")` непосредственно в SQL-синтаксис. Парсер перехватывает этот вызов.
3. **Выполнение (Execution):**
   - Сначала txtai исполняет векторный поиск по индексу (`self.indexes` из `base.py`) для вычисления семантической релевантности и получения внутренних `id` подходящих документов.
   - Затем подлежащая СУБД выполняет SQL-запрос. Условия `WHERE` (например, фильтрация по датам или авторам) применяются поверх документов, найденных (или пересекающихся с) результатами векторного поиска.
   - Поддерживаются агрегации (`group by`), сортировки и комбинирование полнотекстового индекса БД с плотным векторным индексом.

Это дает бесшовный опыт, когда разработчик может выполнить запрос вида: `SELECT id, text, score FROM txtai WHERE SIMILAR('AI') AND date >= '2023-01-01'`, и `txtai` под капотом технически свяжет векторный HNSW/Faiss индекс с SQL-движком базы данных.
