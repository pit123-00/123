# Технический анализ OpenViking: Информационные слои контекста (Context Layers L0/L1/L2)

Одной из главных архитектурных особенностей OpenViking является трехуровневая информационная модель (L0/L1/L2). Это решает ключевую проблему LLM-агентов: как дать агенту доступ к огромным базам знаний, не переполняя контекстное окно (Token Limit) и не расходуя дорогостоящие токены.

## Архитектура слоев (L0, L1, L2)

### L0: Abstract (Абстракция)
- **Файл:** `.abstract.md`
- **Лимит токенов:** Около 100 токенов.
- **Техническая роль:** Используется в качестве основного вектора для предварительного поиска (Vector search) и быстрой фильтрации. Это ультра-короткое описание (выжимка), которое позволяет системе и агенту за миллисекунды понять, относится ли данный файл/каталог к запросу. Для бинарных файлов (изображения, видео) этот файл содержит краткое текстовое описание.

### L1: Overview (Обзор)
- **Файл:** `.overview.md`
- **Лимит токенов:** Около 2 000 токенов.
- **Техническая роль:** Используется для стадии переранжирования (Rerank) и навигации. L1 действует как "оглавление" папки или документа. Он содержит подзаголовки, ключевые факты и точные ссылки (`viking://...`) на детали (L2). Чаще всего именно этот слой попадает в контекст LLM-агента, так как он достаточно информативен, чтобы решить задачу без чтения всего текста.

### L2: Detail (Детальный уровень)
- **Файлы:** Исходные файлы и подкаталоги (например, `oauth.md`).
- **Лимит токенов:** Не ограничен (Unlimited).
- **Техническая роль:** Полный контент. Этот слой подгружается **строго по требованию** (On-demand loading), когда агент осознанно решает, что ему нужны полные детали (вызывая метод `read("viking://...")`).

## Механизм генерации (Generation Mechanism)

Создание структуры L0/L1 происходит автоматизировано в двух сценариях:
1. **При добавлении ресурсов (Resources):** Документ проходит стадию парсинга (Parser), а затем асинхронный компонент `SemanticQueue` (используя `SemanticProcessor`) генерирует L0 и L1.
2. **При архивации сессий (Sessions):** Компонент `SessionCompressor` генерирует абстракты и обзоры для исторических сегментов чатов.

**Порядок генерации — "Снизу-вверх" (Bottom-up):**
Сначала генерируются L0/L1 для листовых узлов (файлов). Затем абстракты дочерних файлов агрегируются для генерации L1 родительского каталога. Это позволяет строить иерархическую навигацию по файловой системе.

## Мультимодальность
Слои L0 и L1 **всегда** представляют собой текст в формате Markdown. Слой L2 может содержать файлы любого формата (изображения, аудио, видео). При парсинге (например, скриншота) LLM описывает его содержимое, и это описание ложится в основу `.overview.md` и `.abstract.md`, позволяя агенту "искать" картинки с помощью текстового семантического поиска.
