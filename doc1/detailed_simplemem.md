# Технический анализ SimpleMem: Многопроекционное индексирование и Адаптивный поиск

## Многопроекционное индексирование (Structured Indexing)
SimpleMem преобразует разрозненные элементы общения (фрагментированные атомы) в высокоуровневую молекулярную структуру памяти. Этот процесс реализован в `core/memory_builder.py`.
Для того, чтобы поиск был максимально надежным, память индексируется в трех слоях (проекциях):
1. **Семантический слой (Semantic Layer):** Создание плотных векторов (embeddings) через модели (например, OpenAI embeddings), чтобы улавливать общий смысл и тематику.
2. **Лексический слой (Lexical Layer):** Сохранение точных ключевых слов с помощью алгоритмов типа BM25. Полезно для точного совпадения имен, аббревиатур.
3. **Символический слой (Symbolic Metadata):** Хранение метаданных (абсолютные временные метки событий, участники, авторы).

Эти три слоя синхронно записываются в LanceDB (или аналогичное векторное хранилище).

## Адаптивный поиск (Adaptive Query-Aware Retrieval)
Традиционные системы извлекают строго заданное (Top-K) число документов (k=5, k=10). В `core/hybrid_retriever.py` (Hybrid Retriever) реализован механизм, динамически изменяющий глубину поиска на основе оценки сложности пользовательского вопроса.

1. **Планирование запроса (Intent-Aware Retrieval Planning):** LLM анализирует вопрос пользователя и разбивает его на три подзапроса: $q_{sem}$ для семантического поиска, $q_{lex}$ для BM25 и $q_{sym}$ для фильтрации по метаданным. Одновременно вычисляется "сложность запроса" ($C_q$).
2. **Динамическая глубина:** Если вопрос сложный и многогранный, базовое количество результатов увеличивается: $k_{dyn} = \lfloor k_{base} \cdot (1 + \delta \cdot C_q) \rfloor$.
3. **Параллельное извлечение и слияние (Result merging):** Поиск идет параллельно по трем слоям (semantic, bm25, metadata). Затем результаты объединяются: $R_{sem} \cup R_{lex} \cup R_{sym}$. Это гарантирует, что ни одна деталь (даже точное совпадение слова или дата) не будет потеряна.
