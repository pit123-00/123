# Технический анализ Mastra: Интеграция Postgres для Workflows

## Схемы баз данных для рабочих процессов
Mastra использует Postgres для персистентного хранения состояния детерминированных графов выполнения (Workflows) и памяти агентов. В исходном коде (`packages/core/src/storage/constants.ts` и `stores/pg/src/storage/db/index.ts`) определены основные таблицы и их структуры.

### 1. Таблица `mastra_workflow_snapshot` (TABLE_WORKFLOW_SNAPSHOT)
Эта таблица хранит состояние выполнения конкретного рабочего процесса. Схема включает в себя:
- `workflow_name` (text): Имя выполняемого процесса.
- `run_id` (text): Уникальный идентификатор запуска.
- `resourceId` (text, nullable): Привязка к конкретному ресурсу.
- `snapshot` (jsonb): Полное сериализованное состояние процесса, включая пройденные шаги, результаты промежуточных вычислений и переменные контекста.
- `createdAt` (timestamp): Время создания снапшота.
- `updatedAt` (timestamp): Время последнего обновления состояния.

При инициализации Postgres хранилища, Mastra динамически генерирует запросы `CREATE TABLE IF NOT EXISTS`, используя эти схемы. Для `mastra_workflow_snapshot` также создается уникальный constraint на комбинацию `workflow_name` и `run_id`, чтобы гарантировать идемпотентность запусков.

### 2. Другие ключевые таблицы
- `mastra_messages` и `mastra_threads`: Хранят историю переписки агентов. `messages` сохраняет контент, роли и привязки к `threadId`.
- `mastra_agents` и `mastra_agent_versions`: Сохраняют конфигурации агентов и их версионирование.

### Механика работы
Когда `Workflow` запускается, движок выполнения (`Execution Engine`) периодически (или на каждом шаге) вызывает интерфейс хранилища, чтобы обновить запись `snapshot` в таблице `mastra_workflow_snapshot`. Формат `jsonb` позволяет гибко сохранять древовидную структуру данных (ProcessorState). Это дает возможность приостанавливать, возобновлять и отменять (cancel) длительные конвейеры, восстанавливая их состояние из Postgres.
