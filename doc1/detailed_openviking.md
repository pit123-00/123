# Технический анализ OpenViking (volcengine/OpenViking)

## Архитектура Context Database
OpenViking — это специализированная "Контекстная база данных" (Context Database) для AI агентов. Она решает проблему фрагментированного контекста, объединяя воспоминания (Memory), ресурсы (Resource) и навыки (Skill) в единую файловую структуру (Viking URI).
Система спроектирована как единый менеджер состояния для ИИ. Кодовая база содержит:
- **`viking_fs`** — реализация виртуальной файловой системы для хранения данных (`viking://user/...` и `viking://agent/...`).
- Интеграция с векторными базами данных, такими как LanceDB, для семантического поиска (`openviking/storage/viking_db.py`).

## Трехуровневая модель извлечения информации (Context Layers)
Вместо того чтобы при каждом запросе загружать полный текст документов (что тратит огромное количество токенов), OpenViking использует модель `L0 / L1 / L2`:
- **L0 (Abstract):** Краткая выжимка контента (основная суть документа). Хранится в файле `.abstract.md`.
- **L1 (Overview):** Оглавление и профиль документа (заголовки, ключевые моменты). Хранится в файле `.overview.md`.
- **L2 (Full Content):** Полный текст документа.
Система подгружает нужный уровень детализации "по требованию". Сначала агент видит только L0/L1, а полный текст (L2) читается лишь в случае необходимости. Это кардинально экономит токены LLM, как показано в бенчмарках OpenClaw.

## Иерархический поиск (Hierarchical Retriever)
В `openviking/retrieve/hierarchical_retriever.py` реализован механизм `_recursive_search`, который позволяет глубоко погружаться в файловую структуру.
Процесс поиска разбит на две стадии:
1. **Предварительный отбор (Vector Search + Intent Analysis):** Извлечение кандидатов из векторной базы данных (`_global_vector_search`) на основе векторного подобия (Semantic Search) с последующим ре-ранжированием (`_rerank_scores`) с помощью внешнего `RerankClient` (например, Cohere или BGE-reranker).
2. **Директорийный поиск:** Учитывая файловую парадигму `viking://...`, система обходит директории `_recursive_search`, читая `overview.md` или `abstract.md`, чтобы определить, нужно ли спускаться на более глубокие уровни (L1 -> L2). Это объединяет традиционный поиск по папкам (как на жестком диске) с семантическим поиском.

## Автоматическая сессионная итерация памяти
Функция автоматического управления сессиями извлекает значимую информацию из бесед и переводит её в долгосрочную память.
Реализовано в `openviking/session/memory_extractor.py` и `openviking/session/memory/extract_loop.py`.
- Система отслеживает 8 категорий воспоминаний (User: `profile, preferences, entities, events`. Agent: `cases, patterns, tools, skills`).
- В конце сеанса запускается оркестратор (`ExtractLoop`), который использует ReAct (Reasoning and Acting) подход с единым вызовом LLM для принятия решений.
- Обновление памяти (Compressor/Deduplicator) сжимает новые факты из чата, дедуплицирует их и формирует JSON, который записывается по URI `viking://user/memories/` или `viking://agent/memories/`.
- Память жестко разделяется на User Space и Agent Space с помощью системы изоляции `RequestContext`, обеспечивая четкую Multi-tenant изоляцию.
