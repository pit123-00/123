# Технический анализ OpenViking (volcengine/OpenViking)

## Архитектура Context Database
OpenViking — это специализированная "Контекстная база данных" (Context Database) для AI агентов. Она решает проблему фрагментированного контекста, объединяя воспоминания (Memory), ресурсы (Resource) и навыки (Skill) в единую файловую структуру (Viking URI).

## Трехуровневая модель извлечения информации (Context Layers)
Вместо того чтобы при каждом запросе загружать полный текст документов (что тратит огромное количество токенов), OpenViking использует модель `L0 / L1 / L2`:
- **L0 (Abstract):** Краткая выжимка контента (основная суть документа).
- **L1 (Overview):** Оглавление и профиль документа (заголовки, ключевые моменты).
- **L2 (Full Content):** Полный текст документа.
Система подгружает нужный уровень детализации "по требованию". Сначала агент видит только L0/L1, а полный текст (L2) читается лишь в случае необходимости.

## Иерархический поиск (Directory Recursive Retrieval)
Технически процесс поиска разбит на две стадии:
1. **Предварительный отбор (Vector Search + Intent Analysis):** Извлечение кандидатов из подлежащей векторной базы данных (на основе LanceDB) на основе векторного подобия (Semantic Search) с последующим ре-ранжированием (Rerank).
2. **Директорийный поиск:** Учитывая файловую парадигму `viking://...`, система позволяет делать поиск только в рамках конкретных URI.

## Автоматическая сессионная итерация памяти
Функция автоматического управления сессиями (Session Commit) извлекает значимую информацию из бесед и переводит её в долгосрочную память.
- Система отслеживает 8 категорий воспоминаний (например, предпочтения пользователя, факты о сущностях).
- В конце сеанса запускается асинхронный процесс (`MemoryExtractor`), который сжимает и дедуплицирует новые данные с помощью LLM (Compressor), после чего сохраняет их по URI `viking://user/memories/` или `viking://agent/memories/`.
- Память разделяется на User Space и Agent Space, обеспечивая четкую изоляцию контекста (Multi-tenant isolation).
