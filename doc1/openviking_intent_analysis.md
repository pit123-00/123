# Технический анализ OpenViking: Анализ намерений и API поиска (Intent Analysis)

OpenViking разделяет процессы извлечения информации на два логических потока: простую фильтрацию и интеллектуальный семантический поиск, управляемый контекстом сессии.

## Отличие `find()` и `search()`
API поиска предоставляет два разных метода:
1. **`find()`:** Используется для прямолинейных запросов, когда пользователю нужно найти конкретный файл. Не требует контекста сессии, не использует LLM для анализа намерений. Отличается низкой задержкой (Low latency) и выполняет только один `TypedQuery`.
2. **`search()`:** Применяется для выполнения комплексных задач ("Помоги мне написать документ RFC"). Этот метод требует передачи текущего сессионного контекста (истории чата), имеет более высокую задержку и привлекает LLM для формирования от 0 до 5 специфичных поисковых запросов `TypedQuery`.

## Модуль `IntentAnalyzer`
Модуль `IntentAnalyzer` является "мозгом" функции `search()`. Перед тем как обращаться к файловой системе или векторной базе данных, он:
1. Собирает саммари сессии (Session compression summary), последние 5 сообщений из чата и текущий запрос пользователя.
2. Отправляет эти данные в LLM (VLMBase) для декомпозиции задачи.

### Структура `TypedQuery`
LLM генерирует список (query plan) из нескольких `TypedQuery`. Каждый запрос строго типизирован по контексту:
- **`query` (str):** Переписанный и очищенный поисковой запрос.
- **`context_type` (ContextType):** К какой части файловой системы обращаться (MEMORY, RESOURCE, SKILL).
- **`intent` (str):** Текстовое описание того, зачем нужен этот запрос (для последующего Rerank).
- **`priority` (int):** Приоритет от 1 до 5.

Например, для `context_type=skill` запросы начинаются с глагола ("Create RFC document", "Extract PDF tables"), для `resource` — с существительного ("API usage guide"), а для `memory` — указывают на пользователя ("User's code style preferences").

### Обработка исключений
- Если запрос представляет собой простой `Привет!` (chitchat), `IntentAnalyzer` может вернуть пустой план (0 запросов), чтобы не тратить ресурсы на поиск.
- Если задача комплексная, `IntentAnalyzer` сгенерирует сразу несколько параллельных поисковых потоков: один пойдет искать навык форматирования в `SKILL`, другой — документацию в `RESOURCE`, а третий — стиль написания конкретного человека в `MEMORY`.

Это обеспечивает максимальную релевантность и точность ответа агента.
