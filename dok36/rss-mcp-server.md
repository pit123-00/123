# Анализ репозитория: rss-mcp-server

## 1. Техническая реализация и архитектура
Проект `rss-mcp-server` представляет собой сервер, реализующий протокол MCP (Model Context Protocol). Он написан на Python и служит мостом между Large Language Models (LLM) и RSS-сервисами, поддерживающими FreshRSS API (в частности, совместим с Google Reader API).
В основе архитектуры лежит библиотека `fastmcp`, которая оборачивает Python-функции в инструменты MCP, доступные для LLM. Для выполнения HTTP-запросов к RSS-сервису используется синхронная библиотека `requests`. Код монолитен и сосредоточен в одном файле `main.py`. Сервер запускается и работает по протоколу SSE (Server-Sent Events) или STDIO, что характерно для MCP.

## 2. Функции и как логически это работает
Сервер предоставляет более 20 инструментов (`@mcp.tool()`), позволяющих LLM управлять RSS-подписками пользователя:
- **Подписки и папки:** добавление (`add_subscription`), удаление, переименование, перемещение подписок и создание папок.
- **Управление статьями:** получение списков статей (`get_all_entries`, `get_starred_articles`, `parse_feed_url`), отметка как прочитанных/непрочитанных.
- **Теги и закладки:** добавление/удаление тегов, управление избранным (starred) и шарингом.
- **Поиск:** поиск по каталогу и конкретным статьям.

Логика работы:
1. При старте сервер инициализирует класс `GoogleReaderClient`, считывая логин, пароль и базовый URL из переменных окружения (`.env`).
2. Клиент аутентифицируется (`ClientLogin`) и получает токены `SID`, `Auth` и `T`.
3. LLM через клиент MCP вызывает один из зарегистрированных инструментов.
4. Функция-инструмент формирует нужные параметры (ID статьи, URL фида и т.д.) и вызывает `client.make_request`.
5. Класс-клиент проверяет валидность токена (при необходимости переподключается), выполняет HTTP-запрос к FreshRSS API и возвращает распарсенный ответ.

## 3. Как происходит обмен информации память потоки данных
- **Память и состояние:** Состояние приложения минимально и хранится в экземпляре класса `GoogleReaderClient` (в виде токенов `sid`, `auth`, `token`). Если сервер перезапускается, токены запрашиваются заново.
- **Потоки данных:**
  1. Входной поток от LLM поступает через FastMCP в виде JSON-RPC вызовов инструментов.
  2. Внутри Python эти параметры преобразуются в HTTP `GET` или `POST` запросы (часто с передачей данных в формате `application/x-www-form-urlencoded` или query-параметрах).
  3. RSS-сервер (FreshRSS) возвращает данные в форматах JSON или XML.
  4. Метод `make_request` читает заголовки ответа (`Content-Type`). Если это JSON, он использует `json.loads()`; если XML — парсит через `xml.etree.ElementTree`. Тексты предварительно очищаются от экранирования через `html.unescape`.
  5. Распарсенные данные (словари Python) сериализуются FastMCP обратно в текстовый/JSON формат и отправляются LLM.
