# Отчет по анализу репозитория twitter-rss

## 1. Техническая реализация и архитектура
Проект **twitter-rss** — это утилита на TypeScript/Node.js, которая ищет твиты по заданным ключевым словам и конвертирует результаты поиска в статические RSS-ленты.
- **Язык:** TypeScript.
- **Сборка и зависимости:** Используется Node.js. Зависимости (указаны в `package.json`): `twitter-openapi-typescript` (неофициальный клиент к API Twitter), `twitter-scraper` (для процесса логина и получения cookie), `fast-xml-parser` (для генерации XML), `log4js`.
- **Инфраструктура:** Проект имеет `Dockerfile` и `docker-compose.yml`, что позволяет запускать его в изолированном контейнере, а также скрипт `entrypoint.sh` для запуска по cron-расписанию (`CRON_SCHEDULE`).
- **Архитектура:** Это CLI-приложение (скрипт). Основная логика содержится в единственном файле `src/main.ts`.

## 2. Функции и как логически это работает
Twitter-rss парсит X (Twitter) и делает RSS ленту конкретно **по результатам поиска**.

**Логика работы:**
1. При старте (`main.ts` -> `main()`) приложение проверяет наличие директории `output/`.
2. **Авторизация (`getAuthCookies`):** Поскольку Twitter запрещает поиск без авторизации, скрипт использует логин и пароль (`TWITTER_USERNAME`, `TWITTER_PASSWORD`, и опционально `TWITTER_EMAIL`, `TWITTER_2FA_SECRET`), переданные через переменные окружения. Он использует библиотеку `twitter-scraper` (которая имитирует браузер, вероятно через Puppeteer или CycleTLS) для входа в аккаунт и получения сессионных кук (`auth_token` и `ct0`). Эти куки кэшируются в файл `.cookies.json`, чтобы не логиниться каждый раз.
3. **Парсинг поиска (`generateRSS`):**
   - Скрипт инициализирует клиент `TwitterOpenApi` с полученными куками.
   - Читает файл `data/searches.json`, в котором лежат пары "Имя ленты": "Поисковый запрос".
   - В цикле для каждого поискового запроса:
     - Вызывает API Twitter: `client.getTweetApi().getSearchTimeline({ rawQuery, product: 'Latest' })`.
     - Извлекает массив твитов (`tweets`).
     - Отфильтровывает рекламные твиты (`!tweetResult.promotedMetadata`).
     - Формирует `TweetData`: извлекает текст, автора, дату, медиа (картинки).
     - Превращает `TweetData` в RSS Item (`escapeHtml` используется для предотвращения XSS).
     - Генерирует XML с помощью `fast-xml-parser` (класс `XMLBuilder`).
     - Записывает результат в файл `output/<filename>.xml`.
4. **Создание индекса (`generateList`):**
   - После генерации всех XML-файлов скрипт читает содержимое папки `output/`.
   - Берет шаблон `template.html`.
   - Генерирует корневой `index.html` со списком ссылок на все сгенерированные RSS-ленты.
5. Приложение завершает работу (с очисткой процессов `cycleTLS`).

## 3. Обмен информации, память, потоки данных
- **Память и Данные:** Состояние хранится в виде файлов на диске: `data/searches.json` (входные настройки), `.cookies.json` (кэш авторизации) и папка `output/` (результат). В памяти скрипт хранит только текущий скачиваемый кусок данных поиска.
- **Потоки данных (Data Flow):**
  1. Чтение `searches.json` с диска.
  2. Если кэша авторизации нет или он просрочен -> запуск браузерного скрапера -> POST логин -> получение Cookies.
  3. Для каждого запроса: HTTP GET (через неофициальное API) к серверам Twitter с передачей Cookie `auth_token` и `ct0`.
  4. Получение JSON от Twitter.
  5. Трансформация JSON -> RSS XML-строка.
  6. Сохранение XML на диск.
  7. Чтение всех файлов -> генерация HTML -> сохранение HTML на диск.
- **Особенности и ограничения:** В скрипте реализован механизм повторных попыток (`withRetry` с exponential backoff), так как API Twitter может вернуть 429 Rate Limit Error или 500/502/504 ошибки (что часто бывает при парсинге). Используется `twitter-openapi-typescript`, который генерирует REST-клиент из OpenAPI спеки внутренних (приватных) API Twitter.
