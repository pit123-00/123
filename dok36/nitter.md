# Отчет по анализу репозитория Nitter

## 1. Техническая реализация и архитектура
Проект **Nitter** — это свободный, легковесный и ориентированный на конфиденциальность альтернативный фронтенд для Twitter/X.
- **Язык:** Nim (компилируемый статически типизированный язык с синтаксисом в стиле Python, отличающийся высокой производительностью).
- **Основа (Фреймворк):** Использует `Jester` (веб-фреймворк для Nim) и встроенные в язык средства асинхронности (`asyncdispatch`).
- **СУБД/Кэш:** В качестве кэша и базы данных используется Redis. Nitter не хранит информацию о пользователях в долгосрок (кроме локальных настроек браузера/cookies), Redis нужен только для агрессивного кэширования ответов от API Twitter.
- **Архитектура:** Приложение представляет собой монолит (`src/nitter.nim`), разделенный на логические модули:
  - `src/api.nim`, `src/apiutils.nim` — взаимодействие с неофициальным API Twitter.
  - `src/parser.nim` — парсинг JSON ответов от Twitter.
  - `src/routes/` — обработчики роутов (лента, профили, поиск, медиа).
  - `src/views/` — HTML генерация. Вместо традиционных текстовых шаблонизаторов (как Jinja/ERB) используется библиотека `htmlgen` (или кастомные макросы Nim), генерирующая HTML прямо на этапе компиляции из кода.

## 2. Функции и как логически это работает
Главная задача Nitter — позволить читать Twitter без необходимости логиниться, без JavaScript, без трекеров и без рекламы, экономя при этом трафик. Также он предоставляет RSS-ленты для Twitter-аккаунтов.

**Логика работы:**
1. Приложение при старте загружает пул "сессий" (`sessions.jsonl`). Это гостевые (или сгенерированные скриптами) токены авторизации Twitter, так как Twitter закрыл доступ без авторизации.
2. Когда пользователь запрашивает профиль `https://nitter.net/username`, запрос перенаправляется в роутер профилей (`src/routes/timeline.nim`).
3. Роутер проверяет кэш в Redis. Если кэш валиден, сразу отдается HTML.
4. Если нет — Nitter делает асинхронный HTTP(S) запрос (через свой `http_pool.nim`) к эндпоинтам GraphQL/v1.1 API Twitter (например, `api.twitter.com/graphql/...`). Для этого используются ротируемые токены из пула сессий.
5. Полученный от Twitter JSON парсится модулем `parser.nim`.
6. Сформированные структуры данных (твиты, пользователи, медиа) сериализуются и сохраняются в Redis (`redis_cache.nim`), чтобы следующие запросы (включая RSS ридеры) получали данные мгновенно и не расходовали лимиты Twitter.
7. Генератор представлений (`views/`) собирает минималистичный HTML. Все ссылки на медиа (картинки, видео) переписываются на локальные `/pic/...` или `/video/...`, чтобы пользователь не делал запросов напрямую к серверам Twitter (для защиты IP-адреса). Nitter проксирует медиа через себя (роут `media.nim`).
8. В Nitter реализован полноценный обработчик настроек (Preferences). Пользователь может выбрать тему, язык, формат проксирования видео. Эти настройки хранятся в Cookies (`prefs.nim`).

## 3. Обмен информации, память, потоки данных
- **Память и Многопоточность:** Nim компилируется в C/C++ и работает очень быстро. Для работы с сетью используется неблокирующий I/O (модуль `asyncdispatch`). Кэш полностью вынесен в Redis (`redisPool`), что позволяет запускать несколько инстансов Nitter за балансировщиком нагрузки.
- **Потоки данных (Data Flow):**
  1. `HTTP Request` -> `Jester Router`.
  2. Парсинг `Preferences` из Cookies.
  3. `redis_cache` проверяет наличие ключа.
  4. Если промах кэша (Cache Miss) -> берется свободный токен из пула сессий (`auth.nim`).
  5. `http_pool` формирует запрос к Twitter API (GraphQL) с подменой заголовков, чтобы имитировать браузер/официальное приложение.
  6. Twitter API отвечает JSON-ом. Если ответ 429 (Rate Limit), Nitter может пометить токен сессии как заблокированный и попробовать другой (или вернуть ошибку пользователю).
  7. Данные парсятся в Nim-объекты (`types.nim`).
  8. Данные пишутся в `Redis`.
  9. Nim-макросы HTML генерируют страницу (или RSS XML, если это был запрос `/username/rss`).
  10. Ответ с HTTP-заголовками отправляется клиенту.
- **Проксирование медиа:** Крайне важный элемент потока данных — медиа. Запросы вида `/pic/enc/...` попадают в `media.nim`. Модуль расшифровывает URL картинки (кодированный в Base64 с опциональным HMAC, чтобы избежать использования Nitter как открытого прокси для любых картинок в интернете), загружает изображение с серверов `pbs.twimg.com` и стримит (или отдает) его клиенту.
