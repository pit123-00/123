# Отчет по анализу репозитория Invidious

## 1. Техническая реализация и архитектура
Проект **Invidious** — это альтернативный легковесный веб-фронтенд для YouTube, созданный с фокусом на приватность и отсутствие рекламы.
- **Язык:** Crystal (строго типизированный компилируемый язык с синтаксисом, похожим на Ruby).
- **Основа (Фреймворк):** В качестве веб-фреймворка используется **Kemal** (микрофреймворк для Crystal, аналог Sinatra в Ruby).
- **СУБД:** PostgreSQL (взаимодействие идет напрямую через драйвер `DB`, пакет `pg`).
- **Архитектура:** Приложение представляет собой монолит (`src/invidious.cr` — точка входа).
  - Директория `src/invidious/routes/` содержит описания маршрутов (контроллеры).
  - Директория `src/invidious/yt_backend/` содержит логику работы с внутренним API YouTube (включая извлечение ключей, дешифровку подписей).
  - Директория `src/invidious/jobs/` содержит фоновые процессы (обновление подписок, кеширование популярных видео).
  - Директория `src/invidious/database/` отвечает за маппинг и запросы к PostgreSQL.
  - Фронтенд (HTML) рендерится на сервере (SSR) с помощью встроенных в Crystal макросов для шаблонов (`.ecr`), которые лежат в `src/invidious/views/`.
  - Директория `assets/` содержит статику (шрифты, CSS, а также плеер `videojs`).

## 2. Функции и как логически это работает
Главная задача Invidious — парсить YouTube (без использования официального ключа разработчика YouTube API, чтобы не зависеть от квот и ограничений) и предоставлять пользователям видео, поисковую выдачу и возможность управлять подписками локально.

**Логика работы:**
1. Приложение парсит непубличные API YouTube (такие как `Innertube API`, `pbj=1`, `ajax` эндпоинты) напрямую.
2. При запросе пользователя (например, просмотр видео `/watch?v=...`) контроллер вызывает функции из `yt_backend` (`extract_video_info`).
3. Invidious скачивает HTML или JSON страницу самого YouTube, парсит массивы данных (используя Regex, JSON парсеры и логику распаковки). Важной частью является модуль расшифровки (decipher) видеопотоков, так как YouTube защищает прямые ссылки на MP4.
4. После получения прямой ссылки на потоки (adaptive streams) и метаданных, данные передаются в шаблон `video.ecr`.
5. В браузере загружается плеер (на базе Video.js), который напрямую играет видеопоток (иногда через прокси Invidious, если включена опция "Proxy videos", чтобы полностью скрыть IP пользователя от Google).
6. **Пользовательская система:** Пользователи могут регистрироваться в инстансе Invidious (данные хранятся в PostgreSQL). Это позволяет подписываться на каналы и создавать плейлисты локально, без необходимости иметь аккаунт Google. Фоновые джобы (`RefreshChannelsJob`) периодически проверяют каналы на наличие новых видео и присылают пользователям уведомления/формируют ленту (feed).

## 3. Обмен информации, память, потоки данных
- **Память и Потоки:** Crystal компилируется в эффективный нативный код. Для ограничения одновременных соединений к YouTube и предотвращения блокировки IP используются пулы подключений `YoutubeConnectionPool` (с ограничением `pool_size` из конфигурации). Фоновые задачи реализованы через легковесные процессы (Fibers в Crystal), которые запускаются через методы класса `Invidious::Jobs`.
- **Потоки данных (Data Flow):**
  - **Запрос видео:**
    1. HTTP Request `/watch?v=xyz` -> `Kemal Router` -> `WatchController`
    2. `WatchController` -> `yt_backend.extract_video_info`
    3. `YoutubeConnectionPool` делает HTTPS запрос к `www.youtube.com/watch?v=xyz`
    4. Парсинг ответа (получение `player_response` JSON).
    5. Расшифровка URL-адресов видео/аудио потоков.
    6. Рендеринг страницы `watch.ecr`. Ответ отдается клиенту с встроенным `Video.js`.
  - **Проксирование медиа (опционально):**
    Если пользователь хочет проксировать медиа, Invidious выступает как стриминговый мост. Запрос `/videoplayback` попадает в Invidious -> Invidious открывает стрим к серверам Google (googlevideo.com) -> чанками переливает данные клиенту.
  - **База данных:** Используется для кэширования сессий, хранения пользователей (логин/пароль/настройки сессии хранятся в таблице `users`), подписок (`channels`, `subscriptions`), плейлистов и хранения статистики (`statistics`). Взаимодействие идет через пул соединений `PG_DB`.
  - **Уведомления:** Для оповещения пользователей о новых видео используется `::Channel` (каналы в Crystal для межпотокового взаимодействия) и `PQ::Notification` (механизм Pub/Sub в PostgreSQL).
