# Отчет по анализу репозитория RSS-Bridge

## 1. Техническая реализация и архитектура
Проект **RSS-Bridge** генерирует RSS-ленты из сайтов, на которых их изначально нет (аналогично RSSHub, но на стеке PHP).
- **Язык:** PHP (требуется >= 7.4).
- **Основа (Фреймворк):** Проект не использует тяжеловесные фреймворки (типа Laravel или Symfony). Это легковесный кастомный движок. Он использует собственную реализацию DI (Dependency Injection) через `Container.php`, кастомный роутинг (на базе файлов действий в `/actions`) и кастомную обработку запросов (`Request`, `Response`).
- **Архитектура Мостов (Bridges):** Основа системы — "мосты". Все скрипты интеграций лежат в директории `bridges/`. Каждый мост (например, `YouTubeBridge.php`, `TwitterBridge.php`) наследуется от базового класса `BridgeAbstract.php`.
- **Архитектура Форматов (Formats):** Как данные из моста будут представлены пользователю, решают классы форматов в директории `formats/` (например, `AtomFormat.php`, `JsonFormat.php`, `PlaintextFormat.php`).
- **Сторонние библиотеки:** Зависимостей минимум. Встроен простой HTML DOM парсер (`simple_html_dom`), библиотека Markdown (`parsedown`). Управление зависимостями через `composer.json` есть, но ядро может работать и просто за счет автолоадера.

## 2. Функции и как логически это работает
Главная задача: принять HTTP запрос пользователя, выбрать нужный "мост", выполнить логику парсинга и отдать данные в запрошенном формате (RSS, Atom, JSON и т.д.).

**Логика работы:**
1. Точка входа `index.php`. Выполняется базовая проверка окружения, инициализируется DI-контейнер (`lib/dependencies.php`) и перехватчики ошибок.
2. `index.php` создает инстанс `RssBridge` и вызывает `main()`.
3. Запрос парсится на наличие параметра `action`. По умолчанию вызывается `FrontpageAction` (отрисовка стартовой страницы со списком мостов).
4. При запросе RSS ленты вызывается `DisplayAction.php`. Он извлекает из запроса параметры `bridge` (имя нужного моста) и `format` (тип вывода).
5. Инициализируется цепочка `middlewares/` (базовая авторизация, кэширование, обработка исключений).
6. В `DisplayAction` инстанцируется класс конкретного моста через `BridgeFactory.php` и вызывается его метод `collectData()`.
7. Внутри `collectData()` мост использует вспомогательные функции (типа `getContents()` или `getSimpleHTMLDOM()`), делает HTTP запрос к целевому сайту, скрапит HTML или парсит JSON API сайта и заполняет внутренний массив `$this->items` объектами `FeedItem`.
8. `DisplayAction` инстанцируется нужный `Format` через `FormatFactory.php`, передает в него собранные элементы и вызывает `$format->render()`.
9. Результат возвращается пользователю. Если происходит ошибка (например, сайт заблокировал IP), она может быть отрендерена прямо в RSS-ленту как новая статья, чтобы уведомить пользователя.

## 3. Обмен информации, память, потоки данных
- **Память и Кэширование:** Архитектура кэширования строго модульная. Поддерживаются разные драйверы (описаны в `caches/`): `FileCache` (по умолчанию, файлы пишутся в `/cache/`), `MemcachedCache`, `SQLiteCache`, `ArrayCache`. Кэширование срабатывает на уровне Middleware (`CacheMiddleware.php`) перед вызовом моста и в самом `DisplayAction.php`. Кэшируется как финальный HTTP-ответ (срок жизни зависит от настроек моста, по умолчанию 1 час), так и промежуточные данные внутри мостов (например, токены).
- **Потоки данных (Data Flow):**
  1. `index.php` -> `Request` object -> `RssBridge->main()`.
  2. `RssBridge` -> `Middlewares` -> `DisplayAction`.
  3. `DisplayAction` -> `Cache::get()`. Если кэш есть, сразу отдаем `Response`.
  4. Если кэша нет: `DisplayAction` -> `TargetBridge->collectData()`.
  5. `TargetBridge` -> `http.php` (`getContents()` используя cURL).
  6. Целевой сайт возвращает данные (HTML/JSON).
  7. `TargetBridge` парсит данные и генерирует объекты `FeedItem`. Массив сохраняется в памяти инстанса моста.
  8. `DisplayAction` забирает `$bridge->getItems()` и передает их в `Format`.
  9. `Format` конвертирует `FeedItem` в строку XML/JSON.
  10. `DisplayAction` -> сохраняет ответ в `Cache` -> формирует `Response` -> `index.php` -> `echo`.
- **Обработка ошибок:** Сложная система обработки сбоев. Если целевой сайт недоступен, выдается `ClientException` или `HttpException`. Ошибки могут складываться в кэш и при достижении лимита отчетов (`report_limit`) ошибка может выводиться пользователю прямо как запись в RSS, содержащая URL для быстрого создания Issue на GitHub (`createGithubIssueUrl`).
- **Синхронность:** В отличие от TelegramRSS (Amphp) или RSSHub (Node.js), RSS-Bridge полностью синхронный. Каждый запрос блокирует PHP-воркер (php-fpm), пока не завершится запрос к целевому сайту.
