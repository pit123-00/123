# Отчет по анализу репозитория GitHubTrendingRSS

## 1. Техническая реализация и архитектура
Проект **GitHubTrendingRSS** — это CLI-утилита, написанная на языке **Swift** (с использованием Swift Package Manager), которая собирает данные о трендовых репозиториях на GitHub и генерирует из них статические RSS-ленты и `index.html`.
- **Язык:** Swift 5+.
- **Сборка и зависимости:** Используется `Package.swift`. Основные зависимости: `Kanna` (для парсинга HTML), `Stencil` (для шаблонизации), `PathKit`, `RxSwift` (возможно использовался ранее, сейчас код активно использует Swift Concurrency `async`/`await`).
- **Архитектура:** Приложение разделено на два модуля (targets):
  - `GitHubTrendingRSS` — исполняемый файл (точка входа `main.swift`).
  - `GitHubTrendingRSSKit` — библиотека с бизнес-логикой. Содержит модели (Models) и менеджеры (Managers: `DownloadManager`, `GitHubDownloader`, `GitHubPageParser`, `GitHubGraphQLManager`, `FeedFileCreator`).
- **Модель работы:** Это статический генератор. При запуске он скачивает страницу GitHub Trending, парсит все языки, затем асинхронно скачивает репозитории для каждого языка и периода (daily, weekly, monthly), генерирует XML (RSS) файлы и складывает их в директорию `output/` (или настроенную), а также собирает главную страницу `index.html`.

## 2. Функции и как логически это работает
Поскольку у GitHub нет официального RSS для раздела Trending, этот инструмент восполняет этот пробел.

**Логика работы (`main.swift`):**
1. Инициализируются менеджеры (загрузчик, парсер, шаблонизатор `Stencil`).
2. Вызывается `gitHubDownloader.fetchTopTrendingPage()`, который скачивает HTML-страницы `https://github.com/trending`.
3. `GitHubPageParser.languageTrendingLinks` скрапит ссылки на тренды по всем доступным языкам программирования.
4. В цикле по периодам (`daily`, `weekly`, `monthly`) создаются асинхронные задачи (TaskGroups, `parallelDownloadChunk = 4`), чтобы не скачивать все последовательно (ускоряет работу).
5. Для каждого языка:
   - `gitHubDownloader.fetchRepositories(...)` скачивает тренды конкретного языка.
   - Скрапится базовая информация: название репозитория, описание, звезды, форки, кто закоммитил.
   - Опционально для популярных языков скачивается и парсится `README.md`.
   - `GitHubGraphQLManager.fetchRepositoriesOGImages` через официальный GraphQL API GitHub достает картинки OpenGraph для репозиториев (используя токен авторизации).
6. Собранные данные передаются в `FeedFileCreator`, который через `SiteSourceMaker` (на базе Stencil) генерирует XML файл ленты RSS (например, `output/daily/swift.xml`).
7. В конце `FeedFileCreator` генерирует корневой `index.html` со списком всех сгенерированных RSS-лент.
8. Программа завершается с кодом 0.

## 3. Обмен информации, память, потоки данных
- **Память и Асинхронность:** Вся работа с сетью построена на современном Swift Concurrency (`async`/`await` и `TaskGroup`). Приложение делает множество параллельных HTTP-запросов (HTML скрапинг и GraphQL запросы). Потребление памяти ограничено разбиением запросов на чанки (chunked).
- **Потоки данных (Data Flow):**
  1. `DownloadManager` делает HTTP GET запрос -> получает сырой `String` HTML.
  2. `GitHubPageParser` (через библиотеку `Kanna`) конвертирует `String` в DOM, применяет CSS-селекторы (XPath) и извлекает `[Repository]`.
  3. `GitHubGraphQLManager` формирует POST-запрос с JSON к `api.github.com/graphql` и обогащает `Repository` ссылками на `OpenGraphImageUrl`.
  4. Модели передаются в шаблонизатор `Stencil` (внутри `SiteSourceMaker`), где подставляются в XML-шаблон (вместе с поддержкой GitHub Emojis, которые парсятся на лету и заменяются на картинки).
  5. Сгенерированная строка XML пишется на диск через `FileManager`.
- **Интеграция / Деплой:** Предполагается, что скрипт запускается по расписанию (cron или GitHub Actions), собирает папку со статическими `xml/html` файлами и деплоит их на GitHub Pages или любой другой статический хостинг. Этим объясняется отсутствие демона/веб-сервера (в отличие от RSSHub или Podsync).
