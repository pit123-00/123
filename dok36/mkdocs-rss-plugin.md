# Анализ репозитория: mkdocs-rss-plugin

## 1. Техническая реализация и архитектура
Проект `mkdocs-rss-plugin` представляет собой плагин для популярного генератора статических сайтов `MkDocs`. Написан на Python.
Архитектурно он встраивается в хуки (hooks) жизненного цикла сборки MkDocs. Плагин наследуется от базового класса плагинов MkDocs и регистрирует свои методы на определенные события (например, конфигурация, обработка страниц, финализация сборки).
Для своей работы он не требует сложных баз данных или серверных процессов. Все данные генерируются локально во время выполнения команды `mkdocs build`.

## 2. Функции и как логически это работает
Основная задача плагина — автоматическая генерация лент новостей в форматах RSS 2.0 и JSON Feed 1.1 на основе Markdown-страниц сайта.
**Функционал:**
- Автоматически извлекает даты создания и модификации из Git логов (команда `git log`) или из метаданных страниц (YAML frontmatter).
- Генерирует 4 файла фидов: 2 файла сортируются по дате создания (RSS и JSON) и 2 по дате обновления (RSS и JSON).
- Учитывает параметры из `mkdocs.yml`: заголовок сайта (`site_name`), описание (`site_description`), URL (`site_url`).
- Поддерживает фильтрацию: какие пути/страницы включать в фид, сколько элементов выводить (лимит).
- Умеет генерировать превью статей (abstracts), обрезая контент по символам или специальному делителю (например, `<!-- more -->`).
- Интегрируется с темой Material for MkDocs (подхватывает картинки `social cards`, поддерживает блог-функционал темы).

**Логика работы:**
1. Плагин инициализируется и читает свою конфигурацию из файла `mkdocs.yml`.
2. На этапе обработки каждой страницы плагин извлекает её метаданные, HTML-контент, дату из Git или YAML.
3. Собранные данные (страницы) агрегируются во внутренний список.
4. В конце сборки сайта плагин сортирует этот список по датам, обрезает по заданному лимиту длины, формирует XML и JSON файлы и сохраняет их в директорию `site` (вместе с остальными сгенерированными HTML файлами).

## 3. Как происходит обмен информации память потоки данных
- **Память и состояние:** Состояние плагина существует только во время выполнения сборки `mkdocs build`. Плагин накапливает объекты с метаданными страниц (путь, заголовок, даты, URL картинки, абстрактный текст) в памяти (часто в виде Python-словарей или датаклассов) на протяжении всего процесса генерации сайта.
- **Потоки данных:**
  1. Вход: Маркдаун файлы проекта, конфигурация `mkdocs.yml`, история локального репозитория (Git).
  2. MkDocs парсит Markdown в HTML и передает контекст страницы плагинам через хуки (`on_page_content`, `on_page_context`).
  3. `mkdocs-rss-plugin` перехватывает эти данные, извлекает текст (очищая HTML), даты, и сохраняет в свой внутренний кэш. Если дата берется из Git, плагин делает системные вызовы subprocess к утилите `git`.
  4. После завершения обработки всех страниц срабатывает финальный хук (`on_post_build`). Плагин берет массив страниц, применяет шаблонизацию или прямую генерацию XML/JSON строк, и выполняет файловый ввод-вывод (I/O), записывая итоговые `feed_rss_updated.xml`, `feed_json_created.json` и др. в выходную директорию сборки.
  5. Никаких сетевых обменов или внешних сервисов при этом не задействуется.
