# Отчет по анализу репозитория peekscreen

## 1. Техническая реализация и архитектура
Проект **peekscreen** — это сервер MCP (Model Context Protocol), написанный на языке **Rust**, который предоставляет ИИ-агентам (LLM) возможность делать скриншоты окон или всего экрана компьютера пользователя.
- **Язык:** Rust.
- **Основа (Фреймворк):**
  - Используется библиотека `rmcp` (вероятно, реализация Model Context Protocol на Rust) для создания сервера и роутинга тулзов (tools).
  - Для работы с изображениями используется крейт `image`.
  - Для захвата экрана (кроссплатформенного) используется крейт `xcap`.
  - В качестве асинхронного рантайма выступает `tokio`.
  - Логирование построено на `tracing` и `tracing-subscriber`.
- **Архитектура:** Приложение представляет собой небольшой микросервис (CLI-демон), который работает в фоне и общается через стандартный ввод/вывод (stdio).
  - `src/main.ts` (или `main.rs`) — точка входа, инициализирует логгер и запускает MCP сервер (`ScreenshotServer::new().serve(stdio())`).
  - `src/capture.rs` — системный слой, оборачивающий библиотеку `xcap`. Содержит функции для перечисления окон (`list_windows`), поиска нужного окна по ID или названию (`find_window`), а также непосредственно функции захвата пикселей с экрана/окна (`capture_window`, `capture_screen`).
  - `src/imaging.rs` — слой обработки изображений. Отвечает за ресайз (масштабирование, если изображение слишком большое) и кодирование скриншота в формат Base64 (PNG или JPEG), чтобы его можно было передать по текстовому протоколу MCP.
  - `src/server/mod.rs` — слой MCP протокола. Реализует структуру сервера и определяет доступные инструменты (tools) через макросы (`#[tool]`).

## 2. Функции и как логически это работает
Главная задача — дать ИИ агенту "глаза" на рабочем столе пользователя, чтобы он мог читать текст из интерфейсов, проверять верстку, анализировать ошибки.

**Логика работы:**
Сервер экспортирует 3 основных инструмента (tools) для LLM:
1. `list_windows`:
   - Вызывает `xcap::Window::all()`.
   - Отфильтровывает свернутые окна, окна с пустым заголовком и окна нулевого размера.
   - Возвращает JSON-массив с ID, названием, приложением и размером каждого окна.
2. `screenshot_window`:
   - Принимает параметры: `title` (поиск по названию), `id` (точный ID), `max_width` (для ограничения размера файла), `format` (PNG/JPEG).
   - Если ID/Title не переданы, делает скриншот *активного* (focused) окна.
   - Изображение захватывается, конвертируется в Base64.
   - Возвращает агенту массив `CallToolResult`, содержащий саму картинку (`Content::image`) и текстовую информацию о размере и статусе фокуса.
3. `screenshot_screen`:
   - Аналогично, но для целых мониторов. По умолчанию делает скриншот главного (primary) монитора. Можно передать `monitor_id`.

## 3. Обмен информации, память, потоки данных
- **Память и Ограничения:** Скриншоты занимают много памяти, а передача их в LLM расходует токены. Поэтому `imaging.rs` реализует опциональный даунскейл (уменьшение разрешения), если ширина превышает `max_width` (по умолчанию 1920 пикселей). Конвертация в JPEG также помогает снизить объем передаваемых данных по сравнению с PNG. Состояния между вызовами сервер не хранит (stateless).
- **Потоки данных (Data Flow):**
  1. LLM-клиент (например, приложение Claude Desktop) запускает процесс `peekscreen`.
  2. Общение идет через `stdio` (stdin/stdout) по протоколу MCP (Model Context Protocol, JSON-RPC).
  3. LLM отправляет запрос на вызов тулза `screenshot_window` (в формате JSON).
  4. `rmcp` роутер парсит JSON в структуру `ScreenshotWindowParams` и вызывает соответствующий метод.
  5. `capture.rs` делает системный вызов к API ОС (например, ScreenCaptureKit на macOS или DXGI на Windows) через крейт `xcap`. ОС возвращает сырой буфер RGBA пикселей.
  6. Буфер оборачивается в `DynamicImage::ImageRgba8`.
  7. Изображение ресайзится (если нужно) и кодируется в Base64 строку.
  8. Сервер формирует JSON-RPC ответ с закодированной картинкой и отправляет его в `stdout`.
  9. LLM-клиент читает `stdout`, декодирует Base64 и показывает картинку нейросети.
- **Особенности среды:** Приложение сильно зависит от графической подсистемы (Windowing system) операционной системы. Для корректной работы (особенно на macOS и Wayland/Linux) требуются специфические системные разрешения (Screen Recording permissions), о чем есть специальные подсказки в коде.
