# Анализ репозитория: ayrshare-mcp

## 1. Техническая реализация и архитектура
Проект `ayrshare-mcp` — это MCP (Model Context Protocol) сервер, предоставляющий доступ к функционалу сервиса Ayrshare Social Media API. Приложение написано на Python (требует 3.10+) и построено поверх библиотеки `fastmcp` для интеграции с LLM.
В архитектуре четко выделено два основных слоя:
1. **API Client (`ayrshare_client.py`):** Асинхронная обертка над REST API Ayrshare с использованием библиотеки `httpx`. Отвечает за аутентификацию, формирование запросов, обработку ошибок API и Pydantic-модели для ответов.
2. **MCP Server (`server.py`):** Слой, который регистрирует методы API клиента как MCP инструменты (tools) и ресурсы (resources).

Это микросервисное/адаптерное решение, которое само не хранит базу данных, а работает как умный прокси между LLM и облачным сервисом Ayrshare.

## 2. Функции и как логически это работает
Сервер покрывает весь спектр (более 75 инструментов) Ayrshare API. Основные функции:
- **Постинг и отложенный постинг:** публикация текста, картинок и видео в 13+ соцсетей (Facebook, Twitter, LinkedIn, Instagram и т.д.).
- **Управление медиа:** загрузка и валидация изображений и видео.
- **Аналитика:** получение статистики по постам, профилям и хэштегам.
- **Комментарии и DMs:** чтение и ответы на комментарии, управление личными сообщениями.
- **Мультиарендность (Multi-user SaaS):** создание и управление отдельными профилями клиентов.
- **AI-генерация:** инструменты для автогенерации хэштегов, подписей к изображениям.

**Логика:**
1. MCP-сервер запускается локально (через `fastmcp run`) и подключается к LLM (например, Claude Desktop).
2. LLM вызывает определенный инструмент, например `schedule_post`, передавая текст, даты и платформы.
3. Сервер через инжектированный асинхронный экземпляр `AyrshareClient` вызывает нужный метод (например, `client.post(...)`).
4. Клиент добавляет Bearer токен (и Profile-Key, если используется), сериализует параметры в JSON и делает HTTP-запрос к `app.ayrshare.com`.
5. Результат (успех или текст ошибки) возвращается LLM.

## 3. Как происходит обмен информации память потоки данных
- **Память и состояние:** Приложение полностью stateless (без состояния). Все данные и история постов хранятся на серверах Ayrshare. Учетные данные считываются из конфигурации/окружения (`.env`) при инициализации клиента.
- **Потоки данных:**
  - LLM и MCP-сервер общаются через `stdio` или HTTP (SSE), обмениваясь JSON-RPC сообщениями (вызовы функций, чтение ресурсов).
  - MCP-сервер переводит эти вызовы в вызовы асинхронных методов Python. Пул соединений `httpx.AsyncClient` эффективно управляет сетевыми запросами к Ayrshare API.
  - Ayrshare API принимает и возвращает стандартный JSON.
  - Класс `AyrshareClient` валидирует ответы с помощью HTTP-кодов статуса, при необходимости выбрасывая кастомные исключения (`AyrshareAuthError`, `AyrshareValidationError`), которые затем MCP-сервер преобразует в понятные для LLM текстовые сообщения.
  - В проекте также активно используются **Ресурсы (Resources)** (`ayrshare://...`), позволяющие LLM запрашивать "живые" агрегированные данные (историю постов, дашборды, календари) в виде структурированного текста.
