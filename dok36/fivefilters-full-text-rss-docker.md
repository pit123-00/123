# Отчет по анализу репозитория fivefilters-full-text-rss-docker

## 1. Техническая реализация и архитектура
Проект **fivefilters-full-text-rss-docker** — это не оригинальный код приложения Full-Text RSS, а лишь Docker-окружение (оболочка) для удобного развертывания популярного PHP-приложения "Full-Text RSS" от компании FiveFilters.
- **Технологии:** Docker, Docker Compose, PHP, Apache.
- **Архитектура:**
  - Используется официальный образ `php:8.3-apache`.
  - В файле `Dockerfile` прописана установка необходимых системных зависимостей (zlib, libxml, tidy) и PHP-расширений (`curl`, `mbstring`, `dom`, `tidy`, `opcache`), которые требуются для работы парсера.
  - Оригинальный код Full-Text RSS скачивается из официального репозитория (`bitbucket.org/fivefilters/full-text-rss.git`) непосредственно во время сборки (build) образа.
  - Настройки (конфигурация) передаются через файл `custom_config.php`, который копируется в контейнер и перезаписывает настройки по умолчанию (в частности, настройку `admin_credentials` и кэш).
- **Инфраструктура:** Имеется `compose.yml` для быстрого старта с пробросом 80 порта, а также `docker-bake.hcl` для более сложной сборки и публикации образов.

## 2. Функции и как логически это работает
Главная задача этого репозитория — предоставить пользователю "one-click" решение (через `docker compose up`) для запуска локального инстанса Full-Text RSS.

Сам инструмент Full-Text RSS (который устанавливается внутрь) делает следующее:
1. Принимает на вход URL обрезанной (частичной) RSS-ленты или URL обычной веб-страницы.
2. Идет по ссылкам из ленты, скачивает HTML-страницы статей.
3. Используя заложенные алгоритмы и регулярные выражения (и огромную библиотеку "site config" правил для конкретных сайтов), извлекает из HTML только полезный контент (текст статьи и картинки), вырезая меню, рекламу, комментарии и футеры.
4. Отдает пользователю новую, полноценную RSS-ленту, которую можно читать в любом ридере не переходя на оригинальный сайт.

Этот Docker-образ настраивает PHP-Apache так, чтобы:
- Права доступа были корректными (`chown -R www-data:www-data`).
- Кэширование (директория `cache`) работало прямо внутри контейнера без ошибок прав доступа.

## 3. Обмен информации, память, потоки данных
Так как репозиторий является только Docker-оберткой, потоки данных относятся к конфигурации окружения:
- **Память и Хранение:** В `compose.yml` не используются именованные тома (volumes) для персистентного хранения. Это означает, что кэш скачанных статей (папка `cache`) и логи хранятся внутри самого контейнера и сбрасываются при его пересоздании.
- **Конфигурация:** В `custom_config.php` видно множество опций настройки (хоть большая часть закомментирована/дефолтная). Основной способ передачи конфигурации — это переменные окружения, которые в PHP читаются и применяются (это реализовано в самом Full-Text RSS).
- **Потоки данных (Data Flow):**
  1. Пользователь обращается к порту 80 контейнера через браузер (`webui`).
  2. Запрос обрабатывается Apache и передается в `makefulltextfeed.php` (скрипт оригинального приложения).
  3. Скрипт использует `cURL` для загрузки оригинальной RSS-ленты.
  4. Скрипт использует `cURL` (с поддержкой прокси, CORS, подменой User-Agent, если настроено в `custom_config.php`) для загрузки HTML страниц.
  5. HTML парсится через `libxml` или `html5php` (настройки из `custom_config.php`).
  6. Сгенерированный XML отдается обратно через Apache.
- **Особенности среды:** В Dockerfile включается модуль `rewrite` для Apache, что позволяет использовать красивые URL (ЧПУ). Также в корне лежит файл `calls.http` — это набор тестовых HTTP-запросов (вероятно, для расширения REST Client в VS Code), чтобы разработчик мог быстро проверить работоспособность запущенного контейнера.
