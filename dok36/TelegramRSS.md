# Отчет по анализу репозитория TelegramRSS

## 1. Техническая реализация и архитектура
Проект **TelegramRSS** — это легковесный и быстрый асинхронный сервер на PHP, предоставляющий Telegram-каналы в форматах RSS или JSON.
- **Язык:** PHP 8+
- **Основа (Фреймворк):** Использует [Amphp](https://amphp.org/) для асинхронной работы и HTTP-сервера (`Amp\Http\Server\SocketHttpServer`).
- **Связь с Telegram:** Общение происходит не напрямую с Telegram API (MTProto), а через сторонний клиент [TelegramApiServer](https://github.com/xtrime-ru/TelegramApiServer) (по умолчанию ожидается на `127.0.0.1:9503`), который выступает в роли прокси для Telegram.
- **Архитектура:**
  - `server.php` — точка входа (CLI-скрипт), который запускает HTTP-сервер. Запускается из командной строки с передачей аргументов (IP и порты для HTTP сервера и для Telegram клиента) или читает настройки из `.env` файлов.
  - Директория `app/Server` содержит конфигурацию и запуск асинхронного `SocketHttpServer`. Там же находится простейший встроенный роутер.
  - Директория `app/Controller` содержит контроллеры для обработки разных энпоинтов: отдача RSS (`RSSController`), JSON (`JsonController`), медиа-файлов и иконок.
  - Директория `app/RSS` содержит классы для преобразования массива сообщений (полученных из Telegram) в формат RSS (сборка `SimpleXMLElement`).

## 2. Функции и как логически это работает
Главная задача приложения — позволить подписываться на Telegram-каналы через обычные RSS-ридеры, не используя клиент Telegram.

**Логика работы (на примере запроса RSS):**
1. Пользователь запрашивает URL вида `http://server:port/rss/channel_name`.
2. Роутер в `app/Server/Router.php` (не показан в деталях, но логика следует из структуры) направляет запрос в `RSSController`.
3. `RSSController` вызывает метод `getFeed()`, который делает запросы к клиенту Telegram через `TgClient.php`.
4. Класс `TgClient` использует асинхронный HTTP-клиент от `Amphp` для запроса к TelegramApiServer (метод `getHistoryHtml`, `getFullInfo`).
5. Полученный ответ в формате JSON парсится.
6. Класс `Messages` (в `app/RSS`) подготавливает эти сообщения, вытягивая нужные поля, формируя ссылки на медиа (картинки, видео).
7. Класс `Feed` собирает финальный XML (со стандартом RSS 2.0). Он генерирует структуру тегов `<channel>`, `<item>`, `<enclosure>`, обрабатывает прикрепленные веб-страницы и медиа, а также встраивает статистику (просмотры, реакции) в теги `media:community`.
8. Сервер возвращает собранный XML с соответствующими заголовками (Content-Type: text/xml, ETag, Last-Modified) пользователю.

Помимо RSS сервер умеет отдавать те же данные в JSON-формате и отдавать оригинальные медиафайлы из постов (через `MediaController`), которые также запрашиваются через `TgClient`.

## 3. Обмен информации, память, потоки данных
- **Память и Асинхронность:** Сервер базируется на `Amphp`, что означает использование Event Loop. Запросы не блокируют процесс, все внешние I/O операции (запросы к TelegramApiServer) выполняются асинхронно, используя пулы подключений. Ограничение памяти можно выставить через `MEMORY_LIMIT` в `.env`. Лимит соединений контролируется `ConnectionLimitingServerSocketFactory` и семафором на 1000 запросов.
- **Потоки данных (Data Flow):**
  1. `HTTP Request (Amphp Request)` -> `Router` -> `Controller`.
  2. `Controller` -> `TgClient::get` -> Формируется POST-запрос с JSON Payload (`$parameters`) к TelegramApiServer.
  3. `TelegramApiServer` отвечает JSON'ом.
  4. `TgClient` проверяет статусы ответов (200, 206, 302). Если есть ошибки — выбрасывается Exception или делается ретрай (`$retry`). В случае успеха JSON декодируется.
  5. Данные (массивы сообщений) передаются в `app/RSS/Messages` -> `app/RSS/Feed`.
  6. `Feed` формирует строковый XML с использованием `DOMDocument`.
  7. Данные передаются обратно в `Controller`, который устанавливает тело ответа `Amp\Http\Server\Response`.
  8. Ответ уходит клиенту.
- **Медиа-файлы:** При запросе больших медиа-файлов используется потоковая передача. Метод `downloadToResponse` в `TgClient` проксирует запрос загрузки от `TelegramApiServer` прямо в Response (асинхронные потоки Amphp).
- **Логирование и кэширование:** В приложении реализован логгер (`TelegramRSS\Logger`). Запросы кэшируются через HTTP-заголовки (ETag, Last-Modified), чтобы RSS-ридеры не загружали данные повторно, если канал не обновлялся.
