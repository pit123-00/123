# Отчет по анализу репозитория Podsync

## 1. Техническая реализация и архитектура
Проект **Podsync** написан на Go и предназначен для конвертации видео и аудио из различных платформ (YouTube, Vimeo, SoundCloud, Twitch) в подкасты (RSS-ленты), которые можно слушать в любом плеере.
- **Язык:** Go.
- **Основа:** Приложение является автономным демоном/сервером. Работает без веб-фреймворков, используя стандартную библиотеку `net/http` (кастомный роутер в `services/web`).
- **Ключевой механизм (Зависимость):** Для скачивания медиафайлов под капотом используется утилита `youtube-dl` (или ее форки `yt-dlp`), а для конвертации аудио — `ffmpeg`/`avconv`. Podsync вызывает их через системные вызовы (пакет `os/exec`).
- **СУБД и Хранилище:**
  - **БД:** Используется встроенная key-value база данных **Badger** (`github.com/dgraph-io/badger`) для хранения метаданных (какие эпизоды загружены, состояния фидов).
  - **Хранилище файлов:** Скачанные файлы (mp3, mp4) могут храниться локально (`fs.NewLocal`) или отправляться в S3 совместимое хранилище (`fs.NewS3`).
- **Архитектура:**
  - `cmd/podsync/main.go` — точка входа, инициализирует БД, хранилище, запускает крон-задачи и веб-сервер.
  - `pkg/builder/` — классы-сборщики (Builders) для различных провайдеров (YouTube API, Vimeo API и тд), которые получают списки новых видео.
  - `pkg/ytdl/` — обертка над бинарником `youtube-dl` для скачивания файлов и извлечения метаданных.
  - `services/update/` — менеджер обновлений, оркеструющий процесс проверки новых эпизодов и их загрузки.

## 2. Функции и как логически это работает
Главная задача — регулярно скачивать новые видео с заданных каналов, конвертировать их (если запрошен аудио-подкаст) и раздавать пользователям в виде XML RSS-лент и медиафайлов.

**Логика работы:**
1. При старте программа читает `config.toml`, в котором указаны токены для API (YouTube, Vimeo) и список фидов (какие каналы скачивать, в каком формате - видео/аудио, качество).
2. Запускается крон-планировщик (`github.com/robfig/cron`), который по расписанию (или каждые X минут) отправляет конфигурации фидов в канал `updates`.
3. Горутина-воркер слушает канал `updates`. Получив задание, менеджер обновлений (`services/update`) обращается через `pkg/builder` к официальным API (например, YouTube Data API), чтобы получить список последних видео на канале.
4. Новые видео добавляются в базу BadgerDB со статусом "ожидает загрузки".
5. Вызывается `ytdl.Download()`. Формируются аргументы для `youtube-dl` (например, для аудио: `--extract-audio --audio-format mp3`). `youtube-dl` скачивает файл во временную директорию.
6. В случае успеха файл перемещается в локальное хранилище (`/data`) или загружается в S3.
7. Обновляется статус в BadgerDB.
8. Пользователь может обратиться к веб-серверу (например, по адресу `http://localhost:8080/channel_id.xml`).
9. Веб-сервер генерирует XML RSS на лету, доставая метаданные из БД Badger и подставляя ссылки на локально сохраненные/S3 медиафайлы.

## 3. Обмен информации, память, потоки данных
- **Память и Асинхронность:** В Go используется многопоточность на основе горутин. Для управления жизненным циклом и graceful-shutdown используется `golang.org/x/sync/errgroup` и контексты (`context.Context`). Процесс скачивания тяжелый, поэтому скачивания идут в фоне, не блокируя веб-сервер.
- **Потоки данных (Data Flow):**
  - **Обновление фидов (Background):**
    1. Крон срабатывает -> `updates <- feedConfig`.
    2. Воркер -> `Updater.Update()` -> `Builder.Build()` (запрос к YouTube API через HTTP).
    3. Ответ API мапится в `model.Feed`. Сравнивается с БД (`Badger`).
    4. Для каждого нового `model.Episode` -> `ytdl.Download(URL)` (запуск процесса ОС).
    5. Загрузка во временную папку -> перемещение в `Storage` (Local IO или S3 HTTP PUT).
    6. Сохранение статуса в `Badger`.
  - **Обработка запроса пользователя (Web Server):**
    1. HTTP GET `/feed.xml` -> Роутер.
    2. Из БД `Badger` извлекаются данные о канале и скачанных файлах.
    3. Шаблонизатор генерирует XML строку.
    4. Ответ клиенту.
    5. HTTP GET `/data/file.mp3` -> `fs.Local` (если файлы локально) отдает статический файл клиенту (подкаст-плееру).
- **Взаимодействие с внешними бинарниками:** Поскольку используется `youtube-dl` и `ffmpeg`, `pkg/ytdl` строго контролирует таймауты (`context.WithTimeout`) и ограничивает одновременные обновления самого `youtube-dl` через мьютексы (`sync.Mutex`), чтобы избежать порчи бинарника при его встроенном self-update.
