# Отчет по анализу репозитория splitrail

## 1. Техническая реализация и архитектура
Проект **splitrail** — это инструмент командной строки (CLI) с псевдографическим интерфейсом (TUI) и встроенным MCP сервером, написанный на **Rust**.
- **Язык:** Rust (2021 edition).
- **Сборка и зависимости:** Используется `Cargo`. Основные крейты: `tokio` (асинхронность), `ratatui` (для отрисовки интерфейса в терминале), `crossterm` (работа с терминалом), `serde` (сериализация), `reqwest` (HTTP клиент), `notify` (наблюдение за изменениями файлов).
- **Инфраструктура:** Проект имеет `Dockerfile` (отсутствует в корне, но проект подготовлен для CI/CD), скрипты в папке `scripts/`, а также содержит субмодуль/папку `vscode-splitrail` для создания расширения VS Code.
- **Архитектура:** Приложение имеет четкое разделение на модули:
  - `src/main.rs` — точка входа, инициализация конфигурации (`Config`), парсинг аргументов командной строки.
  - `src/tui/` — реализация терминального пользовательского интерфейса (Dashboard) для отображения статистики ИИ-агентов.
  - `src/analyzers/` — модули для парсинга и анализа логов работы различных AI-кодинг ассистентов (например, Cursor, Cline, OpenCode, Aider).
  - `src/mcp/` — интеграция Model Context Protocol (MCP) для предоставления данных о метриках другим AI-инструментам.
  - `src/watcher.rs` — фоновый процесс для наблюдения за изменениями файлов логов в реальном времени.

## 2. Функции и как логически это работает
Главная задача Splitrail — это агрегация, анализ и визуализация логов работы AI-кодинг инструментов локально на машине разработчика. Он помогает понять, сколько "работы" (строк кода, API запросов, сессий) выполняет AI-ассистент.

**Логика работы:**
1. При запуске (`splitrail dashboard`) инициализируется реестр анализаторов (`AnalyzerRegistry`).
2. Каждый анализатор (из `src/analyzers/`) настраивается на поиск логов специфичного инструмента в системных папках (например, логи Cursor в `~/.cursor-tutor`, логи Cline в профиле VS Code).
3. Инструмент парсит эти файлы, извлекая полезную метрику (количество сессий, количество сгенерированного кода, API-вызовы).
4. Запускается File Watcher (`notify`), который "слушает" директории с логами. Если файл обновляется, анализатор инкрементально перечитывает изменения (`reload_file_incremental`).
5. Собранные метрики агрегируются (в структуры типа `AgenticCodingToolStats`) и передаются в TUI.
6. `ratatui` отрисовывает красивые графики и таблицы прямо в терминале (активность по дням, количество сообщений, список сессий).
7. Дополнительная функция: MCP сервер (`splitrail mcp`), который позволяет другим ИИ-агентам (например, Claude Desktop) запрашивать у Splitrail статистику о том, как пользователь взаимодействует с ИИ.

## 3. Обмен информации, память, потоки данных
- **Память и Оптимизация:** Поскольку логи могут быть огромными, Splitrail использует стратегию кэширования в памяти (DashMap в `AnalyzerRegistry`) и парсит только изменения в файлах (инкрементальные обновления). Для быстрого парсинга JSON используется `reqwest_simd_json.rs` (через simd-json) для векторизованной обработки.
- **Потоки данных (Data Flow):**
  1. `Watcher` (фоновый поток) обнаруживает изменение файла (FS Event).
  2. Событие передается через `tokio::sync::mpsc` канал в главный поток обработки.
  3. `AnalyzerRegistry` определяет, какому анализатору принадлежит файл (по `directory_to_analyzer_mapping`).
  4. Анализатор считывает обновленный файл, парсит новые сообщения (`ConversationMessage`).
  5. Метрики в кэше обновляются (файлы помечаются как "грязные" `mark_file_dirty`).
  6. Если запущен TUI, он с определенной частотой (Tick) запрашивает у `AnalyzerRegistry` текущее состояние (Views) и перерисовывает экран.
  7. Если работает MCP-сервер, он ждет JSON-RPC запросы на `stdio`, читает кэш и отдает JSON-ответ клиенту.
- **Интеграция с редакторами:** Функция `discover_vscode_extension_sources` предназначена для автоматического поиска директорий с логами расширений внутри VS Code (например, `globalStorage/cline.cline`), что делает конфигурацию для пользователя прозрачной (Zero-config).
