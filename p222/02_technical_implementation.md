# Отчёт 2: Техническая реализация и внутреннее устройство решений

Настоящий отчёт детально разбирает исходный код обоих проектов: устройство сетевых движков, потоковую обработку (SSE/WebSocket), конкурентность, алгоритмы маршрутизации, схемы трансляции протоколов, подсистемы кэширования и технические преимущества каждого решения.

## 1. Техническая реализация CLIProxyAPI (Go)

### 1.1. Сетевой уровень и обработка потоков (Streaming Engine)
Кодовая база CLIProxyAPI построена вокруг фреймворка **Gin** и стандартных низкоуровневых интерфейсов `net/http`, расширенных кастомными пулами соединений:
- **uTLS (Mimic Handshake):** В файлах `sdk/cliproxy/executor/tls_handshake_timeout.go` и `internal/util/proxy.go` реализовано прямое управление TLS-отпечатками через uTLS. Это позволяет эмулировать ClientHello официальных CLI и браузеров Chrome/Anthropic, предотвращая Cloudflare/Akamai fingerprint блокировки.
- **Двунаправленные вебсокеты (`internal/client/codex/live`, `sdk/cliproxy/executor/websocket.go`):** Полноценная поддержка протокола OpenAI Responses / Realtime API. Реализована обработка WebSocket-фреймов в реальном времени с поддержкой WebRTC Media Relay (RTP/RTCP, STUN/TURN, ICE-серверы для аудио/видео каналов).
- **Продвинутый Bootstrap Buffering (`StreamBootstrapBuffering`):** В коде `internal/config/config_types.go` и `sdk/cliproxy/auth/conductor_stream.go` реализован механизм отложенной фиксации HTTP-заголовков (до 48 фреймов или 1 МБ данных). Если upstream возвращает ошибку перегрузки (`server_is_overloaded`) в потоке HTTP 200, буфер отбрасывается, downstream-клиент ничего не замечает, а шлюз прозрачно перезапускает запрос на следующем токене из пула.
- **Zero-Allocation JSON Parsing:** Для минимизации аллокаций памяти и задержек используется библиотека `github.com/MoeForge/moego/ojson` и быстрый парсинг `gjson`/`sjson` без десериализации всего JSON-дерева в структуры (`ParseGJSONBytesNoCopy`).

### 1.2. Конкурентность и управление состоянием
- **Горутины и каналы Go:** Автономные воркеры обновления токенов (`AuthAutoRefreshWorkers`), синхронизированные мьютексами (`sync.RWMutex`) и атомарными операторами `sync/atomic`.
- **In-Memory + BoltDB + Распределенные бекенды:**
  - `internal/kvstore/bolt_store.go`: встраиваемая база bbolt (ACID транзакции на B+ деревьях) для хранения кулдаунов и сессионных пинов.
  - `internal/store/postgresstore.go`: возможность синхронизации кулдаунов и состояния через PostgreSQL.
  - `internal/store/objectstore.go`: синхронизация состояния через S3/MinIO.
  - `internal/store/gitstore.go`: хранение и версионирование конфигураций и токенов в Git-репозитории.
- **Реактивное обновление через fsnotify (`internal/watcher/watcher.go`):** Изменение `config.yaml` или добавление JSON-файла с токеном в папку `auths/` моментально перехватывается через системные вызовы ядра (inotify/kqueue) и обновляет структуры в памяти без перезапуска процесса.

### 1.3. Обработка ошибок и классификация
В `sdk/cliproxy/auth/conductor_request_scoped_errors.go` и `internal/config/config_types.go` заложен мощный механизм классификации:
- Запросы проверяются по коду ответа (400, 401, 403, 408, 429, 500, 502, 503, 504, 520-526) и регулярным выражениям текста ошибки.
- Действия гранулированы:
  - `stop`: немедленный возврат ошибки клиенту (не является сбоем провайдера).
  - `stop-and-cooldown`: возврат ошибки и отправка токена на кулдаун.
  - `continue`: прозрачная смена токена без кулдауна текущего.
  - `continue-and-cooldown`: перевод текущего токена в кулдаун и переключение на запасной.

### 1.4. Нормализация схем вызова функций (`internal/util/gemini_schema.go`)
Файл занимает более 82 КБ кода и содержит исчерпывающую санитизацию JSON Schema для Google Gemini и Antigravity:
- Очистка недопустимых для Gemini ключевых слов OpenAPI/JSON Schema (`additionalProperties`, `$schema`, `definitions`, `patternProperties` и т.д.).
- Инлайнинг локальных ссылок `$ref`.
- Исправление некорректных типов свойств, автогенерация полей `placeholder` для обязательных параметров, защита пользовательских аргументов от искажения.

## 2. Техническая реализация freellmapi (TypeScript / Node.js)

### 2.1. Сетевой уровень и обработка потоков (Streaming Engine)
Сервер freellmapi построен на базе **Express 5** и асинхронного Event Loop Node.js:
- **Express Middleware Chain (`server/src/app.ts`):** Строгая цепочка промежуточных обработчиков: `createHostGuard`, `helmet`, `cors`, `express.json({ limit: '10mb' })`, `clientContextMiddleware`, аутентификация по единому ключу (`requireAuth`), `rateLimiter`.
- **Потоковая передача SSE (`server/src/lib/proxy.ts`, `server/src/lib/stream-keepalive.ts`):** Реализован механизм `stream-keepalive`, отправляющий каждые $N$ миллисекунд комментарий-сердцебиение (`: keep-alive\n\n`) для предотвращения обрыва соединения по таймауту у клиентов с агрессивным watchdog (например, Claude Code).
- **Сжатие данных (`server/src/services/compression`):** Двунаправленное сжатие трафика (gzip/deflate/brotli) с логированием сохраненных байтов в аналитику.

### 2.2. Архитектура хранилища и персистентность
- **Реляционная база данных SQLite (`server/src/db/node-sqlite.ts`, `index.ts`):**
  - Поддержка нативного движка Node 22 (`node:sqlite`) с автоматическим фолбэком на `better-sqlite3`.
  - WAL-режим (Write-Ahead Logging) для быстрых параллельных чтений.
  - Система миграций (`server/src/db/migrate/runner.ts`), гарантирующая целостность схемы БД при обновлениях.
- **Криптографическая подсистема (`server/src/lib/crypto.ts`):**
  - Все API-ключи внешних провайдеров шифруются алгоритмом AES-256-GCM.
  - Ключ шифрования извлекается из `ENCRYPTION_KEY`, файла `.encryption-key` или автоматически генерируется с правами `0600`.
  - При смене мастер-ключа доступен скрипт ротации ключей шифрования (`rotate-encryption-key.ts`).

### 2.3. Алгоритмическая маршрутизация и скоринг
Ключевое ядро freellmapi находится в `server/src/services/router.ts` и `server/src/services/scoring.ts`:
- **Scoring Engine (Multi-Armed Bandit):**
  $$Score = w_{rel} \cdot Reliability + w_{spd} \cdot Speed + w_{int} \cdot Intelligence$$
- **Thompson Sampling:** Использование бета-распределения `sampleBeta(successes + 1, failures + 1)` для адаптивного выбора моделей в условиях неопределенности.
- **Учет суточных циклов (Peak Hours):** В часы пик (по умолчанию с 13:00 до 21:00 UTC) приоритет скорости автоматически снижается на 20%, а надежности — пропорционально увеличивается.
- **Headroom Factor и Quota Forecasting:** Штрафы моделей, у которых исчерпывается поминутный или суточный лимит токенов.

### 2.4. Восстановление поврежденных вызовов инструментов (`tool-call-rescue.ts`)
В отличие от превентивной очистки схемы в CLIProxyAPI, freellmapi решает проблему рассинхронизации диалектов на лету в выходном тексте:
- Если модель в результате переключения выдала вызов инструмента в виде текста (токены DeepSeek/Kimi `<|tool_calls_section_begin|>`, XML теги Qwen `<tool_call>`, псевдо-теги `<function=...>` или markdown JSON), парсер извлекает эти данные, сопоставляет с сигнатурами из исходного запроса и упаковывает в стандартный массив `tool_calls`.

### 2.5. Нативный MCP-сервер (`server/src/routes/mcp.ts`)
Реализация протокола Model Context Protocol (спецификация 2025-06-18) поверх Streamable HTTP:
- 14 встроенных инструментов (диагностика пула, запуск вычислений, переключение стратегий, очистка кэша, статистика квот).
- Полная совместимость с современными AI-агентами (Claude Code, Cursor, Cline).

## 3. Технические преимущества каждого решения

### Преимущества CLIProxyAPI:
1. **Экстремальная производительность и низкие накладные расходы:** Написан на компилируемом языке Go, использует пулы горутин и zero-allocation JSON-парсинг. Способен держать десятки тысяч одновременных соединений при минимальном потреблении RAM.
2. **Низкоуровневый сетевой контроль (uTLS + HTTP/2 + WebSocket/WebRTC):** Полная имитация браузерных и CLI-клиентов на уровне отпечатков TLS и заголовков.
3. **Бесшовная защита стриминга (Bootstrap Buffering):** Способность скрыть перегрузку апстрима и переключить токен прямо во время установки соединения, когда клиент еще не получил первый токен.
4. **Промышленная отказоустойчивость хранения:** Возможность работать без локальной БД, хранить токены в S3, синхронизировать кулдауны через PostgreSQL или версионировать пул аккаунтов в Git.

### Преимущества freellmapi:
1. **Интеллектуальная адаптивная маршрутизация:** Математический аппарат (Multi-Armed Bandit, Thompson Sampling, пиковые часы, типы задач), обеспечивающий автоматический выбор лучшей и быстрейшей бесплатной модели в реальном времени.
2. **Глубокая безопасность учетных данных:** Встроенное AES-GCM шифрование всех секретов в реляционной базе данных SQLite.
3. **Экосистема MCP:** Родная поддержка Model Context Protocol позволяет внешним агентским системам опрашивать состояние шлюза и управлять им как инструментом.
4. **Комплексная инфраструктура "из коробки":** Наличие готового веб-интерфейса (React Dashboard), трей-приложения (Electron) и кросс-платформенного CLI.
