# Отчёт 4: Плюсы и минусы решений в управлении агентами, субагентами и пайплайнами

Настоящий отчёт сфокусирован на анализе подсистем оркестрации: управлении агентами (Agents), дочерними процессами (Subagents), командами агентов (Agent Teams), пайплайнами (Pipelines / Workflows) и обработке параллельных потоков задач на основе исходного кода **deepseek-harness** и **opencode**.

---

## 1. Сравнительный анализ механизмов оркестрации

### 1.1. Оркестрация в deepseek-harness

В deepseek-harness реализована трехуровневая модель работы с агентами:
1. **Базовый уровень: Субагенты (`@deepseek-ai/dsh-subagent`)**:
   - `ActivationPool` и `ChildLock`: контролируют максимальную емкость одновременно работающих субагентов в процессе.
   - Механизм адресации: иерархические пути агентов (`names.ts`: `ROOT_AGENT_NAME`, `agentAddress`, `joinAgentPath`, `parentAgentPath`).
   - Изоляция жизненного цикла: `subagent-fork-in-process` (форк контекста внутри процесса), `subagent-spawn-in-process` и внешние субагенты через протокол ACP (`subagent-acp`) или адаптеры Claude Code / Codex.
   - Наследование политик: родитель передает ребенку строгие ограничения глубины вызовов (`depth.ts`, `resolveChildDepth`) и ограничения инструментов.
2. **Командный уровень: Agent Teams (`@deepseek-ai/dsh-team`)**:
   - Полноценный граф задач: `task-graph.ts` проверяет DAG перед каждым изменением на циклы (`cycle`), дубликаты (`duplicate`) и отсутствующие зависимости (`missing`).
   - Доска задач (`task-board.ts`): синхронизирует состояние между несколькими параллельными агентами. Агенты берут задачи из очереди, как только разблокируются зависимости (`blockedBy: []`).
3. **Пайплайны: Workflow PTC (`@deepseek-ai/dsh-workflow-ptc`)**:
   - Скриптовый движок для пайплайнов, исполняемый в гостевой виртуальной машине (`node:vm`).
   - Предоставляет встроенные комбинаторы:
     - `dsh.agent(prompt, options)` — атомарный вызов агента с JSON-схемой результата (`schema`).
     - `dsh.parallel([...items], fn)` — параллельный маппинг с жестким ограничением параллелизма.
     - `dsh.pipeline([...stages])` — последовательный конвейер передачи данных между этапами.
   - Жесткие барьеры: `maxTotalAgents` (предотвращает рекурсивный взрыв вызовов), `syncTimeoutMs`.

### 1.2. Оркестрация в opencode

В opencode оркестрация построена на функциональных примитивах Effect-ts:
1. **Агенты как сущности конфигурации (`@opencode/schema/agent`, `@opencode/core/src/agent.ts`)**:
   - Агенты декларируются статически или через конфигурационные файлы: `Info { id, name, model, mode: 'subagent' | 'primary' | 'all', permissions, steps }`.
   - Режим `mode` жестко определяет, может ли агент запускаться пользователем напрямую (`primary`) или только другим агентом (`subagent`).
2. **Инструмент `subagent` (`packages/core/src/tool/plugin/subagent.ts`)**:
   - Агент запускает субагента вызовом инструмента с параметрами: `agent`, `prompt`, `description`, опционально `model`, `sessionID`, `background: boolean`.
   - Поддерживает продолжение диалога с ранее запущенным субагентом (передача `sessionID`).
   - Контроль глубины: рекурсивный обход `parentID` в родительской сессии предотвращает бесконечную вложенность.
3. **Фоновые субагенты (`SubagentJob` поверх `Job.Service`)**:
   - При флаге `background: true` субагент запускается как асинхронная фоновая работа (Job).
   - Родительский агент получает мгновенный ответ с идентификатором задачи и инструкцией: «Субагент работает в фоне, продолжайте другую работу или завершите ход».
   - По завершении субагента система генерирует синтетическое событие в родительской сессии (`SubagentCompletion.deliver`), уведомляя родителя о готовом результате.
4. **Пайплайны в opencode**:
   - Нет отдельного скриптового VM-рантайма. Пайплайны организуются либо на уровне цепочек вызовов инструментов, либо через встроенные Effect-комбинаторы (`Effect.all`, `Effect.forEach` с `{ concurrency: N }`).

## 2. Плюсы и минусы deepseek-harness

### Плюсы (Преимущества):
1. **Специализированная среда для пайплайнов (Workflow PTC)**:
   Наличие гостевой виртуальной машины позволяет агенту генерировать произвольные алгоритмы оркестрации (условные ветвления, циклы, параллельный map-reduce) на чистом JavaScript/TypeScript, избегая дорогостоящих обращений к LLM на каждом шаге.
2. **Настоящая командная координация (Agent Teams & DAG)**:
   Готовый математически верифицируемый граф задач (`task-graph.ts`) исключает дедлоки и циклические блокировки между агентами, обеспечивая прозрачный статус выполнения сложных многоэтапных проектов.
3. **Гетерогенные рантаймы субагентов**:
   Возможность прозрачно делегировать задачу субагенту, работающему как внешний процесс через протокол ACP, или запускать субагенты других экосистем (Claude Code, Codex).
4. **Строгий контроль емкости ресурсов**:
   `ActivationPool` гарантирует, что количество одновременных активных агентов в процессе не превысит лимиты памяти и CPU.

### Минусы (Недостатки):
1. **Повышенная сложность архитектуры**:
   Связка из 59 модулей, Cordis-контекстов, проекций сессий и проброса типов через изоляты VM усложняет отладку и порождает специфичные ошибки сериализации данных между Host и Guest.
2. **Изоляция в Node VM не является полноценной аппаратной песочницей**:
   Использование `node:vm` накладывает ограничения на скорость передачи больших объемов данных (сериализация/десериализация JSON через мост) и требует жесткого контроля за утечками прототипов.
3. **Высокий порог входа**:
   Требуется глубокое понимание экосистем Cordis, Schemastery и внутренних механизмов Event Sourcing.

## 3. Плюсы и минусы opencode

### Плюсы (Преимущества):
1. **Элегантная интеграция с моделью фоновых задач (`Job.Service`)**:
   Асинхронные субагенты работают в фоне без блокировки основного диалога. Доставка результатов через детерминированные синтетические сообщения в сессию исключает потерю статуса.
2. **Интуитивная модель агентов через схемы (`Effect.Schema`)**:
   Агентов очень просто конфигурировать, наделять специфичными правами (`Permission.Ruleset`) и переопределять используемые модели.
3. **Безупречная надежность параллелизма (Effect Fibers)**:
   Благодаря модели `Fiber` и `Scope`, при отмене задачи или падении родителя гарантированно и мгновенно прерываются все дочерние подпроцессы, сетевые запросы и обработчики, предотвращая появление зомби-процессов.
4. **Возможность продолжения диалога с субагентом**:
   Параметр `sessionID` позволяет агенту вести многораундовый интерактивный диалог с конкретным субагентом, уточняя задачи и исправляя ошибки по ходу дела.

### Минусы (Недостатки):
1. **Отсутствие встроенного координатора сложных графов задач (DAG / Task Board)**:
   Нет встроенного механизма разрешения зависимостей задач уровня Agent Team. Вся координация ложится на плечи промпта главной LLM или ручные вызовы `subagent`.
2. **Отсутствие гостевой песочницы для пайплайнов**:
   Нет изолированного рантайма скриптов наподобие PTC VM. Любой вызов субагента или инструмента проходит полный цикл через сериализацию вызова в LLM-лупе.
3. **Блокирующий характер при отсутствии флага background**:
   При синхронном вызове субагента родительская сессия блокируется до полного завершения работы дочерней сессии.

## 4. Сравнительная матрица подсистем оркестрации

| Функция / Возможность | deepseek-harness | opencode |
| :--- | :---: | :---: |
| **Параллельный запуск субагентов** | Да (`dsh.parallel`, `ActivationPool`) | Да (`background: true`, `Effect.all`) |
| **Интерактивное продолжение сессии субагента** | Да (`ContinuableCreateRequest`) | Да (`sessionID` в параметрах `subagent`) |
| **Граф зависимостей задач (DAG)** | **Да** (`assertTaskGraphCandidate`) | Нет (только плоские фоновые джобы) |
| **Доска задач команды (Team Task Board)** | **Да** (`task-board.ts`) | Нет |
| **Изолированный VM-рантайм пайплайнов (PTC)** | **Да** (`workflow-ptc` в `node:vm`) | Нет |
| **Гарантированное прерывание утечек процессов** | Средне (ручные хуки очистки) | **Превосходно** (структурированный `Scope` Effect-ts) |
| **Поддержка гетерогенных агентов (ACP/Claude Code)** | **Да** (нативные плагины) | Ограничено (внешние плагины) |
| **Простота декларации новых агентов** | Средняя (плагины + пресеты) | **Высокая** (декларативные JSON/TS конфиги) |

---

## 5. Заключение по четвертому отчёту
- Для сценариев, требующих **сложной коллективной работы нескольких агентов с зависимостями задач, глубоких алгоритмических пайплайнов и изоляции кода в песочницах**, **deepseek-harness** предлагает значительно более развитый и мощный инструментарий (Agent Teams + Workflow PTC).
- Для сценариев, где важны **простота конфигурирования, надежность фонового исполнения, непрерывная интерактивность, устойчивость к сбоям и предсказуемость системных ресурсов**, архитектура на Effect-ts в **opencode** демонстрирует высочайшую стабильность и чистоту инженерного исполнения.
