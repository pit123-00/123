# Отчёт 1: Ключевые отличия между deepseek-harness и opencode на основе анализа исходного кода

Настоящий отчёт подготовлен на основе прямого и глубокого анализа кодовых баз двух репозиториев:
- **deepseek-harness** (`@deepseek-ai/dsh-*`)
- **opencode** (`@opencode/*`)

Анализ сфокусирован исключительно на исходном коде проектов, внутренней механике, конфигурационных структурах, типах данных и архитектурных контрактах.

---

## 1. Сводная таблица ключевых отличий

| Критерий / Подсистема | deepseek-harness (`dsh`) | opencode |
| :--- | :--- | :--- |
| **Базовый фреймворк и рантайм** | **Cordis** (IoC / Dependency Injection контейнер, события, форки контекстов) + Node.js (v24+) + pnpm. | **Effect-ts** (функциональный монадический фреймворк: Fibers, Layers, Scope, Schema) + Bun / Node + Turbo. |
| **Философия конфигурации** | Модульная реактивная схема на `@deepseek-ai/schemastery`, многоуровневые профили (`cordis.patch.yml`, профильные оверлеи, HMR). | Централизованная строготипизированная схема на `@opencode/schema` (Effect.Schema), JSON/YAML конфигурация проекта и глобальные настройки. |
| **Фокус на LLM-провайдерах** | Глубокая адаптация под стек **DeepSeek** (нативные эндпоинты, кэширование контекста DeepSeek, API-расширения, токен-метры DeepSeek), с поддержкой Claude Code / Codex / ACP как внешних рантаймов. | **Широкий мультивендорный шлюз** (`@opencode/ai`): более 25 провайдеров (OpenAI, Anthropic, Gemini, Bedrock, Groq, Mistral, Moonshot, Venice, OpenRouter, Cerebras и др.) через унифицированный стриминговый протокол. |

| **Оркестрация агентов** | Полнофункциональные **Agent Teams** с направленными ациклическими графами задач (DAG Task Graph), валидацией зависимостей, очередями и семантическими чекпоинтами. | Иерархические субагенты в виде фоновых или блокирующих задач (`SubagentJob` поверх `Job.Service`), отслеживание через системные синтетические события. |
| **Пайплайны выполнения** | Специализированный модуль **Workflow PTC** (`workflow-ptc`): гостевой рантайм с примитивами `agent()`, `parallel()`, `pipeline()` и жесткими лимитами выполнения. | Пайплайны на примитивах `Effect` (параллельные файберы `Effect.all`, очереди, генераторы `Effect.gen`). |
| **Интерфейс пользователя** | Desktop (Electron/Cordis Host), Web (Vite/React frontend), CLI (профильный запуск с аргументами). | Терминальный TUI (`@opencode/tui` на Ink/React), CLI, Web UI (`@opencode/web`), Desktop (`@opencode/desktop`), Cloud-сервисы (SST). |

## 2. Глубокое различие в базовой парадигме (Cordis vs Effect-ts)

### 2.1. deepseek-harness: Модульность через Service Context (Cordis)
В deepseek-harness вся логика построена вокруг сервис-контейнера Cordis:
```typescript
// deepseek-harness: внедрение зависимостей через Context
import type { Context } from '@deepseek-ai/cordis'

export function apply(ctx: Context, config: Config) {
  ctx.provide('agentLoop')
  ctx.inject(['session', 'llm', 'tools'], (ctx) => {
    // Реактивная инициализация плагина при доступности сервисов
  })
}
```
- **Свойства подхода**: Каждый компонент (`packages/*`) оформлен как независимый плагин Cordis. Жизненный цикл плагина управляется контейнером (load, unload, dispose, HMR).
- **Изоляция и наследование**: Контексты могут разветвляться (fork). Субагенты и изолированные воркфлоу получают дочерний `Context`, в котором можно переопределить настройки, перехватить события или изолировать хранилище.

### 2.2. opencode: Монадический функциональный стек (Effect-ts)
В opencode весь код написан на Effect-ts — строго типизированной функциональной системе эффектов:
```typescript
// opencode: сервисы и эффекты
import { Effect, Layer, Context } from "effect"

export class Service extends Context.Service<Service, Interface>()("@opencode/Agent") {}

const layer = Layer.effect(
  Service,
  Effect.gen(function* () {
    const bus = yield* Bus.Service
    const state = yield* State.Service
    // ...
  })
)
```
- **Свойства подхода**: Отсутствие неконтролируемых побочных эффектов. Каждая операция возвращает `Effect<Success, Error, Requirements>`. Ошибки типизированы на уровне компилятора (`AIError | SessionRunnerModel.Error | AgentNotFoundError`).
- **Многопоточность и управление ресурсами**: Использование легковесных файберов (Fibers), структурированного параллелизма (`Scope`), прерывания (interruption) и потоков данных (`Stream`).

## 3. Различия в конфигурациях и глубоких настройках

### 3.1. deepseek-harness
1. **Профильная композиция**: Архитектура базируется на концепции профилей (`profile-boot.ts`). Профиль собирается из слоев патчей (`cordis.patch.yml`, `--patch`).
2. **Динамическая реактивность (Volatile Forms)**: Схемы настроек строятся на базе `@deepseek-ai/schemastery`. Поля, помеченные флагом `volatile`, поддерживают обновление «на лету» без перезапуска сервисов. Секреты (токены, ключи) автоматически скрываются через `redactSecrets`.
3. **Настройки среды выполнения**:
   - `ptc-runtime`: настройки таймаутов изолята VM (`syncTimeoutMs`, `maxTotalAgents`, `maxItemsPerCall`).
   - `sandbox-policy`: списки разрешений файловой системы, Windows ACL правила, фильтры bash/pwsh.
   - `compaction`: пороги сжатия контекста, выгрузка тяжелых артефактов и изображений (`compaction-image-offload`), отсечение старых результатов инструментов (`compaction-tool-result-pruner`).

### 3.2. opencode
1. **Единая схема конфигурации (`@opencode/schema/config`)**:
   - `shell`: конфигурация системного интерпретатора.
   - `compaction`: процент контекстного окна (`Percent = regex /^([1-9]\d?(\.\d+)?)%$/`) и лимиты токенов `Keep.tokens`.
   - `policy`: декларативные правила `allow / deny` для инструментов, провайдеров и интеграций (`provider.use`, `tool.use:shell:*`).
   - `warming`: параметры прогрева контекста LLM (`interval: "auto" | Duration`, `duration`, фоновый пинг 90% от cache TTL).
   - `watcher`: пути исключений для отслеживания файловой системы.
   - `flags`: развитый реестр фиче-флагов (`OPENCODE_FLAGS`), контролирующий экспериментальные функции.
2. **Иерархическая загрузка**: Конфигурация собирается от глобального уровня к уровню воркспейса с динамическим слиянием через Effect-пайплайн.

## 4. Сравнение интеграции с LLM и работы с контекстом

1. **deepseek-harness**:
   - Оптимизирован под архитектуру рассуждающих моделей (DeepSeek-R1 / V3).
   - Нативная поддержка протокола DeepSeek API, разметки мыслей (`reasoning_content`), подсчета токенов и биллинга.
   - Поддерживает интеграцию с Claude Code и протоколом ACP (Agent Client Protocol) как внешними исполнителями.
2. **opencode**:
   - Полностью абстрагированный и унифицированный модуль `@opencode/ai`.
   - Поддержка десятков провайдеров через единый интерфейс генерации, нормализацию ответов, причин остановки (`finishReason.normalized = "length" | "stop" | "tool_calls"`) и частичный парсинг потокового JSON (`partial-json`).

---

## 5. Выводы по первому отчёту
- **deepseek-harness** — это модульный, управляемый событиями и плагинами фреймворк на базе Cordis, ориентированный на глубокое раскрытие возможностей моделей DeepSeek, мощные графы задач (Team DAG) и безопасный запуск скриптов в песочнице PTC (Programmatic Tool Calling).
- **opencode** — это надежное полностековое монолитное приложение на базе строгой функциональной парадигмы Effect-ts, ориентированное на максимальную универсальность по провайдерам, богатую инфраструктуру UI/TUI/Cloud и строгую типизацию каждого шага пайплайна.
